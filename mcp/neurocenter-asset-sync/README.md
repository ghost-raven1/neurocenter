# neurocenter-asset-sync — кандидат MCP 0.9.0

Локальный stdio MCP для OpenCode и worker Нейроцентра. Он связывает серверный проект с папкой на компьютере, устанавливает одобренные скиллы/MCP/плагины вместе с готовыми платформенными зависимостями, настраивает MCP через локальный мастер, ищет и принимает существующие инструменты в проекте, сверяет файлы и возвращает выбранные ручные изменения. Локальная LanceDB синхронизируется с проектной PostgreSQL/pgvector.

Локальная приёмка текущего кандидата завершена в описанных границах. **Выпуск и production: NO-GO.** Доказательства и ограничения приведены в [отчёте 0.9](../../docs/reliable-installation-0.9-2026-10-18.md) и [описании системы](../../docs/current-implementation.md). История [0.8](../../docs/project-inventory-2026-10-18.md) не подтверждает новый архив; семь остальных нативных платформ и настоящий production ещё не приняты.

## Установка пользователя

Откройте страницу «Начало работы» своего Нейроцентра. OpenCode устанавливается отдельно через `install_opencode.sh` / `install_opencode.ps1`; мост — через `install.sh` / `install.ps1`. Используйте команды, показанные именно вашим сервером. Глобальная `npm install -g opencode-ai` не требуется.

Архив моста содержит Node.js **24.22.0** и зависимости. Установщик проверяет SHA, ОС/архитектуру, сохраняет прежний клиент и обновляет существующий JSON/JSONC OpenCode. Пользователю не нужны системные Node/npm и npm-реестр. Отсутствующий архив останавливает обновление до замены клиента.

Установщик пытается открыть страницу подтверждения автоматически; код остаётся запасным способом. Проверьте имя и отпечаток компьютера и подтвердите подключение. Установленные файлы без подтверждения аккаунтом ещё не означают доступный online MCP.

## Папка → установка → настройка → диагностика

1. **Папка:** выберите подключённый компьютер и общую папку на странице «Проекты». Для серверного проекта выберите локальный подкаталог и подтвердите подготовку мастера. У разных людей пути могут различаться.
2. **Установка:** администратор одобряет точный пакет, полный граф и SHA платформенных артефактов; разработчик устанавливает комплект из проектного каталога одним нажатием. Отсутствующий подходящий комплект блокирует установку с объяснением.
3. **Настройка MCP:** при необходимости откройте локальный мастер на выбранном компьютере, задайте параметры и обновите готовность настройки в каталоге. Для зависимостей MCP параметры задаются каждому инструменту отдельно.
4. **Сверка:** «Проверить файлы» сравнивает известную установку с неизменяемым серверным пакетом. Наблюдателю проекта эта проверка доступна. «Файлы сверены» не подтверждает запуск OpenCode.
5. **Диагностика:** после полной сверки и настройки выберите «Ещё → Проверить запуск в OpenCode» и дайте отдельное согласие на точный одобренный комплект и текущие ревизии параметров.

Мутации требуют права разработчика, собственного online устройства и действующей привязки. Сервер и worker повторно проверяют доступ; скрытая кнопка не является защитой API. История прежних папок доступна только для просмотра. Перед действием проверяется ожидаемый binding, поэтому смена папки не перенаправляет старую открытую модалку.

## Готовые зависимости без установочных скриптов

Формат 5 содержит ссылки `config.extra.runtimeArtifacts` на неизменяемые TAR.GZ для конкретных ОС, архитектуры и Linux libc. Одобрение закрепляет target, SHA, размеры, число файлов и точку входа. Изменение артефакта меняет manifest и требует нового одобрения. Оператор импортирует заранее собранный архив через [CLI публикации артефактов](../../scripts/production/import-runtime-artifact.mjs); сервер не выполняет присланные install hooks.

Архив хранится на отдельном постоянном серверном томе по SHA и передаётся только текущему авторизованному заданию установки. Том входит в полный backup/restore. На компьютере пользователя worker проверяет SHA и содержимое, распаковывает в закрытый неизменяемый кэш и переключает управляемую установку файловой транзакцией. Подмена, прерывание загрузки, недостаток места или несовместимая платформа сохраняют прежнюю установку.

Пределы одного архива: 256 МиБ сжатых данных, 1 ГиБ полезного содержимого и 20 000 файлов; локальный кэш — 2 ГиБ с резервом свободного места. Принимается ограниченный USTAR: ссылки, устройства, PAX, выход за каталог и конфликтующие переносимые пути запрещены. Кэш повторно проверяется перед использованием. Пользовательский компьютер не запускает npm/pip/Bun и не скачивает зависимости из стороннего реестра. JS-комплект использует поставляемый Node, нативная команда должна входить в одобренный платформенный артефакт; плагин OpenCode остаётся импортируемым JS-модулем.

## Закрытая локальная настройка MCP

`config.extra.localConfiguration` задаёт схему полей: ID, русское название, тип, обязательность, признак секрета и назначение env для локального MCP либо header для удалённого. Настройка скиллов и плагинов через персональные адаптеры в этот этап не входит.

Подготовка закрепляет установленный tuple, физический instance и digest схемы. Открытие запускает краткоживущую страницу на `127.0.0.1` выбранного компьютера и сразу освобождает очередь. Одноразовый токен передаётся во fragment; Host, Origin, CSRF и CSP ограничивают доступ к форме. Сессия действует 15 минут. Перед единственной попыткой сохранения сервер заново проверяет права, устройство, установленный комплект и одобрение; ошибка требует нового открытия мастера.

Параметры хранятся в закрытом локальном файле вне проекта: POSIX-каталог `0700`, файл `0600`; Windows — ACL текущего пользователя. Keychain/системное хранилище не используются. Привязка включает сервер, устройство, проект, физический instance, инструмент и digest схемы. Переименование того же instance сохраняет настройку; новая копия не получает значения автоматически. Сохранённые секреты не возвращаются даже в локальную форму.

Сервер видит только готовность, ID недостающих обязательных полей, случайную ревизию и дату проверки. Значения, их отпечатки и локальный URL формы не передаются в задания, журналы или конфиг проекта. Параметры не входят в резервные копии установленных файлов. Отдельный launcher подставляет env только соответствующему MCP; stdio-прокси удалённого MCP добавляет заголовки только одобренному URL, без redirects, OAuth или discovery.

Изменение параметров создаёт новую ревизию и аннулирует прежнюю диагностику. Перед запуском и после проверки сверяются ревизии всех настраиваемых MCP полного графа; исходное согласие не переносится на новые параметры. Private store ограничен 1 ГиБ и 10 000 записей, запись одного metadata-дескриптора — 8 МиБ. Значения имеют отдельный лимит 64 КиБ суммарно и до 8192 символов на поле. Автоматического удаления закрытых записей нет.

## Экземпляр папки

Marker `.opencode/neurocenter.json` v2 содержит `instanceId`. Приватный реестр закрепляет `realpath`, физические `dev`/`ino`, время создания и случайную привязку. Копия marker не доказывает прежний экземпляр; клон по тому же пути и подменённый каталог также отклоняются. Обычное чтение, heartbeat и `resolve_project_key` не принимают старую папку или копию автоматически.

| Режим | Поведение |
| --- | --- |
| `new` | Новый экземпляр для чистой папки; повтор для действующей текущей папки сохраняет её identity |
| `adopt-legacy` | Явная миграция marker v1 с проверкой закреплённых файлов и сохранением исторического происхождения |
| `new-copy` | Доступный зарегистрированный оригинал и копия проверяются; копия получает новый instance и binding |
| `transfer` | Проверенный перенос на том же компьютере сохраняет instance, меняет binding и управляемые абсолютные подключения. Переименование допустимо только для того же физического каталога |
| `resume` | Возврат ранее зарегистрированной A после B: проверка A, сохранение instance A, новый binding |

`prepare-bind-project` и `bind-project` разделяют подготовку и подтверждение. Подготовка закрепляется job ID/SHA и действует 15 минут. Для `resume` источник A берётся из подготовки; текущая B его не заменяет. Перенос не принимает подмену прежнего пути. Копия с другого компьютера без местного приватного реестра не становится проверенным переносом.

Старая v1-папка до явной миграции доступна как история; запись RAG требует подтверждённого экземпляра. Явный `projectKey` не обходит эту проверку. После прерывания подготовленная identity-запись откатывается, зафиксированная восстанавливается вперёд с долговечным результатом. Исторические задания не переписываются.

## Ручные правки и резервные копии

В «Ещё → Сравнить и восстановить файлы» подготовка закрепляет установленную версию, одобренный комплект, binding/instance и снимок файлов. Браузер видит относительные имена, операции добавления/замены/удаления, размеры и SHA. Предложенные замены ещё не применяются.

«Открыть полный diff на компьютере» открывает приватный HTML локально. Полный diff, исходники и ручные байты не передаются серверу. После явного «Сохранить локальный вариант и восстановить» повторно проверяются права, одобрение, digest и снимок; одна файловая транзакция сохраняет ручной вариант и восстанавливает одобренный. Устаревший план через 15 минут, новая правка или смена папки требуют новой подготовки. Неоднозначная конфигурация блокирует запись.

«Открыть резервные копии на компьютере» работает также после ошибки квоты и успешного восстановления. Она открывает приватную историю текущей папки, не удаляет файлы и не требует одобрения конкретного инструмента. При необходимости верните нужные сохранённые байты вручную без активной операции и повторите сверку. Автоматического слияния произвольных ручных правок нет.

Ограниченные чтения отклоняют FIFO, ссылки и подмену снимка. До записи `statfs` проверяет бюджет операции/отката и резерв **128 МиБ** на каждой файловой системе; расходы проекта и состояния на одном диске складываются. Суммарные pending/history копии ограничены **1 ГиБ**, приватные JSON/HTML планы — отдельным **1 ГиБ**. Старые копии и просроченные планы автоматически не удаляются. Это предварительная проверка места, а не его резервирование против других процессов.

## Найденные инструменты и выбранные локальные файлы

На вкладке **«Найдено в проекте»** наблюдатель явно запускает поиск только в подтверждённой папке собственного online-компьютера. Глобальный профиль и другие проекты не сканируются, код не исполняется. Вывод ограничен 200 относительными записями с типом, состоянием и фиксированной причиной. Неполный поиск не разрешает принятие.

Разработчик выбирает конкретный инструмент/версию проектного каталога с действующим одобрением. `prepare-adopt-installation` связывает точный одобренный набор со scan/candidate UUID и digest. После отдельного подтверждения `apply-adopt-installation` пишет **только квитанции и ledger**. Байты файлов и конфигурация OpenCode не меняются. Неканоническое расположение, неизвестное владение и несовпадение пакета дают отказ без переноса или переустановки. После принятия нужна новая сверка; запуска нет.

**«Ещё → Сохранённые локальные варианты»** показывает наблюдателю до 100 метаданных копий. Подготовка и применение требуют разработчика и одобренной текущей версии. Возврат допустим только для того же подтверждённого физического instance с текущими квитанциями, правами на пути и точными root/SET SHA/refs. Другая версия/копия, недоказанный legacy и изменения используемой общей зависимости блокируются.

`prepare-local-restore` сначала показывает полное сравнение. По умолчанию выбраны все файлы; после изменения галочек нажмите **«Подготовить выбранные изменения»**. Новый preview закрепляет `restorePaths`, старое согласие сбрасывается. Первоначальный список сохраняется, исключённые файлы можно вернуть. Пока точный выбранный набор не подготовлен, применение и старый diff недоступны; пустой набор не отправляется. Смена варианта/tuple/instance/прав или известного текущего состояния сбрасывает выбор.

`apply-local-restore` сохраняет нынешние байты в новую копию, затем возвращает только просмотренные выбранные файлы и собственные элементы JSONC. Метаданные управления и весь старый config не восстанавливаются. Ручной вариант не становится одобренным релизом и не меняет версию каталога. Полные diff/backup bytes остаются локально; после применения нужна сверка, автоматического запуска нет.

## Что проверяет запуск

Нужны актуальное одобрение установленной версии, полная сверка, текущая папка и отдельный `consentManifest` — SHA точного одобренного пакета/комплекта. Используется закреплённый OpenCode **1.14.48** со сверкой SHA и новым временным HOME/XDG/профилем. Личный OpenCode из PATH не используется. Отсутствующий движок даёт `unsupported`; запуск из исходников сам по себе не подтверждает наличие готового диагностического движка.

- Скилл: структура; скрипты не исполняются.
- MCP: подключение/handshake и списки tools/resources/prompts. `tools/call` не вызывается; удалённый MCP может получить эти разрешённые запросы.
- Плагин: загрузка и поддерживаемая серверная инициализация. Возвращаемые hooks, произвольные события и TUI не регистрируются и не проверяются.

Автоматических npm/pip/Bun установок, OAuth и вызовов LLM нет. Ресурсы входят в пакет либо одобренный готовый артефакт; персональные параметры MCP задаются локальным мастером. Неразрешённая настройка или недостающая зависимость дают `needs_configuration`, неподдерживаемый сценарий — `unsupported`. Прежние placeholders сами по себе не подтверждают готовую локальную настройку.

Изоляция профиля не является песочницей ОС для одобренного кода. Deadline диагностики — **59 секунд**; завершаются только собственные группы процессов, на Windows — собственный Job Object. Сервер получает фиксированные статус/код, дату, версию/SHA движка, согласованные ревизии конфигурации и счётчики, без сырого stdout/stderr, исходников и значений секретов. `passed` относится только к перечисленной области всего комплекта, а не ко всем hooks или бизнес-сценариям.

Windows-поставка требует `bin/neurocenter-job.exe` нужной PE-архитектуры с SHA в `runtime.json`. Helper собирается через [MSVC-скрипт](../../scripts/build-windows-job-helper.ps1) и передаётся упаковщику через `--windows-job-helper=<файл>`. Он помещает только собственный suspended child в новый Job до запуска и наблюдает собственного Node-родителя; при его смерти Job закрывается вместе с дочерними процессами. Чужие процессы по имени не перечисляются и не завершаются. Без закреплённого собственного helper возможность остаётся `unsupported`; наличие исходника и синтетических PE-тестов не подтверждает нативную приёмку Windows. Ограничение 59 секунд относится к диагностике, а не к обычной длительной работе MCP.

## Контракт и инструменты

Очередь использует protocol **2**. Готовые артефакты и схема локальной настройки требуют package format **5**; чтение форматов 2–4 сохраняется. Install/uninstall даже одиночного пакета требуют `install-set-v1`. Новые возможности проверяются отдельно: отсутствие диагностики не должно блокировать выбор общей папки или обычные RAG-сценарии.

| Capabilities | Назначение |
| --- | --- |
| `durable-completions`, `managed-installations` | Сохранённые подтверждения и управляемые установки |
| `package-v3`, `package-v4`, `package-v5`, `install-set-v1` | Совместимые форматы, атомарный комплект и владельцы зависимостей |
| `runtime-artifacts-v1` | Готовые платформенные зависимости по закреплённым SHA |
| `local-mcp-config-v1` | Закрытый локальный мастер MCP и готовность без передачи значений |
| `installation-inspection-v1` | Сверка известной установки без исполнения |
| `workspace-instance-v1` | Подтверждённые экземпляры и мастер папок |
| `local-change-plan-v1` | Подготовка/применение восстановления, приватный diff и открытие копий |
| `runtime-probe-v1` | Отдельная диагностика с согласием |
| `project-inventory-v1` | Явный поиск только в выбранном проекте |
| `adopt-installation-v1` | Принятие точного одобренного инструмента без замены файлов/config |
| `local-recovery-v1` | Метаданные локальных вариантов и возврат выбранных файлов через preview |

Установки и изменения выполняются через серверную очередь, а не обходной MCP tool. Пакет/версия/SHA и права закрепляются сервером; общий комплект ограничен 20 инструментами, 200 файлами и 16 МиБ. Повтор ACK не повторяет файловую запись. Старые `install_asset` / `install_plugin_bundle` удалены.

В stdio зарегистрированы подключение/статус, сканирование скиллов и плагинов, определение проекта, `resolve_project_key`, инспекция/дельта LanceDB, публикация скиллов, синхронизация/обратная передача RAG, чтение версий/файлов пакетов. Сканирование не присваивает найденные файлы управляемой установке. Инструменты записи не являются read-only; входы валидируются. Наличие зарегистрированного `activate_bundle_version` не означает готовый rollback: серверный маршрут пока отвечает 501.

Серверная миграция **1 — `reliable-local-installation`** вводит планы и события экземпляров. Миграция **2 — `project-inventory-local-variants`** добавляет `purpose` (`repair` / `adopt` / `restore-local`) и `source_id`. Прежние планы остаются ремонтными; kind задания и purpose проверяются совместно, подготовку другого вида применять нельзя. Настройка MCP использует метаданные существующих заданий, без изменения прежних миграций. История миграции хранит SHA SQL; применение транзакционно и последовательно под advisory lock. Общий downgrade/rollback стека этим не реализован.

## Платформы и допуск

Результаты текущего кандидата, SHA архивов и фактически повторённые сценарии приводятся только в [отчёте 0.9](../../docs/reliable-installation-0.9-2026-10-18.md). Предыдущие проверки не засчитываются новой сборке автоматически. Нативная матрица включает macOS ARM64/x64, Windows x64/ARM64, Linux glibc x64/ARM64 и Linux musl x64/ARM64. Наличие архива, MSVC-исходника или синтетической фикстуры не равно запуску на соответствующей платформе; init не подтверждает все hooks.

Linux-диалог папки требует графической сессии и zenity/kdialog; ожидание ограничено двумя минутами. Нативная LanceDB — отдельная возможность: отсутствующий пакет не блокирует базовый MCP, но явно блокирует неподдерживаемую локальную RAG; macOS x64 остаётся таким ограничением текущей поставки.

Локальная приёмка кандидата не объявляется завершённой до сохранения всех доказательств. Непроверенные нативные варианты, реальные Blitz/сервер, независимое внешнее восстановление, нагрузка и длительный прогон остаются условиями допуска; CI и публикация не подтверждены, `.git` в checkout отсутствует. **Release/production NO-GO.** Изоляция диагностического профиля не заменяет песочницу ОС.

## Разработка

Для воспроизводимого локального прогона используйте Node.js **24.22.0**, совпадающий с поставкой. В каталоге этого пакета:

```bash
npm ci
npm run typecheck
npm test
npm run build
```

`npm run dev` запускает stdio из исходников. Самостоятельная source-сборка не заменяет автономный runtime-архив и нативную приёмку. Проверки используют временные папки, собственные устройства и изолированные профили; личные OpenCode/MCP не являются целями установки.

| Каталог | Ответственность |
| --- | --- |
| `src/index.ts`, `src/tools/` | stdio и MCP tools |
| `src/bridge/` | Подключение, очередь, экземпляры, файловые транзакции, сверка и восстановление |
| `src/features/runtime-probe/` | Изолированный профиль, закреплённый движок, ограниченные MCP/plugin/skill проверки |
| `src/features/runtime-artifacts/` | Выбор платформы, проверка и закрытый кэш готовых комплектов |
| `src/features/local-configuration/` | Локальный мастер, private vault, launcher и удалённый stdio-прокси |
| `src/lib/` | Конфигурация, обнаружение проекта и работа с локальной LanceDB |
