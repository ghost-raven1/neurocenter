# Разработка и поиск дефектов

Рабочий цикл Neurocenter: установить причину → воспроизвести отказ тестом → исправить код → повторить тест с покрытием → собрать текущие исходники → провести независимое ревью. Команды используют уже установленный Node 24 и зависимости; они не устанавливают недостающий runtime.

## Найти причину

В Codex доступен диагностический MCP `neurocenter-dev`: `workspace_status` показывает checkout и версии, `services_health` проверяет фиксированные локальные endpoints, `service_logs` читает ограниченный журнал сервиса, `verification_summary` объясняет сохранённый отчёт покрытия. [Подключение и ограничения](agent-kit.md#mcp-для-разработки-neurocenter).

Сопоставляй действие пользователя с ошибкой, временем, загруженным артефактом и ревизией. Затем попроси Codex добавить воспроизводящий регрессионный тест, исправить причину и запустить относящиеся проверки. Код меняется обычными средствами редактирования; диагностический MCP не выполняет произвольные команды и не меняет рабочие данные.

## Проверить выбранный модуль

```sh
npm run check -- --help
npm run check -- --package frontend --step typecheck
scripts/dev.sh check --package frontend --step typecheck
```

`--package` и `--step` можно повторять. Выбор ограничивает план их пересечением. Отдельный шаг `test` не запускает сборку. Пустое пересечение возвращает ошибку: например, у API Gateway нет npm-скрипта `test`, поэтому его тесты запускай командой покрытия ниже. Селекторы не включают общие контракты или Compose. Вызов без селекторов сохраняет прежний полный план, включая сборку в обычный `dist`.

Справка и неверные аргументы обрабатываются до создания отчёта и запуска проверок. `dev.sh check` передаёт выбранные параметры и код результата, не загружая активные dotenv-файлы. Отчёт выполненного плана сохраняется в `.run/check/<попытка>/report.json`.

## Воспроизвести баг и измерить покрытие

```sh
npm run coverage -- --package frontend --test-file test/error-message.test.ts
```

Укажи ровно один пакет и до 32 относительных `--test-file` внутри его `test/`. Допускаются обычные тестовые файлы без ссылок, обхода каталогов и инфраструктурных сценариев. Команда запускает только выбранные unit-тесты. Для PostgreSQL, S3, native и integration нужны отдельные профили с собственными фикстурами.

В отчёте перечислены запрошенные файлы, фактически выполненные тесты, исключения по выбору и отдельные инфраструктурные исключения. Невыполненный или лишний файл делает проверку неполной. Знаменатель покрытия включает исходники выбранного пакета, в том числе не импортированные выбранным тестом модули. `complete` относится к запрошенному набору; это не 100% покрытия модуля или проекта.

Без `--test-file` остаётся прежний режим покрытия пакетов; без `--package` он выбирает все восемь. HTML, исходный JSON и `manifest.json` сохраняются в новом `.run/coverage/<попытка>/`. Не смешивай AST unit-покрытие и native V8 как один процент.

## Собрать текущие правки отдельно

```sh
npm run build:isolated -- --package frontend --plan
npm run build:isolated -- --package frontend
npm run build:isolated -- --all
```

Проверка копирует текущие отслеживаемые и новые неигнорируемые файлы Git, учитывая локальные правки и удаления. Активные dotenv, файлы секретов по известным именам, пользовательские npm-настройки, зависимости и готовые выходы исключаются из снимка. Состав и SHA сохранены в отчёте. Изменение исходников во время подготовки останавливает сборку; изменение после запуска не считается проверкой текущего состояния.

Компиляторы работают последовательно в `.run/isolated-build/<попытка>/repository` с отдельными HOME, кэшем и журналами. Никаких установок зависимостей; кандидат не копируется в рабочий `dist`. Отчёт проверяет ожидаемые точки входа, SHA артефактов и сохранность рабочих выходов всех восьми пакетов. Отказ и отмена сохраняют причину и частичный результат.

Это изоляция исходников и выходов, а не защитная песочница: уже установленные `node_modules` подключаются ссылками, содержимое зависимостей не заморожено. Доверенный build-скрипт может писать через ссылку; offline-настройка npm не является сетевым фильтром. Отмена завершает только собственную группу процессов; эта проверка жизненного цикла подтверждена на macOS. Сборка не подтверждает работу API, браузера, миграций или production.

Канонические идентификаторы: `frontend`, `catalog-service`, `api-gateway`, `feature-flags-service`, `oauth2-bridge`, `rag-sync-service`, `skills-service`, `bridge`. Тяжёлые сборки и профили покрытия запускай по очереди. Сохраняй отдельно пройденное, пропущенное и непроверенное; бэклог обновляй после реализации и проверок.
