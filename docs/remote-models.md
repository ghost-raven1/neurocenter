# Модели: удалённый API и импорт OpenCode

Карточка модели содержит публичную техническую идентичность. Для локальной модели это Ollama tag и SHA манифеста; для удалённой — протокол `remote-openai` или `remote-ollama`, точный model ID и объявленная версия. Удалённый API не имеет SHA весов: `verificationSha256` подтверждает проверенную конфигурацию подключения и размерность ответа.

Адрес и авторизация находятся в отдельном приватном подключении площадки. Управлять им может главный администратор через интерфейс. API-ключ — write-only; GET возвращает только факт его наличия. Ключи, env-значения и адрес провайдера не входят в публичную карточку, экспорт ассета, аудит и установку на компьютер.

## Хранение ключей

Для ввода ключа через UI задайте `NEUROCENTER_MODEL_CREDENTIAL_KEY` — ровно 32 случайных байта в каноническом base64. Поддерживается существующий механизм `NEUROCENTER_MODEL_CREDENTIAL_KEY_FILE`; одновременно оба варианта задавать нельзя. Например, оператор может создать файл с режимом `0600` командой Node, которая записывает `crypto.randomBytes(32).toString('base64')` непосредственно в файл, без вывода значения в терминал.

Ключи моделей шифруются AES-256-GCM: отдельный nonce, AAD с model ID и ревизией подключения, проверка master key ID. Fallback на internal token или plaintext отсутствует. Без master key UI предлагает серверную env-ссылку `NEUROCENTER_REMOTE_MODEL_*` или API без ключа; ввод нового stored key отключён.

Master key должен входить в закрытую процедуру резервного копирования отдельно от БД. Замена master key без перешифровки делает сохранённые ключи недоступными; UI и inference возвращают явную ошибку, прежние записи не изменяются. Ротация самого provider key выполняется через UI с повторной проверкой, без изменения семантического pin при неизменных model/version/endpoint/dimension.

## Подключение и история

«Сохранить и подключить» сохраняет приватную конфигурацию и запускает существующее durable задание проверки. Удалённому провайдеру отправляется ограниченная настоящая проба. Векторы проверяются на количество, порядок, размерность, конечность float32 и ненулевое значение; vision проходит проверку числа и цвета. Streaming, redirects и повтор оплачиваемого запроса без явного действия не используются.

Запись настроек защищена CAS карточки и приватного подключения. Probe повторно проверяет права и обе ревизии перед фиксацией. Исторические project pins читают immutable descriptor и соответствующее проверенное подключение. Изменение head не заменяет модель внутри старого индекса. Перестроение индекса и смена размерности проходят управляемый проектный reindex.

Удаление карточки через общий impact dialog сохраняет историю и позволяет главному администратору выбрать судьбу проектных назначений. Отдельное удаление приватного подключения отзывает все его исторические ревизии. Оно блокируется с перечнем проектов, пока подключение выбрано для их RAG. Удаление назначений модели также блокируется для активных индексов: сначала нужно явно переключить модель или отключить эмбеддинги в настройках проекта; режим «только общий каталог» сохраняет их работу.

## OpenCode

В каталоге выберите проект, затем «Из OpenCode» и подключённый компьютер. Мост читает документированные глобальные/project/custom/inline/managed-file конфиги и только факт наличия авторизации из `auth.json`. Парсинг JSONC поддерживает комментарии и завершающие запятые. Ссылки `{file:...}` и `{env:...}` не раскрываются. Родительские проекты, организационные network-конфиги и macOS MDM preferences не сканируются; UI явно сообщает об ограничениях.

Поддерживаются явно OpenAI-compatible провайдеры. Другие SDK, custom headers и модельные overrides отмечаются как требующие ручной настройки; они не подменяются похожим протоколом. Выбранные `model` и `small_model` тоже попадают в список. Chat не превращается автоматически в embedding. После импорта адрес подставляется в приватную форму; ключ с компьютера не переносится.

Одновременные `opencode.json` и `opencode.jsonc`, повторяющиеся JSON-ключи, ошибки чтения, symlinks и изменение файлов прекращают выдачу пригодного списка. Импорт проверяет owner, устройство, текущую папку/instance, роль и срок отчёта. Повтор того же импорта возвращает ту же карточку.

Документированный порядок OpenCode проверен по [официальной конфигурации](https://opencode.ai/docs/config/) и [провайдерам](https://opencode.ai/docs/providers/). Это импорт ограниченной локальной metadata, не обещание полного resolved runtime всех источников OpenCode.

## Локальная поставка

Локальный запуск использует только зарегистрированный `model-bundle` нового source envelope из `neurocenter-assets`. `AssetSourcesService.modelSupply` выдаёт серверному исполнителю exact lock, native bundle и checked blob paths. Native engine собирает и проверяет файлы, используя локальный transport без сетевого fallback. `/api/pull` и автоматический seed встроенных карточек удалены. Ручное создание карточки поддерживает удалённые API; локальные карточки появляются при импорте ассета.

Внутреннее имя локальной модели — immutable alias `neurocenter/<manifest SHA>:v1`. Публичное имя не меняется. Импорт дополняет набор aliases атомарно под файловой lease, сохраняя прежние версии для активных индексов и соседних проектов. Разные SHA одного публичного Ollama tag не перетирают друг друга.

Проверка без настоящих API-ключей и платных вызовов: `node scripts/test/remote-models-db.mjs`. Она создаёт отдельную БД, поднимает локальный HTTP provider, проверяет CAS/историю/отзыв/metadata import и native bundle installation, затем удаляет только собственные fixtures. Отчёт: `output/remote-models/database-report.json`.

## Разрешения установленного RAG

Каждый запрос устройства передаёт exact установку `{kind,id,version,manifest}` вместе с project/binding/instance и сохранённым revision/modelPin. Нужен мост с `hosted-rag-grants-v1`. Current и historical модели используют один путь: наличие текущего выбора само по себе не разрешает запрос.

Явный connect intent регистрирует разрешение при авторизации задания, до локального commit. Пока кандидат строится, прежнее разрешение сохраняется для отката. Только подтверждённое успешное завершение заменяет прежние разрешения той же установки. Failed, timeout и потерянный ACK не доказывают отсутствие локального commit и не отзывают разрешение молча. Смена общей модели сохраняет работу других установок и компьютеров по их историческим pins; это разрешение на inference, а не на запись старого поколения в серверный индекс.

На каждом batch и после inference повторно проверяются устройство, роль, проект, папка/instance, установка, проектное назначение пакета, одобрение, UUID эпохи назначения модели и immutable model history. Удаление и повторное добавление модели или пакета не оживляет старое разрешение. Отключение embedding, отзыв роли/одобрения/приватного подключения, удаление установки и подтверждённая смена identity устройства/папки отзывают разрешения постоянно. Offline, pause и неполный промежуточный report не являются отзывом.

Одноразовая миграция принимает только проверенные успешные connect jobs с совпавшим результатом, действующей установкой/одобрением, неизменённым назначением и доступной историей модели. Во время inference старые jobs не используются как fallback.

Регрессионная проверка настоящих PostgreSQL locks, отката и отзывов: `node scripts/test/hosted-rag-grants-db.mjs`; отчёт `output/remote-models/hosted-grants-report.json`. Тест использует собственную БД и синтетические модели без платных API.
