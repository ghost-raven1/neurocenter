# Модели: удалённый API и импорт OpenCode

Карточка модели содержит публичную техническую идентичность. Для локальной модели это Ollama tag и SHA манифеста; для удалённой — протокол `remote-openai` или `remote-ollama`, точный model ID и объявленная версия. Удалённый API не имеет SHA весов: `verificationSha256` подтверждает проверенную конфигурацию подключения и размерность ответа.

Адрес и авторизация находятся в отдельном приватном подключении площадки. Управлять им может главный администратор через интерфейс. API-ключ — write-only; GET возвращает только факт его наличия. Ключи, env-значения и адрес провайдера не входят в публичную карточку, экспорт ассета, аудит и установку на компьютер.

## Хранение ключей

Для ввода ключа через UI задайте `NEUROCENTER_MODEL_CREDENTIAL_KEY` — ровно 32 случайных байта в каноническом base64. Поддерживается существующий механизм `NEUROCENTER_MODEL_CREDENTIAL_KEY_FILE`; одновременно оба варианта задавать нельзя. Например, оператор может создать файл с режимом `0600` командой Node, которая записывает `crypto.randomBytes(32).toString('base64')` непосредственно в файл, без вывода значения в терминал.

Ключи моделей шифруются AES-256-GCM: отдельный nonce, AAD с model ID и ревизией подключения, проверка master key ID. Fallback на internal token или plaintext отсутствует. «Настроить API» доступно на карточке удалённой модели независимо от состояния проверки. При создании карточки следующий шаг явно открывает подключение. По умолчанию форма показывает поле API-ключа; без master key объясняет причину, по которой его пока нельзя сохранить. Можно выбрать серверную env-ссылку `NEUROCENTER_REMOTE_MODEL_*` или API без ключа. Пустое поле сохраняет прежний ключ только для уже сохранённого `stored`-подключения; переход с env на stored требует нового ключа.

Master key должен входить в закрытую процедуру резервного копирования отдельно от БД. Замена master key без перешифровки делает сохранённые ключи недоступными; UI и inference возвращают явную ошибку, прежние записи не изменяются. Ротация самого provider key выполняется через UI с повторной проверкой, без изменения семантического pin при неизменных model/version/endpoint/dimension.

## Подключение и история

«Сохранить и подключить» сохраняет приватную конфигурацию и запускает существующее durable задание проверки. Удалённому провайдеру отправляется ограниченная настоящая проба. Векторы проверяются на количество, порядок, размерность, конечность float32 и ненулевое значение; vision проходит проверку числа и цвета. Streaming, redirects и повтор оплачиваемого запроса без явного действия не используются.

Запись настроек защищена CAS карточки и приватного подключения. Probe повторно проверяет права и обе ревизии перед фиксацией. Исторические project pins читают immutable descriptor и соответствующее проверенное подключение. Изменение head не заменяет модель внутри старого индекса. Перестроение индекса и смена размерности проходят управляемый проектный reindex.

### Параметры подключения

В разделе «Параметры модели» настраиваются приватные значения по умолчанию. Они передаются сервером провайдеру, а не остаются декоративными полями карточки.

| Поле | Диапазон | Применение |
| --- | --- | --- |
| Температура (`options.temperature`) | 0–2 | Chat и vision |
| Top-p (`options.topP`) | 0–1 | Chat и vision |
| Лимит ответа (`options.maxOutputTokens`) | 1–32768, целое | Chat и vision |
| Размер контекста (`options.contextWindow`) | 128–2097152, целое | Chat и vision: объявленный бюджет OpenAI-compatible; для Ollama также `num_ctx` |
| Таймаут (`timeoutMs`) | 1000–300000 мс, целое | Все удалённые модели, по умолчанию 90000 мс |

Пустые поля означают настройки провайдера; ноль не считается пустым значением. Явные параметры отдельного inference-запроса переопределяют сохранённые значения. OpenAI-compatible API получает `temperature`, `top_p`, `max_tokens`; Ollama — `temperature`, `top_p`, `num_predict`, `num_ctx`. Для OpenAI-compatible `contextWindow` — объявленная оператором вместимость из документации провайдера: она используется серверным планировщиком чата и не передаётся как параметр API. Такое значение не увеличивает настоящее окно модели. Параметры генерации не принимаются для embedding.

Эти пределы ограничивают запросы Нейроцентра; конкретный провайдер может поддерживать меньший диапазон или не поддерживать отдельный параметр. Проверка подключения возвращает его отказ явно. Dimension эмбеддингов задаётся в карточке и подтверждается пробой, флаг запроса размерности — в подключении. Уже построенный индекс меняет модель/размерность только через переиндексацию.

Параметры генерации входят в семантический pin и сохраняются вместе с исторической ревизией подключения. Таймаут является операционной настройкой и не меняет pin. Смена ключа также не меняет pin. Внешние лимиты клиента, шлюза и RAG-запроса могут завершить вызов раньше выбранного таймаута; device embedding ограничен 105 секундами на весь запрос.

Удаление карточки через общий impact dialog сохраняет историю и позволяет главному администратору выбрать судьбу проектных назначений. Отдельное удаление приватного подключения отзывает все его исторические ревизии. Оно блокируется с перечнем проектов, пока подключение выбрано для их RAG. Удаление назначений модели также блокируется для активных индексов: сначала нужно явно переключить модель или отключить эмбеддинги в настройках проекта; режим «только общий каталог» сохраняет их работу.

## OpenCode

В каталоге выберите проект, затем «Из OpenCode» и подключённый компьютер. Мост читает документированные глобальные/project/custom/inline/managed-file конфиги и только факт наличия авторизации из `auth.json`. Парсинг JSONC поддерживает комментарии и завершающие запятые. Ссылки `{file:...}` и `{env:...}` не раскрываются. Родительские проекты, организационные network-конфиги и macOS MDM preferences не сканируются; UI явно сообщает об ограничениях.

Поддерживаются явно OpenAI-compatible провайдеры. Учитываются upstream ID из `model.id`, запасной адрес `provider.api`, списки разрешённых/запрещённых моделей. Безопасные числовые `model.options.temperature`, `topP`, `maxOutputTokens` и `provider.options.timeout` подставляются в форму подключения для проверки перед сохранением. `model.temperature` — признак поддержки, а `model.limit` — возможности модели: они не превращаются в параметры запроса. Другие SDK, custom headers и неподдерживаемые overrides отмечаются как требующие ручной настройки; они не подменяются похожим протоколом. Выбранные `model` и `small_model` тоже попадают в список. Chat не превращается автоматически в embedding. Ключ с компьютера не переносится. При повторном импорте уже настроенное подключение имеет приоритет над подсказками из сканирования.

Одновременные `opencode.json` и `opencode.jsonc` объединяются в порядке JSON → JSONC, сохраняя непересекающиеся настройки. Учитываются глобальный `config.json`, домашняя `.opencode`, custom/inline/managed-file конфиги и `OPENCODE_DISABLE_PROJECT_CONFIG`. Повторяющиеся JSON-ключи, ошибки чтения, symlinks и изменение файлов прекращают выдачу пригодного списка. Импорт проверяет owner, устройство, текущую папку/instance, роль и срок отчёта. Повтор того же импорта возвращает ту же карточку.

Документированный порядок OpenCode проверен по [официальной конфигурации](https://opencode.ai/docs/config/), [провайдерам](https://opencode.ai/docs/providers/) и исходникам закреплённой версии 1.14.48. Это явное чтение и импорт доступных локальных настроек. Автоматического наблюдения за файлами и обратной записи в OpenCode нет; исходные конфиги и `auth.json` не изменяются.

## Чат с моделью

В разделе «Модели» кнопка «Чат» открывает текстовый диалог с выбранной chat- или vision-моделью. Подключение должно быть проверено; в выбранном проекте модель должна быть назначена, а у участника нужна рабочая роль — разработчик или выше. Главный администратор также может открыть чат из общего каталога. Embedding-модели не предлагают чат. Архивная карточка, сохранённая в проекте, остаётся доступна его участникам по действующим правам.

Личные диалоги обслуживаются `/api/model-chats` через API Gateway. Модель использует сохранённые серверные параметры и ключ; форма чата не получает адрес или ключ провайдера. Проект ограничивает доступ, но его документы, RAG и инструменты автоматически в переписку не добавляются. Для vision-моделей этот экран также отправляет только текст.

История и вложения сохраняются на сервере; диалоги личные, с привязкой к модели и выбранному проекту. Даже главный администратор не читает чужой диалог по ID. Список позволяет найти, переименовать и удалить диалог; закрытие окна сохраняет переписку. «Новый диалог» начинает отдельный контекст. Enter отправляет сообщение, Shift+Enter добавляет строку; подтверждение IME не отправляет текст. «Остановить» отменяет HTTP-запрос по цепочке браузер → Gateway → Catalog → провайдер. После ошибки или отмены можно повторить то же сообщение без дубликата либо вернуть его в редактор. Идемпотентные идентификаторы предотвращают повторный платный вызов при повторной доставке запроса. Автоматических повторов нет.

Документы добавляются кнопкой, перетаскиванием или вставкой файла из буфера. Поддерживаются PDF с текстовым слоем, DOCX, TXT/Markdown, CSV/TSV и распространённые исходники. Сервер проверяет содержимое и извлекает plain text в отдельном worker с ограничением времени и памяти. Предпросмотр показывает именно текст, который получит модель; страницы PDF помечаются. Файл без текста, PDF с паролем, повреждённый документ, неподдерживаемая кодировка или превышение лимита возвращают явную ошибку. При частично пустом PDF показывается предупреждение. Код и HTML из файлов не выполняются, инструкции из документа остаются частью пользовательского сообщения.

Лимиты вложений: 10 МиБ на файл, 100 КиБ извлечённого текста, 100 страниц PDF, до пяти файлов в сообщении, 50 МиБ и 100 загрузок на диалог; до 100 диалогов на пользователя. Общий текст нового сообщения вместе с файлами ограничен 128 КиБ. Оригиналы хранятся в приватных бакетах Ceph/S3, извлечённый текст и ссылки — в PostgreSQL. Удаление неиспользованного вложения или диалога ставит объекты в durable очередь удаления. Перенос старых bytea выполняется с проверкой размера и SHA-256. Настройка, локальное S3-хранилище, обновление и требования к резервированию описаны в [доставке файлов чата](chat-files-ceph.md). Загрузка в чат не публикует файл в каталоге и не добавляет его в проектный RAG.

Предела в 40 сообщений нет. При приближении оценки к 80% известного входного бюджета либо превышении транспортного бюджета сервер автоматически готовит сводку ранней части беседы той же выбранной моделью. Контекст для ответа состоит из сохранённой сводки и оставшейся полной части; исходная история и файлы не изменяются. Старые сообщения загружаются страницами с ограничением объёма ответа. За один явный запрос допускается до восьми вызовов сжатия; большой диалог сохраняет прогресс и предлагает продолжить повтором. Предварительная оценка при наборе текста модель не вызывает. Сжатие может терять детали и требует дополнительных inference-вызовов; полные оригиналы доступны в истории.

Каждый текстовый фрагмент inference ограничен 128 КиБ UTF-8; сериализованный JSON-запрос — 8 МиБ. Большие сохранённые ответы передаются полными последовательными фрагментами, пока вмещаются в общий бюджет. Если новое сообщение или документ сами больше настроенного окна, сжатие прошлого не помогает: сервер отклоняет отправку с конкретной причиной. При неизвестном окне модели размер не угадывается; автосжатие реагирует на транспортный/ресурсный бюджет, а реальный предел провайдера всё ещё может оказаться меньше. Ошибка или отмена сжатия не удаляет историю; валидные сохранённые промежуточные сводки переиспользуются при повторе.

При смене технической идентичности или настроек модели нужен новый диалог; обычное изменение названия/описания историю не сбрасывает. Каждый запрос чата передаёт `expectedModelPin`: сервер проверяет выбранную семантику до и после каждого вызова провайдера, включая сжатие. Отзыв доступа, отключение хостинга моделей или отмена блокируют фиксацию позднего ответа. Если модель достигла лимита ответа, интерфейс показывает причину; можно попросить продолжить.

Основной индикатор контекста занимает одну строку; оценки, окно модели, резерв и технические ограничения раскрываются по запросу. При отсутствии контекстного лимита процент заполнения не рисуется. Счётчики последнего ответа показываются как данные провайдера только при их наличии; отсутствие usage отличается от настоящего нуля. Оценка до запроса не является точным подсчётом токенизатором. Во время сжатия показывается фактическая серверная стадия, а не предположение по длительности запроса.

Для управляемой локальной Ollama `MODEL_CHAT_CONTEXT_WINDOW_TOKENS` одновременно задаёт бюджет планировщика и отправляемый `num_ctx`. Native managed dev и Compose явно используют 4096 по умолчанию, согласованно с `OLLAMA_CONTEXT_LENGTH`. Это выделенное окно выполнения, а не заявление о максимальной вместимости модели. Для отдельного внешнего runtime без настройки окно остаётся неизвестным. Для OpenAI-compatible его можно объявить в форме подключения по документации провайдера.

Ответ отображается как Markdown с блоками кода и таблицами, доступно копирование. HTML не выполняется, внешние изображения не загружаются, ссылки доступны только по HTTP(S). Потоковой выдачи токенов в этой версии нет.

## Локальная поставка

Локальный запуск использует только зарегистрированный `model-bundle` нового source envelope из `neurocenter-assets`. `AssetSourcesService.modelSupply` выдаёт серверному исполнителю exact lock, native bundle и checked blob paths. Native engine собирает и проверяет файлы, используя локальный transport без сетевого fallback. `/api/pull` и автоматический seed встроенных карточек удалены. Ручное создание карточки поддерживает удалённые API; локальные карточки появляются при импорте ассета.

Внутреннее имя локальной модели — immutable alias `neurocenter/<manifest SHA>:v1`. Публичное имя не меняется. Импорт дополняет набор aliases атомарно под файловой lease, сохраняя прежние версии для активных индексов и соседних проектов. Разные SHA одного публичного Ollama tag не перетирают друг друга.

Проверка без настоящих API-ключей и платных вызовов: `node scripts/test/remote-models-db.mjs`. Она создаёт отдельную БД, поднимает локальный HTTP provider, проверяет CAS/историю/отзыв/metadata import и native bundle installation, затем удаляет только собственные fixtures. Отчёт: `output/remote-models/database-report.json`.

HTTP-проверка параметров, ключей, прав и ошибок через настоящий Gateway: `MODEL_CONNECTION_TEST_ADMIN_URL=postgresql://qa:qa-test-only@127.0.0.1:59604/postgres node --test scripts/test/model-connections-http.test.mjs`. Укажите порт собственного одноразового PostgreSQL; fixture запрещает стандартный порт 5432, создаёт отдельную БД и удаляет её после проверки. Сервисы должны быть предварительно собраны.

## Разрешения установленного RAG

Каждый запрос устройства передаёт exact установку `{kind,id,version,manifest}` вместе с project/binding/instance и сохранённым revision/modelPin. Нужен мост с `hosted-rag-grants-v1`. Current и historical модели используют один путь: наличие текущего выбора само по себе не разрешает запрос.

Явный connect intent регистрирует разрешение при авторизации задания, до локального commit. Пока кандидат строится, прежнее разрешение сохраняется для отката. Только подтверждённое успешное завершение заменяет прежние разрешения той же установки. Failed, timeout и потерянный ACK не доказывают отсутствие локального commit и не отзывают разрешение молча. Смена общей модели сохраняет работу других установок и компьютеров по их историческим pins; это разрешение на inference, а не на запись старого поколения в серверный индекс.

На каждом batch и после inference повторно проверяются устройство, роль, проект, папка/instance, установка, проектное назначение пакета, одобрение, UUID эпохи назначения модели и immutable model history. Удаление и повторное добавление модели или пакета не оживляет старое разрешение. Отключение embedding, отзыв роли/одобрения/приватного подключения, удаление установки и подтверждённая смена identity устройства/папки отзывают разрешения постоянно. Offline, pause и неполный промежуточный report не являются отзывом.

Одноразовая миграция принимает только проверенные успешные connect jobs с совпавшим результатом, действующей установкой/одобрением, неизменённым назначением и доступной историей модели. Во время inference старые jobs не используются как fallback.
