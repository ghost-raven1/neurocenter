# Повторный аудит ранних возможностей — 22 октября 2026

Проверены выбранные границы фич, реализованных до последнего аудита Ceph: доступ и роли, флаги, импорт ассетов, конфигурация OpenCode, переиндексация и синхронизация RAG, контракты привязки папки и обучения, чат в шапке и установщики. Исходная точка — `748ca9d`. Прежние зелёные отчёты использованы для выбора сценариев; текущие результаты получены заново.

Это аудит перечисленных контрактов, а не полная приёмка всех старых функций. Модульное покрытие, настоящий PostgreSQL/LanceDB, браузер, нативный OpenCode, CI и production имеют разные границы доказательства.

## Подтверждённые дефекты

| Область | Воспроизведение | Исправление и проверенная граница |
| --- | --- | --- |
| Платформенные пользователи | Запрос проходил начальную проверку главного администратора, ждал блокировку, затем выдавал права после отзыва роли или отключения аккаунта | Полный `IAccessActor` проверяется внутри транзакции после общей блокировки; `FOR SHARE` удерживает действующие права до COMMIT. Отзыв, успевший первым, запрещает запись; изменение, успевшее первым, завершается перед отзывом |
| Участники проекта | Ожидавший запрос менял назначение после удаления проектного допуска или отключения аккаунта | Та же транзакционная авторизация проверяет выбранную роль и точное назначение проекта. Иерархия целей, CAS, аудит и последний главный администратор сохранены. Неявный привилегированный actor убран из этих writes; bootstrap остаётся отдельным |
| Импорт ассетов | Флаг выключался во время supply, но карточка публиковалась. Повторное ревью добавленных проверок также выявило начало публикации после stop во время ожидавшего guard на промежуточном исправлении | Проверки перед runtime import и native publication повторяются после ожиданий; перед новым действием проверяется AbortSignal. Проверенные файлы сохраняются, явный повтор даёт одну версию |
| SQL-сессии старых workers | Потерянный ACK взятия/снятия advisory lock оставлял блокировку в пуле. Неудачный ROLLBACK импорта возвращал открытую транзакцию | Import worker и `RagGenerations.build` уничтожают сессию с неизвестным состоянием. Здоровые сессии, подтверждённая занятость lock и исходные результаты/ошибки сохраняют прежний контракт |
| Отмена применённой переиндексации | После следующего переключения модели отмена старого плана удаляла его поколение, хотя сам план оставался `applied` | Состояние плана читается `FOR UPDATE` после блокировки проекта. Применённый план получает 409 до cancel RPC. Проверена и гонка `ready → applied`, пока отмена ждёт lock |
| RAG COMMIT + потерянный ACK + OFF | RAG уже фиксировал строки, Catalog оставался `uncertain`; отключение `rag_sync` давало 403 и ошибочно переводило intent в `failed` с сообщением «без изменения индекса», снимая barrier | Точная завершённая квитанция читается до допуска новой записи. Совпадают id, проект, поколение и payload hash; Catalog intent по-прежнему авторизуется. Только `403/feature-disabled` сохраняет неопределённость, включая поздний COMMIT. Generic 403 и подтверждённый failed receipt сохраняют прежнюю definitive-семантику |

SQL и блокировки в этих воспроизведениях настоящие. Независимые соединения проверяют committed rows, PID, locks, сохранённые байты и ревизии. В fault injection меняется только конкретный transport ACK; чистые RED и последующие GREEN сохранены отдельно. Подменённые HTTP/provider boundaries указаны в квитанциях.

Граница RAG OFF: запрещены новые записи **данного sync-пакета в подготовленный шард**; завершённый receipt не запускает повторный `applyDelta`. Общий `ProjectDatabases.withProject` остаётся lifecycle чтения и может создавать/мигрировать проектную БД, настраивать квоты и брать lease. Нулевой след SQL/CREATE/MIGRATE при OFF здесь не заявляется. Для running/отсутствующей квитанции barrier сохраняется до подтверждения результата; поздний ответ не превращается в доказанный отказ.

Финальные Access/Gateway/flags/import/OpenCode/RAG/Catalog/frontend наборы имеют сверку файлов и SHA до/после. Binding/learning и partial-scan сверены с явным списком файлов команды, но не имеют раннего collection receipt; это ограничение сохранено. Ранние RAG 72 и Catalog 26 заменены финальными 91 и 36, повторные запуски не складываются.

Первый запуск пяти native CLI остановился на устаревшей retention-фикстуре: три общих PATCH получили 503, потому что fixture Proxy направлял запрос флагов в Catalog без evaluated endpoint. Исправлена только обвязка: собственный endpoint требует fixture token и отдаёт полный evaluated snapshot. RBAC и assertions сохранены. Затем все пять скриптов целиком прошли заново; старый RED и его штатная очистка сохранены.

Все пять CLI теперь требуют явный `PUBLICATION_TEST_PG_URL`, `TEST_ADMIN_PG_URL` или `CATALOG_TEST_PG_URL`: `127.0.0.1`, явный порт кроме 5432, база `/postgres`. Обычный application `CATALOG_PG_URL` не считается разрешением на тестовые мутации. Базы создаются случайными именами и удаляются штатным DROP. Основные PG5432/S319010 и рабочие файлы пользователей не использовались для тестовых записей.

## Остаток и свидетельства

Свежей полной браузерной матрицы, настоящего IdP/OpenCode/provider, всех нативных платформ, cross-host DR, Ceph, полного workspace-прогона и CI этим аудитом не получено. Остаток B01–B06 сохраняется. Другие транзакционные lifecycle, включая неоднозначный ROLLBACK в ещё не проверенных модулях, требуют отдельных причинных тестов; совпадение строки `catch` само по себе не считается новым подтверждённым дефектом.

Большие существующие `CatalogController/Service/Db` по-прежнему требуют разделения по ответственности. В текущем изменении новая логика вынесена в feature-local access helper; посторонний рефакторинг не выполнялся. Небольшой устаревший комментарий `rbac.ts` про `ADMIN_USERS` остаётся документальным долгом, а не доказательством обхода реальной PostgreSQL-авторизации.

Исправления проверены автором, root и независимыми агентами по source/test/causal boundary. Исходники закоммичены по фичам. Основное локальное приложение, сервер, release pins и опубликованный мост не обновлялись; push не выполнялся.
