# Системные агенты

AI-админ, Автоконфигуратор и Индексатор используют один ограниченный исполнитель `SystemRoleService`. Упаковщик в общем чате работает как консультант: рецепт, сборку, runtime-проверку и публикацию продолжает выполнять существующий `PackageBuildService`.

Открытие, история и подготовка контекста не вызывают модель. Для нового запуска пользователь явно выбирает проверенную модель с точным pin, смотрит подготовленный контекст и подтверждает передачу. Бюджет — не более двух шагов модели, четырёх измерений, четырёх целей и двух минут. Второй вызов разрешён только для исправления JSON-контракта; сетевой отказ, отмена, смена прав или версии не покупают автоматический повтор. После перезапуска старые платные задания не возобновляются.

Проектный запуск требует текущего администратора проекта. Общая диагностика площадки доступна главному администратору. Администратор проекта использует назначенные проверенные модели; главный администратор может выбрать модель общего каталога. Права, флаги, pin модели и версии выбранного контекста перечитываются перед физическим запросом после ожидания лимита.

Новые запуски управляются флагами `system_ai_admin`, `system_autoconfigurator`, `system_indexer` и `tool_build_agent`. История, отмена и откат подтверждённых изменений остаются доступны после выключения нового исполнения. Для запуска из системного чата дополнительно проверяются его флаг и сохранённый immutable intent; отменённое сообщение не разрешает новый вызов модели.

## Измерения и контекст

AI-админ читает готовность Catalog, состояние выбранного проекта, безопасные возможности собственных мостов и состояние контейнеров площадки. Факты с временем измерения и недоступные наблюдения показаны отдельно от объяснения модели. Журналы, ENV, credentials, Docker API и произвольные команды модели недоступны.

Контейнеры наблюдает существующий доверенный snapshot runner. Оператор задаёт `SNAPSHOT_RUNNER_COMPOSE_PROJECT` на исполнителе, совпадающий `SYSTEM_ROLE_COMPOSE_PROJECT` и точный `SNAPSHOT_VERIFIER_IMAGE_DIGEST` в Catalog. Раз в 15 секунд максимум выполняется фиксированный `docker ps` с фильтром этого Compose-проекта. Через действующий закрытый heartbeat передаются только имя сервиса, state, health и время. Старое наблюдение старше минуты, отсутствие исполнителя, Docker или настроек дают явное unavailable. Новый входящий сервер и Docker socket в Catalog не нужны.

Публичный чат выбирается явно; его последние 20 завершённых сообщений читает действующий владелец комнаты с текущей проверкой PUBLIC и ACL. Личный контекст диалога включается только отдельным выбором: не более пяти завершённых ответов с точными ссылками, ревизиями и digest. Новая платная проверка повторно проверяет эти ссылки. История не добавляется в prompt автоматически.

Индексатор получает ограниченные сведения о профиле embedding, снимках, sync intents и планах reindex выбранного проекта. Реальные операции выполняют действующие мастера снимков и базы знаний с их pinned проектом, компьютером, папкой и подтверждением. Семантический поиск чатов имеет отдельного владельца; объяснение агента не выдаётся за выполненный поиск или синхронизацию.

## Проверка и применение

Автоконфигуратор предлагает полный новый текст выбранного промпта, скилла или промпта агента. Для плагина доступно описание и рекомендации; код, поставка, зависимости и локальные значения не меняются. AI-админ предлагает параметры существующего адаптера. Адрес, учётные данные и транспорт сохраняет их владелец; автоматического probe нет.

Приватные строки и неизвестные строковые JSON-значения показаны маркерами. Модель не может удалить, продублировать или перенести их. Общий журнал операций содержит только контролируемые этапы и статусы. Текст, предложенные параметры и private diff читают инициатор с текущим доступом либо уполномоченный администратор.

Применение запускает человек после просмотра версии и замены. Каждый доменный владелец проверяет собственный CAS и возвращает подтверждённую версию. При потерянном ACK запись не повторяется автоматически: состояние unconfirmed требует проверки владельца. Откат доступен только по реально подтверждённым квитанциям и текущей совпадающей версии.

## Проверки candidate-среза

Узкие unit-проверки и TypeScript не подтверждают миграцию или работу реального провайдера. Физический контракт migration28 намеренно закрывает readiness до измерения на собственном PostgreSQL 16. Платные модели, пользовательские конфиги, действующая база и CI этим срезом не вызываются.
