# Пересборка локальных сервисов при изменении исходников

Запуск: `scripts/dev.sh up --watch` или `scripts/dev.sh watch`. Профили `--profile fast|standard|full` сохраняют прежний смысл. Это запускает dev-стек с отдельным владельцем процессов. Обычный `up` сохраняет прежнее поведение. Первоначальная подготовка использует существующий dev runner; автоматические пересборки не выполняют `npm ci`, не устанавливают зависимости и не запускают Docker.

Состояние: `scripts/dev.sh status`. Остановка watcher и его сервисов: `scripts/dev.sh down`. Watcher останавливается первым, чтобы не перезапустить сервис во время `down`. PostgreSQL, объектное хранилище, модели и пользовательский мост не удаляются. Статус и компактные квитанции: `.run/dev-watch/`; основной лог: `.run/logs/neurocenter-source-watch.log` (либо выбранный `LOGDIR`).

Изменения `src`, `content`, TypeScript/Nest/package manifests выбранных backend-пакетов обнаруживаются ограниченным обходом раз в 750 мс. Зависимости, `dist`, `.run`, Git и ссылки пропускаются. События объединяются за 600 мс. Сборки выполняются последовательно, включая изменения, поступившие во время предыдущей сборки. Изменение `services/shared` пересобирает backend-потребителей и мост. Изменение пакета MCP пересобирает также Catalog и RAG: новые процессы получают точный `ASSET_SYNC_MCP_BIN` этого поколения. Vite продолжает штатный HMR frontend.

Сборка использует существующий isolated build текущих dirty/new/deleted исходников. Если снимок изменился, результат не применяется и запрос объединяется со следующей попыткой. Ошибка компиляции оставляет предыдущий сервис работающим. После успешной сборки перезапускаются только затронутые сервисы, с проверкой фактической готовности. Ошибка запуска возвращает предыдущий runtime выбранного сервиса; ошибка отражается в статусе. Установленные глобальные зависимости и пользовательские конфиги не меняются.

Работающий код и его относительные `services/shared` CJS/JSON сохраняются в `.run/dev-watch/generations/<uuid>/repository/`. Это позволяет откатить сервис вместе с прежними shared-байтами. Активные поколения удерживаются только пока на них ссылается текущий сервис или MCP-подключение; неиспользуемые поколения удаляются. Временные build manifests и исходники не остаются после передачи поколения. Сохраняются компактный последний результат и один набор ошибок компиляции, до 256 КиБ на пакет, с правами 0600. Ограничения: до 20 000 просматриваемых записей, глубина 24, до 64 МиБ исходников одного активируемого поколения. Зависимости связаны ссылками; это изоляция выходов, а не OS sandbox.

Окружения сервисов передаются по приватному IPC и остаются в памяти. Они не записываются в состояние или аргументы команд. Дочерние владельцы держат process group до завершения сервиса/компилятора и убирают группу при потере IPC. Поэтому SIGKILL основного watcher не оставляет Nest/npm watchers. Проверки PID/cwd/start identity защищают чужие процессы и повторно использованные PID. Обнаружение без `processes.json` признаёт только известный child owner или точный путь поколения этого checkout, вместе с исходным рабочим каталогом сервиса.

Режим предназначен для macOS/Linux с Node24 и уже установленными зависимостями. Проверка на временных процессах/портах отдельно от подтверждения обычного dev-стека, CI или production. Изменения самого runner требуют явного перезапуска watch.
