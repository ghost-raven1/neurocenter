# Подготовка пилота: ресурсы скиллов и наблюдаемость

Цель согласованного плана — масштаб и цели восстановления, задаваемые оператором площадки. Выпуск единый после нативной приёмки клиентских платформ. На Intel Mac допускается установка инструментов без локального RAG. Этот документ фиксирует выполненную часть плана, а не разрешение production-запуска.

## Полная версия скилла

- Создание и обновление принимают `resources`: массив `{path, content, encoding?}`. Каталоги ресурсов — `scripts/`, `references/`, `assets/`. Текст передаётся в UTF-8, бинарные файлы — каноническим base64. Симлинки и архивы не принимаются.
- Лимиты: 99 ресурсов, 1 МиБ на файл, 4 МиБ на ресурсы. Сформированный `SKILL.md`, включая шапку, должен помещаться в 1 МиБ. Проверяются конфликты регистра, Unicode NFC, файлов и каталогов, зарезервированные имена Windows и длина компонентов UTF-8.
- Отсутствие `resources` при обновлении сохраняет прежний состав; `[]` явно удаляет ресурсы. Изменение только ресурса создаёт новую версию. Синхронизация текста из прежнего MCP сохраняет серверные ресурсы.
- В формах общего магазина доступны загрузка файлов и папки, изменение путей и удаление ресурсов. Ошибка чтения не добавляет половину набора; сохранение блокируется до завершения чтения. Загрузка не запускает скрипты и не устанавливает их сторонние зависимости.
- Ресурсы хранятся внутри версионируемого Markdown-конверта в YAML. Потребителю выдаются отдельно от метаданных. Список каталога не удерживает тела и вложения всех карточек одновременно.
- Перед обновлением сохраняется неизменяемый снимок предыдущего файла в `.neurocenter-skill-versions/`. `GET /api/skills/<path>?version=N` выдаёт конкретную версию. Для установки каталог использует отдельный контракт `GET /api/skills/_package/<path>?version=N`, где версия обязательна: старый сервис не может незаметно отбросить ресурсы и вернуть только текст.
- Снимки имеют расширение `.snapshot`, чтобы старый обход Markdown не принял архивы за общие скиллы. Снимки разделены по поколению публикации. Удаление и повторное создание того же пути не присваивает новую карточку старой истории. Старые тексты до внедрения снимков не восстанавливаются из одной лишь записи метаданных: отсутствующая версия возвращает 404.

## Доставка и MCP 0.4.0

- Текстовые пакеты сохраняют формат 2. Новые пакеты с бинарными ресурсами или не-ASCII путями используют формат 4: кодирование входит в манифест, размер и SHA256 считаются по исходным байтам.
- Новый мост объявляет `package-v4`, сохраняя поддержку форматов 2/3. Формат 4 канонизирует ключи и пути без localeCompare: русская и английская ОС получают одинаковый хэш. Сервер проверяет поддержку при создании и выдаче задания; старый клиент получает предложение обновиться до записи файлов. Общий протокол надёжного подтверждения остаётся версии 2.
- Локальные квитанции учитывают кодирование. Установка, повтор, обновление и удаление сравнивают исходные байты. Журнал отката и закрытая резервная копия сохраняют бинарное содержимое без преобразования в UTF-8.
- Новый архив macOS ARM64 включает Node 24.22.0 и зависимости. Bash/PowerShell-шаблоны запрашивают 0.4.0. Отсутствующий архив другой платформы по-прежнему даёт явный отказ с сохранением прежней установки.
- Установка файлов не означает успешный запуск: результат остаётся `readiness: unverified`. Исполняемый бит автоматически не выдаётся; скрипты запускаются через соответствующий интерпретатор после отдельной настройки.

## Исправление production-конфига

Сквозной сценарий очереди обнаружил пропущенный `SKILLS_SERVICE_URL` в production Compose: каталог пытался читать скиллы с `127.0.0.1:4200` своего контейнера и возвращал 500. В конфиг добавлен `http://skills-service:4200`; каталог production теперь требует явный корректный адрес при старте. Сетевой отказ и повреждённый ответ сервиса возвращают понятный 502 без создания задания и записи файлов. Проверка публикации карточки отдельно от выдачи установочного пакета этот дефект не выявляла.

Также закрыт обход проектной области через `project_assets`: ссылка на скилл чужого проекта не создаётся, существующая некорректная запись не позволяет получить пакет через очередь или повторную авторизацию. Проверка путей выполняется до обращения к внутреннему сервису; общие коллекции и собственные проектные скиллы остаются доступны по прежним ролям. Для переноса между проектами нужна отдельная копия или публикация в общий каталог.

## Метрики

Все пять backend-сервисов получили `GET /metrics` в формате Prometheus: число запросов по HTTP-статусам, гистограмма времени ответа, активные запросы, uptime, RSS, heap и CPU процесса. Метки содержат только фиксированные имя сервиса, HTTP-метод, группу маршрута и статус. Тела, заголовки, почта, ID проектов, пути и query-параметры не сохраняются.

Endpoint требует отдельный `NEUROCENTER_METRICS_TOKEN` либо `NEUROCENTER_METRICS_TOKEN_FILE`; авторизация — `Bearer` или `x-neurocenter-metrics`. Внутренний ключ API и пользовательская сессия права чтения не дают. Без ключа endpoint закрыт. Слабый явно заданный ключ запрещён в production. Публичный nginx возвращает 404 для `/metrics`.

Production-конфиг создаёт отдельный приватный `secrets/metrics_token`. Операторские `setup.mjs up` и `seed` добавляют его в прежний приватный конфиг без ротации остальных секретов. Проверка симлинков и атомарная публикация не позволяют заменить посторонний файл.

В `deploy/production/monitoring/` находятся шаблоны scrape и правил недоступности, HTTP 5xx и p95. Они не запускают Prometheus/Alertmanager и не настраивают адресата оповещений. Сборщик подключается к backend-сети и получает только `metrics_token`. Проверенный канал уведомлений, метрики очереди, диска, PostgreSQL и свежести внешних копий остаются следующей частью эксплуатации.

Откат сервиса скиллов на прежний формат после публикации ресурсов не принят. Полное восстановление выполняется с тем же комплектом образов; безопасный upgrade/rollback и миграционные проверки остаются обязательным этапом.

## Следующие обязательные работы

1. План установки с закреплённым графом MCP/плагинов, одобрение конкретных версий администратором и транзакционное применение всего комплекта с учётом общих зависимостей. Сейчас `mcp/plugins` остаются требованиями в метаданных. Платформенные варианты сторонних инструментов и доставка их интерпретаторов/зависимостей также ещё не реализованы.
2. Проверка запуска в OpenCode, OAuth и недостающих секретов; фактическая инвентаризация и безопасное восстановление ручных изменений.
3. Общие версионированные миграции, полный аудит прав/публикаций, физические ограничения ресурсов и непривилегированные runtime-контейнеры.
4. Независимые автоматические копии, контроль свежести и восстановление в пределах RPO/RTO 4 часа. Текущая операторская полная копия с остановкой приложений не является готовым фоновым расписанием.
5. Канонический Git, CI и воспроизводимый выпуск/откат; реальные Blitz и сервер. В checkout отсутствует `.git`.
6. Нативные Windows, Linux glibc/musl и Intel Mac; нагрузка целевого масштаба и суточный прогон. Контейнерные и симулированные проверки не заменяют эти испытания.

Production и пилот с рабочими данными остаются **NO-GO** до закрытия соответствующих условий. Большие immutable-образы LanceDB, release profiles, Redis и Kafka в эту часть работ не включены.

## Проверка

Актуальные логи и машинные результаты находятся в `.run/pilot-implementation-20261017/`. Итоговые числа и идентичность образов фиксируются в `summary.json` после завершения прогонов. Нативный установщик проверяется только в изолированном профиле; рабочая установка MCP и глобальный OpenCode пользователя не обновляются этими тестами.

### Итог текущей проверки

- 631 Vitest: каталог 231, скиллы 54, RAG 60, frontend 186, MCP 100; typecheck и сборки всех семи пакетов успешны.
- 95 Node-проверок; 7 сквозных HTTP/worker-сценариев; 5 проверок распакованного runtime и 3 нативных Bash-сценария macOS ARM64.
- 40 HTTPS-сценариев на финальном комплекте образов, включая выдачу старой версии через очередь, запрет бинарного пакета старому клиенту и чужого проектного скилла. Blitz имитируется; TLS, gateway, PostgreSQL и Socket.IO настоящие.
- Браузер: публикация и редактирование ресурсов, возврат чистого черновика, ширины 390/1280 без горизонтального переполнения. Известное предупреждение Ant Design Table/defaultProps остаётся. Нативный picker не проверялся.
- 8 собственных Compose-проектов, включая один неуспешный прогон до исправления SKILLS_SERVICE_URL, удалены вместе с томами. Рабочие проекты, RAG, идентичность устройства, установленный MCP и глобальный OpenCode совпали с контрольными хэшами; шесть проверок готовности вернули 200.
- Образы имеют метку verify-20261017-pilot-release. Это локальная проверка; push, CI, реальный deploy и допуск пилота не выполнялись.
