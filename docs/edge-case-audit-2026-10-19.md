# Поиск тупиков и ошибок по агентам — 19 октября 2026

Три агента независимо проверили каталог, доступ/очередь/скачивание и интерфейс. Основной агент проверил RAG, воспроизвёл браузерные сценарии и применил финальные сборки. Исправлены **шесть групп ошибок**. Рабочие проекты, пользователи, назначения, скиллы и карточки сохранены; мост остаётся **0.9.4**, повторная установка не выполнялась.

Completion integration вызывает настоящий `DeviceController → identity/access → complete → PostgreSQL`, без старта отдельного HTTP-сервера. RAG recovery поднимает отдельный настоящий Nest HTTP и БД с временными ролями: 42501 → восстановление прав → retry тем же объектом, затем HTTP 503 → GRANT → HTTP 200 с данными. Все собственные БД/роли удалены обычным DROP, без принудительного разрыва рабочих соединений.

[Пять UI-сценариев](../output/edge-audit-20261019/frontend/ui.json) проверены через MCP: допустимые ручные режимы, переход в упаковку, browser Back внутри SPA, DELETE409 и повтор DELETE200. GET настоящие; оба DELETE — явные fixtures, рабочий проект не удалялся. [390 px](../output/edge-audit-20261019/frontend/packaging-mobile.png) без горизонтального переполнения; [повтор удаления](../output/edge-audit-20261019/frontend/delete-retry.png). Первые ошибки UI harness касались AntD select, анимации закрытия и menuitem вместо anchor; они не объявляются продуктовыми багами. [Console](../output/edge-audit-20261019/frontend/console-errors.txt) содержит ожидаемый 409 и прежние AntD/React deprecations.

Первый SQL harness прошёл четыре проверки, но ошибка переменной в cleanup оставила собственную БД. Переменная исправлена, [собственный остаток удалён после проверки отсутствия клиентов](../output/edge-audit-20261019/rag/harness-cleanup.json); полный повтор GREEN с обычным cleanup. Это ошибка harness, не продукта.

RAG, catalog и gateway применены после двух свежих idle-снимков и проверки PID checkout: [idle](../output/edge-audit-20261019/idle.json), [restart](../output/edge-audit-20261019/restart.json). [Шесть сервисов готовы](../output/edge-audit-20261019/health.json), [baseline/cleanup](../output/edge-audit-20261019/cleanup.json) подтверждают прежние данные. Своя сессия завершена, закрыта только своя вкладка; [мост online 0.9.4 и прежний device](../output/edge-audit-20261019/session.json).

MCP, skills и auth в этом проходе не изменялись и полностью повторно не тестировались. Их прежние результаты остаются в [аудите S01–S29](scenario-audit-2026-10-19.md) и [выпуске 0.9.4](bridge-release-0.9.4-2026-10-19.md). Вложенные targeted-наборы не прибавляются к полным unit-наборам.

## Оставшиеся пробелы

В `CatalogService.fetchRetainedEstimate()` ещё есть старый fallback 0 при недоступности RAG: исправление F06 гарантирует честный ответ именно RAG size API, но не состояние агрегированной карточки проекта. Нужен отдельный статус неизвестного размера и отображение его в UI без подмены нулём. Оценка размера сама по себе не является внешней проверенной резервной копией.

Открыты шесть внешних P0, семь других native-целей, snapshot/web restore с 501, общий executor retry/cancel, purge и согласованное FS/PG восстановление. Предупреждения AntD и размер общего bundle остаются техническим долгом. `.git` отсутствует; commit/push, CI и production deployment не выполнялись. Production-допуск — **NO-GO**.
