## B26: подтверждённый отказ установки, причина сети открыта

Фото пользователя показывает npm cache hit за0–1мс и fetch архивов с EAI_AGAIN, затем heartbeat ожидания сборки. Это временный отказ разрешения сетевого имени, а не свидетельство блокировки warning или проверки сертификата. Последующее фото getent на Linux-хосте содержит IPv4/IPv6 registry.npmjs.org; ранний ответ «пусто» не доказывает постоянную поломку DNS хоста.

Следующий ответ пользователя: getent в уже скачанном Node-контейнере с обычной сетью дал пустой вывод. Это сужает различие host/container, но ещё не измеряет DNS отдельного builder. Проверка с host network запрошена, успешной новой Linux-установки пока нет. Остаётся проверить resolver/proxy и временный отказ под параллельной загрузкой; URL npm не определяет, имя какого узла не разрешилось. Критерий B26 — воспроизводимый успех загрузки не кэшированных архивов и dev.sh up, с выбранными корпоративными DNS/proxy, сохраняя HTTPS. [Диагностические команды](../docker-build-ca.md); без автоматической смены DNS, host network или перезапуска чужого daemon.

## Результат аудита DROP INDEX

Чужой plan id под URL проекта A отвергается Catalog owned(id, project_id) до RPC; URL проекта B требует его ACL. Internal RAG требует service token; withProject выбирает отдельную физическую БД проекта. Публичный путь A → удаление индекса B не подтверждён. Низкоуровневый cancel при совместном размещении A/B всё ещё требует отдельного RED: UPDATE0 может предшествовать DROP по hash(id). Этот source-кандидат не выдаётся за проверенную публичную уязвимость и текущей правкой не закрывается.
