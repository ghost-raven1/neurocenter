# Сохранение модели роли и создание нового диалога

Срез основан на `main a2d887d4`. Он исправляет два воспроизведённых отказа чатов сервисных ролей; сервер, миграции, квоты и установленный мост не изменяются.

## Результат

- Выбранная модель сохраняется отдельно для пользователя, проекта и роли в текущей вкладке, включая обычное обновление страницы. Хранится только идентификатор модели или явная очистка выбора. Недоступная модель требует нового выбора; незавершённый запрос сохраняет исходную модель. Автоматической отправки нет.
- После создания первой переписки на текущем экране кнопка «Новый диалог» возвращала пользователя в прежнюю историю. Теперь явный новый черновик остаётся пустым при обновлении списка, а старый диалог открывается по выбору пользователя. Смена владельца контекста и восстановление отправки продолжают работать.

## Проверки

Две React/DOM-регрессии выбора модели сначала воспроизвели сброс к первой модели. Отдельный тест с настоящим hook чата воспроизвёл лишнее автоматическое чтение старой переписки после «Нового диалога». После правок совместный целевой набор прошёл **52/52**, frontend TypeScript — exit 0. Production frontend build прошёл на `2e9ad9b0`: 96 файлов; сохранено предупреждение о крупном JS-чанке. Исходники и Git-состояние при сборке не изменились.

Прямой браузерный GREEN выполнен на отдельном frontend-кандидате `2e9ad9b0` с собственными Auth/Gateway и неизменённым backend тестового стенда D `0f7db83a` / Catalog `cbf2d10c`. Origin не переписывался; реальный `/auth/me` подтвердил собственного QA-администратора. Backend D также содержит отдельную разработку квот; она не входит в этот срез.

- Для AI-админа и Координатора выбраны две разные модели и введены разные тексты. Переключение ролей и обычное обновление страницы сохранили точные модели и черновики. На этом этапе задачи не отправлялись.
- На том же экране впервые создан и завершён диалог Индексатора. После «Нового диалога» история содержала ноль сообщений и пустой выбор. Обновление списка не открыло старую переписку. Следующая явная подготовка и отправка создали другой идентификатор диалога с одним ответом. После обновления страницы явный выбор первой истории вернул её исходный ответ.

Обе отправки сделаны через обычный UI с показом контекста и согласием. Модель и эмбеддинги — собственные протокольные фикстуры без платных обращений. Бизнес-успехи не подменялись. Root проверял desktop 1280×720; параллельные CLI-прогоны использовали 1440×1000. Другие размеры и ОС этим не приняты.
