# Живой вывод Docker/npm при dev.sh up — 26 октября 2026

## Наблюдаемое поведение

Сборка сразу печатает этап и лимит, затем каждые 15 секунд — прошедшее время, даже когда Docker молчит. stdout/stderr передаются через inherit без накопления до завершения. Объём слоёв виден в собственном выводе Docker; helper не вычисляет проценты, число пакетов или выдуманные байты. BuildKit по умолчанию получает `BUILDKIT_PROGRESS=plain`, явно заданное значение сохраняется. Legacy builder не получает нового CLI-флага.

`npm ci` всегда использует `--loglevel=http --foreground-scripts --update-notifier=false`: видны сетевые события и вывод установочных скриптов, отключено уведомление о новой версии npm. Это не подавление всех возможных npm notice и не изменение stderr/exit status. HTTP-событие может появиться только после ответа, повтора или отказа; текущий долгий запрос остаётся виден как ожидание Docker.

`SNAPSHOT_VERIFIER_NPM_DIAGNOSTICS=1` теперь дополнительно меняет только fetch timeout/retries и запись debug-логов. При выключенном режиме исходные сетевые бюджеты npm сохраняются. HTTPS, TLS0, command-scoped NODE_NO_WARNINGS, пустые npm configs, whitelist proxy-аргументов, проверка signing identity и runtime-настройки не менялись. Проверка сертификатов уже отключена на RUN установки; повторно выключать TLS для «шага10» не требуется.

Асинхронный supervisor дожидается close собственного Docker CLI. При лимите он возвращает ETIMEDOUT после SIGKILL, при SIGINT/SIGTERM пересылает сигнал и через секунду добивает игнорирующий процесс. После close удаляются только собственные timers/listeners; нулевой exit после отмены не объявляется готовностью. `withDockerBuildCa` ожидает завершения до удаления своих CA-файлов. Это не доказательство отмены задания Docker daemon.

Для Linux после обновления кода можно получить короткий сетевой отказ вместе с живым выводом:

```sh
SNAPSHOT_VERIFIER_NPM_DIAGNOSTICS=1 ./scripts/dev.sh up --profile=fast
```

Без этой переменной этап, время и npm HTTP/lifecycle-вывод также показываются. Успешная установка на Linux и причина прежней десятиминутной задержки требуют свидетельств с этого компьютера.
