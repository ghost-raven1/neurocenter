## Неизвестный SQL-откат

`setupRagQuota` и `reserveLegacyRagQuota` раньше возвращали соединение в pool после отказа ROLLBACK. Настоящий следующий запрос мог зафиксировать чужую инициализацию, бюджет или аудит. Аналогично `migrateRag` оставлял незавершённые DDL/журнал, а `checkRagMigrations` и `checkRagQuotaMigration` могли передать писателю открытую READ ONLY-транзакцию с последующим `25006`.

Все пять владельцев транзакций теперь вызывают `release(true)` при неподтверждённом ROLLBACK, сохраняя первичную ошибку. При подтверждённом откате сохраняется reuse. SQL миграций, checksum, проверка схемы и порядок блокировок не менялись. После потерянного COMMIT ACK принятые данные сохраняются, повтор не создаёт вторую запись.

Проверки выполняли production SQL на отдельном управляемом PostgreSQL 16.15, loopback-порт 57024, с admission по SCRAM/nonce/PID/birth/lease. Это не подключение к рабочему 5432. Fault injection контролировал доставку ROLLBACK или ответ после настоящего SQL/COMMIT; это не физический сетевой разрыв. Для квот использовался минимальный chunk fixture с real[] и совместимой `vector_dims`, без pgvector; полная миграция embedding-схемы не проверялась.

## Остановка после `(node:7)`

Фото Linux показывает `npm ci` образа `snapshot-verifier`, который использует package/lock Catalog. `7` — PID, а предупреждение печатается при подготовке первого TLS-соединения после отключения проверки сертификатов. На собственном Node 24.22.0 проверен управляемый TCP peer, который принимает соединение и не отвечает на TLS: предупреждение появляется, event loop работает, запрос прерывается по AbortSignal и дочерний процесс завершается. Свидетельство: `.run/backlog-maintenance-20261026/tls-warning-probe.json`. Это объясняет возможный последний видимый вывод, но не устанавливает причину задержки Linux.

Добавлена явная передача шести HTTP/HTTPS/NO_PROXY переменных обоих регистров: Docker получает имена build args, значения остаются в окружении CLI. Отсутствующие переменные не переопределяют Docker client config; явно пустые передаются. Настройки Docker daemon этим не меняются.

`SNAPSHOT_VERIFIER_NPM_DIAGNOSTICS=1` добавляет только фиксированные флаги npm: HTTP/lifecycle-вывод, `fetch-timeout=30000`, `fetch-retries=0`, `logs-max=0`. По умолчанию режим выключен; допускаются только строки `0/1` до подготовки БД/секретов, только когда образ собирается. Настройка не передаётся сервисам. 30 секунд относятся к одному fetch, а не ко всей установке или lifecycle-скрипту. HTTPS, `strict-ssl=false`, `NODE_TLS_REJECT_UNAUTHORIZED=0`, lockfile integrity и общий Docker timeout сохранены.

Причинный RED новых сетевых контрактов в терминале основного агента: 31 тест, **18 PASS / 13 FAIL**, до добавления двух дополнительных invalid-value случаев. Срез до подавления предупреждений: три Node-файла (`dev-snapshots-build`, `docker-build-ca`, `npm-build-isolation`) — **53 PASS / 2 opt-in Docker SKIP**, 0 fail/cancelled/TODO, `network-green.log`. Snapshot-файл в этом срезе — 33/33. Два случая исполняют фактическую RUN-команду Dockerfile через `/bin/sh` с собственным stub npm; это не сборка настоящего Docker-образа. Независимое ревью подтвердило границы opt-in/proxy/runtime.

После этого пользователь отдельно попросил отключить предупреждения. Только `npm ci` verifier получил command-scoped `NODE_NO_WARNINGS=1`, без постоянной ENV и без перенаправления stderr. Параметр подавляет предупреждения Node, включая TLS0; также наследуется lifecycle-процессами. Ошибки npm, их exit status и HTTP-диагностика остаются. Это изменение вывода, не сетевого поведения. RED дополнения: **31 PASS / 3 FAIL**, `warning-red.log`; настоящий Node сначала печатает контрольное предупреждение, затем через фактический RUN проверяются его отсутствие, видимый `npm error` и сохранённый exit37. Финальный прогон тех же трёх файлов: **54 PASS / 2 opt-in Docker SKIP**, snapshot-файл 34/34, 0 fail/cancelled/TODO; `warning-green.log`. Предыдущие пересекающиеся прогоны к нему не прибавляются.

Повтор для получения конкретной сетевой ошибки:

```sh
SNAPSHOT_VERIFIER_NPM_DIAGNOSTICS=1 ./scripts/dev.sh up --profile=fast
```

Нужны последующие `npm http`/`npm error` с Linux. Локальная проверка не доказывает доступность registry/GitHub, работу корпоративного proxy, TLS handshake или успешную установку пакетов на том сервере.

Во всех 568 lock-записях версии и набор пакетов сохранились, production-записей стало 258 вместо 257.
