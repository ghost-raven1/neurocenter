## Что включено в текущую работу

Основной мастер не отмечает посещённый шаг завершённым. Он показывает отчёт моста, точную папку и результаты инструментов, а отсутствие автоматической проверки пользовательского CLI указывает прямо. После отказа сохраняются выбранный проект, этап и существующие квитанции. Клавиатурный переход переносит фокус в открытый шаг. Браузерная и модульная приёмка фиксируются в отчёте поставки отдельно от этого исследования.

Ревью текущего изменения уже ведётся по конкретным условиям и доказательствам: закрыты room-lock race, утечка произвольных аргументов общей проверки, обход флага прямым HTTP-контроллером и потеря child exit code PowerShell wrapper. Исправление source-контракта PowerShell не считается нативной проверкой Windows.

## Следующий проверяемый срез ревью

1. Зафиксировать HEAD/diff и единую опись файлов для preview и исполнения. У каждого исключения есть причина; изменение исходников инвалидирует продолжение.
2. Нормализовать замечания как `path/line/rule/severity/trigger/evidence`. Неполный JSON, отсутствующая группа файлов или неверная позиция не превращаются в PASS.
3. Анализ выполняет существующий выбранный агент с его моделью и правами. Отдельный reviewer подтверждает дефект и устраняет дубли. Проверить на fixtures с известными ACL/race/idempotency ошибками.
4. Сырые thinking, исходники и приватные snippets не публикуются в общий чат. Публикуется только разрешённая структурированная квитанция.

Это план следующей интеграции, а не заявление об установленном OpenCodeReview или готовом новом runtime ревью. Персональные tool profiles остаются в [проекте AP02](../project-agent-tool-profiles-design-2026-10-27.md).
