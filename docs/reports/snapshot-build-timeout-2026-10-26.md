# Таймаут сборки исполнителя снимков — 26 октября 2026

На фотографии Linux сборка остановилась на `npm ci` в `snapshot-verifier`. Пользователь подтвердил ожидание около десяти минут. В `prepareDevSnapshots` найден соответствующий `spawnSync` timeout600000; ETIMEDOUT и любые другие отказы ранее превращались в одинаковую ошибку. Само предупреждение `NODE_TLS_REJECT_UNAUTHORIZED=0` не доказывает отказ npm. Причина медленной загрузки внутри контейнера по снимку не установлена.

Изменение сохраняет default600с, добавляя явный `SNAPSHOT_VERIFIER_BUILD_TIMEOUT_SECONDS` от1 до3600. Неверное значение отклоняется до БД и создания ключей. Параметр не попадает в runtime Catalog/runner; готовый `SNAPSHOT_VERIFIER_IMAGE` по-прежнему пропускает build. Отдельно выводятся таймаут с числом секунд, код ошибки запуска Docker, сигнал и exit status; сохраняется cause, произвольный текст ошибки не копируется в сообщение. Build и inspect получают SIGKILL для завершения собственного клиента при таймауте.

После применения ветки для первой медленной установки:

```sh
SNAPSHOT_VERIFIER_BUILD_TIMEOUT_SECONDS=1800 ./scripts/dev.sh up --profile=fast
```

Также поддерживается `.env`. Увеличение бюджета не исправляет недоступный registry/proxy. Завершение локального Docker CLI не считается доказательством остановки работы Docker daemon.
