# Strict SSL при сборке и установке зависимостей — 26 октября 2026

Реализация разделена на коммиты `369250a` (build/Docker), `abbe79f` (Catalog) и `cf78f55` (установщики).

По явному запросу пользователя проект задаёт `strict-ssl=false` во всех путях установки npm и сборки: dev CLI, обычный checker, изолированная сборка, подготовка native runtime/SDK, рецепты и дочерний сборщик Catalog. Корень и восемь пакетов имеют согласованные `.npmrc`. Очищенное окружение сборщика заново задаёт собственные значения, поэтому родительские `strict-ssl=true` и `NODE_TLS_REJECT_UNAUTHORIZED=1` их не перекрывают. Глобальные настройки npm пользователя не меняются.

Все восемь Dockerfile применяют политику к 24 npm-командам, включая обе стадии RAG. В Catalog загрузка ключа PostgreSQL использует `curl --insecure`, все четыре `apt-get` — локальные `Verify-Peer=false`/`Verify-Host=false`. HTTPS URL, подписи apt, `signed-by`, lock/integrity и проверки архивов сохраняются. Загрузка базового образа самим Docker daemon имеет отдельные настройки.

Прямые загрузки Compose, ассетов и OpenCode получают политику фазы подготовки. Catalog читает метаданные npm через отдельный HTTPS Agent, сохраняя лимит ответа, timeout, proxy и запрет redirect; глобальный TLS его runtime не меняется. Bash/PowerShell-установщики и начальные команды UI отключают проверку сертификата загрузки. В PowerShell 5.1 прежний callback восстанавливается перед выполнением скачанного скрипта; PowerShell 7 использует параметр отдельного запроса.
