# Сохранённые результаты MCP в истории роли

Чаты ролей показывали идентификатор шага MCP, но не позволяли прочитать сохранённый ответ инструмента. Исправление `abb0347c` добавляет свёрнутые «Результаты MCP» в общий результат роли. Явная кнопка читает существующий авторизованный GET: имя, состояние, UUID квитанции и фактический вывод. Просмотр не запускает инструмент или модель. Ошибка чтения даёт повтор; смена пользователя, прав, проекта, роли или run отбрасывает устаревший ответ. Неизвестный исход и отмена сохраняются при позднем выводе. Ошибка инструмента и обрезка обозначаются отдельно; текст и JSON экранируются.

Backend, миграции и флаги не меняются. Разрешённая история читается при выключенном `system_role_mcp`. Вывод ограничен существующим серверным DTO; UI не приписывает ему отсутствующие сведения об устройстве или runtime. Область вывода переносит длинные строки, ограничена 240px и прокручивается.

## Проверки

- Причинный DOM RED воспроизведён на `main ab773cb8`. Затем 74/74 целевых проверок прошли; после добавления стилей повторены 34/34 затронутые проверки и frontend TypeScript. Независимое ревью не нашло блокирующих замечаний.
- Production TypeScript и Vite build прошли на `abb0347c`. Исходники/HEAD сохранены; предупреждение о крупном JS-чанке остаётся. Проверенный frontend-пакет содержит 855 публичных файлов без ключей, окружения и зависимостей.
- В отдельном E-стенде с настоящими сервисами, PostgreSQL/schema45 и S3 через обычный UI созданы собственные проект, проверенная API-карточка и MCP. Источник модели — явная протокольная фикстура; MCP выполнил настоящий `qa_ui_echo`. В исходном UI `ab773cb8` результат отсутствовал. Кандидат `abb0347c` прочитал тот же сохранённый ответ и UUID, без нового исполнения.
- Потеря ответа на фактический GET200 дала понятную ошибку; явный повтор вернул прежнюю квитанцию. После обычной перезагрузки и выключения MCP до revision2 история осталась доступна. Исходное включённое состояние восстановлено revision3. Журнал фикстуры не изменился при просмотре, повторе и OFF: один проверочный запрос подключения, два шага роли и один вызов инструмента.
- Независимое чтение БД подтвердило один успешный MCP-вызов, закрытую серверную сессию и две успешные записи расхода с одним dispatch каждая. Штатная остановка кандидата подтвердила отсутствие процессов и неизменность исходников/конфигурации.

Frontend-кандидат использовал собственные Auth/Gateway с backend E `ab773cb8`, без переписывания Origin или переноса cookies. Настоящий `/auth/me` подтвердил QA-владельца. Это dev-вход, не приёмка внешнего IdP. Root проверял desktop1280×720. При такой высоте общий чат всё ещё оставляет тесную область истории; уплотнение рабочего пространства вынесено в следующий срез. Другие ОС, native MCP, CI и production этим не приняты.
