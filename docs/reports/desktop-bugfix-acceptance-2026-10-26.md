# Исправления после десктопного плейтеста — 26 октября 2026

Все три пользовательских сценария повторены в настоящем десктопном браузере. Это локальная приёмка изменений в рабочем дереве `main` поверх `4ca9b8c2d1e13ec97f0b8b08688a2c5655f2b2ed`.

## Что исправлено

- **D1 — восстановление командного чата после reload.** Черновик, reply, адресаты и исходный pending intent сохраняются в `sessionStorage` до POST. Ключ хранения изолирован по человеку, проекту и диалогу; смена роли того же человека сохраняет путь проверки. Сохранённый payload проверяется перед чтением. ACK очищает pending; неоднозначный исход и отказ повторной проверки сохраняют исходный ключ. При недоступном хранилище новый POST не начинается, ввод остаётся редактируемым. Хранение действует в пределах той же вкладки браузера.
- **D2 — достоверная сводка операций.** Фоновые polling/socket/visibility обновления ждут незавершённое чтение. До первой подтверждённой сводки показывается проверка; после отказа — ошибка или последние полученные данные. Явное обновление сохраняет защиту от поздних ответов. `listOperations` получил HTTP timeout 30 секунд, чтобы полностью зависшее чтение освобождало следующий цикл.
- **U1 — выход из ошибки упаковки.** Для неудачной или отменённой сборки текущий главный администратор получает «Открыть упаковщик». Ссылка открывает существующую форму, сохраняет проект операции и не повторяет старую сборку. Закрытие удаляет только `packaging=open`, сохраняя проект, поиск и якорь. Создание нового запроса по-прежнему проверяет действующие флаги и права внутри формы. В frontend-тип операций добавлен `BUILD`, уже присутствующий в backend DTO.
