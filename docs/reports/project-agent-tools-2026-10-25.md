# Инструменты обычных агентов проекта — 2026-10-25

Реализован ограниченный `json-actions-v1` цикл для личного чата, группового раунда и агентов комнаты проекта. Модель получает фактическое описание доступных инструментов и сама запрашивает до трёх действий. Это текстовый JSON-протокол; наличие нативных function calls у локального Codex не предполагается.

## Пользовательский контракт

- `agentTools` принимается вместе с сообщением и сохраняется в исходном пользовательском сообщении. Протокол, RAG, разрешение системной помощи и явно подтверждённая embedding-модель публичного поиска входят в неизменяемый grant. Повтор использует сохранённый grant.
- Старый `research` и новый цикл взаимно исключаются. Одинаковый первоначальный RAG-запрос использует уже полученный результат, без второго embedding. Явное выключение RAG пропускает и первоначальный embedding.
- Действия: `rag_search`, `rag_read` только найденного источника, `public_chat_search`, `request_system_role`, `finish`. MCP объявлен недоступным. Произвольных файловых операций, команд и применения системных настроек в этом срезе нет.
- Системная помощь вызывает настоящего владельца справки и диагностики с текущими правами разработчика. Привилегированное выполнение остаётся отдельным действием пользователя; повышение прав агента не происходит. Для ответа в комнате проекта владелец источника не читает личные устройства и очередь инициатора.
- `GET /api/agent-tools/capabilities?projectId=…` проверяет текущие права, флаги и закреплённые доступные embedding-модели без inference. История `GET /api/agent-tools/steps` и `/steps/:id` доступна при выключенном флаге выполнения. Gateway выставляет `no-store` до проверки авторизации.

## Владение и сохранность

Миграция42 добавляет отдельный журнал `agent_tool_steps` и grants двух владельцев чата. Источник, инициатор, роль, проект, агент, модель/pin, поколение, последовательность и срок неизменяемы. SQL-триггер связывает запись с реально принятым сообщением и адресатом. Каждый planner и инструмент получает сохранённую отметку отправки до эффекта. Неизвестное подтверждение сохраняется как `unknown` и автоматически не отправляется снова.

Перед отправкой и фиксацией повторно проверяются права, pin, поколение, lease, отмена и срок. Срок INSERT опирается на один timestamp PostgreSQL, сохраняя физический предел двух минут. Потеря подтверждения rollback приводит к удалению SQL-клиента из pool с сохранением исходной ошибки.

Журнал использует отдельный pool с `max:1`, принадлежащий сервису. Финальные проверки группового ответа используют уже переданный owner transaction. Проверены отсутствие повторного захвата соединения и отмена при удерживаемой SQL-блокировке журнала с обоими pools `max:1`.

Публичный поиск использует существующий владелец задания `ChatSearchService`. В журнале сохраняется только ссылка на его результат. Текст повторно проверяется по текущим видимости и revision перед использованием моделью и при чтении истории; закрытый источник не восстанавливается из копии журнала. Автоматическая индексация не добавлена.
