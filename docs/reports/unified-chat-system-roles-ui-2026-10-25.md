# Системные задачи в существующих чатах

Кандидат: feature/unified-chat-roles-20261025, поверх backend40 `251e253`.

Системная @задача из личного, группового или проектного чата открывает подготовку в той же истории. Она не отправляется обычным агентам и не публикуется людям. Модель и роль известны заранее, дополнительные данные и инструменты раскрываются отдельно. Отправка требует просмотра контекста и отдельного согласия.

Карточки хранятся в прежнем private role workflow, привязанном к исходному чату неизменяемой ссылкой40. Потерянный ACK сохраняет исходный request в browser session с отдельным ключом origin. Чтение и повторная проверка не запускают модель. Новый source берёт canonical dialog ID из ответа bind. Прежняя service-история доступна из общего чата без отдельного режима новой переписки.

Черновик исходного composer очищается после подтверждённого принятия только при неизменном владельце и том же тексте/снимке ввода. Ошибка preview сохраняет всю задачу. Неуспешное автоматическое чтение истории не создаёт цикл повторов; повторяет человек.

Проверено: 131/131 в девяти полных frontend suites, без пропусков; TypeScript noEmit. Среди них настоящий DOM AntD: компактная форма, один основной шаг, отсутствие inference до consent, неизвестный ACK, сохранение задачи после отказа preview, повтор чтения bound history. Остальные проверки покрывают @адресацию, ошибки, scope смену, origin receipts, прежние чаты и UI рабочих диалогов. В layout suite остаётся предупреждение AntD4 findDOMNode в StrictMode.

Это не браузерная или production приёмка. Реальный inference, native provider tool calling и расширенные агентские инструменты этим срезом не подтверждаются. Broker и развёрнутые ответы системных ролей идут следующими отдельными изменениями.
