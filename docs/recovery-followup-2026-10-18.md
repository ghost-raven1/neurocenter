# Восстановление сборок и обновление — 18 октября 2026

Продолжение плейтеста: исправлены потеря запроса при reload, запоздалые ответы и гонки владения серверным сборщиком. Процедура обновления сохраняет общую блокировку до остановки после ошибки. Локальные проверки проходят; промышленный допуск остаётся **NO-GO**.

## Исправления

| Проблема | Результат |
| --- | --- |
| localStorage запрещён: после reload теряется UUID | Ключ запроса и затем ID найденной сборки сохраняются в истории вкладки, с областью владельца и без исходников/токенов. URL и существующие поля Router не меняются. |
| Недоступны и storage, и история | Отправка останавливается до POST; понятная ошибка и редактируемая форма позволяют исправить настройки и повторить. |
| Поздний POST воскрешает сброшенную сборку | Сброс меняет поколение запроса; старый ответ и его finally не подменяют новую сборку. Подготовка metadata отделена от ожидания POST. |
| Поздняя сетевая ошибка перекрывает найденный успех | Ответ отправки не портит результат, уже найденный через GET. |
| После потери PG-сессии сборщик остаётся 503 | Владелец и standby повторяют захват с backoff 1–15 с; живую реплику не прерывают. Перед восстановлением обработки дожидаются старого worker и очистки. |
| Старый владелец принимает задание после takeover | Приём, публикация и startup recovery используют ожидаемую PG-сессию advisory lock. Один feature-local gate сериализует BEGIN и включает передачу worker. Потеря сессии откатывает незавершённую транзакцию. |
| Ошибка обновления останавливает сервисы после unlock | Stop и failed-квитанция завершаются под daemon-lock. Ошибка cleanup после completed не останавливает уже обновлённый релиз. |

Транзакции приёма и публикации получают явно типизированный PoolClient и освобождают только собственное соединение. Восстановление интерфейса вынесено в небольшой helper своей feature; серверный gate остаётся внутри package-build.

## Плейтест и отказы

1. Закрытие/открытие упаковки три раза сохраняет один POST.
2. Lookup находит успех, затем «Упаковать ещё» возвращает активную форму.
3. Новая сборка B с прогрессом 47% переживает поздний ответ A и его сетевую ошибку.
4. Смена роли/владельца игнорирует старый ответ и показывает чистую форму нового владельца.
5. SecurityError localStorage → reload pending UUID → найденная сборка → reload с прогрессом 37%; новый POST не отправляется. Фильтр, query/hash и checkpoint сохраняются.
6. Полный отказ persistence: POST=0, поле редактируется, primary доступна.
7. Настоящий PostgreSQL: self-reacquire, standby takeover, drain старого worker и rollback публикации при потере lease — **4/4**.
8. Настоящий PostgreSQL: прежний admission после takeover отклоняется; потеря lease перед COMMIT откатывает job/operation; разные/одинаковые requestKey и публикация не смешивают BEGIN — **5/5**.
9. Обновление: stop/failed до unlock, stopFailed, сохранение completed при cleanup error; настоящий SIGTERM процесса applying запрещает повтор миграций и сохраняет SHA-комплект.
