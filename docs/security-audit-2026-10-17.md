# Аудит безопасности Нейроцентра — 17 октября 2026

## Результат и границы

Проверены исходники основных границ доверия, зависимости семи пакетов, работающий локальный стек, роли, изоляция проектов, HTTP/WebSocket, сессии, подключение MCP, файловые операции, установка и удаление инструментов, синхронизация и восстановление PostgreSQL. Воспроизведённые нарушения исправлены и проверены повторно. Остаются существенные ограничения для многопользовательской промышленной эксплуатации: квоты, права PostgreSQL и полнота аудита.

Это аудит локального checkout и воспроизводимых сценариев. Он не подтверждает безопасность промышленного сервера, корпоративного SSO, всех внешних MCP, операционных систем или недоступной истории Git. Проверки выполнялись на временных проектах, устройствах и файлах; пользовательские данные не включены в публичный отчёт. Не выполнялись нагрузочное исчерпание диска, атаки на чужие системы или чтение настоящих пользовательских секретов.

Артефакты текущего запуска: [папка доказательств](../.run/security-2026-10-17/), [машинная сводка](../.run/verification-summary.json), [плейтест интерфейса](playtest-2026-10-17.md). Отчёты ниже относятся к реализации после исправлений, а файлы `*-before*` сохраняют воспроизведения до них.

## Исправленные нарушения

### SEC-01 — Высокий: доступ между проектами через совпадение имени и ID

**Условие:** проект, созданный главным администратором или старым импортом, назван как постоянный ID другого проекта. Назначенный администратор такого проекта получал разрешение на чужой ID, поскольку ACL сравнивал одну строку и с `projectId`, и с `projectName`.

**Доказательство:** на двух временных проектах чтение и изменение чужого скилла возвращали HTTP 200; добавление участника уже отклонялось. Отдельно воспроизведён перенос чужой строки из прежней общей RAG-базы в свою проектную БД. Самостоятельное переименование через PATCH не являлось доказанным вектором: сервер игнорировал это поле.

**Исправление:** пространство `prj-` зарезервировано; ID разрешается только как ID. Защита действует в ACL, фильтрации ответов, разрешении проектных БД и копий, CRUD каталога и миграции прежнего RAG. Старые конфликтующие записи тоже не дают доступ к чужому ID. Для инструментов аналогично исключена неоднозначность `ai-plug-`; новые имена с этим префиксом отклоняются.

Код: [projectLevel](../services/catalog-service/src/access/access.model.ts), [CRUD проектов](../services/catalog-service/src/catalog/catalog-db.ts), [миграция RAG](../services/rag-sync-service/src/rag/project-databases.ts), [репозиторий инструментов](../services/catalog-service/src/publication/plugin-repository.ts). Доказательства: `project-isolation-before.json`, `project-isolation-rag-before.log`, итоговый `project-isolation.json` — **5/5**; отдельный сценарий БД проверяет чтение, обновление и удаление при старой коллизии.

### SEC-02 — Высокий: запросы с чужого сайта могли подтверждать MCP

**Доказательство:** cookie-запрос подтверждения с посторонним Origin и простая HTML-форма проходили до исправления; WebSocket принимал чужой Origin. Одного CORS недостаточно для защиты WebSocket.

**Исправление:** изменяющие cookie-запросы требуют `X-Neurocenter-Request: 1`, разрешённый Origin и отсутствие `Sec-Fetch-Site: cross-site`. В auth-сервисе наличие постороннего Authorization не отменяет эту проверку. WebSocket проверяет Origin в `allowRequest` до подключения к комнате; затем проверяет личность. Нативные Bearer-клиенты сохраняют свой контракт. Origin берётся из `PANEL_URL`, а не из forwarded-заголовков.

Код: [middleware шлюза](../services/api-gateway/src/security/browser-security.ts), [middleware входа](../services/oauth2-bridge/src/security/browser-security.ts), [WebSocket handshake](../services/api-gateway/src/main.ts). Повторные проверки CSRF и Origin проходят в `security-scenarios.json`; проверки middleware и сессий — в `auth-security.log`.

### SEC-03 — Высокий: старое сканирование раскрывало файлы серверного компьютера

`/api/local-assets/scan` был доступен наблюдателю и читал конфигурации на сервере. Проверка использовала собственную временную папку с искусственным маркером, без настоящих секретов.

Endpoint закрыт: наблюдателю возвращается 403, главному администратору — 410 с переходом к личному MCP. Серверное сканирование не подменяет подключение компьютера пользователя. Код: [политика доступа](../services/catalog-service/src/access/access-policy.ts), [контроллер каталога](../services/catalog-service/src/catalog/catalog.controller.ts). Повторная проверка пройдена.

### SEC-04 — Средний: симлинк обходил файловую границу скиллов

Лексическая проверка пути не защищала от симлинка внутри разрешённой коллекции. Для эксплуатации требовалась возможность разместить такой симлинк в хранилище.

Теперь проверяются канонический корень и компоненты пути, включая конечный Markdown-файл; перед фиксацией записи путь проверяется повторно. Пять воспроизведений чтения, создания, изменения и удаления через ссылки проходят после исправления. Код: [FsSkillsStorage](../services/skills-service/src/storage/fs-skills-storage.ts), [тесты симлинков](../services/skills-service/test/symlink-boundary.test.ts). Это не доказательство полной защиты от гонки с привилегированным локальным процессом: права ОС на каталог остаются необходимыми.

### SEC-06 — Средний: неограниченные сессии и ненадёжный выход

Серверная сессия теперь имеет срок действия: по умолчанию 8 часов, настройка ограничена 60–86400 секундами. Cookie получает соответствующий срок, HttpOnly, SameSite=Lax и Secure для HTTPS-площадки. POST logout сначала удаляет серверную сессию; фронтенд дожидается ответа. При ошибке обмена OAuth в лог не выводится полный объект HTTP-клиента с возможными секретами.

OAuth state сохраняет проверку nonce; SameSite=Lax допускает возврат от внешнего провайдера. После входа восстанавливается только разрешённый относительный маршрут площадки, включая шаг подключения. Произвольный внешний redirect отклоняется. Код: [сессии](../services/oauth2-bridge/src/auth/session.service.ts), [auth controller](../services/oauth2-bridge/src/auth/auth.controller.ts), [возврат после входа](../services/oauth2-bridge/src/auth/login-return.ts). **24** Node-проверки auth/middleware/лимитов/фильтрации пройдены; выход и возврат на `/start?step=1` также проверены в браузере. Настоящий корпоративный SSO не проверялся.

### SEC-07 — Средний: подмена адреса в установщике

Скрипт мог содержать адрес из подставного `X-Forwarded-Host`. Теперь базовый URL формируется из доверенной настройки `PANEL_URL`. Живой сценарий с чужим forwarded-host пройден. Код: [BridgeController](../services/api-gateway/src/bridge/bridge.controller.ts).

### SEC-08 — Средний: защита браузерной поверхности и сборочного контекста

Добавлены CSP, запрет встраивания, nosniff, no-referrer; JSON auth/API не кэшируется. Production CSP разрешает скрипты своей площадки; встроенные стили сохранены для Ant Design. В dev разрешены inline-скрипты, необходимые Vite Refresh; эта настройка не переносится в nginx. `.env*` и `.run` исключены из корневого контекста Docker, отдельные контексты исключают свои `.env*`.

Образ frontend **собран**. В отдельном nginx-контейнере проверены HTTP 200, CSP, X-Frame-Options, nosniff, Referrer-Policy и загрузка скомпилированного JavaScript. Доказательства: `frontend-image.log`, `nginx-smoke.json`. Это проверка образа frontend, а не развёртывание всего production-стека.

### SEC-09 — Средний: общий лимит polling мешал нескольким компьютерам

Ранее бюджет 60 запросов в минуту делился по IP прокси между подключениями. Теперь отдельные бюджеты старта и polling: 15 стартов/IP/мин, 60 polling/code/IP/мин и общий предел 6000 polling/IP/мин. Код проверяется по формату, ключ лимита содержит его хэш. Проверено, что исчерпание одного кода не блокирует следующий и общий предел сохраняется. При работе за несколькими прокси и репликами потребуется общий limiter.

## Что ещё не подтверждено

Корпоративный OAuth/SSO, Windows/Linux на реальной машине, запуск системного браузера на всех ОС, диалог выбора настоящей пользовательской папки, большие индексы, нагрузка/DoS, полное отключение питания и fsync, конкурентные реплики, CI, образы всех сервисов и промышленный deploy. В checkout отсутствуют метаданные Git: синхронизацию веток, CI и серверную версию проверить здесь нельзя.

Текущая синхронизация переносит строки порциями. Она не является атомарной заменой полного образа LanceDB с общим CAS; проверки передачи строк нельзя выдавать за готовность всего проектировавшегося хранилища образов.

## Источники критериев

- [OWASP: CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) — нестандартный заголовок, проверка Origin и Fetch Metadata.
- [Socket.IO: Handling CORS](https://socket.io/docs/v4/handling-cors/) — отдельная проверка WebSocket через `allowRequest`.
- [Express: Production security](https://expressjs.com/en/advanced/best-practice-security/) — TLS, заголовки, cookies и обновление зависимостей.
- [Vite security advisory GHSA-356w-63v5-8wf4](https://github.com/vitejs/vite/security/advisories/GHSA-356w-63v5-8wf4) — необходимость обновления dev-инструментов.
- [Node.js: Previous releases](https://nodejs.org/en/about/previous-releases) — статус поддержки версий среды. Нулевой результат npm audit не проверяет срок поддержки установленного Node.
