# Исследование в личном чате

Кнопка «Чат» в общей шапке открывает личные диалоги. Для проектного чата можно включить «Исследовать источники» у конкретного сообщения. Это явное согласие на дополнительные обращения к модели и выбранным источникам; следующее сообщение по умолчанию снова обычное. Настройки сохраняются с сообщением и не меняются при повторе.

Доступны дополнительные поисковые шаги по готовому индексу текущего проекта и внешний поиск через назначенный проекту поисковый MCP. Обычный контекст проекта и прикреплённые документы сохраняются независимо от дополнительных шагов. До отправки интерфейс читает только метаданные доступности: открытие настроек и предварительная оценка контекста не вызывают модель или MCP. Если выбранный источник недоступен, нужно исправить выбор или выключить исследование; отправка не превращается молча в обычный чат.

Внешний MCP закрепляется тройкой `assetId`, `version`, `manifest`. Для первого адаптера допустим только проверенный native MCP с `schemaVersion:5`, `transport:stdio`, `extra.hostedMcp:true` и `extra.researchMcp:{adapter:'exa',tools:['web_search_exa','web_fetch_exa']}`. Нужна подходящая серверная поставка `runtimeArtifacts`. Каталог повторно проверяет назначение и содержимое пакета, Gateway проверяет полный пакет, поставку, список инструментов и их readonly/non-destructive annotations. Ни браузер, ни модель не выбирают команду запуска, endpoint, credentials или имя произвольного инструмента.

## Исполнение и источники

Выбранная chat-модель возвращает один JSON-объект из закрытого union: завершение, поиск по проекту, чтение уже найденного фрагмента, внешний поиск или чтение внешних страниц. Неизвестные поля, команды и неподдерживаемые параметры отклоняются. Модель получает свои обычные настройки и, для участника группы, его закреплённый проектный prompt и выбранную модель. Источники передаются как недоверенные справочные данные, отдельно от системных инструкций.

Поиск проекта возвращает идентификаторы фрагментов текущего индекса. Прочитать можно только фрагмент, найденный в этом исследовании; произвольный путь или другой проект не принимается. Источники у ответа содержат фрагменты, действительно переданные этому получателю. Внешние ссылки сохраняются отдельно от проектных фрагментов.

Внешний поиск и чтение проходят через API Gateway и разрешённый MCP. Поисковые запросы и адреса страниц передаются провайдеру MCP. В URL разрешены HTTP(S) доменные имена без учётных данных; literal IP, локальные/служебные имена и нестандартные порты отклоняются. В запросе чтения не более пяти URL. Для поиска нужны `query` и `objective`, до десяти результатов; для чтения `maxCharacters` не более 10000. Модель не получает ключи провайдера или произвольные заголовки.

## Проверяемые пределы

- До шести JSON-решений на один ответ, включая явное завершение; неверное решение тоже завершает текущую попытку с ошибкой.
- До шестнадцати исполнений внешних инструментов на весь групповой раунд; проверка списка инструментов — отдельная служебная операция.
- До 64 КиБ текста на результат одного инструмента и до 96 КиБ собранного текста на ответ одного получателя.
- Один общий срок до пятнадцати минут на подготовку, сжатие, исследование и все ответы участников.
- Транспортные пределы чата и фактическое/неизвестное окно каждой модели продолжают действовать. Материалы не обрезаются молча, чтобы изобразить полный ответ.

При исчерпании шести шагов модель готовит ответ на основании собранного, а интерфейс показывает предупреждение об ограниченности исследования. Ошибка источника, отмена, изменение индекса, назначения, prompt или model pin не выдаются за успешный поиск. При отсутствии места в контексте требуется уточнить запрос или выбрать подходящую модель.

Перед каждым новым платным вызовом проверяются актуальные права, закреплённая модель, получатель и применимые feature flags. `research_tools` проверяется также перед первоначальной подготовкой контекста и сжатием. Отключение флага останавливает новые вызовы; уже оплаченный ответ не отбрасывается лишь из-за этого переключения. Отзыв доступа, изменение pin/индекса и отмена по-прежнему запрещают фиксацию запоздалого результата.

## История, повтор и отмена

Каждый фактический шаг получает durable receipt с попыткой, порядком, получателем, статусом и безопасными параметрами. Текст результата сохраняется отдельно от метаданных истории. При отмене или истечении lease незавершённые шаги переводятся в отменённые триггерами PostgreSQL. Терминальные receipts неизменяемы. Повтор использует исходный consent и новый request ID; успешные ответы других участников сохраняются.

Под ответом видны шаги текущей попытки. «Все попытки исследования» загружает метаданные страницами, полный результат одного шага открывается отдельно. Старые попытки доступны после повтора, без скрытой обрезки истории и без загрузки всех больших результатов сразу. Диалог, страницы истории и результаты принадлежат одному пользователю; чтение каждый раз проверяет владельца и актуальный доступ к проекту и модели. Удаление диалога каскадно удаляет receipts.

Планирование отмечается в обязательном журнале использования моделей с purpose `research`; подготовка поиска, сжатие и финальные ответы имеют свои purpose. Эти события не подменяются одним вымышленным «запросом исследования».

## API

- `GET /api/model-chats/research-tools?modelId&projectId` — доступные источники до создания диалога.
- `GET /api/model-chats/:id/research-tools` — источники текущего личного диалога.
- `POST /api/model-chats/:id/turns` — обычный send DTO и необязательный `research:{project:boolean,external?:{assetId,version,manifest}}`; нужен хотя бы один источник.
- `POST /api/model-chats/:id/turns/:turnId/retry` — сохраняет исходный `research`, не принимает его замену.
- `GET /api/model-chats/:id/turns/:turnId/research-steps?before=<stepId>&limit=50` — все попытки, метаданные в убывающем порядке `(created_at,id)`, максимум 100 записей на страницу, строгий scoped cursor.
- `GET /api/model-chats/:id/research-steps/:stepId` — полный результат одного шага.

`detail/history` несут только сводки последней попытки каждого получателя, включая сохранённые успешные ответы предыдущего запроса. В группах у каждого ответа собственные источники и фактическое окно модели; единого вымышленного окна группы нет.
