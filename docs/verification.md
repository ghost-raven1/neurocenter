# Проверка изменений

Проверяйте текущий checkout и сохраняйте область каждой проверки. Локальные unit-тесты, работа с базой, сборка, браузер, CI и установленная площадка подтверждают разные свойства.

## Команды

Используйте Node 24 и установленные зависимости пакетов. Действующие команды:

```sh
npm run lint
npm run format:check
npm run check -- --package frontend --step typecheck
npm --prefix frontend test
npm run build:isolated -- --help
```

`npm run check` выполняет проверки runtime-пакетов, включая обычные сборки. Для проверки кандидата без замены работающих `dist` используйте [изолированную сборку](developer-tools.md). Общие правила исходников и тестов описаны в [service-eslint.md](service-eslint.md); инструкции измерения покрытия — в [coverage.md](coverage.md).

## Что считать результатом

| Свидетельство | Что подтверждает |
| --- | --- |
| ESLint, форматирование, TypeScript | Проверенные исходники соответствуют конфигурации и типовым контрактам |
| Unit-тесты | Наблюдаемое поведение выбранных модулей при заданных входах и контролируемых внешних зависимостях |
| Интеграционные тесты | Проверенный контракт между реальными компонентами и конкретным тестовым окружением |
| Изолированная сборка | Собираемость зафиксированного кандидата, без доказательства его установки |
| Браузер или установленный runtime | Только реально пройденные сценарии на указанной версии и площадке |
| Coverage | Измеренные строки/ветви в явно названном знаменателе; количество passed не заменяет покрытие |

Удаление старых тестов не переносит их прежние результаты на новый набор. Нулевой найденный набор, пропуски, отключённые зависимости и изменившиеся во время запуска исходники должны оставаться видимыми в отчёте. Не складывайте пересекающиеся прогоны.
