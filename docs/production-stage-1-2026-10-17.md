## Реализовано

- Отдельный `compose.production.yml`: только публичные 80/443, TLS, CSP/HSTS, ограничение входов, log rotation, restart policy, CPU/память, grace period. Node 24.22.0, nginx 1.30.6 и PostgreSQL/pgvector закреплены digest.
- Приватные файлы секретов с минимальным набором на сервис. Проверка конфигурации до Nest/БД запрещает dev-обходы, отключённую проверку TLS, HTTP-площадку, чужой callback и незаполненные обязательные поля. Shell оператора не перекрывает выбранный env-файл.
- Мастер настройки и отдельная команда seed. Пароли БД сохраняются при повторной настройке. В production отсутствуют демоданные и локальный dev-администратор. Bootstrap под транзакцией/advisory lock работает только в пустом каталоге и не восстанавливает отозванные права. Bootstrap и изменения платформенных пользователей имеют транзакционный аудит.
- Blitz: PKCE S256, одноразовая десятиминутная серверная транзакция, `client_secret_basic`, защищённый userinfo и правильный URL выхода. Повторный callback не повторяет обмен кода. POST-выход отзывает сессию и возвращает 200.
- Разделены роли PG для каталога, RAG, provisioner и backup. Рабочие роли без superuser/CREATEROLE; CREATEDB есть только у provisioner. pgvector готовится оператором в шаблоне, который клонирует RAG.
- `/ready` проверяет зависимости, `/health` — процесс; публичный `/ready` отражает состояние шлюза. Добавлены shutdown hooks и закрытие Socket.IO. RAG допускает 8 активных и 16 ожидающих обращений, далее 503; ограничены пакеты и идентификаторы.
- RAG/MCP собирается по lock-файлу без повторной установки с `--package-lock=false`. Проверена Linux GNU LanceDB после prune. В gateway проверены четыре установщика, архив моста и восемь архивов OpenCode.

## Production-стенд и данные

`production-stack.mjs` сам создаёт тестовый TLS через OpenSSL, локальный Blitz, уникальный Compose-проект и чистые volumes. Используются loopback-порты. HTTPS-клиент проверяет CA и имя; тестовый CA добавлен только auth-контейнеру. После проверки собственный стек удаляется. Локальный container healthcheck nginx не проверяет сертификат loopback; внешние тестовые запросы проверяют сертификат.

Пройдены: чистый и повторный seed; отсутствие демоданных; HTTPS/CSP/HSTS и отказ API без сессии; полный PKCE-поток до ролей и Secure-cookie; запрет повторного callback; Socket.IO-событие; создание отдельной БД без superuser; запись знаний и pg_dump ролью чтения; отказ PG с readiness 503 при живом `/health`; восстановление PG; SIGTERM с живым WebSocket; сохранность данных/авторизации после перезапуска gateway; выход с закрытием доступа.

Остановка gateway с активным WS на последнем прогоне — **269 мс**. Nest после hooks повторно посылает SIGTERM: код 143 штатный, OOM/SIGKILL не было. Остановка длительных активных операций ещё требует отдельной репетиции. Настоящий корпоративный Blitz не использовался: локальный IdP подтверждает протокол, но не настройки реального приложения.

В браузере повторены семь разделов при 1280×900 и 390×844: нет сообщений об ошибке загрузки и переполнения ширины документа. Это не сертификация доступности и не повтор всех модальных сценариев.

Очистка удаляла только созданные этим прогоном тестовые БД по собственным фикстурам: `dev-integrity.json`. Реальные пользовательские файлы не использовались для установочных тестов.
