# Размеры проектов: отказы и восстановление — 19 октября 2026

**P1-SIZE закрыт локально:** список и обзор проекта больше не подменяют недоступный замер нулём. Исправлены сетевое измерение копии знаний и файловый подсчёт `.opencode`. Три агента проверили интерфейс, файловые метрики и доступ; основной агент свёл контракт и проверил браузер. Production-допуск остаётся **NO-GO**.

## Изменения

| Ошибка | Поведение после исправления |
| --- | --- |
| Catalog возвращал 0 при отсутствии RAG, HTTP/JSON/сетевой ошибке | `retainedBytes: null` и безопасная `retainedSizeError`; проект остаётся доступен. Только точный неотрицательный safe integer от нужного `projectKey` считается замером. |
| Медленный ответ продлевал ожидание, тело не ограничивалось | Общий дедлайн 5 секунд, максимум 16 КиБ, HTTP/HTTPS; timeout, обрыв, неверный статус и превышение размера закрывают запрос. Внутренний URL, токен и upstream body не попадают в причину. |
| Файловый подсчёт ходил по ссылкам, циклы раздували размер; ошибки давали 0 | Ссылки внутри дерева пропускаются; ссылка вместо `.opencode` даёт `null`. Нет настроенной/существующей серверной папки или чтение неполно — `logicalBytes: null` и причина. Существующая папка без `.opencode` и пустой `.opencode` дают настоящий 0. |
| Длительный обход папки удерживал карточку | Бюджет 10000 элементов, глубина 32, дедлайн файлового замера 1 секунда (полная карточка также ждёт RAG, таймер зависит от event loop). Уже начатый системный I/O может завершиться позже; дальнейший обход прекращается. Частичная сумма не публикуется. |
| UI форматировал ошибку как пустые данные | Общий `ProjectSize` показывает «Недоступно», причину и read-only «Повторить»; настоящий ноль — «0 Б». Повтор сохраняет поиск/страницу/URL, не открывает строку и не принимает старый ответ другого владельца. Здоровый ответ убирает причину. |

Контракт GET list/detail: `logicalBytes`, `retainedBytes` и вложенные `quota.currentBytesUsed`/`quota.retentionBytesUsed` допускают `null`; причины — необязательные строки. Существующая валидация входных квот не менялась. Живые значения не записываются обратно в SQL; write-response не является отдельным новым измерением. Клиенты должны загружать GET после изменения проекта.

Сетевой reader вынесен из большого `CatalogService` в отдельный модуль; frontend использует один компонент для обеих метрик. Остальные домены большого сервиса не перерабатывались.

## Ограничения и следующие задачи

Это оценка файлов и develop-индекса, а не атомарный снимок и не независимая внешняя копия. Серверный `fsRootPath` не измеряет папку на клиентском компьютере; чтения RAG по прежнему контракту могут лениво подготовить проектную БД. Гарантия неизменности произвольно меняющейся файловой системы и крупная нагрузка этим проходом не принимаются.

Найден дополнительный старый stub `PATCH /api/projects/:id/retention`: возвращает тело без сохранения и проверки проекта. Текущий UI его не вызывает; обычный `PATCH /api/projects/:id` сохраняет retention. Задача P2-RET внесена в реестр: соединить отдельный endpoint с существующим валидируемым сохранением и проверить 404/400/повтор/аудит. В этом проходе endpoint не менялся.

Внешние шесть P0, семь остальных native-целей, web/snapshot restore, generic executor retry/cancel, purge и согласованное FS/PG восстановление остаются открыты. `.git` отсутствует; commit/push, CI и production deployment не выполнялись.
