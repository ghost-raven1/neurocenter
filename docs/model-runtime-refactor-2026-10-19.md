# Повторная проверка локального хостинга моделей — 2026-10-19

Работа ведётся в ветке `codex/refactor-model-hosting`. Сохраняются проектный контейнер Ollama, закреплённые модели, API, расположение весов и существующие npm-команды.

## Изменения

- Общая обработка `up`, `check`, `status`, `down` находится в `scripts/models/control-cli.mjs`. Embedding и vision передают свой профиль; содержательные проверки моделей различаются.
- Общий HTTP-клиент находится в `scripts/models/http.mjs`. Прежний экспорт `requestJson` из embedding-клиента сохранён для совместимости.
- Чтение, атомарная запись и проверка отметок готовности находятся в `scripts/models/readiness.mjs`. Docker и порядок подготовки остаются в runtime.

## Исправленные сценарии

| Сценарий | Поведение после исправления |
| --- | --- |
| `down --help` | Справка без остановки контейнера и обращения к конфигурации |
| Неизвестный или лишний аргумент | Ошибка до Docker и загрузки модели |
| Импорт файла CLI | Команды не выполняются |
| Пустой ответ, HTTP 204, `null`, неверная JSON-форма | Понятная ошибка протокола без внутреннего TypeError |
| Ошибка OpenAI API | Сохраняются HTTP-статус и ограниченный текст `error.message` |
| Длинная Unicode-строка состояния загрузки | Лимит 64 КиБ считается по UTF-8-байтам |
| Прогресс после `success` с последующим обрывом | Загрузка не считается завершённой |
| Ответ embedding с другим именем модели | Содержательная проверка отклоняет ответ |
| Неверные capabilities или JSON-наблюдение vision | Проверка отклоняет ответ без отметки готовности |
| Повреждённая, слишком большая квитанция, ссылка или FIFO | `status` возвращает `unchecked`, `checkedAt: null` и `verificationIssue` |
| Владелец освободил блокировку между попыткой захвата и чтением | Новая команда захватывает свободную блокировку или сообщает о занятости |
| Ошибка публикации новой квитанции | Временный файл очищается; неизвестный целевой каталог не удаляется |

Квитанция ограничена 16 КиБ; специальные файлы и ссылки не читаются. Отказ vision не изменяет квитанцию embedding. Таймауты HTTP, ограничения тела, запрет перенаправлений, SHA весов и проверка принадлежности контейнера сохраняются.

Полный прогон также выявил два прежних расхождения тестов с реализацией. Ожидание ревизии OpenCodeRAG обновлено до `2.4.4-mcp.pack.4`. Проверки установщика закрепляют действующий публичный сценарий: ключ из `OPENCODE_API_KEY` не сохраняется и не печатается; провайдер выбирается через `opencode auth login`. Версия пакета и поведение установщика не меняются в рамках этого рефакторинга.

## Проверка

Регрессии воспроизводятся на собственных временных каталогах, HTTP-серверах loopback и дочерних процессах. Подставной Docker в unit-тестах не подключается к настоящему daemon. Изображения и тексты синтетические.

```sh
node --test scripts/test/local-embedding.test.mjs scripts/test/vision-*.test.mjs scripts/test/model-*.test.mjs scripts/test/workspace-check.test.mjs
VITEST_MAX_WORKERS=2 npm run check
```

Полный прогон проверяет типы и сборки сервисов, frontend и моста, затем тесты и Compose-конфигурацию. Число Vitest workers ограничивается для локальной приёмки; пропущенные проверки учитываются отдельно. Локальные свидетельства сохраняются в `.run/model-refactor/` и `.run/check/` и не входят в Git.

Результат всех 22 этапов: типы и сборки семи пакетов прошли; **3415 тестов прошли, 12 пропущены**.

В общие Node-проверки входят 94 проверки хостинга моделей; отдельно к сумме они не прибавляются. После исправления двух устаревших ожиданий повторены общие контракты и две Compose-проверки. Первоначальный отчёт сохранён, объединённое подтверждение всех этапов — `.run/model-refactor/verification.json`.

Фактический проход через закреплённый проектный runtime также прошёл:

- Обе команды `down --help` с ошибочным портом показали справку; контейнер не остановился.
- Embedding-команда вернула корректные векторы размерности 2560 до vision и после переключения обратно.
- Vision-команда прочитала `42/red` через native API; OpenAI API вернул те же признаки. CLI с русским вопросом ответил `42, красный`.
- Обе модели имеют `verified`. Идентификатор и время запуска контейнера, inode/размер/mtime файлов весов и список глобальных моделей Ollama сохранились. Новые веса не скачивались.

Свидетельство фактического прохода — `.run/model-refactor/live.json`. Проверка проводилась на macOS arm64 и CPU; она не является подтверждением других платформ или production-стенда.

## Границы

После аварии между созданием файла блокировки и записью PID пустая блокировка требует диагностики. Оставшийся после аварии `control.lock.recovery` также требует проверки оператором: автоматическое удаление неоднозначной блокировки не выполняется. Обычное завершение, исключения и восстановление блокировки с известным завершившимся PID покрыты проверками.

Эта работа не подтверждает production-допуск, настоящий внешний IdP, восстановление на другом хосте или нативную матрицу всех платформ. Эти критерии остаются в [документе готовности](implementation-readiness.md).
