Источник: замечания Алексея в текущем чате. Изменения только в запрошенных областях.
Статусы ниже отражают фактически выполненную работу; локальные проверки не означают проверку сервера или всех платформ.

Прямое требование Алексея: перейти на единый новый формат `neurocenter-assets`, прежние source-описи, seeds и обходные runtime-пути удалить. Существующие версии и связи проектов сохраняются явной миграцией данных. Параллельный legacy-режим, автоматический downgrade и подстановка старого cache при отказе нового источника не допускаются.

## Обязательная матрица проверки каждого блока

- Нормальный путь и граничные данные: 0 / 1 / много объектов, длинные и одинаковые имена, отсутствующие необязательные поля.
- Loading, пустой ответ, offline, timeout, неверный ответ, отказ API, частичный успех, ошибка записи, повтор после ошибки.
- Повторные клики, одновременные операции, поздние ответы, закрытие окна, переход на другую страницу, перезагрузка.
- Смена пользователя, роли, проекта и выбранного компьютера во время запроса; отсутствие действий над чужими данными.
- Повторное подключение, удалённая / частично удалённая / устаревшая `.opencode`, существующие настройки и локальные изменения.
- Клавиатура, фокус, доступные названия действий, узкий экран, прокрутка и доступность основных кнопок.
- Регрессионный тест на каждый воспроизведённый дефект; проверки уровня API/bridge и браузера там, где unit-тест не подтверждает реальное поведение.

## Упаковка: сценарии, которые нельзя потерять

- npm: bin / exports / main, несколько команд, отсутствующий файл, библиотека без исполняемой точки, фиксированная версия.
- GitHub: repo, branch/tag/commit, monorepo-подпапка, скачивание исходников, Release-ассеты, несуществующий ref, rate limit и обрыв сети.
- ZIP: некорректный формат, лимиты, опасные пути, несколько корней, отсутствующие и дублирующиеся файлы.
- JS/TS, Python, Java, .NET, Go, Rust и готовые бинарники: фактическая поддержка runtime, OS/архитектура, зависимости и проверяемый entrypoint. Неподдерживаемый вариант объясняется явно.
- Автоопределение неуверенно / несколько кандидатов / нет кандидатов: понятный запрос только недостающих данных.
- Разрешения, секреты, несовместимая платформа, повреждённый кэш, прерванная сборка, падение worker, восстановление после перезапуска.
- Повторная отправка, неизвестный результат POST, сохранение точного плана и исходников, повтор после reload, существующая карточка / новая версия / дубликат.
- Публикация только после проверки содержимого; происхождение, commit/версия и лицензия сохраняются.

## Зафиксированные ограничения и найденные проблемы

- Все23 уникальных runtime-архива существующих source tools доступны в native runtime storage: 20 были сохранены,3 восстановлены из проверенного SHA-кэша через штатный importer. Старые версии карточек и project pins не подменялись. Три старых демо-скилла требуют решения главного админа: Memory и Jest без description/исходного v1 snapshot; Code Review с orphan-проектом и named dependencies. Отдельные unresolved project refs сохраняются честно, без подстановки head. [Итоговый аудит](../output/final-new-format-legacy-audit.md).
- Готовые payload других языков определяются по содержимому. Компиляция произвольных Go/Rust/Java source без закреплённого toolchain не поддержана и не обещается; поддержанные/неподдержанные варианты показываются явно.
- Точный план и исходники теперь фиксируются в IndexedDB до первого POST. 83 исходные целевые проверки и 6 сценариев настоящего browser IndexedDB прошли; новые проверки повреждённых source и Release wiring выполняются отдельно.
- Нет обещания отсутствия любых багов: завершение подтверждается перечисленными сценариями и фактическими результатами, непроверенные платформы и интеграции указываются отдельно.
