# Персональный профиль инструментов проектного агента

Статус: техническое решение следующего среза AP02; реализация и runtime-проверка ещё не выполнены. Продолжает [общую очередь командной площадки](agent-discussions-tooling-backlog-2026-10-23.md), не заменяет принятые требования BMAD/OpenSpec.

## Фактические границы

В определении агента сейчас есть prompt, mode, model и scalar разрешения встроенных инструментов. Назначение закрепляет версию и overrides, а configure-project-agents сохраняет compiled manifest и SHA файла. Skills, MCP и plugins устанавливаются в общую папку проекта; отдельного профиля назначений этих ресурсов нет.

Проверен исходный контракт закреплённого OpenCode 1.14.48:

| Ресурс | Возможность native runtime | Следствие для интерфейса |
| --- | --- | --- |
| Skills | Фильтрация доступных имён через `permission.skill`, повторная проверка разрешения при вызове. [Список](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/skill/index.ts#L253-L257), [вызов](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/tool/skill.ts#L28-L33) | Можно назначать точные имена и показывать allow/ask/deny; это не запрещает доверенному bash/read читать тот же файл. |
| MCP | Вызов проверяет точный native tool key; список модели фильтруется по разрешениям. [Вызов](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/session/prompt.ts#L425-L442), [фильтр](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/session/llm.ts#L425-L430) | Привязывать разрешение к наблюдённому ключу и схеме установленного MCP, не к endpoint или имени из ответа модели. |

Нельзя обещать, что снятый персональный checkbox отключает startup hook для одного агента. |

Native поддерживает вложенные правила и порядок последнего совпадения: [schema](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/config/permission.ts#L21-L46), [оценка](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/permission/evaluate.ts#L8-L13). Первый UI должен предлагать только общий default и точные управляемые имена, без произвольных шаблонов и неочевидного порядка правил.

## Первый проверяемый профиль

1. Пользователь выбирает несколько навыков из назначенных проекту ассетов. Сервер разрешает `assetId/version/manifest/name` по существующим immutable package pins. Имя выводится из проверенного SKILL.md; произвольный текст модели не становится назначением.
2. Профиль хранит точные references и policy для каждого имени. Отсутствующий, изменённый, неоднозначный или неустановленный навык получает `needs_setup`. Установка выполняется явным существующим UI действием; запуск задачи не устанавливает зависимости автоматически.
3. Версия карточки и project overrides включают references в digest. Новая capability обозначает поддержку профиля, старые scalar определения остаются совместимыми. JSONB определений позволяет это без новой таблицы, но не отменяет runtime-проверку.
4. Bridge-private receipt следующей версии хранит разрешённые references, actual relative paths и file SHA, связанные с approved compiled manifest. Нынешняя schema2 содержит только агентные файлы: из неё нельзя восстановить выдуманное подтверждение навыков.
5. Перед запуском, при poll и перед результатом мост проверяет владение управляемым файлом, хеш, уникальное effective имя и профиль native агента. Старый receipt или другая capability блокируют новый режим с доступным переходом к настройке.
6. Карточка показывает отдельно заданный профиль и последний наблюдённый runtime: имя, pin, policy, состояние и время проверки. `ask` требует явного пути одобрения; неинтерактивный исполнитель не подтверждает его сам.

MCP следует тем же принципам immutable discovery/schema и fresh authority. Это следующий адаптер после навыков, а не автоматический доступ ко всем MCP проекта. Plugins остаются общей средой; изоляция загрузки требует отдельного управляемого окружения и собственного контракта.

## Проверка до закрытия AP02

- Совместимость прежних scalar definitions и их compiled manifest; новая версия не переписывает старые карточки.
- Сервер отклоняет несуществующий/снятый pin и подмену имени; флаг OFF сохраняет историю и восстановление.
- Реальный configure → private proof → native skill list → разрешённый вызов и запрещённый вызов; контролируемая локальная модель без платного повтора.
- Изменение или коллизия SKILL.md после конфигурации блокирует dispatch/poll; исходный файл и ручные настройки сохраняются.
- UI проверяется в пустом состоянии, после отказа установки и после перезагрузки; «настроено» и «проверено в runtime» различаются.
- Отдельно фиксируются установка моста, настоящий провайдер, другие ОС, CI и production. Исследование исходников не закрывает эти проверки.
