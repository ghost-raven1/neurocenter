# Восстановление обновления моста

## Подключение уже установленного моста

На странице «Начало работы» → «Компьютер» выберите «Мост уже установлен». Команда запускает автономный Node и имеющийся `dist/index.js`; скачивать пакет, устанавливать npm или регистрировать MCP заново не требуется. После запуска нажмите «Проверить подключение».

- Если компьютер просто не в сети, используется `--connect-open`: действующее подключение сохраняется, worker запускается.
- Если доступ истёк, требуется другая назначенная роль или в текущем профиле ещё нет устройств, используется `--reconnect-open` с подтверждением имени и отпечатка на сайте. Продление доступа не требует замены программы.
- Несовместимый протокол или отсутствующие возможности предлагают «Обновить мост». При нескольких устройствах компьютер выбирается явно.
- Систему можно выбрать вручную: macOS/Linux или Windows PowerShell. При наличии отчёта начальный выбор соответствует системе компьютера, иначе — браузера.
- Если мост принадлежит другому профилю, продлить его может прежний владелец. Для переноса сначала отключите устройство в прежнем профиле, затем повторите команду подключения. Подтверждение другим профилем не обходит проверку владельца.

Команда использует адрес открытой площадки. Для перехода между площадками нужен вариант установки/обновления: он также меняет адрес MCP в конфигурации OpenCode. Прямое подключение не меняет эту конфигурацию. При нестандартном каталоге установки укажите путь к имеющемуся мосту (`INSTALL_DIR` для Bash).

## Замена программы

Повтор установки обновляет программу, сохраняя подключение, настройки OpenCode, квитанции и журналы файловых операций.

- Живой worker и активное задание: выдача новых заданий ставится на паузу, установщик ждёт завершения текущего. Через 30 секунд возвращается конкретная причина отказа; файлы программы сохраняются, очередь возобновляется.
- Worker отсутствует или его PID завершился: серверная запись `running`/`reconciling` сама по себе не запрещает замену программы. Установщик удерживает серверную паузу до окончания замены. После запуска worker восстанавливает журналы и повторяет доставку сохранённых результатов.
- Worker отсутствует, ключ просрочен или отозван: HTTP 401/403 не мешает установке файлов. Серверная пауза не считается полученной; установщик переходит к обычному восстановлению подключения с подтверждением владельца.
- Ошибка сети, HTTP 503, повреждённая блокировка или неподтверждённый ответ сервера останавливают обновление. Ошибка показывается в терминале.

Оба установщика снимают только действительно полученную паузу. Для старого ответа CLI без поля `paused` сохраняется прежний порядок завершения. При отказе регистрации совместимая предыдущая программа возвращается на место.

Незавершённые серверные записи автоматически не объявляются успешными или отменёнными. Без сохранённого локального результата остаётся необходимость сверки. Для живого worker с `reconciling` сохраняется защита до подтверждённого завершения; истечение аренды не доказывает, что запись локальных файлов остановилась.

Повторите исходную команду установки после устранения показанной причины. Удалять квитанции, файловые журналы или блокировку живого worker для обхода проверки нельзя: они нужны для восстановления результата.
