# Восстановление обновления моста

## Подключение уже установленного моста

На странице «Начало работы» → «Компьютер» выберите «Мост уже установлен». Команда скачивает сценарий `/api/bridge/connect.sh` или `/api/bridge/connect.ps1` с проверенного Gateway, полученного из `/api/bridge/config`; UI origin не подставляется при ошибке настроек. До окончания загрузки или после ошибки копирование команды недоступно, есть повтор получения настроек. После запуска нажмите «Проверить подключение».

Connect endpoint не требует импортированной поставки. При исправной установке сценарий напрямую запускает её автономный Node и `dist/index.js`, включая старый мост без launcher. Системные Node/npm и повторное скачивание архива не нужны. Короткая команда восстанавливается по возможности, её отказ не блокирует прямое подключение.

- Если компьютер просто не в сети, сценарий использует `--connect-open`: действующее подключение сохраняется, worker запускается.
- Если доступ истёк, требуется другая назначенная роль или в текущем профиле ещё нет устройств, команда получает `?reconnect=1` и использует `--reconnect-open` с подтверждением имени и отпечатка на сайте. Продление доступа не требует замены программы.
- Несовместимый протокол или отсутствующие возможности предлагают «Обновить мост». При нескольких устройствах компьютер выбирается явно.
- Систему можно выбрать вручную: macOS/Linux или Windows PowerShell. При наличии отчёта начальный выбор соответствует системе компьютера, иначе — браузера.
- Если мост принадлежит другому профилю, продлить его может прежний владелец. Для переноса сначала отключите устройство в прежнем профиле, затем повторите команду подключения. Подтверждение другим профилем не обходит проверку владельца.

Сценарий выбранного Gateway задаёт целевые SITE/API. На прежней площадке собственная регистрация сохраняется побайтно; при переходе атомарно меняются только её два адреса. JSONC-комментарии, пользовательское окружение, другие MCP/агенты, права файла и ключи старого namespace сохраняются. Обычное прямое подключение не вызывает `--init`; новая площадка использует свои ключи или новое подтверждение. Ручная короткая команда по-прежнему использует последнюю сохранённую площадку. [Правила перехода и проверки](bridge-installers.md#переход-между-площадками--22-октября-2026).

Отсутствие runtime или известная необходимость восстановить регистрацию на предварительной проверке запускает установщик выбранной площадки один раз. Для этого нужна доступная поставка. Ошибка запущенного Node/CLI не повторяет установку; сначала устраните показанную причину. Повреждённая, чужая, неоднозначная или изменившаяся регистрация не считается отсутствующей. Если стандартного runtime нет, custom root определяется по точному полному формату управляемого launcher: его пути читаются как данные, сам launcher не исполняется. Для неизвестного/чужого legacy-формата или custom root без подтверждённого launcher явно задайте `INSTALL_DIR` в окружении Bash или PowerShell; это не обязательная настройка любого нестандартного каталога.

При ошибке списка устройств сохраняются повтор его загрузки и независимые команды connect/install с проверенного Gateway. Неизвестный список не вызывает принудительное переподключение и не разрешает операции с папками как будто компьютер готов. Загрузка или ошибка самой Gateway-конфигурации по-прежнему убирает команду до успешного повтора.

## Что означает статус подключения

«Онлайн-обновления» в шапке — канал событий между сайтом и сервером. Он не подтверждает состояние локального моста или OpenCode. При обрыве этого канала HTTP-проверка компьютеров может продолжать работать.

«Мост на связи» у выбранного компьютера означает недавний авторизованный ответ фонового worker. Он работает независимо от окна OpenCode и терминала. Сервер снимает online через 40 секунд без heartbeat; видимая вкладка перечитывает состояние каждые 15 секунд. Рядом показано время последнего ответа моста.

При ошибке чтения или отсутствии свежей проверки в течение 30 секунд интерфейс показывает «статус не проверен», сохраняет имя и сведения о папке, но блокирует действия, которым нужны актуальные данные. Это не доказательство выключенного компьютера. Возврат фокуса или видимости вкладки сразу запускает проверку. Успех в окне подтверждения называется «Подключение подтверждено»: это результат шага, а не обещание постоянной доступности.

Проверка 19 октября 2026: 25 новых проверок интерфейса и свежести, весь набор из 1048 frontend-тестов, TypeScript и production-сборка прошли. На настоящем PostgreSQL 8 сценариев подтвердили границу 40 секунд, отсутствие heartbeat, просроченный доступ, фильтрацию чужих/отозванных устройств и неизменность времени при чтении. Проверка использовала временную таблицу и завершилась `ROLLBACK`; пользовательский worker не останавливался. В браузере настоящие компоненты с тестовыми ответами проверены при обрыве канала событий, отказе и зависании API, переходах online/offline, восстановлении фокуса и на ширине 390 px.

Отдельная находка для worker: heartbeat отправляется внутри обработки очереди, поэтому длительное задание может задержать его и дать ложный offline. Эта серверная оценка присутствия во время долгой операции не проверена как исправленная; текущая правка устраняет устаревший online в интерфейсе.

## Замена программы

Повтор установки обновляет программу, сохраняя подключение, настройки OpenCode, квитанции и журналы файловых операций.

- Живой worker и активное задание: выдача новых заданий ставится на паузу, установщик ждёт завершения текущего. Через 30 секунд возвращается конкретная причина отказа; файлы программы сохраняются, очередь возобновляется.
- Worker отсутствует или его PID завершился: серверная запись `running`/`reconciling` сама по себе не запрещает замену программы. Установщик удерживает серверную паузу до окончания замены. После запуска worker восстанавливает журналы и повторяет доставку сохранённых результатов.
- Worker отсутствует, ключ просрочен или отозван: HTTP 401/403 не мешает установке файлов. Серверная пауза не считается полученной; установщик переходит к обычному восстановлению подключения с подтверждением владельца.
- Ошибка сети, HTTP 503, повреждённая блокировка или неподтверждённый ответ сервера останавливают обновление. Ошибка показывается в терминале.

Bash после фактически начатой подготовки пытается снять и неподтверждённую паузу: ошибка или потерянный ответ CLI не доказывают, что сервер не успел её поставить. Подтверждённый `paused:false` не требует снятия паузы. Неполный ответ не разрешает замену файлов. При отказе регистрации совместимая предыдущая программа возвращается на место; нативная проверка Windows для этого прохода остаётся открытой.

Незавершённые серверные записи автоматически не объявляются успешными или отменёнными. Без сохранённого локального результата остаётся необходимость сверки. Для живого worker с `reconciling` сохраняется защита до подтверждённого завершения; истечение аренды не доказывает, что запись локальных файлов остановилась.

Повторите исходную команду установки после устранения показанной причины. Удалять квитанции, файловые журналы или блокировку живого worker для обхода проверки нельзя: они нужны для восстановления результата.
