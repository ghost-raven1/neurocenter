# BMAD и OpenSpec: задача, код и проверки

В каталоге откройте вкладку «Агенты», выберите проект и раскройте «BMAD / OpenSpec · задача через локальный мост». Здесь можно описать задачу, выбрать методику и команды проверки, а затем получить результат с изменёнными файлами и артефактами.

## Перед первым запуском

Администратор площадки включает «BMAD и OpenSpec через локальный мост» в настройках функций. Для запуска нужны права администратора проекта и подключение моста с подходящей ролью. Выберите компьютер и свяжите точную папку проекта. Новая возможность моста называется `agent-method-workflow-v1`; если её нет, интерфейс предложит обновить мост.

В папке проекта должны быть настроены OpenCode и его модель. Кнопка «Настроить OpenCode» использует существующий мастер провайдера. Исполнитель использует проверенную версию OpenCode 1.14.48; подходящий управляемый runtime имеет приоритет перед программой из PATH.

Методика готовится на этом же компьютере для этой же папки:

- BMAD 6.12.4: установлен CLI `bmad`, есть `_bmad/_config/manifest.yaml` с этой версией и проектные workflows `bmad-help`, `bmad-spec`, `bmad-build-auto`, `bmad-code-review`.
- OpenSpec 1.15.0: установлен CLI `openspec`, есть `openspec/config.yaml`, команды `context --json` и `list --json` разрешают именно выбранную папку проекта. Нужны проектные workflows `openspec-propose`, `openspec-apply-change`, `openspec-verify-change`, `openspec-archive-change`.

Workflows читаются из `.opencode/skills/<имя>/SKILL.md` или `.agents/skills/<имя>/SKILL.md`. Личные skills другого приложения не подставляются автоматически. OpenSpec verify — дополнительный workflow: одного стандартного набора может быть недостаточно. Подготовьте его через установленный официальный OpenSpec с выбранным набором workflows. Существующие проектные файлы и настройки не заменяются автоматически.

Для совместного режима нужны обе методики и их проектные файлы. BMAD формирует или переиспользует brief, PRD и архитектуру; OpenSpec принимает эти документы как вход изменения и ведёт единственную реализацию с проверками.

Официальные инструкции: [стабильный BMAD](https://github.com/bmad-code-org/BMAD-METHOD/tree/v6.12.4), [настройка проекта OpenSpec](https://openspec.dev/docs/setup), [профили workflows OpenSpec](https://openspec.dev/docs/profiles). Версии методик закреплены; скрытого обновления или установки при отправке задачи нет.

## Как выполняется задача

### Запуск выбранного проектного агента

Для этого режима администратор включает также «Полный цикл выбранного проектного агента». В проекте включите нужного агента, задайте явную модель и режим основного агента или «Все». Примените текущие настройки агентов к выбранной папке OpenCode, затем выберите исполнителя в блоке задачи. Первый доступный агент не выбирается автоматически.

Нужен мост с возможностью `agent-method-selected-agent-v1`. Если настройки ещё не доставлены, профиль изменён либо модель недоступна, задача сохраняется и показывает следующий шаг настройки. Перед запуском проверяются версия профиля, фактический файл агента и соответствие модели. Подагент и отсутствующая модель не заменяются значениями по умолчанию.

В истории сохраняются native имя и версия выбранного исполнителя. Ошибка, потеря связи или выключение функции сохраняют выбор для восстановления. Для возврата к прежнему режиму после выключения новой функции явно очистите выбранного агента; автоматического перехода нет. Старые задания без выбора агента продолжают читаться как прежние запуски.

Skills, плагины и MCP пока устанавливаются для общей папки проекта. Выбор агента не создаёт отдельную изоляцию этих ресурсов и не подтверждает выполнение всех назначений.

### Общий порядок

1. Выберите BMAD для работы от замысла и требований, OpenSpec — для изменения существующей системы.
   В режиме «BMAD → OpenSpec» требования и архитектура BMAD становятся входом одного изменения OpenSpec: спецификация, задачи, реализация и проверка. Второй PRD и повторный отдельный этап реализации BMAD не создаются.
2. Опишите нужный результат. Выберите команды проверки, которые действительно существуют в проекте: `npm run typecheck`, `npm test`, `npm run check` или их сочетание. Для корня репозитория Нейроцентра используется `npm run check`.
3. Проверьте показанные компьютер и папку. Нажмите «Выполнить задачу».
4. Мост проверит методику и исполнителя, загрузит проектные инструкции и выполнит работу. После этого отдельно запустит выбранные команды проверки.
5. В истории будут показаны результат, изменённые относительные пути, артефакты и фактические исходы команд. «Не запускалась» и «Ошибка» не считаются успехом.

Проект должен быть Git-репозиторием. Обход не включает игнорируемые зависимости и не следует за символическими ссылками. В одном результате помещаются до 64 изменённых файлов и 64 артефактов; превышение предела требует просмотра локального результата и не даёт ложного успеха.

Отправка фиксирует текст задачи, методику, команды и выбранную папку. Файлы читаются на момент фактического запуска: изменения документов во время ожидания попадут в контекст исполнителя. Захват отдельной утверждённой ревизии документов до постановки в очередь пока не поддерживается.

## Ошибка, потеря связи и отмена

Введённая задача сохраняется перед отправкой. Если неизвестно, принят ли запрос, сначала нажмите «Проверить отправку». Проверка не запускает модель. После подтверждённого отсутствия запроса доступен точный повтор с тем же ключом и папкой.

Если сервер отклонил отправку из-за смены папки, после проверки отсутствующей квитанции можно явно вернуться к задаче для текущей папки. Текст сохраняется; новая отправка получит новый ключ. Неизвестный исход POST таким способом автоматически не сбрасывается.

Если мост уже начал работу, потеря подтверждения не приводит к новому исполнению. Сохранённый результат доставляется повторно; неизвестный исход требует просмотра файлов и локального журнала на компьютере. Новое задание создавайте после такого просмотра.

«Отменить задание» останавливает процессы этого задания. Отмена не откатывает уже сделанные изменения кода: просмотрите список файлов и состояние папки. Выключение функции запрещает новые задания, сохраняя доступную владельцу историю и отмену.

## Если хранилище Quirk повреждено

Quirk — вспомогательные знания, которые не заменяют принятые требования BMAD/OpenSpec. Перед загрузкой плагина исполнитель проверяет доступный источник целиком. Битый JSONL, неполное чтение или изменение во время проверки не считаются здоровым хранилищем.

При `QUIRK_STORAGE_INVALID` запуск останавливается до загрузки плагина. Не выполняются автоматические очистка, reconcile, переиндексация и удаление прежних данных. Сохраните исходное хранилище и используйте проверенную копию либо явно подготовьте проект без этой зависимости. После устранения причины можно создать новое задание; прежний результат останется в истории. Локальная проверка источника не является доказательством целостности всех индексов LanceDB.

Рабочая папка и запрет внешних каталогов в OpenCode ограничивают область задачи, но не являются изоляцией операционной системы. Используйте доверенную проектную конфигурацию и выбранную модель. Сейчас выполнение поддерживается на macOS и Linux; другие платформы получают явное состояние недоступности.
