## Обязательные зависимости

- Сохранённая сессия после 503 — состояние интерфейса, а не новое разрешение. Сервер заново проверяет актуальные права перед защищённым действием.
- Актуальные 401 и подтверждённый отказ назначений 403 от `/auth/me`, выход и смена владельца очищают прежние данные. Запоздалый ответ старого запроса не возвращает их.
- Недоступный обязательный Catalog PostgreSQL или неподтверждённая схема не объявляются готовностью. Обхода обязательной схемы в обработчиках необязательных ошибок нет.
- Недоступность сервиса фичафлагов не считается выключенным флагом или разрешением по умолчанию. Новые защищённые операции и вызовы модели проходят действующую проверку.
- Начальная durable-квитанция использования модели нужна до платного вызова. Если её записать нельзя, провайдер не вызывается. Отказ после выполнения обрабатывается отдельно.
- Ослабление стартового `depends_on` не отменяет проверку свободного места/резерва непосредственно перед операцией записи. Неизвестное подтверждение операции не означает успешную отмену или безопасный повтор.
- Получение проекта без живого замера не меняет действующие квоты: потребители используют идентичность проекта; RAG проверяет собственный ledger и резерв ёмкости, модельные лимиты и начальная durable-квитанция проверяются отдельно.
- Настройки S3 и проверки закрытости бакета остаются строгими. Файлы не перенаправляются молча в БД или локальную папку; прежние координаты объектов и исходные байты не заменяются.

## Проектный контекст, самообучение и уведомления

Личный диалог с выбранным проектом при включённом `project_search` автоматически подготавливает проектный контекст: `ModelChatService` → `ModelChatProjectContext.prepare` → выбранная embedding-модель → RAG search. Если этот контекст недоступен или изменился, соответствующий turn завершается ошибкой. Подготовленные знания не отбрасываются молча ради ответа без источников.

Диалог без проекта не вызывает этот поиск. При явно выключенном `project_search` используется честно обозначенная метаинформация проекта. Общая комната проекта использует собственный контекст сообщений и одобренные знания агента; это отдельный путь от поиска личного диалога. Ближайшие проверки: `chat-project-context.test.ts`, `chat-learning-context.test.ts`.

Кварки OpenCode-RAG и синхронизация с MCP Memory выполняются отдельными явно запрошенными заданиями устройства. Обычный inference не вызывает удалённый граф Memory или сбор кварков. Их отказ не отменяет сохранённые одобренные знания в Catalog. Проверки прав, версии знаний, папки и задания при синхронизации обязательны.

Уведомление каталога отправляется после commit с ограничением 1,5 секунды; ошибка доставки поглощается. Канал уведомлений не откатывает изменение. Пропущенное уведомление может потребовать обновить данные в интерфейсе.

Проверка границ выше выполнена чтением фактических вызовов. Это не утверждение об испытании каждого сочетания отказов Memory, RAG и внешних моделей.
