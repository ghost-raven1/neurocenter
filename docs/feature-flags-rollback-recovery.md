# Фичафлаги: откат и повтор сохранения

Локальный срез B09 от 23 октября 2026 года закрывает четыре подтверждённых дефекта освобождения SQL-соединения и потерю выбора администратора после неизвестного результата записи. Это расширяет принятую часть цепочки 1 MVP, но не закрывает весь первый запуск, весь B09 или весь сервис флагов.

## Серверный контракт

`FlagsRepository.patch`, defaults в `FlagsRepository.setup`, `migrateFeatureFlags` и `checkFeatureFlagsMigrations` владеют своими транзакциями. Подтверждённый ROLLBACK возвращает соединение в пул; отказ или потеря подтверждения ROLLBACK уничтожает его через `release(true)`. Следующий запрос не получает незавершённую чужую транзакцию. Исходная ошибка сохраняется, автоматического повтора нет. Это соответствует [контракту node-postgres](https://node-postgres.com/apis/pool).

SQL, порядок операций, авторизация, expectedRevision/CAS, no-op, аудит и неизменяемые миграции не менялись. Ошибка ответа сама по себе не доказывает отмену операции: COMMIT мог уже состояться. Ранее зафиксированные изменения автоматически не отменяются.

## Сценарий администратора

Переключатель показывает последнее подтверждённое сервером значение. После неизвестного ACK, 503 или 409 выбранное значение сохраняется в открытой панели текущего администратора. Сначала нужно успешно перечитать состояние; после конфликта перечитывание запускается автоматически, запись — только явно.

- Если значение отличается, «Применить сохранённый выбор» отправляет его с ревизией последнего успешного GET. Следующий конфликт снова требует отдельного решения.
- Если GET уже совпал с выбором, интерфейс сообщает только о совпадении. Второй PATCH и сообщение об успешном сохранении прежнего запроса не появляются.
- «Оставить серверное значение» убирает локальный выбор после успешной проверки; это не отмена уже отправленной операции.
- Ошибка GET сохраняет выбор и оставляет путь повторной загрузки. Смена владельца или панели очищает прежнюю область; поздние ответы её не восстанавливают.

Выбор хранится в памяти текущей панели. Сохранение после reload этим срезом не реализовано и не заявляется.

## Воспроизведение и ограничения

Opt-in инструмент — `scripts/test/flags-rollback-integrity.mjs`. Нужны Node24, явно выбранный собранный кандидат (`FLAGS_ROLLBACK_CANDIDATE`), source receipt (`FLAGS_ROLLBACK_SOURCE_RECEIPT`), фаза `baseline`/`candidate` (`FLAGS_ROLLBACK_PHASE`) и приватная опись собственного PostgreSQL (`FLAGS_ROLLBACK_CONNECTION_FILE`). Инструмент проверяет nonce, lease, PID/data/port и запрещает основной 5432. Он не скачивает PostgreSQL и не запускается обычным unit-check; переносимый bootstrap остаётся B12.

Native проверяет реальную семантику PostgreSQL с синтетической потерей driver ACK/отправки ROLLBACK и pool max1. Реальный сетевой разрыв, полный HTTP/Gateway/RBAC middleware, нагрузка с production-пулом, другие ОС, CI и работающая площадка требуют отдельной приёмки. Browser-стенд не проверяет настоящий hook/socket/auth/full app. MCP через настоящий SDK обнаружил пять инструментов и прочитал свежий отчёт вызовами `verification_summary` и `coverage_gaps`; это не доказательство обнаружения tools в текущем сеансе Codex.

Следующие B09-кандидаты — `ragQuota` и `AgentTrialRepository.transaction`. У квоты следующий просмотр того же проекта может стать COMMIT для прежней неизвестной записи; у trial следующий `expire()` может зафиксировать queued-вставку без запуска. Пока это гипотезы по исходникам: сначала нужен actual-PG RED с нормальным откатом как контролем.
