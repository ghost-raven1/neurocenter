# Расширение: каталог MCP-пакетов и плагинов

Это вариант следующего этапа. В базовом проекте обязательны образы LanceDB и Markdown-скиллы; распространение MCP и плагинов добавляется без отдельного хранилища или набора микросервисов.

## 1. Что именно распространяется

| Тип | Содержимое | Что получает пользователь |
| --- | --- | --- |
| Локальный MCP server package | Проверенный архив приложения, manifest, точная точка входа и зависимости | Версию локального сервера для выбранных OS/architecture/runtime |
| Remote MCP connection profile | URL, transport, схема OAuth и ссылки на локальные credentials | Настройку подключения; сервер при этом работает отдельно |
| OpenCode plugin package | JS/TS-модуль или подготовленный npm-пакет, manifest и зависимости | Версию плагина для проверенной версии OpenCode |

MCP — протокол, поэтому «загрузка MCP» означает загрузку пакета сервера либо профиля подключения. Registry не запускает загруженные серверы на backend. Docker-based MCP потребует отдельного OCI registry/доступа к нему; копия container manifest в MinIO не заменяет OCI-доставку.

OpenCode поддерживает локальные команды MCP и remote endpoints. Для локального сервера устанавливается точная проверенная команда, без `npx ...@latest` в воспроизводимом релизе. OAuth remote MCP и credentials других инструментов остаются отдельными локальными профилями. [MCP в OpenCode](https://opencode.ai/docs/mcp-servers/).

OpenCode загружает локальные плагины из `.opencode/plugins/` и `~/.config/opencode/plugins/` при старте; npm-плагины и их зависимости устанавливает через Bun. Поэтому помещение файла в plugins directory уже подготавливает выполнение кода на следующем старте. По умолчанию управляется только проектный scope. [Плагины OpenCode](https://opencode.ai/docs/plugins/).

## 2. Хранение и модель

Используются существующие API, Worker, PostgreSQL, staging и direct S3 transfer. Разница — дополнительный тип каталога и проверки manifest/совместимости. Полная база LanceDB по-прежнему хранится по своей типизированной модели; не нужно заменять все связи универсальным JSONB-документом.

| Дополнительная сущность | Назначение |
| --- | --- |
| `package_collections` | Общий или проектный каталог, external resource ID, scope |
| `packages` | collection, kind, name, текущая версия и монотонная head revision |
| `package_versions` | Неизменяемая версия, автор, status, manifest hash/key, происхождение |
| `package_variants` | OS, architecture, runtime, blob refs, размер и entrypoint конкретного варианта |
| `profile_package_pins` | Точные package version/variant IDs в проектном release profile |

Final blobs хранятся в приватном `package-blobs/collections/<collectionId>/<sha256>`, manifests — отдельно. Дедупликация ограничена разрешённой коллекцией; проверки наличия хешей не раскрывают другой scope. Blob refs включаются в GC, reservations и независимый backup наравне с образами/скиллами.

Manifest содержит package kind, точную версию, content hashes, размеры до/после распаковки, платформы, диапазон совместимости OpenCode/MCP SDK, runtime и dependency lock. Сохраняются source/producer, лицензия и требуемые точки доступа. Это метаданные пакета; подпись сервиса подтверждает целостность и источник registry, но не доказывает безопасность кода.

Для npm-зависимостей доставка только tarball верхнего пакета не гарантирует работу offline. Выбирается self-contained bundle либо фиксированный dependency graph из разрешённого registry с lock/integrity. Native modules требуют подходящего platform variant. Если build/install scripts необходимы, они исполняются в выделенном build-процессе до распространения; не во время обычного скачивания и не в API/Worker проверки архива.

## 3. Права и операции

Дополнительные действия внешнего сервиса прав:

| Действие | Разрешает |
| --- | --- |
| `package.download` | Получить разрешённую версию/вариант или профиль remote connection |
| `package.publish` | Загрузить кандидата в указанную коллекцию |
| `package.head.update` | Выпустить проверенного кандидата, выбрать current или rollback |
| `package.install` | Управляемую локальную установку/замену пакета или конфигурации |
| `package.delete`, `package.collection.manage` | Удаление незащищённых версий и управление коллекцией |

Каталог и поиск фильтруются по resource scope. Публикация пакета не даёт права менять проектный release profile. Его автору нужны `project.profile.manage` и права доступа к закрепляемым пакетам; каждый получатель проверяется отдельно. Administrator действует через эти же ACL.

Предлагаемые MCP tools: `packages_list/search`, `package_download`, `package_publish`, `package_activate`, `package_install`. Скачать можно без установки. Публикация создаёт кандидата, а продвижение требует отдельного head.update; серверные CAS включают expected version ID и revision. Инструменты установки/запуска включаются только в разрешённом режиме клиента.

Скачанный архив попадает в обычный downloads/cache вне auto-load directories. Сервер проверяет hashes, подпись, manifest, безопасные пути, распакованный размер и совместимость, но не импортирует пользовательский JS/TS и не запускает MCP server. При необходимости функциональные package tests — отдельный изолированный build pipeline.

## 4. Релиз и локальная установка

1. Издатель загружает кандидат в staging; Worker проверяет закреплённые object versions и переносит их в immutable final.
2. Maintainer с head.update выпускает пакет. Проектный профиль закрепляет точные версии образа, скиллов и, при включённом расширении, пакетов.
3. Клиент скачивает только отсутствующие package variants, проверяет подпись и платформу до изменения конфигурации.
4. Управляемый installer проверяет package.install, локальные изменения и ownership конфигурации. Сохраняется прежняя версия и журнал для восстановления.
5. Между сессиями OpenCode активируются подготовленные файлы/настройки; MCP process перезапускается отдельно, plugin начинает работать при следующем старте. Владелец устройства сохраняет контроль над запуском.

Удаление или замена своего активно работающего registry MCP откладывается до перезапуска/внешнего installer; нельзя обещать безопасную горячую самозамену процесса. Config merge затрагивает только управляемые записи и возвращает конфликт при ручных изменениях.

Секреты не входят в package archive, manifest или opencode config template. После установки нужный OAuth/credential profile связывается локально; installer передаёт только явно назначенные credentials. Сам по себе registry не изолирует исполняемый код: обычный plugin или MCP process работает с правами пользователя ОС и может читать доступные ему файлы. Если нужна изоляция от остальных локальных секретов, необходим отдельный OS sandbox с ограничением filesystem, environment и network. Проверяются конфликты имён tools и совместимость с установленными глобальными плагинами; глобальный каталог не переписывается проектным релизом.

Клиент, не поддерживающий требуемые package pins профиля, отклоняет установку до активации образа/скиллов. Опциональный пакет можно пропустить только если профиль явно допускает такой режим. Rollback выбирает прежний профиль/версию с увеличением revision и сохраняет аудит.

## 5. Влияние на ёмкость и волну

Хранение: сумма уникальных package blobs всех retained versions/variants. Раздача: сумма отсутствующих package bytes по клиентам. Наличие общего каталога экономит хранение, но не отменяет копию пакета на каждом компьютере.

Пример для оценки, не реальный размер: 100 пакетов по 100 МБ, пять полностью независимых версий и один platform variant → 50 ГБ logical, около 143 ГБ raw при EC_factor=2 и 70% заполнения. Несколько вариантов платформ и зависимости увеличивают эту сумму.

Трафик пакетов рассчитывается по размеру отсутствующих у каждого клиента версий и включается в общий бюджет раздачи. Для remote connection profile передаются только метаданные; последующая нагрузка на remote MCP server рассчитывается отдельно.

Панель AntD 4 расширяется разделом «MCP и плагины»: коллекции, версии, варианты платформ, происхождение, совместимость, pins проектов, операции и отзыв версии. Existing installed code нельзя отозвать удалением записи на сервере; registry может запретить новые установки и уведомить о требуемом обновлении.
