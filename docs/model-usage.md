# Использование моделей

Раздел `/model-usage` показывает реальные обращения к моделям после включения журнала. Старые запросы задним числом не восстанавливаются. Метаданные хранятся в PostgreSQL, таблица `model_usage_calls` создаётся миграцией 18.

Каждый фактический вызов получает UUID перед обращением к провайдеру. Учитываются чаты, отдельные ответы агентов, сжатие истории, поиск по проекту, индексирование с компьютеров, переиндексация, проектное обучение, прямые API-запросы и проверки модели при подключении. Получение списка моделей и просмотр состояния без inference не создают вызовов. Повтор отправки с прежним ключом идемпотентности чата не создаёт новый вызов модели.

Сохраняются модель, протокол, назначение, пользователь, проект и идентификаторы связанной операции, статус, длительность и полученные счётчики токенов. Тексты запросов, ответов, файлов, ключи, адреса подключения и тела ошибок провайдера в журнал не записываются. Название протокола не означает компанию-провайдера: OpenAI-совместимый API может обслуживаться любым сервером.

Если провайдер не передал счётчик, значение остаётся неизвестным. Сообщённый ноль отличается от отсутствующего значения. Итоги токенов — точная сумма известных счётчиков; рядом показано количество вызовов без счётчика. Цена не рассчитывается. Сводки включают все доступные вызовы за 1, 7 или 30 дней; список моделей показывает 100 наиболее используемых моделей, журнал вызовов имеет страницы до 100 записей.

Главный администратор видит весь журнал. Администратор проекта — вызовы в проектах, которыми он сейчас управляет. Разработчик — свои вызовы в доступных ему проектах и свои вызовы без проекта. Наблюдателю раздел недоступен. Отзыв доступа к проекту сразу исключает его вызовы из выдачи. Удаление проекта или модели не удаляет исторические метаданные; видеть их по-прежнему может главный администратор.

## Сбои и завершение процесса

Если PostgreSQL не подтвердил начальную запись, запрос провайдеру не отправляется. Ошибка возвращается вызывающему: можно повторить позже.

Если модель завершила работу, а запись результата в журнал временно не удалась, её ответ сохраняет обычную семантику вызывающего сервиса. Процесс повторяет только запись метаданных по прежнему UUID, не оплачиваемый запрос модели. Если процесс потерян до восстановления записи, истёкшая аренда помечается «Результат не подтверждён», токены остаются неизвестными. Такой статус не утверждает, что провайдер не потратил ресурсы, и не вызывает автоматический повтор inference.

Живой процесс продлевает аренды каждые 30 секунд; истечение — 2 минуты. Восстановление не трогает действующие аренды других процессов. При штатном завершении свои текущие запросы отменяются, а оставшиеся незавершённые записи отмечаются без подтверждённого результата. Поздно подтверждённый результат того же процесса может уточнить ранее истёкшую запись. Готовность сервиса зависит от схемы PostgreSQL, не от доступности внешних моделей.
