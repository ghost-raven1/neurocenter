# Установка, восстановление и временная недоступность сервисов — 19–20 октября 2026

Продолжение [проверок неопределённого результата привязки](workspace-binding-uncertainty-2026-10-19.md). Проверены соседние действия с установленным инструментом и очередью. Четыре новых дефекта воспроизведены до исправления; для каждого добавлена регрессия.

## Исправления

- **Диагностика после отказа каталога.** Неудачная первая загрузка точного одобрения оставляла окно без плана и с единственной недоступной кнопкой запуска. Добавлена «Повторить загрузку одобрения»: она повторяет только чтение плана. Код не запускается, согласие не появляется автоматически; свежая проверка плана перед запуском сохранена.
- **Повтор истории удалённого проекта.** История предлагала повтор bridge-job, хотя проект уже удалён и реальный retry всегда получал 404. Существование проекта проверяется в прежнем batch-запросе обогащения операций; для удалённого проекта `retrySupported=false`, история сохранена. Задание `choose-root` без проекта остаётся повторяемым. Поле проверки не добавлено в публичный DTO.
- **Временная ошибка проверки входа превращалась в выход.** OAuth service уже отвечал 503 при недоступности каталога, но gateway превращал любой неуспех проверки в 401. Теперь 401/403 по-прежнему означают отказ авторизации; сетевые ошибки, таймауты, некорректный ответ и временная недоступность дают безопасный 503. Прежняя identity не используется, downstream не вызывается. HTTP-controller возвращает Promise в Nest; WebSocket обрабатывает отказ подключения и завершает соединение при неуспешной очередной проверке, без необработанного Promise.
- **Онлайн-канал не восстанавливался после отказа авторизации соединения.** После `server disconnect` или `CONNECT_ERROR` установленная Socket.IO прекращает штатный reconnect, а обёртка возвращалась при наличии прежнего raw socket. Поэтому API-polling и heartbeat моста уже восстанавливались, но сайт оставался без событий. Добавлен один повтор через пять секунд только для неактивного namespace, с сохранением экземпляра и подписок. Штатный повтор транспорта не дублируется; logout отменяет таймер и отзывает прежний экземпляр. Поздние callbacks не переподключают новую сессию.

Исходники автономного моста **0.9.7** не менялись. Изменены frontend диагностики и общий SocketClient, обогащение операций catalog и проверка авторизации gateway. Установка, CAS, права на запись, согласие на выполнение и формат пакетов не расширялись.

Это не дефект release-архива и не засчитывается как успешная диагностика. Launcher переключён на packaged Node; фактический движок **OpenCode 1.14.48**, exit 0, SHA совпал с runtime.json. Новый UI probe после исправления успешен. Проверки файлов и привязок до исправления launcher относятся к release JS на host Node. Уточнения добавлены к двум предыдущим отчётам, без переписывания их исторических чисел.

## PostgreSQL, HTTP и регрессии

Удалённый проект проверен в изолированных настоящих схемах PostgreSQL: до DELETE повтор доступен; после DELETE list и detail сохраняют операцию, но не разрешают retry. Прямой retry отвечает 404 без создания задания: jobs 1 → 1, operations 1 → 1. Сначала тест RED, после исправления GREEN; обе схемы удалены. В рабочем UI главного администратора до исправления наблюдалась ложная кнопка; повтор рабочего задания не запускался. Новый Developer-стенд не используется для этого UI-доказательства: его ACL скрывает историю удалённого проекта, права для теста не расширялись.

Отказ проверки авторизации воспроизведён настоящим HTTP guard+proxy: auth-upstream 503 раньше давал 401, теперь даёт 503; обращений к защищённому ресурсу 0. Session и Bearer проверяются без fallback к прежним правам. Невалидный Bearer и реальные 401/403 остаются отказами входа.
