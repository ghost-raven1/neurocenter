# Изоляция моста в командных диалогах

Подготовленное исправление 32 устраняет распространение ожидания Codex на независимые ответы и комнаты проекта. Готовый ответ серверного агента сохраняется, пока Codex продолжает работать; общий итог появляется после завершения всех адресатов. Ошибка одного провайдера сохраняется у его ответа. Явный повтор вызывает только агентов, чей ответ ещё не получен.

Внутри одной комнаты вопросы сохраняют FIFO: следующий вопрос агентам ждёт завершения предыдущего. Другие комнаты проекта работают независимо. Сообщения только людям сохраняют прежний путь без вызова модели.

## Исполнение и данные

- Один экземпляр Catalog допускает для проекта один активный серверный вызов и один вызов device-codex. Ограничение общее для всех комнат этого проекта; увеличение числа комнат не умножает число вызовов.
- Ожидающая транспортная очередь поддерживает отмену. Отмена вопроса останавливает его ожидания и ответы, сохраняя уже завершённые результаты и не прерывая вопрос другой комнаты.
- Модель классифицируется через inference-порт по актуальному закреплённому описанию. После получения разрешения на исполнение повторяются действующие проверки прав, аудитории комнаты, модели, флагов, поколения и lease. Поздний ответ после отмены или отзыва доступа не публикуется.
- Startup/recovery и прежний `schedule(projectId)` находят все комнаты с принятыми вопросами. При обычных send/retry передаётся точный roomId. Существующие общие лимиты 100 ожидающих/исполняемых вопросов проекта и 20 вопросов автора сохранены.
- Миграция 32 заменяет уникальный индекс одного running-вопроса проекта на один running-вопрос `(project_id,room_id)`. Короткие проектные advisory-транзакции и неизменность атрибуции остаются. Исторические SQL 23, 25 и 31 не изменены; сообщения и квитанции не переписываются.

## Подтверждённые проверки

Все PostgreSQL-проверки выполнялись на отдельном loopback-инстансе, с отдельными UUID-базами. Модельные HTTP/Codex transports заменены управляемыми фикстурами; реальные inference, usage ledger, ACL, runner и SQL использованы.

| Отдельный прогон | Результат |
| --- | --- |
| Причинный RED на прежнем исполнителе | 1 положительный контроль, 8 воспроизведённых блокировок |
| Runtime и миграция 32 | 15 пройдено, без отказов и пропусков |
| Связанные диалоги и learning receipts | 35 пройдено, без отказов и пропусков |
| Unit/public access | 30 пройдено, без отказов и пропусков |
| Frozen migration contracts и rollback 32 | 7 пройдено; 63 других случая исключены фильтром имени |
| Catalog `tsc --noEmit --incremental false` | Успех; 650 Catalog/shared файлов не изменились во время проверки |

Различающие сценарии удерживают Codex на барьере и наблюдают серверный ответ до его освобождения. Проверены FIFO комнаты, продвижение другой комнаты, предел двух вызовов проекта, сохранность завершённого ответа/learning receipt при retry, отмена ожидающего вопроса, отзыв приватной аудитории и project ACL, остановка обоих транспортов, поздний результат и stop во время возврата SQL claim. Миграция проверена с сохранением истории/строк, инъекцией ошибки и повтором; readiness обнаруживает ослабленный или удалённый индекс.

Свидетельства сохранены отдельно в `.run/reliability-regressions-20261024-b0952ea0/project-chat-isolation-*`. Имена новых PostgreSQL-наборов заканчиваются на `-postgres.test.ts`, поэтому unit-safe профиль явно исключает их. Процент покрытия эти отдельные наборы не устанавливают.

## Границы

Предел двух активных вызовов действует внутри одного экземпляра Catalog. SQL обеспечивает эксклюзивность вопроса комнаты между процессами; общий transport-лимит между несколькими репликами требует отдельного протокола leases и в это исправление не входит. Ожидание транспорта входит в действующий срок обработки вопроса.

Эти проверки подтверждают подготовленный код и миграцию в изолированной среде. Применение на работающей площадке, браузер, реальные внешние модели, CI и другие ОС требуют своих свидетельств.
