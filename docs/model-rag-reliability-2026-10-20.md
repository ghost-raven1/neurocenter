# Модели и RAG: пустой индекс, очередь и отмена запросов

Срез после [проверки моделей и независимых grants](model-rag-friction-2026-10-20.md). Исправления находятся в `main`; версия моста — **0.9.10**, build `864c437ffda9f5f4471ea0e87083a1b6eb2fd4f4668d0ceae7d8f36decbafa11`. Каталог **2026-10-20.3 / OpenCodeRAG pack.8** и поставка моделей сохранены.

## Исправленные сценарии

| Сценарий | Поведение |
| --- | --- |
| Пустая серверная копия уже связана с прежней моделью | Первая порция с проверенными ненулевыми векторами атомарно сохраняет новый профиль и строки. Пустое сообщение или запрос seal не меняют уже закреплённый профиль. |
| Два клиента одновременно отправляют разные модели | Общая блокировка записи допускает одного победителя. Второй видит фактические строки и получает 409. |
| Новый профиль пытаются передать вместе с удалением всех прежних строк | Проверка наличия любых строк выполняется до удаления; непустой индекс сохраняется. Legacy-строка без вектора тоже считается данными. |
| Сервер принял задание, обновление очереди задержалось | Локальное подтверждение удерживает обе кнопки синхронизации. Потерянный ответ повторяет исходный ключ запроса. |
| Завершённое задание выпало из последних 100 записей | «Обновить состояние задания» повторяет исходный запрос с тем же ключом и принимает только прежний ID и контекст. Новое задание не создаётся. |
| Чтение очереди отказало или сменились пользователь, проект, папка, компьютер | Ошибка видна; прежние ответы не меняют новый экран. Уже подтверждённый terminal не превращается обратно в queued. |
| Клиент закрыл соединение во время embedding | Gateway отменяет соответствующий upstream-запрос, очищает слушателей и не запускает поздний inference после проверки доступа. Соседний запрос продолжает работу. |

Сервер перепривязывает уже закреплённый профиль только внутри той же транзакции, что и первые строки, под `RAG_WRITE_LOCK`. Проверка использует фактическое наличие строк проекта. Нулевые/неполные векторы, legacy-запрос без профиля, пустая порция и `complete: true` не разрешают перепривязку. Проверенный deferred-отказ COMMIT откатывает профиль, строки и квоту вместе. Финальная готовность по-прежнему требует отдельного seal всего снимка.

Мост разрешает этот переход только для согласованного V1 manifest: нулевые строки/usable/incomplete, пустые ids/fingerprints, `complete: false`, `snapshotHash: null`, `indexState: syncing`. Отсутствие новых счётчиков при смене профиля закрывает доступ; старый same-profile manifest остаётся совместимым. Сервер повторно проверяет состояние под блокировкой. Для нового поведения нужны **обновлённые сервер и мост 0.9.10**.

В SQL/transport стендах подставлено резервирование физического места; логическая квота и транзакции PostgreSQL настоящие. Эти проверки не принимают физическое переполнение диска. Тесты реальной БД проверяют переход пустого профиля, гонку клиентов, отказ изменения непустого индекса, rollback при deferred COMMIT failure, квоту, изоляцию проектов и прямого legacy SQL-писателя. Наблюдатель блокировок работает отдельным autocommit-соединением: первоначальный RED помощника, читавшего cached `pg_stat_activity` внутри удерживаемой транзакции, сохранён отдельно от последующего PASS.

## Локальное применение и очистка

RAG перезапущен **88695→96026**, затем gateway **72514→96514**. Оба `/ready` успешны; исходные **83/85** env entries сохранены точно. Catalog **86546** и остальные рабочие listeners сохранены. Перед каждой остановкой взяты два свежих READ ONLY SQL-снимка. HTTP metrics возвращали 403 и оставались явно неизвестными. Перезапуск выполнен graceful SIGTERM без SIGKILL; admission gate между снимком и остановкой не добавлен. После подтверждения удалены три приватных process captures; закрытые рабочие логи сохранены.

Собственные БД, контейнеры, тома, профили, браузерный стенд и его два PID удалены. Упакованный MCP initialize дополнительно создал detached worker собственного стенда: он остановлен по точному UID/argv/PID, отсутствие оставшихся процессов и private-каталога подтверждено повторно. Исходная pre-cleanup квитанция сохранена. **70** остальных container IDs и **79** имён томов совпали; их динамические состояния и большие веса моделей этим срезом заново не аттестованы. Вызовов embedding-провайдера не было; пользовательский глобальный мост и его папки не менялись.

Перед упаковкой удалены только пять старых локальных runtime-cache архивов, каждый после сверки размера/SHA с sidecar и опубликованным GitHub asset. Освобождено **775 597 422 байта**; текущая 0.9.9 и исторические sidecars сохранены. Временная упаковка контролировала floor **6 ГиБ**. Новые автономные архивы подготовлены на Darwin ARM64 и в Linux x64 Docker; это не приёмка остальных ОС.

## Публичная поставка

[Релиз bridge-v0.9.10](https://github.com/ghost-raven1/neurocenter/releases/tag/bridge-v0.9.10) опубликован как обычный выпуск; неизменяемый тег указывает на `c4e20a3bf82e779dfba28b1fa33288bcfbd2b2f1`. Все **7/7** файлов скачаны свежими анонимными GET: **326 508 368 байт**, размеры и SHA совпали. Каждый прошёл с первой попытки, без авторизации, cookies, дисковых копий архивов и переиспользования прежних доказательств. Метаданные, описание и ref сверены до/после. Квитанции — `delivery-publish.json` и `delivery-verify.json`. Оба локальных установщика возвращают 0.9.10; runtime HEAD/metadata/sidecar и полные cache SHA подтверждены отдельно. Установщики на пользовательском компьютере не запускались.

Первоначальный помощник ошибочно считал 404 маршрута GitHub releases/tags отсутствием черновика и создал два лишних пустых черновика. Исходные неуспешные квитанции сохранены; оба собственных пустых дубля удалены после проверки. Работа продолжена только по точному ID единственного выпуска `417774459`; независимая свежая сверка приняла все семь файлов до публикации. Опубликованные прежние версии и теги сохранены.

## Что остаётся открытым

- В опубликованном pack.8 повторяемый тест настоящей фабрики embedding с подставленным провайдером дал **32 вызова на восемь текстов** при отказе. Это чистый тест алгоритма, без обращений к модели и без замера длительности реального inference. Рекурсивные повторы и общие бюджеты времени ещё требуют исправления; отмена gateway их не устраняет. Gateway/relay по-прежнему ограничивают один запрос 120 секундами, runtime inference — 600.
- Переход модели у **непустого** индекса требует отдельной согласованной миграции или нового проекта. Размерность должна совпадать с `RAG_DIM`; автоматической конвертации векторов нет.
- Пользовательская установка 0.9.4 не обновлялась. Новый архив и установщик сами не связывают пользовательскую папку и не меняют разрешения модели.
- Настоящий IdP, остальные платформы, независимое cross-host восстановление и production остаются внешними критериями [P0](implementation-readiness.md). Этот срез подтверждает указанные локальные проверки и доставку.
