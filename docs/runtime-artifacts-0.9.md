# Готовые платформенные комплекты MCP 0.9

Пакет формата 5 закрепляет заранее собранные зависимости через `config.extra.runtimeArtifacts`. SHA пакета, затем SHA полного installation set включают все descriptors. Форматы пакета 2–4 читаются по прежним правилам. Наличие схемы `localConfiguration` также выбирает формат 5.

```json
{
  "target": "darwin-arm64",
  "sha256": "<64 строчные hex-цифры SHA-256 архива>",
  "compressedBytes": 12345,
  "unpackedBytes": 67890,
  "filesCount": 12,
  "entrypoint": "runtime/server.mjs",
  "executable": false
}
```

`runtimeArtifacts` содержит от 1 до 8 элементов с уникальными `target`: `darwin-arm64`, `darwin-x64`, `linux-arm64-glibc`, `linux-x64-glibc`, `linux-arm64-musl`, `linux-x64-musl`, `win32-arm64`, `win32-x64`. Неподходящая ОС, архитектура или libc блокируют установку. Готовые архивы поддерживают локальный MCP и плагины; скилл получает их через закреплённые зависимости. `executable: true` запускает готовый бинарный файл, `false` использует встроенный Node MCP. Аргументы берутся из одобренной конфигурации инструмента. Плагину нужна импортируемая точка входа с расширением `.js`, `.mjs` или `.cjs`; нативный entrypoint и `executable: true` блокируются до одобрения и повторно в MCP.

## Подготовка оператором

1. Соберите зависимости на изолированном сборочном стенде для конкретной платформы. Подготовьте обычный **USTAR `.tar.gz`** с относительными именами без ведущего `./` и без ссылок, PAX/GNU extensions, устройств и install hooks. Например, из каталога готового комплекта: `tar --format=ustar -czf /отдельная-папка/готовый.tar.gz runtime`.
2. Сформируйте descriptor по фактическим сжатым байтам, сумме размеров обычных файлов и их числу. Права исполняемого entrypoint должны быть установлены до упаковки. Симлинки зависимостей нужно материализовать на сборочном стенде. Архив не более 256 МиБ, обычные распакованные файлы суммарно не более 1 ГиБ, максимум 20 000 файлов.
3. Каталог выбранного стека должен быть запущен с миграцией 3. На хосте production выполните импорт, указав уже созданный конфиг и нужный стек:

```sh
node scripts/production/import-runtime-artifact.mjs \
  --directory /закрытый-каталог/production \
  --project-name neurocenter-production \
  --archive /готовые-комплекты/готовый.tar.gz \
  --descriptor /готовые-комплекты/descriptor.json
```

Импорт проверяет архив на хосте и внутри отдельного контейнера каталога, берёт общий maintenance lock и регистрирует SHA после сохранения точных байтов. Код содержимого не выполняется. Descriptor затем включается в версию инструмента и проходит обычное одобрение полного графа. Перепубликация конфигурации, графа или артефакта требует нового одобрения.

## Доставка, хранение и восстановление

Сервер хранит неизменяемый объект `<sha256>.tar.gz` в отдельном томе `runtime-artifacts`; в PostgreSQL находится только SHA и числовая опись. Авторизованный маршрут конкретного задания проверяет устройство, действующий lease, доступ и одобрение точного пакета. Произвольные URL загрузки, npm/pip/Bun, сторонние реестры и установочные скрипты в клиентском маршруте отсутствуют.

MCP загружает поток в собственный закрытый staging, проверяет SHA и USTAR до публикации, затем сверяет каждый распакованный файл. Одобренный архив сохраняется в закрытом кэше вместе с описью: перед установкой, проверкой файлов и запуском повторно проверяются SHA архива и реальные байты дерева. Подмена файлов вместе с локальной описью не становится одобренным состоянием. Запись проектной конфигурации остаётся частью существующей файловой транзакции; неудачная загрузка не меняет прежнюю установку.

Кэш имеет отдельный бюджет **2 ГиБ** с учётом сохранённых архивов, распакованных файлов и временных данных; перед загрузкой проверяются бюджет и свободный диск с резервом 128 МиБ. Старые комплекты автоматически не удаляются. Для чтения без записи и запуска требуется уже полностью подготовленный кэш. Потеря кэша приводит к неподтверждённой проверке, повторная обычная установка может загрузить отсутствующий комплект заново; повреждённый существующий объект не перезаписывается автоматически.

Полная серверная копия теперь записывает `neurocenter-recovery-v2` и включает четвёртый том с готовыми архивами. Незавершённый импорт блокирует копирование до переноса файлов. Исторический комплект `neurocenter-recovery-v1` читается и восстанавливается с пустым новым томом; требование совпадения исходных образов сохраняется. Миграция PostgreSQL **3** создаёт реестр артефактов; SQL миграций 1 и 2 не менялся.

Матрица descriptor обозначает допустимые цели поставки. Готовность платформы подтверждается отдельной настоящей нативной приёмкой; существование descriptor или успешный unit-тест такой приёмкой не являются.
