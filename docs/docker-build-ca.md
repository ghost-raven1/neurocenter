# Docker за корпоративным HTTPS-прокси

`dev.sh install`, `build`, `up` и восстановление зависимостей после неудачной сборки выполняют `npm ci` с отдельными пустыми user/global конфигурациями, временным HOME и явным публичным registry. Глобальные `.npmrc`, scoped registry, `NPM_CONFIG_*`, `npm_config_*` и токены компьютера в установку не наследуются. Исходные файлы настроек сохраняются. Docker дополнительно исключает `.npmrc` на всех уровнях build context. Настроенные переменные HTTPS-прокси и доверенного публичного CA сохраняются.

Ошибка npm `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` означает, что Node внутри сборочного контейнера не доверяет цепочке сертификата. Если рабочая сеть подменяет HTTPS своим сертификатом, получите **публичный корневой/промежуточный CA в PEM** у администратора сети. Приватный ключ не нужен. Сертификат сервера npm вместо CA не подходит.

Для локального запуска добавьте в `.env` путь к обычному файлу:

```dotenv
NEUROCENTER_BUILD_CA_FILE=/absolute/path/corporate-ca.pem
```

`scripts/dev.sh up` передаст этот CA сборке исполнителя снимков. Для остальных образов и production используйте:

```sh
export NEUROCENTER_BUILD_CA_FILE=/absolute/path/corporate-ca.pem
node scripts/docker-build.mjs compose build
node scripts/production/setup.mjs build --directory /srv/neurocenter/config
```

Путь может содержать пробелы; в shell заключите значение в кавычки. Если отдельная переменная не задана, используется явно установленный `NODE_EXTRA_CA_CERTS`. Поддерживаются PEM-пакеты до 1 МиБ/256 CA. Ссылки, файлы с приватными ключами, посторонним текстом и сертификатами без признака CA отклоняются до Docker.

Если корпоративный CA уже включён в обычный системный PEM-пакет Linux, можно указать существующий `/etc/ssl/certs/ca-certificates.crt`: все сертификаты в нём должны быть CA. Менять глобальные настройки Node/npm на компьютере не требуется.

Каждая сборка получает собственный публичный `ca-<UUID>.pem` в `docker/build-ca/` и `frontend/docker/build-ca/`. В образ копируется только выбранный файл под именем `extra.pem`; SHA-256 проверяется до включения доверия. Старый `extra.pem` исключён из Docker-контекста. Его наличие, тип и содержимое не блокируют повтор. После завершения удаляются только собственные неизменённые файлы текущего вызова. Параллельные и вложенные сборки, включая разные CA, используют независимые имена.

Без выбранного дополнительного CA Docker копирует пустой `.gitkeep`, а `extra.pem` внутри образа остаётся пустым. Ручная очистка старого `extra.pem` или `.run/docker-build-ca.lock` не требуется. Остатки уникальных публичных файлов после аварийного завершения не выбираются следующей сборкой.

Выбранный исходный CA по-прежнему проходит проверку обычного файла, содержимого и признака CA. `.npmrc`, `.env`, токены и приватные ключи не копируются. npm использует `https://registry.npmjs.org/`. По явной настройке проекта все Docker-этапы npm используют `strict-ssl=false`, а команды установки, сборки и prune получают `NODE_TLS_REJECT_UNAUTHORIZED=0`. У обычных сервисов эта переменная не становится постоянной runtime-настройкой; прежняя отдельная настройка Gateway сохраняется.

Образ каталога также загружает PostgreSQL client через HTTPS curl/apt. Эти команды отключают проверку сертификата только на время загрузки: curl использует `--insecure`, каждый `apt-get` — `Acquire::https::Verify-Peer=false` и `Verify-Host=false`. Проверка подписей apt и `signed-by` сохраняются. Проверенный PEM-пакет по-прежнему разделяется на отдельные CA-сертификаты и добавляется к системным корням до загрузок; глобальный `apt.conf` не меняется.

Сборка работает с обычным Docker builder и BuildKit. При прямом `docker build` или `docker compose build` без обёртки используется пустой CA по умолчанию. Для передачи корпоративного CA используйте команды обёртки выше: они передают согласованные имя файла и SHA. Общая блокировка сборок и перезапись старого `extra.pem` больше не используются.

Если сборка исполнителя снимков останавливается примерно через 10 минут, проверьте итоговую причину: `ETIMEDOUT` означает лимит ожидания Docker в dev CLI. По умолчанию он равен 600 секундам. Для медленной первой загрузки можно явно выбрать от 1 до 3600 секунд в `.env` или на один запуск:

```sh
SNAPSHOT_VERIFIER_BUILD_TIMEOUT_SECONDS=1800 ./scripts/dev.sh up --profile=fast
```

Параметр относится только к подготовке образа, в окружение сервисов не передаётся. При выбранном `SNAPSHOT_VERIFIER_IMAGE` сборка пропускается. Ошибка указывает таймаут, код выхода, сигнал или код отказа запуска Docker; прежние сервисы до успешной подготовки не останавливаются. Предупреждение `NODE_TLS_REJECT_UNAUTHORIZED=0` само по себе не означает отказ npm.

Этот механизм исправляет доверие **внутри Node-образов**. Ошибка скачивания базового образа самим Docker требует настройки доверенного CA у Docker daemon администратором сервера. Недоступность GitHub и истечение сетевого таймаута — отдельные причины, добавление CA их не устраняет.

При полностью закрытом GitHub первый build также не сможет получить закреплённую npm-зависимость `@neurocenter/asset-contract` с `codeload.github.com`. В таком окружении заранее собирайте образы для архитектуры рабочего сервера на машине с доступом к источникам и переносите их через `docker image save` / `docker image load`. Для native dev заранее загруженный исполнитель снимков можно выбрать через `SNAPSHOT_VERIFIER_IMAGE`; тогда `dev.sh up` проверяет существующий образ и не пересобирает его. Каталог ассетов после подготовки работает независимо от GitHub в [автономном режиме](assets.md#работа-без-доступа-к-github).

Проверки: `node --test --test-concurrency=1 scripts/test/docker-build-ca.test.mjs scripts/test/docker-build-ca-lifecycle.test.mjs`. Новый набор: 32 PASS и один явный Docker-skip. Отдельно `DOCKER_BUILD_CA_TEST=1` дал 16/16 в основном файле: настоящие legacy/BuildKit сборки на уже доступном закреплённом Node-образе, без npm-загрузок. Проверены выбранный CA, неверный SHA, отсутствие CA и исключение старого пустого/приватного `extra.pem` из контекста. Эти16 пересекаются с основным набором и к32 не прибавляются. Полная сборка приложения и корпоративный Linux этим не приняты. Квитанции: `.run/docker-ca-isolation-20261022/{final,real-docker}/receipt.json`, `compose-receipt.json`.

Основание: [CA в Docker](https://docs.docker.com/engine/network/ca-certs/), [NODE_EXTRA_CA_CERTS в Node.js](https://nodejs.org/docs/latest-v24.x/api/cli.html#node_extra_ca_certsfile).
