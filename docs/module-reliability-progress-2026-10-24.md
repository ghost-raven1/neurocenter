## Область и ограничения

- A2 касается временно недоступного корректно настроенного S3. Неполный или синтаксически неверный `CHAT_S3_*` остаётся ошибкой настройки при создании сервиса; это отдельный случай. Проверка Nest использует настоящий lifecycle с контролируемым storage boundary, а не запуск всего `AppModule`. Настоящие PG/MinIO проверяют отдельные файловые цепочки. Пользовательский Ceph не отключался.
- В A3 допуск проверяется через Catalog после получения write locks в RAG; это явная граница admission двух сервисов. Миграция 30 должна применяться вместе с обновлением Catalog/RAG. Смешанные версии протокола отказывают в новой записи. Ошибка подтверждения ROLLBACK отдельно просмотрена по исходникам; этот частичный отказ в новом native прогоне не вводился.
- A4 не подтверждает живой импорт пользовательских quirks, публикацию новых пакетов или Memory sync/cleanup на рабочем проекте. Оба новых флага остаются OFF до отдельной приёмки.
- CI, другие платформы, внешний DR и production этим локальным срезом не проверены. Численные проектные квоты пока описаны в [проекте квот](project-quotas-design-2026-10-24.md).
- Объединённый набор проверен на schema30: Catalog 191/191, Gateway 29/29, frontend 94/94 и bridge safety 19/19; всего 333 выбранные проверки, пять свежих TypeScript и frontend build прошли. Хеши всех 66 относящихся к изменению файлов совпали до/после. Первый набор имел один 5-секундный timeout на диалоге 5 МиБ; финальный запуск получил явный fixture budget 15 секунд. Проверки содержимого и истории не ослаблялись. Первый отчёт сохранён рядом с итоговым.
- На копии рабочего Catalog успешно выполнены restore и upgrade29→30: числа проектов, моделей, устройств и заданий сохранены, schema readiness прошла, тестовая база удалена. В копии не было старых RAG intents; их преобразование отдельно доказывает native A3 fixture. Это rehearsal обновления, не внешняя DR-приёмка.
- Полный frontend Docker image в этом срезе не принят: пробная сборка без сети была отменена на свежем npm cache. Host TypeScript/Vite и обе настоящие Nginx-конфигурации проверены; это разные свидетельства.

1. A7: автоматическое восстановление PG и честное отражение readiness в dev status/watch. Restart policy добавлена в `1d33198`; применение и runtime receipt фиксируются ниже. Правки dev-инструментов из другого чата сохраняются отдельно; перевод их проверок с liveness на readiness ещё не завершён.
2. Реальный Codex: доверенная сборка `2823804c-5bd2-47c1-9599-4205298ea1a4` успешно опубликована; настоящий UI-import GPT-6.1-Sol через «Из OpenCode» завершился. Первый личный запрос `53cf0817` завершился `unavailable`: CLAIM принят, dispatch grant отсутствует, `dispatch_count=0`. В кэше 1 891 560 621 байт; комплект требует 470 393 782 байта при лимите 2 147 483 648 — неизбежный capacity blocker. Историческое внутреннее исключение не сохранено, поэтому более ранний preflight-отказ отдельно не исключён. Управляемый бюджет и понятные ошибки проверены выше; остаются их рабочее применение, полезный ответ в чатах/агентной роли и native OpenCode. Автоматического повторного запроса нет.
3. Живая цепочка quirks → reported experience → approval → overlay/Memory → revoke cleanup. Сохранность ручных Memory observations обязательна.
4. Общий долговечный учёт capacity пока не реализован. Текущий guard хранит резервы внутри процесса. Существующий `finally` сборщика освобождает его reservation и при неподтверждённом reap, сохраняя staging; фазовый фикс эту границу не меняет. При snapshot-required режиме release переносит объём в `spent` до нового epoch; без reap proof раннего handoff нет, включая обычный Windows success. Эти случаи не объявляются решёнными общим проектным ledger из проекта квот.
