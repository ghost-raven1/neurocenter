# Кварки RAG и принятые знания в MCP Memory

Новые функции выключены по умолчанию: `project_learning_quirks` и `project_learning_memory`. Флаги управляются через существующий UI. Срез подготовлен отдельно от обновления Codex и требует объединения с текущим main перед приёмкой на работающей площадке.

## Направления данных

Полный `quirks.jsonl` выбранной проверенной установки OpenCodeRAG поступает в неизменяемый сообщённый опыт проекта. Исходный ID, content, tags, confidence, lastObserved и sourceRef сохраняются как происхождение. Повтор того же record hash не создаёт дубликат; изменение содержимого создаёт новый опыт. Автоматического одобрения нет.

В MCP Memory по явному действию администратора поступает только одобренный человеком контекст LearningRepository. Выбираются проект, компьютер и точная установленная версия. Площадка, проект и стабильный ключ входят в namespace. Мост читает выбранные имена через `open_nodes`; общий личный граф не импортируется. Публичные квитанции заданий содержат счётчики и хеши без исходного текста.

## Повтор, отзыв и остановка

Перед мутацией сохраняется приватное намерение; после ответа проверяется фактический результат. Потерянный ACK сверяется чтением уже выполненной операции. После рестарта автоматически доставляется сохранённая квитанция; новые мутации требуют явного продолжения и действующих прав.

Очистка удаляет ранее записанные собственные наблюдения, которых больше нет в текущем одобренном контексте, включая заменённую canonical version при сохранённом ключе. Она не добавляет новую версию. Ручные наблюдения и связи сохраняются; пустые оболочки сущностей намеренно не удаляются. Отмена и поздняя квитанция не возвращают отменённое задание в успех. История, ACK, отмена и очистка доступны после OFF; роли проверяются независимо.

## Объём и доверенная установка

До первой записи проверяются весь план и выбранные ответы Memory. Технические границы: 32 активных записи, 1024 собственные сущности, 20 KiB на собственное наблюдение, 1 MiB на план, 4 MiB на приватный журнал, 2 MiB на выбранные ответы, 256 шагов и один последовательный executor. Это ограничения протокола; настройка общих квот через UI в этот срез не входит. При превышении UI сохраняет выбор и предлагает уменьшить объём и повторить.

Memory требует явный ABI descriptor новой ревизии `1.0.0-pack.2`; RAG MCP/plugin — marker источника в `pack.12`. Неизвестная или старая версия получает blocker. Версия, manifest, одобрение, binding, instance, конфигурация и ревизия контекста проверяются до работы и перед изменениями. Точный npm-source Memory1.0.0 проверен по lock SHA512 без установки и исполнения; существующие cross-process file lock и atomic rename переиспользуются.

## Свидетельства

[Манифест](learning-quirks-memory-2026-10-24.manifest.json) содержит SHA256 исходников, точные focused-файлы и результаты: bridge43, catalog61, frontend24, Node recipes/build fixtures10 — всего138 без ошибок и пропусков. Typecheck bridge/catalog/frontend/gateway и отдельная сборка Catalog прошли на Node24.22.0. Runtime fixtures изолированы от пользовательских профилей. Dependency install, запуск сервисов, публикация пакетов и изменение личного графа этим прогоном не выполнялись.

Зелёные fixtures не заменяют нативную PostgreSQL-приёмку нового среза, live Memory/RAG lifecycle, SIGKILL, Windows/Linux, публикацию точных артефактов и проверку после объединения с main. Общий coverage не собирался; частный прогон не подтверждает 100% покрытия приложения. Сырые RED/GREEN отчёты находятся в `.run/learning-memory`; при архивировании worktree их нужно сохранить отдельно.
