# Аудит Ceph / S3 — 22 октября 2026

Интеграция с Ceph RGW есть через S3 API. На текущей локальной установке отдельный Ceph-кластер не развёрнут: оригиналы файлов чата обслуживает MinIO на `127.0.0.1:19010`, проектные снимки используют файловый каталог, внешний S3 для резервных копий не настроен. `compose.chat-storage.yml` подключает Catalog к существующему хранилищу; Ceph этим overlay не устанавливается. Скиллы хранятся через POSIX API; CephFS требует отдельного монтирования оператором и сейчас не подключён.

Рабочий Ceph endpoint для приёмки не предоставлен. Новый кластер в этом проходе не запускался: свободное место колебалось ниже принятого резерва 8 ГиБ, а хост уже активно использовал swap. Проверены метаданные ARM64-образа без скачивания. Подмена настоящей Ceph-приёмки локальным MinIO не допускается.

## Подтверждённые дефекты и исправления

| Участок | Воспроизведённый отказ | Изменение |
| --- | --- | --- |
| Перенос старых вложений | Пул PostgreSQL с одним соединением зависал: миграция удерживала сессию и запрашивала вторую для durable intent | Intent и отмена используют уже занятую сессию. Intent фиксируется до `BEGIN` и до PUT; исходные байты удаляются только после подтверждённой ссылки |
| Приватность снимков | Публичный S3-бакет принимал PUT и получал LIVE-запись; независимый анонимный GET возвращал оригинал | Общая подписанная проверка policy и ACL выполняется перед записью, чтением и восстановлением незавершённой записи |
| Точная версия снимка | Отсутствующий `version_id` приводил к чтению текущей версии объекта | Чтение требует точную непустую S3-версию и проверяет размер и SHA-256 |
| Восстановление снимков | Изменение target policy в последнем callback перед SQL не останавливало изменение ссылок | Повторная проверка приватности target выполняется непосредственно перед SQL CAS |
| Внешние резервные копии | Публикация и скачивание не требовали доказанной приватности назначения | Проверка до каждого PUT, manifest и финального подтверждения; перед чтением и публикацией скачанного каталога. `policy=` и `acl=` включены в SigV4 |
| Локальные ключи S3 | Неуспешный `docker volume inspect` ошибочно означал отсутствие volume и позволял создать новые ключи | Отсутствие подтверждает только успешный точный inventory Docker. При неизвестном состоянии ключи не перезаписываются |
| Пул PostgreSQL | Потерянное подтверждение acquisition или unlock возвращало удерживающую блокировку сессию; неподтверждённый ROLLBACK оставлял транзакцию открытой | Сессию с неизвестным состоянием уничтожают через `release(true)`, сохраняя исходную ошибку либо уже зафиксированный результат. Незавершённый durable intent остаётся для повтора; подтверждённая занятость lock не уничтожает здоровую сессию |

SQL-дефекты проверяются настоящим PostgreSQL и отдельным наблюдателем. Вставки, транзакции и advisory locks выполняются сервером; подмена касается только точного потерянного подтверждения. Проверка сессии через тот же пул недостаточна: в одном воспроизведении повтор PUT ошибочно сообщал об успехе, хотя независимая сессия не видела ни одной зафиксированной строки.

Общий helper отклоняет неподтверждённую или публичную policy/ACL, malformed XML/JSON, неправильный HTTP status, дубликаты XML-элементов ACL/error, неподдержанные principal и превышение размера. Чтение ответа ограничено 64 КиБ и сроком ожидания. Отсутствующей policy считается только корректный S3 XML error с ожидаемым кодом при HTTP 404. Обычные Deny-правила, включая запрет незашифрованного транспорта, не считаются разрешением публичного доступа.

## Проверки и границы

Полные целевые прогоны чата, снимков и внешнего backup сохраняют исходный лог, счётчики, SHA исходников до и после и результат очистки. Для dev storage сохранены RED/GREEN-логи и SHA после запуска; отдельная квитанция неизменности до/после для него не заявляется. Ранние RED и промежуточные GREEN сохранены отдельно. Изменение production-исходников требует нового прогона; карты старой версии не выдаются за покрытие исправленной.

| Набор | Подтверждение |
| --- | --- |
| Файлы чата | 73/73, пять файлов, без skips: durable transfer, отмена, дедлайны, GC/shutdown, реальные блокировки и lost-ACK/rollback. 29 кейсов используют настоящие PG/S3, 44 — управляемые SDK/HTTP/SQL/clock границы |
| Снимки и восстановление | 143/143, восемь файлов, без skips: filesystem, настоящий PG, подписанный S3, приватность, exact versions, restore, потерянные подтверждения и валидатор QA-конфигурации |
| Внешняя резервная копия | 80/80, без skips и cancellation: CLI, DNS/TLS/HTTP-отказы, ограничения тела, deadlines, повторы, приватность, manifest, exact replay; два сценария используют настоящий подписанный MinIO |
| Локальное S3 и запуск | 28/28: сохранность ключей при неизвестном Docker inventory, восстановление и отказы конфигурации |
| Operator recovery | Отдельные 22/22 Node-теста; actual SDK + PostgreSQL restore также входит в набор снимков |

После полного прогона изменены только проверки переносимости QA fixture: убраны фиксированные порты стенда, сохранены loopback, явный порт и запреты основных хранилищ. Для чата повторены 12/12 новых тестов; для снимков — 32/32: семь тестов соединений и 25 проверок конфигурации. Production SHA не меняются; прежние полные квитанции сохранены с исходными SHA тестов. Эти повторы не прибавляются к полным счётчикам.

Vitest AST для двух chat storage файлов: **100% lines, 100% functions, 93.71% branches, 97.66% statements**. Для `snapshot-storage.ts`: 99.18% lines, 82.60% functions, 79.24% branches, 89.01% statements; для `backup-storage.ts`: 92.30% lines, 90.90% functions, 84.78% branches, 80.51% statements. Это узкие знаменатели; общий Catalog и все модули ими не измерены. Production TypeScript, строгая проверка новых тестов и изолированная сборка Catalog проходят.

Native c8 для `external-backup.mjs`: **100% lines, 100% functions, 93.17% branches, 100% statements**. Это один CLI, а не все модули. Общий S3-helper в том же частичном native-запуске имеет 100% lines/functions/statements и 70.21% branches; его дополнительные 48 HTTP-кейсов входят в другой набор. Попытка собрать их через внешний c8 не получила карту worker: знаменатель пустой, измерение невалидно, процент не присваивается. Native и Vitest AST не объединяются в общий процент.

Файлы чата проверяются на собственном PostgreSQL `59616` и MinIO `59617`. Fixtures создают случайные базы и бакеты, затем штатно удаляют их; основной PostgreSQL `5432` и MinIO `19010` для тестовых мутаций запрещены. Payload ограничен, новые контейнеры не создаются. В двух native S3-кейсах тестовый adapter переводит HTTPS в HTTP только к своему loopback endpoint: это не проверка production TLS.

Старый snapshot S3 fixture больше не использует PostgreSQL по умолчанию и не запускает Docker неявно. Требуются явно заданный QA admin URL и закрытая конфигурация собственного S3. Отдельный запуск временного MinIO требует `SNAPSHOT_S3_TEST_SPAWN_DOCKER=1` и достаточного диска. Без этих условий тесты видимо пропускаются. Валидатор fixture проверен 25 сценариями, включая запрет основного порта и переносимость собственного порта.

## Что остаётся открытым

1. **Настоящий Ceph RGW.** Нужны согласованный тестовый endpoint, закрытые бакеты и учётная запись с проверкой policy/ACL/versions. Затем — PUT, exact-version GET, отказ доступа, перезапуск, очередь удаления и restore на этом кластере. Поддерживаемые S3-операции сверяются с [документацией Ceph](https://docs.ceph.com/en/latest/radosgw/s3/bucketops/).
2. **Согласованное восстановление оригиналов чата.** `recovery-v3` экспортирует снимки и ключи подписей, но не оригиналы из двух chat-бакетов. Для вложений, уже размещённых в S3, PostgreSQL dump содержит ссылки, а не оригиналы. Неперенесённые legacy-байты остаются в `model_chat_attachment_transfers` до успешной фиксации S3-ссылки. Нужен отдельный проверенный backup/replication обоих бакетов с версиями либо расширение формата recovery bundle. Восстановление одной БД не закрывает этот критерий.
3. **Покрытие всех модулей около 100%.** Узкие зелёные наборы и высокий процент одного CLI не заменяют полный знаменатель репозитория. Предыдущие неполные/красные общие прогоны сохраняют свой статус; нужен полный повтор на стабильном стенде.
4. **Внешний DR и production.** Не выполнены cross-host recovery с Ceph, целевой TLS/IdP, длительная нагрузка, вся native-матрица и CI текущего кандидата. Production acceptance остаётся NO-GO.

Изменения этого прохода подготовлены в исходниках и прошли изолированную сборку. Основной локальный runtime не перезапускался, сервер и доверенные release pins не менялись. Шесть основных HTTP readiness возвращают 200/ok; это здоровье прежнего runtime, а не подтверждение применения новых исправлений. Публикации и push этим аудитом не выполнялись.
