# Повторная проверка доступа после ожидания лимита модели

## Исправленное поведение

Если во время COMMIT лимита отключить функцию или отозвать переданную проверкой
владельца авторизацию, запрос больше не отправляется провайдеру. Проверка
выполняется после ожидания лимита независимо от наличия `beforeDispatch`.

Уже принятый ответ сохраняется при последующем выключении функции. Новых
проверок после работы провайдера, повторных запросов или возврата слота при
неподтверждённом COMMIT не добавлено. Отмена сохраняет исходную причину;
неизвестный результат COMMIT сохраняет прежний публичный ответ
`503 MODEL_RATE_STORE_UNAVAILABLE`.

`beforeInference` может вызываться повторно для проверки свежих прав.
Резервирование бюджета остаётся у владельца операции вне этого callback.
В AgentTrial дополнительная проверка может сохранить прогресс с новой ревизией,
но не увеличивает число оплаченных вызовов и не резервирует бюджет повторно.

## Подтверждение

Новый набор использует реальные ModelApiAdmission, ModelRateLimitsService и
repository с управляемым SQL-портом. Он задерживает именно COMMIT. В исходном
коде три запрета всё равно получали ответ провайдера; четыре контрольных
сценария проходили. После исправления все семь сценариев прошли.

Полный выбранный регресс: **73 passed, 0 failed, 0 skipped, 0 todo**, шесть файлов:

- `model-api-rate-commit.test.ts`;
- `model-rate-limits-unit.test.ts`;
- `model-api-transport-admission.test.ts`;
- `model-runtime-admission-boundaries.test.ts`;
- `device-codex-metrics.test.ts`;
- `system-role-mcp-device-admission.test.ts`.

Production TypeScript и строгая проверка двух изменённых тестов с их импортами
прошли отдельно. Compiler options сохранены. Все исходники, инструменты и
зависимости оставались неизменными во время проверок; приватные процессы и
каталоги завершены штатно.

Квитанции в `.run/model-api-rate-commit-20261025/`:

- `model-api-rate-commit-red-v4-20261025-124422-65ed995/receipt.json`;

независимо по сырым результатам; квитанция не переписывалась, повтор ради
изменения классификатора не выполнялся.

## Границы

SQL и fetch управляемые, сетевых подключений не наблюдалось. Проверяется отказ
от `beforeInference`; репозитории ACL и привязки модели этим набором отдельно
не проверены. Настоящие PostgreSQL, провайдер, браузер, архив и работающая
площадка остаются отдельной приёмкой. Процент покрытия этим прогоном не измерялся.
