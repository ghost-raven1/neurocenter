## Проверки

- Frontend: **1313/1313**, **124 файла**, без пропусков.
- Catalog-service: **1336/1336**, **94 файла**, без пропусков.
- Отдельная настоящая PostgreSQL: **9/9**, скомпилированные CatalogController/AccessDb/CatalogService, отдельные pool и временная БД. Ошибки аудита внедрялись SQL-триггерами. Рабочая БД не использовалась для мутаций; созданная база удалена обычным DROP после закрытия собственных соединений. Локальная квитанция: `output/project-audit-fixes-20261019/postgres.json`.
- TypeScript и production-сборки frontend/NestJS прошли. NestJS собран в отдельный кандидат `.audit-fixes-dist`; PostgreSQL-проверка повторена на нём. Vite сохраняет прежнее предупреждение об общем chunk больше 500 КБ.
- Независимые проверки четырёх участков не выявили регрессий. Вложенные targeted-наборы не прибавляются к полным unit-числам.

После проверки пустых очередей локальный catalog-service перезапущен с новым кандидатом. Прежняя сборка и PID-описание сохранены в `.run/audit-fixes-previous-*`. Все семь health успешны; число и SHA содержимого проектов, пользователей, назначений и активов до/после совпали. В браузере после reload открылись прежняя сессия и каталог моделей. Локальные квитанции: `output/project-audit-fixes-20261019/local-apply.json`, `health.json`, `interface-after.png`. Остальные процессы и установленный пользовательский мост не перезапускались; это не развёртывание удалённого сервера.

PostgreSQL-проверка вызывает настоящие методы с доверенным request-контекстом fixture, без запуска Nest HTTP и без внешнего SSO. Unit-тесты UUID и метаданных используют изолированные API/генераторы. Эти свидетельства не подтверждают production, восемь native-целей или установку сторонних пакетов на пользовательский компьютер.

Повтор проверки БД после установки зависимостей на Node.js 24+:

```sh
cd services/catalog-service
node node_modules/typescript/bin/tsc -p tsconfig.build.json --incremental false --outDir .audit-fixes-dist
cd ../..
node scripts/test/project-profile-delete-db.mjs
```

Скрипт читает параметры подключения из окружения проекта; пользователь PostgreSQL должен иметь право создания временной БД. `PUBLICATION_TEST_PG_URL` задаёт отдельное тестовое подключение. `PROJECT_AUDIT_FIXES_DIST` и `PROJECT_AUDIT_FIXES_REPORT` позволяют выбрать скомпилированный кандидат и файл квитанции. Большие веса моделей и сервисы приложения для этого запуска не требуются.

## Эксплуатационные пункты

Повторный аудит обнаружил отсутствующие серверные `fs_root_path` двух локальных проектов. Для исправления нужно определить фактические папки; пустая новая папка не восстанавливает прежние данные. Привязка локальной папки сотрудника и серверный путь проекта — отдельные настройки.

Во время аудита устройство сообщало мост 0.9.4 при исходниках 0.9.6; RAG UI корректно требует не менее 0.9.5. Git и версия исходников актуализированы в [документе готовности](implementation-readiness.md). Внешние SSO/S3/restore/native/нагрузочные P0 остаются отдельной приёмкой.
