# Очистка копий обновления моста

Настройка: **Мои компьютеры → нужный компьютер → Кэш комплектов → Копии после обновления моста**. Требуется мост 0.9.20 или новее с возможностью `bridge-update-cleanup-v1`.

Автоочистка включена по умолчанию: сохраняются две предыдущие проверенные копии, остальные можно удалить после семи дней. Можно выключить уборку, выбрать от одной до десяти копий и срок от одного до девяноста дней. Настройки подтверждает выбранный компьютер; потерянный ответ восстанавливается с прежним ключом запроса. Целевой объём общего кэша меняется отдельно.

На мосте с возможностью `runtime-cache-target-v2` объём кэша — мягкая цель: превышение не блокирует новую установку и не удаляет прежние комплекты. Можно задать положительное целое число МиБ без прежнего диапазона 1024–16384. Перед загрузкой по-прежнему проверяется физическое место для архива, распаковки и резерва. Старый протокол настроек сохраняется для доставки прежних подтверждений; интерфейс предлагает обновить старый мост.

После успешной установки установщик сохраняет квитанцию предыдущей версии. Подключённый worker проверяет уборку после запуска и затем не чаще одного раза в час. Перед удалением он заново проверяет настройки, подключение, роль и флаг `bridge_storage_cleanup`. Недоступность сервера или уборки сохраняет копии и не отменяет обновление. Выключение автоочистки, просмотр и восстановление подтверждения доступны при выключенном флаге.

Удаляются только копии, для которых ещё при установке из проверенного архива сохранена полная опись файлов. Опись включает содержимое, пути и права файлов; квитанция привязана к каталогу установки и файловой идентичности копии. Ручные изменения до или после обновления исключают копию из уборки. Последняя проверенная копия для отката сохраняется при любых настройках.

Живой или неопределённый процесс защищает используемый runtime. При сомнении в принадлежности процесса сохраняются также остальные копии этой установки. Работающий OpenCode может отложить уборку до завершения своего процесса. Удаление сериализовано с установкой, а запуск текущего runtime оставляет отдельную метку использования и не ждёт уборку. Частично удалённая копия помечается отдельно: повтор продолжает только подтверждённое удаление, не объявляя остаток пригодным для отката.

Старые копии без исходной описи, каталоги восстановления, карантин ручных изменений, конфигурация OpenCode, ключи и файлы проектов не удаляются. Поэтому обновление с 0.9.19 само по себе не освобождает место за счёт прежних неподтверждённых копий. Проверяемая уборка действует на последующие копии, созданные новым установщиком.

Папки готовых моделей и плагинов в общем runtime-кэше, опубликованные версии каталога и поколения архивов сервера имеют отдельные правила использования. Эта функция их не удаляет и не меняет целевой объём кэша.
