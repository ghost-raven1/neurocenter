# Установка OpenCode и моста

Страница «Начало работы» выдаёт установщики с адресом API Gateway. Например, для локального запуска:

```sh
curl -fsSL 'http://localhost:4000/api/bridge/install_opencode.sh' | bash
curl -fsSL 'http://localhost:4000/api/bridge/install.sh' | bash
```

Первый скрипт устанавливает OpenCode, второй — автономный мост с Node.js 24. Пакеты и SHA-256 скачиваются с выбранной площадки; во время установки обращения к GitHub или npm не нужны. Пакеты каждой целевой платформы администратор предварительно добавляет на сервер. Установщик проверяет SHA-256, безопасные пути и типы файлов архива, версию и работоспособность программы до замены существующей установки. Для моста также проверяются архитектура и отпечаток сборки.

Мост сохраняет адрес сайта отдельно от адреса API Gateway. Это позволяет использовать Gateway для HTTP/WebSocket и сохранить прежнюю идентичность компьютера, привязки папок и локальные ключи. Адреса без паролей и параметров находятся в `installation.json` с правами только владельца. Ключ компьютера остаётся в личном хранилище моста, отдельно от конфигурации OpenCode.

Для уже установленного моста «Начало работы» выдаёт команду подключения с проверенным адресом Gateway из `/api/bridge/config`. Адрес открытой страницы не используется вместо него. Например:

```sh
curl -fsSL 'http://localhost:4000/api/bridge/connect.sh' | bash
```

Для Windows PowerShell:

```powershell
irm 'http://localhost:4000/api/bridge/connect.ps1' | iex
```

Эти endpoint доступны независимо от импортированной поставки. При исправном установленном runtime сценарий запускает его `bin/node` и `dist/index.js` напрямую: короткая команда, системные Node/npm и повторное скачивание архива не нужны. Отсутствие Linux-архива в текущей dev-поставке не запрещает подключение уже установленного Linux-моста. Короткая команда при наличии поддерживаемого CLI восстанавливается отдельно; отказ её восстановления не прерывает прямое подключение.

Обычный повтор сохраняет действующее подключение. Параметр `?reconnect=1` запрашивает явное повторное подтверждение профиля или роли. При недоступном браузере выводятся ссылка и код. Доверенный сценарий выбранного Gateway задаёт целевые SITE/API. Совпадающая собственная регистрация OpenCode сохраняется побайтно; при переходе меняются только её адреса с сохранением JSONC, окружения, чужих записей и ключей прежней площадки. Сохранённые HOME/CA/proxy применяются к runtime, а конфигурация OpenCode и восстановление короткой команды относятся к профилю вызывающего пользователя. Полная регистрация через `--init` в обычном прямом подключении не выполняется.

Если предварительная проверка обнаружила отсутствующий runtime или известную необходимость восстановить регистрацию, сценарий один раз запускает установщик этой площадки; тогда нужна доступная поставка для платформы. Повреждённая, неоднозначная, чужая или изменившаяся регистрация отклоняется. Ошибка Node/CLI после начала подключения показывается пользователю и не вызывает слепую повторную установку.

Сначала проверяется стандартная установка. Если её нет, сценарий может определить нестандартный каталог по точному полному формату управляемого launcher: читает пути как данные, не исполняя launcher, `eval` или `source`. Одной метки недостаточно; неизвестный, чужой или изменённый формат не запускается. Для custom root без подтверждённого управляемого launcher укажите путь явно, например `curl -fsSL 'http://localhost:4000/api/bridge/connect.sh' | INSTALL_DIR='/абсолютный/путь/к/мосту' bash`; в PowerShell задайте `$env:INSTALL_DIR` перед командой. Нестандартный каталог сам по себе не требует `INSTALL_DIR`; произвольные legacy-пути сценарий не угадывает.

Ручная короткая команда остаётся доступной, но использует последнюю сохранённую площадку: `"${HOME}/.local/bin/neurocenter-bridge" connect --open` или `& "$env:USERPROFILE/.local/bin/neurocenter-bridge.cmd" connect --open`. Для выбора площадки используйте её новую Gateway-команду выше.

Обновление моста блокирует параллельную установку, ждёт завершения задания и сохраняет прежний пакет отдельно. Отказ регистрации или её прерывание возвращает совместимую прежнюю версию; несовместимая версия сохраняется отдельно и не запускается автоматически. Отказ скачивания, проверки или распаковки сохраняет действующую программу. После подтверждённой регистрации ошибка соединения не отменяет установленный пакет: команду можно повторить после восстановления связи. Старые резервные пакеты автоматически не удаляются.

OpenCode сохраняет пользовательские JSON/JSONC и `auth.json`. Переданный `OPENCODE_API_KEY` не привязывается к произвольному провайдеру и не печатается. Вариант `--binary /путь/к/архиву.tgz` предназначен для заранее доставленного локального архива; его контрольную сумму нужно проверить при доставке. Для сетевой установки SHA-256 проверяется автоматически.

Скачивание ограничено по времени и имеет повтор при временной сетевой ошибке. При корпоративном CA настройте доверенный сертификат через `CURL_CA_BUNDLE` или `SSL_CERT_FILE` для curl; для PowerShell — через доверенное хранилище Windows. Проверка TLS остаётся включённой. Установщик не меняет корпоративные сертификаты, proxy и конфигурацию npm.

Автоматические проверки выполняются во временных домашних каталогах. Bash, сохранность настроек, отказы и короткая команда проверяются изолированно; нативная приёмка текущего прохода выполняется на macOS ARM64. PowerShell-скрипты требуют отдельного запуска на Windows: исходная проверка текста не подтверждает нативную установку.

## Переход между площадками — 22 октября 2026

Исторический срез `c5be79b`, до новых connect-сценариев ниже: исправлен отказ после успешной SHA-проверки. Bash-установщик больше не останавливается только потому, что адреса сохранённого подключения отличаются от адресов площадки, выдавшей установщик. Обычный запуск её команды доводит до подключения к этой площадке.

При совпадении адресов запись OpenCode сохраняется побайтно. При переходе атомарно меняются только `NEUROCENTER_URL` и `NEUROCENTER_API_URL` собственной записи MCP; JSONC-комментарии, `enabled:false`, timeout, пользовательское окружение, другие агенты и права файла сохраняются. Старый профиль используется для завершения очереди, новый — для подключения. Короткая команда регистрируется в HOME вызывающего пользователя с новыми адресами.

При смене адреса сайта ключи прежнего namespace не копируются и не удаляются. Подключение проходит подтверждение в браузере либо использует уже существующие собственные ключи целевой площадки. При неизменном сайте смена API — явное изменение транспорта из доверенного установщика; namespace сохраняется. Это не универсальная проверка равенства двух backend-серверов.

Недоступная прежняя площадка не мешает переходу на другой сайт, если lock отсутствует или его корректный PID доказанно завершился. Lock повторно сверяется перед публикацией. Живой worker сохраняет защиту задания и обычный pause/resume; повреждённый или чужой lock не считается отсутствующим. Повторная сверка — ограниченная проверка состояния, не обещание непрерывной блокировки всех файловых гонок.

Отказ миграции возвращает совместимый прежний runtime и исходную регистрацию. Откат не перезаписывает последующую пользовательскую замену файла или изменение его прав. При неподтверждённом восстановлении установщик сохраняет приватный каталог со снимком и планом, выводит его путь и не сообщает об успешном подключении. Проверки входного окружения и итогового размера JSONC выполняются до замены программы.
