# Адрес пользователя при публикации

В dev-режиме `DEV_USER_EMAIL` мог содержать заглавные буквы или внешние пробелы. Вход и проверка назначений принимали такой адрес, а точный SQL-поиск перед публикацией skill ошибочно сообщал об отзыве роли. Внутренний Skills API дополнительно требовал адрес без пробелов.

Теперь существующий `normalizeEmail` применяется к двум локальным значениям: параметру поиска роли и исполнителю исходящего native-запроса. Проверки `enabled`/главного администратора, тот же SQL-клиент и `FOR SHARE` сохранены. Некорректный адрес отклоняется с 403 до SQL-запроса или native dispatch. Политика допустимых адресов не менялась.

Исходный actor сессии и заданий сохраняется. `requestKey`, fingerprint, CAS, владелец Operations, tombstones отмены и `imported_by` исходников не переписываются. Повтор прежнего запроса и отмена используют прежние точные ключи. Изменение `DEV_USER_EMAIL` на другое написание и объединение истории разных написаний этим срезом не реализованы; lookup того же UUID от canonical counterpart по-прежнему возвращает 404.

## Локальная проверка — 23 октября 2026

На прежнем кандидате воспроизведены четыре отказа: регистр/пробелы × сборка/публичный импорт. Реальный `AuthService.mockUser` получал через HTTP канонические назначения главного администратора, сохраняя исходный principal. Реальные Gateway headers и Catalog decoding передавали его дальше; PostgreSQL подтверждала существование канонической записи и отсутствие записи с исходным написанием. Сборка завершалась `FAILED`, импорт — 403; native-записи и SQL-квитанции отсутствовали, исходные байты сохранялись. Два канонических контроля проходили.

Окончательный QA на старом кандидате дал четыре точных RED и пять здоровых контролей; на исправленном — **9/9**:

- Шесть публикаций: регистр, внешние пробелы и канонический адрес на обоих путях; native-версия 1, canonical actor в native/audit и исходный actor в SQL-квитанциях.
- Два контроля сохранённого владельца: настоящий `create`/worker, повтор того же запроса, request lookup, отмена, Operations и поздний POST после tombstone. Один прежний job, точный actor/config/hash, `CANCELLED` и поздний 409 без native-записи.
- Некорректный адрес: отказ реальной проверки профиля и публичного импорта до native-записи.

87 критических хешей до и после прогона совпали. Первый QA-прогон содержал недопустимый `targets: []` в двух контрольных запросах и сохранён как непринятый. Исправлен только вход фикстуры; окончательный baseline и candidate используют одинаковые байты QA.

Backend-регресс — **454/454 в 39 файлах**, без пропусков; новые 28 unit-проверок и полный файл из 21 проверки фичафлагов входят в это число. В старом файле исправлены два недостоверных входа: actor без email и mock `observe`, передававший `undefined` вместо обязательного `AbortSignal`. Девять прежних падений последнего воспроизведены на неизменном B14-кандидате; это ошибки тестовой заглушки, не девять дефектов inference. Строгий TypeScript production и нового регресса прошёл.

Общий unit-safe прогон восьми пакетов — **7992 pass / 0 fail / 53 skip**, 582/582 выбранных файлов, 126 потенциально инфраструктурных файлов исключены. AST lines — **65,47% (21494/32830)**, functions — 59,74%, branches — 63,13%, statements — 61,51%; `complete:false`, весь workspace не охвачен. Консервативный профиль исключает и SQL-моки с `pg` type-import, в том числе новый файл из 28 проверок и прежний файл из 21; они отдельно выполнены в целевом наборе 454. Эти числа и native-сценарии не прибавляются к общему проценту.

Во время общего прогона редактировалась Markdown-документация, поэтому исходный manifest честно сохраняет `sourceChangedDuringRun:true`. Все 2560 хешей инвентаризации кода/тестов/инструментов совпали после прогона. Исходные Git digest трёх изменённых файлов кода, трёх новых test/QA файлов, HEAD и status без документации восстановлены точно. Исполняемый код не менялся; исходный manifest не исправлялся. Квитанции: `.run/coverage/dev-actor-final-20261023/manifest.json`, `.run/dev-actor-publication-20261023/coverage-current-equivalence.json`. Разделение чистых unit и инфраструктуры остаётся B16.

Все восемь пакетов собраны отдельно от рабочих `dist`, 1303 текущих `src/shared` файла совпали с кандидатом. Предыдущий [регресс авторизации B14](skill-publication-authorization.md) повторён: **10/10** с 80 стабильными критическими хешами. Отзыв роли, OFF флага, порядок `FOR SHARE` и восстановление прежнего native-журнала сохранены. Все собственные БД и stages очищены; собственный PostgreSQL штатно остановлен с проверкой PID, порта и pidfile. Основная БД и пользовательский мост не менялись.

Квитанции: `.run/dev-actor-publication-20261023/backend/source-receipt.json`, `.run/actor-canonical-publication-20261023/baseline-IFurLz/receipt.json`, `.run/actor-canonical-publication-20261023/candidate-mAfI6q/receipt.json`, `.run/skill-build-authorization-20261023/candidate-Tl99QG/receipt.json`, `.run/dev-actor-publication-20261023/native-cleanup-receipt.json`.

Профиль проверяет настоящий profile HTTP на loopback, методы Gateway/Catalog, PostgreSQL, компилятор данных skill и файловое хранилище Skills. Gateway headers/controller и Skills transport вызываются внутри процесса. Полный Gateway HTTP/middleware, настоящие SSO и cookies, браузер, обычный OpenCode, другие ОС, CI и production требуют отдельной приёмки. Только два контроля владельца запускают настоящий `create`/worker; шесть публикаций вызывают `Service.execute` после явного enqueue либо публичный controller import. Эти наборы не суммируются со строковым покрытием.
