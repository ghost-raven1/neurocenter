# Установка и локальная настройка MCP 0.9 — 18 октября 2026

Кандидат **0.9.0** реализует готовые платформенные комплекты и локальный мастер настройки MCP. Этот документ отделяет реализацию от результатов приёмки. Выпуск и production пока **NO-GO**: нужны семь остальных нативных платформ, настоящий Blitz и целевой сервер, внешний DR, проверка обновления/отката, нагрузка/soak и CI/deployment.

## Что изменилось

- Формат пакета **5** закрепляет платформенные архивы и схему локальных параметров в SHA пакета и всего графа. Чтение форматов 2–4 и протокол очереди **2** сохранены. Новые возможности проверяются отдельно: `package-v5`, `runtime-artifacts-v1`, `local-mcp-config-v1`.
- Локальный MCP получает заранее собранный комплект подходящей ОС/архитектуры/libc. На компьютере пользователя нет автоматических npm/pip/Bun установок и произвольных install hooks. Для плагина допустим JavaScript entrypoint; скилл получает runtime через закреплённые MCP/плагин зависимости.
- Кнопка установки сохраняет файлы и подключения. Затем пользователь видит ближайшее действие: сверить файлы, заполнить настройки или явно разрешить ограниченную диагностику. Успешная запись файлов сама по себе не означает работающий инструмент.
- Настройки MCP вводятся в локальном мастере. Сервер получает только состояние, идентификаторы недостающих полей и случайную ревизию. Значения не входят в API, проектный config, argv, журнал, публичный результат и серверные копии.
- Согласие на диагностику включает ревизии **всех** MCP со схемой настройки в закреплённом графе. Изменение параметров делает прежний runtime-результат устаревшим и требует нового согласия. Поздний ACK и неверные часы компьютера не возвращают старый статус готовности: порядок определяется серверным временем начала задания.

## Границы безопасности и хранения

Артефакт импортирует оператор через [CLI и проверяемый descriptor](runtime-artifacts-0.9.md). Серверная миграция **3** создаёт реестр SHA, сами неизменяемые байты хранятся в отдельном томе `runtime-artifacts`. Доставка идёт потоком по авторизованному маршруту конкретного задания, после повторной проверки lease, прав и одобрения всего графа. Другие архивы по этому разрешению недоступны.

Разрешён строгий gzip USTAR: максимум **256 МиБ** сжатых данных, **1 ГиБ** распакованных файлов и **20 000** файлов. Ссылки, выход за каталог, устройства, PAX/GNU extensions и конфликты имён запрещены. Перед установкой и запуском повторно сверяются SHA сохранённого архива и реальные байты дерева. Кэш **2 ГиБ**, резерв свободного диска **128 МиБ**; рабочие старые версии автоматически не удаляются. Неудачная загрузка не заменяет существующую установку.

Локальные параметры хранятся отдельным закрытым файлом: каталоги **0700**, файлы **0600**, на Windows — ACL текущего пользователя. Это выбранный файловый вариант, без OS keychain и без обещания шифрования от процессов того же пользователя. Запись атомарная, с CAS по ревизии, проверкой владельца и запретом ссылок. Параметры связаны с сервером, устройством, проектом, физическим instance, инструментом и digest схемы. Переименование той же папки сохраняет настройки; отдельная копия получает собственный instance.

Мастер слушает только `127.0.0.1` на случайном порту, живёт **15 минут** и использует одноразовый token во fragment, bootstrap, Origin/Host/CSRF и CSP. URL остаётся локально. Открытие мастера быстро завершает задание и освобождает очередь. Каждая действительная попытка сохранения одноразовая и получает свежее серверное разрешение; отзыв доступа после открытия блокирует запись. Старое сохранённое значение не показывается в форме.

Локальный stdio launcher добавляет параметры только окружению своего процесса. Для удалённого MCP отдельный stdio-прокси добавляет разрешённые заголовки только закреплённому URL; redirect и автоматические OAuth/discovery отключены. Это не песочница ОС для одобренного кода. Диагностика выполняет handshake и list, без `tools/call`; у плагина проверяется поддерживаемая инициализация, у скилла — структура. Все hooks и бизнес-сценарии этим не подтверждаются.

Для Windows реализован helper Job Objects: собственный процесс создаётся приостановленным, включается в job, затем запускается; закрытие job завершает только его дочернюю группу. Сборка требует проверяемый PE helper нужной архитектуры. Синтетические тесты упаковки не заменяют настоящую Windows-приёмку.

## Копии и обратная совместимость

Полная серверная копия записывает **`neurocenter-recovery-v2`** с четырьмя томами, включая runtime-архивы. Исторический v1 читается с пустым новым томом. Миграции 1 и 2 не переписывались. Локальные секреты в серверную копию не попадают. Восстановление копии на отдельном локальном стеке не означает принятие внешнего аварийного восстановления production.

## Исправления, выявленные проверками

- Публичная публикация и JSON-редактор раньше отвергали новые поля формата 5. Теперь они принимают только runtimeArtifacts/localConfiguration; произвольный extra и значения параметров запрещены. Artifact-only MCP/плагин публикуются через API, изменения проходят прежний контроль версий и одобрение.
- Нативный или не-JavaScript entrypoint плагина отклоняется до approval одинаково сервером и мостом.
- Карта параметров в диагностике использует `kind:id`: одинаковые ID разных видов не подменяют исходный скилл/плагин на MCP. Две регрессии проверяют виды и реальные счётчики.
- RAG Dockerfile получает shared parser до сборки встроенного MCP; исходный неудачный BuildKit-прогон сохранён отдельно и в финальную приёмку не входит.
- Тестовая build-фикстура получила собственную копию новой shared-зависимости. Первый параллельный native-прогон достиг 30-секундного ограничения; последовательный повтор прошёл без изменения исходников и таймаута. После исправления kind:id заново собран и принят финальный архив; промежуточный архив и отчёты сохранены отдельно.

Рабочий код не является песочницей ОС. Открыты оставшиеся семь нативных платформ, настоящее окружение Blitz/сервера, внешний DR/RPO/RTO, обновление/откат и нагрузка/soak/CI. В checkout нет `.git`, поэтому commit/push и синхронизация ветки не выполнялись.

Исходные свидетельства текущего этапа: `.run/reliable-installation-20261018-v09/`; сценарии настоящего worker: `.run/reliable-installation-v09-20261018/`.
