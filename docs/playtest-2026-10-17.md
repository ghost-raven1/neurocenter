# Плейтест функционала и подключения MCP — 17 октября 2026

Проверено работающее приложение в браузере: семь разделов при 1280×900 и 390×844. Отдельно пройдены подключение тестового компьютера, сохранение скилла, переключение роли, отмена и повтор очереди, валидация форм, поиск истории, выход и повторный вход. Серверные сценарии установки, удаления и синхронизации проверены живыми API/worker-тестами. [Аудит безопасности и открытые риски](security-audit-2026-10-17.md).

## 1. Подключение компьютера — исправлено, сценарий пройден

**Проблема:** после команды установщик печатал JSON со ссылкой и кодом, а каталог продолжал писать «Компьютер пока не подключён». Пользователь мог принять это за неудачную установку. На странице начала работы блок настройки находился после большого вводного блока и не учитывал уже подключённый Mac.

**Теперь:**

1. Установщик вызывает `--connect-open` и пытается открыть `/start?step=1&connect=…` в системном браузере. При невозможности открыть браузер сохраняет ссылку и понятную ручную инструкцию.
2. Панель показывает отдельное подтверждение с именем, отпечатком и ролью компьютера. Доступ подтверждается человеком; открытие ссылки само по себе его не выдаёт.
3. После подтверждения отображается ожидание фактического heartbeat. Успех появляется только для компьютера с нужным отпечатком. Повторное нажатие во время запроса исключено.
4. После выхода на связь доступна кнопка «Выбрать папку проектов». Она открывает страницу проектов. Настройка общего корня и привязка подкаталога к серверному проекту остаются отдельными явными шагами.
5. Если MCP уже подключён, показываются его состояние и следующий шаг. Команда повторной установки скрыта в «Подключить другой компьютер», ручной код — запасной способ.

Блок настройки перемещён перед вводным блоком. Подписи шагов сокращены; исправлено горизонтальное переполнение на мобильном экране. Основная кнопка подключённого компьютера находится на высоте 718–750 px при viewport 390×844, то есть доступна без дополнительной прокрутки.

Тестовое подтверждение выполнялось отдельной API-сессией на собственном временном устройстве; браузер проверял экран согласия, ожидание и реальный переход после heartbeat. Настоящий Mac не переподключался и не отзывался. Открытие системного браузера проверено на уровне безопасной команды без shell; автоматический запуск браузера на настоящих Windows/Linux этим проходом не подтверждён.

## 2. Каталог и модалки скилла — пройдено

На временном проектном скилле проверены поиск, открытие инструкции, переход в редактор, изменение описания и сохранение. Без изменений кнопка сохранения отключена; во время запроса поля заблокированы. После сохранения карточка показывает новое описание и версию 2. [Результат сохранения](../.run/security-2026-10-17/screenshots/08-skill-saved.jpg).

После выбора назначенной роли «Наблюдатель» исчезают редактирование и административные разделы, карточка остаётся доступной для чтения. [Интерфейс наблюдателя](../.run/security-2026-10-17/screenshots/09-observer.jpg). Реальные запреты серверной записи, чужие проекты, общий каталог и отзыв прав проверены дополнительно через API, а не только скрытием кнопок.

Исправлено отображение проекта, когда URL содержит постоянный ID: в выборе каталога теперь видно понятное название. После удаления временных проектов исходная навигация восстановлена. Установка отключена с объяснением, пока его локальная папка не связана; подключённый MCP при этом отображается корректно.

## 3. Очередь MCP и WebSocket — пройдено

Для собственного отключённого тестового устройства в интерфейсе проверены «В очереди» → отмена с подтверждением → «Отменено» → «Повторить через MCP» → новое задание «В очереди». Настоящий компьютер не получил этих задач. [Отмена и повтор](../.run/security-2026-10-17/screenshots/10-queue-retry.jpg).

Живые тесты дополнительно проверяют отключение и перезапуск worker, reconnect WebSocket, личные события, отзыв устройства и роли до исполнения, транзакционное изменение журнала и очереди, гонки отмены/отзыва. Обновления временных проектов во время API-прогона отражались в открытой панели без ручной перезагрузки.

## 4. Проекты — пройдено в проверенных границах

Пустое название не отправляется: форма показывает «Введите название проекта». У каждого пользователя может быть собственный общий корень; интерфейс объясняет, что название локальной папки может отличаться от серверного проекта. Переход из шага подключения открывает «Проекты».

На настоящем Mac корень пока не выбран. Системный диалог с его файлами не открывался и привязка реального каталога не менялась. Ожидание выбора папки и отмена проверены на временном устройстве; связывание папки с другим названием — живым worker-тестом в временной файловой системе.

## 5. Доступ, обслуживание, базы знаний и история — пройдено с ограничениями продукта

- **Участники и доступ:** список загружается, форма отклоняет некорректную почту; учётная запись не создавалась этим UI-действием. Интерфейс честно объясняет отсутствие отправки письма. Роли и назначения проверены на временных пользователях и проектах через API и изолированную БД.
- **Обслуживание:** сведения о копии и размерах загружаются; интерфейс отмечает состав копии, неполную сводку размеров и отсутствие восстановления из панели. Общесистемная копия настоящих данных вручную не запускалась. Реальный pg_dump временного проекта восстановлен через pg_restore в отдельную временную БД.
- **Базы знаний:** загружается выбранный проект, показываются пустой индекс и переход к синхронизации. Обмен настоящей LanceDB с PostgreSQL проверен на временном проекте, как и разделение одинаковых ID фрагментов между разными базами.
- **История действий:** поиск без совпадений показывает отдельное пустое состояние; сброс восстанавливает записи. Видно ограничение фильтра текущей страницей. Полнота журнала безопасности ещё недостаточна — OPEN-03 в аудите.

## 6. Сессия и возврат на шаг — пройдено

Выход через меню возвращает экран входа. Открытие `/start?step=1` и последующий вход возвращают на тот же шаг; подключённый Mac снова отображается на связи. Серверное удаление сессии, срок действия, небезопасные redirect и OAuth state проверены отдельными тестами. Настоящий корпоративный вход не проверен.

## Следующие улучшения UX

1. **P1:** автономные установщики с собственной средой и подписанным пакетом; сейчас остаётся предварительная установка Node/npm. Запуск через `curl | bash` или PowerShell ещё требуется при первом подключении.
2. **P2:** объединить повторяющиеся сообщения о непривязанной папке в каталоге в один блок с одной кнопкой перехода. Сохранить точное объяснение недоступного действия.
3. **P2:** заменить технические «ключ проекта», «размерность» и «bootstrap не выполнен» в базах знаний на понятные название проекта, состояние готовности и следующий шаг.
4. **P2:** серверный поиск по всему аудиту, полный учёт размеров и проверяемое восстановление копии из панели. Текущие ограничения обозначены, но функции ещё не реализованы.
5. **P2:** на мобильном экране вынести основные действия из правого края широких таблиц и обозначить горизонтальную прокрутку. Особенно это касается синхронизации базы знаний.
