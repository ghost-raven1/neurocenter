# Аудит состава проекта и целостность зависимостей — 18 октября 2026

Продолжена **P1-AUD**: добавление и снятие инструмента в проектном каталоге теперь сохраняют событие вместе с изменением связи. Исправлены два связанных сценария: назначение одновременно с удалением общей карточки и удаление зависимости, которая нужна текущей либо исторической версии другого MCP/плагина.

## Что изменилось

- `ProjectAssetRepository` выделен из большого `CatalogDb`. Добавление/снятие и `project.asset.add/remove` выполняются одной транзакцией. Если INSERT аудита не проходит, связь откатывается. Повтор добавления и снятие отсутствующей связи не создают событие.
- Исполнитель поступает из доверенного gateway-контекста через controller/service/repository. Поле `actor` в теле запроса не назначает исполнителя. Действующее право администратора проекта проверяется до записи.
- Сводка события содержит ID проекта, вид/ID инструмента, первоначального автора и время назначения. Исполнитель снятия хранится отдельно. В общем API истории этот payload скрыт; видны действие, исполнитель и составной ресурс, позволяющий искать по проекту или инструменту.
- Назначение MCP/плагина перечитывает карточку с `FOR KEY SHARE`, сверяет вид и удерживает блокировку до COMMIT. Удаление использует `FOR UPDATE`: если назначение было первым, DELETE ждёт и получает 409; если DELETE был первым, назначение ждёт и получает 404. Осиротевшая связь не записывается.
- Create/update/activate/delete MCP/плагинов получают общую транзакционную блокировку графа **до** строковых блокировок. Перед новой записью перепроверяются существование точной версии зависимости, её тип и SHA пакета, восстановленного из собственного исторического снимка. Удаление учитывает pins других карточек и их сохранённых версий.
- В журнале появились действия «Добавлен в проект» и «Убран из проекта». Описание покрытия обновлено. Существующая gateway-инвалидация проектов уже включает `audit`; открытая история обновляется без ручного reload.

Общая advisory lock намеренно сериализует записи графа MCP/плагинов: это простой согласованный порядок для редких изменений каталога. Независимое ревью не нашло блокирующих замечаний. Новые production-модули — 67 и 49 строк; схема БД не менялась.

Перезапущен только локальный **catalog**; прежний `dist` сохранён в `.run/project-catalog-audit-previous/catalog`. [Idle](../output/project-catalog-audit-20261018/idle.json), [перезапуск](../output/project-catalog-audit-20261018/restart.json). Это локальное применение, не production deployment и не приёмка Docker-образов.

Три собственных QA-проекта и три карточки удалены; в итоговом API-прогоне проверены 404 и сохранность исходных ID. Открытие проекта создало три отдельные пустые RAG-БД: после удаления проектов отдельно проверены точные registry/hash, отсутствие chunks, копий и активных запросов, затем убраны только эти собственные БД/registry. Итоговый список БД равен исходному. Аудит штатно сохранён. [Очистка](../output/project-catalog-audit-20261018/cleanup.json).

Собственная браузерная сессия завершена: logout 200, `/auth/me` 401, браузер закрыт. Все шесть локальных сервисов отвечают 200. [Сессия](../output/project-catalog-audit-20261018/session.json), [готовность](../output/project-catalog-audit-20261018/health-after.json). Глобальный OpenCode, рабочий мост, пользовательские папки, роли и политика обслуживания не менялись. Установки через мост и резервные копии этим проходом не запускались.

## Что остаётся

**P1-AUD остаётся частичной:** изменения самих файловых скиллов ещё не имеют полной гарантии аудита при сбое/восстановлении. Аудит назначения скилла в проект не заменяет аудит изменения его файлов.

**P1-REF:** pins из файловых скиллов находятся в другом сервисе и не участвуют в PostgreSQL-блокировке графа. Удаление цели, на которую ссылается только скилл, пока не защищено этим механизмом. Нужен согласованный межсервисный lifecycle ссылок, включая исторические версии и recovery.

Отсутствуют immutable/SIEM; P1-LIFE автоматической безопасной очистки RAG-БД остаётся открытым. Общая graph lock требует отдельной проверки под целевой нагрузкой. Все исходные шесть P0 остаются открытыми, production — **NO-GO**. Настоящий IdP, остальные семь нативных целей, независимый DR и целевая эксплуатационная нагрузка этим проходом не принимались. Существующие предупреждения AntD/React и Vite не скрывались. `.git` отсутствует: commit/push/CI не выполнялись.
