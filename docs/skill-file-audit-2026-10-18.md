# Устойчивый аудит файловых скиллов — 18 октября 2026

Создание, изменение и удаление файлов скиллов через редактор и проектную синхронизацию теперь имеют сохраняемый аудит. Если файл уже записан, отказ каталога не изображается ошибкой сохранения: ответ содержит `audit: {state:'pending'}`, интерфейс предупреждает и завершает успешное действие. Доставка повторяется с прежним UUID без нового изменения файла и без дубля события.

Это локальная приёмка перечисленных действий в однорепличном стеке. Шесть исходных P0 остаются открытыми; production-допуск — **NO-GO**. [Реестр оставшихся работ](implementation-readiness.md).

## Изменения

| Область | Поведение |
| --- | --- |
| Файловая транзакция | Одиночные CRUD и пакетный sync используют общий журнал. Prepared содержит исходные/целевые тексты и подготовленные события до первой записи. Файлы, журнал, commit marker и каталоги fsync-ятся. |
| Восстановление | Prepared откатывается и не отправляет события. Committed не исполняет файловые изменения повторно: переходит в закрытый outbox `audit-<UUID>.json`. |
| Доставка | Повтор при старте, после мутации и каждые две секунды; пакет до 200 событий. Только подтверждение всех частей разрешает удалить outbox. Таймер очищается при остановке; текущий HTTP-запрос ограничен пятью секундами. |
| Каталог | Защищённый `POST /internal/skill-audit/events`. Квитанция и `security_events` записываются одной транзакцией существующего PostgreSQL-пула. Повтор одинакового UUID/payload — успех, другой сохранённый payload — 409, некорректный вход — 400. |
| Исполнитель | Шлюз вырезает клиентские `x-bridge-*` и формирует actor из сессии. Аудит использует нормализованный email, включая `dev@localhost`; автор истории sync остаётся `mcp-sync`. |
| Данные | Передаются действие, путь, источник `editor/sync/bootstrap`, UUID/время и сводки до/после: поколение, версия, SHA-256. Текст инструкции, ресурсы и произвольные поля в PostgreSQL-аудит не отправляются. Публичная история не раскрывает payload. |
| Интерфейс | Пять существующих CRUD-путей показывают pending как успешную запись с предупреждением. Исправлен прежний ложный успех rejected Redux-запросов старого раздела Skills. Открытая история получает инвалидацию и дополнительно перечитывается каждые десять секунд, если вкладка видима и запрос не выполняется. |
| Диагностика | Неподтверждённый outbox даёт `/ready` скиллов 503. Повреждённый журнал сохраняется и блокирует запуск/восстановление; его нельзя автоматически стереть ради зелёного статуса. |

Коллекции сериализуются и между экземплярами хранилища в одном процессе. Ревью выявило и закрыло гонку: фоновая доставка старого commit могла переместить новый prepared по тому же пути. Архивизация теперь блокирует коллекцию и повторно читает журнал, доставка работает со стабильным именем outbox. Добавлен детерминированный regression test. Положительные pins, история поколений и полный сканер зависимостей сохранены; сканер видит также ссылки из outbox.

Ключевые исходники: [журнал](../services/skills-service/src/storage/skill-journal.ts), [outbox](../services/skills-service/src/storage/skill-audit-outbox.ts), [сводки и HTTP-клиент](../services/skills-service/src/storage/skill-audit.ts), [общий контракт](../services/shared/skill-audit.cjs), [SQL-квитанции](../services/catalog-service/src/publication/skill-audit-repository.ts), [сообщения интерфейса](../frontend/src/modules/Skills/skillMutationFeedback.ts).

## PostgreSQL, HTTP, файловая система и падения

Новый [исполняемый тест](../scripts/test/skill-audit-db.mjs) прошёл **17 сценариев** с настоящими repository, storage, service, HTTP-клиентом и PostgreSQL. HTTP-маршрут в этом стенде — небольшой изолированный adapter; полный Nest/gateway-путь отдельно проверен браузером. [Квитанция](../output/skill-file-audit-20261018/audit-protocol-postgres.json), [лог](../output/skill-file-audit-20261018/audit-protocol-postgres.log).

Проверены CRUD/actor, noop/CAS, смешанный sync, недоступный каталог после файлового commit, потеря ACK после SQL COMMIT, неверный `accepted`, конфликт UUID и полный rollback SQL-пакета, три конкурентные доставки одного события, гонки создания/соседние файлы, повреждённый журнал и закрытый payload публичной истории. Настоящий SQL CHECK отвергает audit INSERT: квитанция откатывается вместе с событием, уже сохранённая версия остаётся на диске и доставляется после снятия отказа.

Два одноразовых Node-процесса принудительно завершены **SIGKILL** на инструментированных границах настоящего файлового пути: после записи head до commit marker и после committed/outbox до подтверждения доставки. После первого head откатился, событий нет; после второго байты сохранились, новый экземпляр доставил одно событие. Это падение процесса на локальной POSIX-ФС, не отключение питания или приёмка другого сетевого тома.

Повторены прежние **49** сценариев: [publication 20](../output/skill-file-audit-20261018/publication-postgres.json), [project-assets 11](../output/skill-file-audit-20261018/project-assets-postgres.json), [зависимости/legacy repair 18](../output/skill-file-audit-20261018/dependency-protocol-postgres.json). Итого в этом проходе 66 сценариев с собственными временными БД; каждая БД/папка удалена, исходный список БД сверён. Unit-тесты дополнительно покрывают отказ fsync/commit, отказ архивизации после commit, отказ unlink после ACK и повтор второй части 201-событийного пакета.

## Оставшиеся границы

Создание каталогов, исторический backfill и ручные изменения FS не аудируются этим механизмом. Независимые restore одного тома или одной БД, согласованное восстановление FS/PG, нагрузка и стоимость накопленного outbox ещё не приняты. Хранилище outbox содержит приватные исходные тексты в файлах 0600 и каталоге 0700; это часть защищаемого тома и согласованной копии. При неустранимом конфликте UUID/повреждении требуется операторский разбор, без автоматического удаления свидетельств.

Доставка аудита eventual: подтверждённая файловая запись может временно отсутствовать в PostgreSQL-истории. API и readiness явно показывают этот случай. Immutable/SIEM, HA нескольких writers и испытание отключением питания не заявлены. Checkout по-прежнему без `.git`: commit/push, CI и deployment не выполнялись; новая точная production-поставка требует собственной приёмки.
