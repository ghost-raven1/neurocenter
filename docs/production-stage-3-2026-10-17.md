# Production: лимиты знаний и устойчивость интерфейса

17 октября 2026 года. Продолжение [этапа восстановления](production-stage-2-2026-10-17.md). Реализован действующий лимит логических данных RAG, проверены конкурентные изменения и ошибки интерфейса. **Промышленный допуск остаётся NO-GO**: защита физического диска/файлов/копий, внешний backup, общий процесс обновления, мониторинг и целевое окружение ещё требуют приёмки.

## Гарантии данных

- Лимит хранится внутри каждой используемой PostgreSQL-базы знаний. Счётчик учитывает UTF8-байты ID, ключа проекта, пути, текста, описательных строковых метаданных и хэша; по 4 байта на заданные номера строк; 8 + 4 × размерность для вектора. Timestamp, индексы, WAL и физические накладные расходы в этот логический объём не входят.
- Триггеры считают фактический INSERT/UPDATE/DELETE и TRUNCATE; запись сериализуется advisory lock. Отложенная проверка оценивает итог всей транзакции, поэтому раннее увеличение может компенсироваться последующим сокращением в том же пакете. Конкурирующий запрос не занимает уже израсходованный остаток повторно.
- HTTP 413 с кодом `RAG_QUOTA_EXCEEDED` отменяет **весь HTTP-пакет**, включая удаления. Предыдущие успешно подтверждённые пакеты большой синхронизации сохраняются. MCP сообщает подтверждённый объём; повтор читает серверный манифест и отправляет остаток. Уменьшение/удаление освобождает квоту; одинаковый upsert не расходует её повторно.
- Длительная конкурентная блокировка ограничена десятью секундами и даёт временную ошибку 503 `RAG_BUSY`. Сообщения объясняют безопасный повтор.
- Изменение лимита требует актуальную ревизию. Устаревший черновик получает 409; повтор того же уже установленного значения допускается после потери ответа. Снижение ниже занятого объёма и превышение операторского максимума отклоняются.
- Чтение разрешено участникам своего проекта, изменение — проектному/главному администратору с подходящей активной ролью. Автор берётся из доверенной сессии шлюза; заголовок/поле тела клиента его не подменяют. Лимит и `rag_quota_events` фиксируются одной транзакцией; отказ аудита отменяет изменение.

SQL находится в `services/rag-sync-service/src/rag/quota/`. Миграция `001-rag-storage-budget` записывает версию и SHA256; изменение уже применённого SQL останавливает инициализацию. Повтор запуска сохраняет лимиты/ревизии. При первом переносе существующих данных лимит не ниже занятого объёма; удаление старых знаний ради нового default не выполняется. При переносе из общей БД учтена длина нового ID; изменённый администратором лимит не повышается автоматически.

По умолчанию новые бюджеты получают 1 ГиБ, максимум нового значения — 16 ГиБ. Оператор задаёт `RAG_DEFAULT_QUOTA_BYTES` и `RAG_MAX_QUOTA_BYTES` в закрытом production-конфиге; ноль не отключает защиту. Это исходные настройки пилота, не результат измерения промышленной ёмкости. Существующий бюджет больше нового default сохраняется. Настройка описана в [инструкции оператора](production-setup.md).

## Удобство и ошибки

- Вкладка «База знаний» показывает расход, лимит и остаток; изменение доступно администратору. Форма «Квоты» использует МиБ/ГиБ, объясняет границы учитываемых данных и причины отказа.
- WebSocket обновляет сведения, сохраняя введённый черновик и исходную ревизию. После конфликта пользователь явно обновляет сведения, проверяет своё значение и повторяет сохранение. Двойное нажатие не создаёт параллельные сохранения. Неподтверждённый ответ сервера не очищает черновик.
- При снижении роли из открытых квот/копий/истории интерфейс переходит на доступный обзор и исправляет URL. Пустой экран закрытой вкладки устранён.
- Отказ чтения RAG больше не показывается как 404 или отсутствие индекса. Последние полученные сведения сохраняются с предупреждением; при первой ошибке показано состояние недоступности. Повтор после восстановления не требует перезагрузки страницы. Общий `Internal server error` заменяется русским сообщением соответствующего экрана.
- При создании проекта больше нет полей справочной квоты и числа будущих immutable-снимков. Достаточно названия; действующий лимит включается автоматически. Внешний идентификатор остаётся дополнительным полем.
- На телефоне заголовок/действие карточки переносятся, поле не обрезает ввод. Ant Design сохранён; frontend остаётся на установленном Redux Toolkit/Less.

Размер/время малой фикстуры находятся в машинном результате и не являются RTO на рабочем объёме. Тестовые TLS/Blitz не заменяют настоящий корпоративный вход.
