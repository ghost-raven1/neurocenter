# Упрощение привязки папки и жёсткий прогон — 19 октября 2026

Обычная привязка теперь состоит из выбора папки и кнопки «Связать папку». Явный выбор сразу запускает проверку мостом. Предустановленная текущая папка, открытие окна, heartbeat и восстановление связи заданий не создают. Перед подтверждением видны проект, компьютер, общая папка и выбранный подкаталог.

Stepper, отдельная галочка согласия и повторная таблица тех же сведений убраны. Редкие операции находятся в «Другие действия с папкой». Пункты совпадают с названиями в серверных отказах; финальные кнопки называют конкретное действие. Копирование и перенос файлов пользователь выполняет заранее: мастер проверяет подготовленную папку и её идентичность.

## Исправления и границы кода

- Состояние вынесено в feature-local `useWorkspaceBinding`; поздние ответы проверяют владельца, экран, проект, устройство и исходный запрос. Синхронная блокировка защищает быстрый повтор ещё до следующего React render.
- Повтор потерянного ACK проверки отправляет исходные данные с прежним requestKey и получает точный job ID. Чужие мутации и выбор общей папки остаются блокирующими; неизвестный job не присваивается по названию.
- Первый окончательный HTTP 400/403/409 освобождает выбор. Если прежде уже был потерян ответ, последующий 4xx сохраняет прежний ключ: отзыв прав до поиска квитанции не доказывает отсутствие старого commit. Оба случая воспроизведены отдельными регрессиями.
- Истечение 15 минут, изменение root/привязки и отказ bind требуют свежей проверки. Отменить можно только queued job; running/reconciling не объявляются остановленными закрытием окна.
- Каталог, карточка инструмента и начало работы передают канонический ID в `bind`. В начале работы проект выбирается перед папкой; старые ссылки с именем проекта принимаются через доступный объект. Общие переходы без выбранного проекта сохранены.

Backend, формат заданий и опубликованный мост **0.9.7** не менялись. Новый выпуск автономного пакета для этого изменения не нужен.

## Настоящий UI → gateway → PostgreSQL → release worker

Использован отдельный стенд `d533ad32` на loopback 127.0.0.1, собственные порты 18573–18580, контейнер/том PostgreSQL, storage и профиль. Запущены настоящие catalog, gateway, OAuth service, skills, RAG, feature flags, Socket.IO и Vite. Авторизация — отдельный synthetic dev/test администратор; настоящий Blitz этим не проверялся. Общий root заранее задан штатным `--projects-root` только во временном профиле, без готовых привязок. Системный picker в этом проходе не принимался.

## Автоматические проверки и оставшиеся ограничения

Финальный frontend: **1464/1464 теста в 132 файлах**, без пропусков; TypeScript, production build и `git diff --check` успешны. Независимый review проверил состояние, отмену и поздние ответы. Lost ACK, отзыв прав, A→B→A владельца/проекта/компьютера, несовпадающий preview, TTL и legacy покрыты управляемыми transport/lifecycle тестами; эти случаи не объявляются настоящими browser/IdP проверками. Legacy-bind с реальной старой установкой через UI здесь не выполнялся.

Lint недоступен: `eslint: command not found`; зависимости ради этого прохода не устанавливались. Сохраняются предупреждение Vite об общем чанке около 834 КБ и React/Ant Design 4 о defaultProps/findDOMNode. В процессе разработки были временные HMR-ошибки при записи файлов; после окончательной заморозки новых ошибок в просмотренных browser logs нет.

Снимки, короткая браузерная диагностика и receipts находятся локально в игнорируемых `output/playwright/workspace-binding-hard-2026-10-19/`, `.run/binding-ui-rig/d533ad32/receipts/`, `.run/binding-ui-rig/d533ad32/cleanup.json` и `.run/ui-final-validation-2026-10-19/`. В публичный Git не добавлены профили, сессии, тестовая БД или скриншоты.

Этот проход принимает локальный сценарий привязки на macOS ARM64 с указанным worker. Установки сторонних инструментов, настоящий Blitz, остальные native OS, целевой сервер и внешнее восстановление требуют отдельных свидетельств. Общие [P0-критерии](implementation-readiness.md) остаются открытыми.
