# Модели из OpenCode

В «Мои компьютеры → Подробнее → Модели OpenCode» главный администратор управляет автоматическим добавлением моделей с принадлежащего ему компьютера. Автодобавление включено по умолчанию; перенос API-ключей выключен. Нужен обновлённый мост с возможностью `opencode-model-sync-v2`. Общая конфигурация читается без проекта и привязанной папки. Для итоговой конфигурации проекта нужна действующая привязка папки.

Мост читает конфигурацию примерно раз в минуту, отправляет изменившиеся метаданные и повторно подтверждает неизменный снимок раз в десять минут. Он не запускает OpenCode, SDK или проверку модели. Новая модель появляется в общем каталоге с подготовленным подключением. Общий источник добавляет модель только в каталог. При первом появлении проектный источник назначает модель тому же связанному проекту. Повторные сканы сохраняют снятое вручную назначение. Проверка API остаётся явным действием администратора; до неё модель не используется в чате.

Читаются JSON/JSONC, глобальные и проектные конфиги, явные `OPENCODE_CONFIG`, `OPENCODE_CONFIG_DIR`, `OPENCODE_CONFIG_CONTENT`, `.opencode` и системные managed-файлы. В Git-проекте учитываются родительские конфиги до ближайшей Git-границы с порядком слоёв OpenCode. У негитовой папки чтение ограничено самой папкой. Организационные сетевые конфиги и macOS MDM preferences не загружаются; предупреждения снимка сохраняют эту границу видимой. Правила сверены с [официальной конфигурацией OpenCode](https://opencode.ai/docs/config/) и [ConfigPaths версии 1.14.48](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/config/paths.ts).

Для OpenAI-совместимых провайдеров сохраняются upstream `model.id`, адрес API, chat/vision capability, поддерживаемые числовые настройки и таймаут. `limit.context` каждой модели становится её контекстным окном; неизвестный размер не выдумывается. `limit.output` показывается отдельно как способность модели и не превращается автоматически в запрошенный бюджет ответа. `disabled_providers` сильнее `enabled_providers`. Неизвестные SDK options, пользовательские заголовки и неподдерживаемые провайдеры требуют ручной настройки.

Одна модель с одинаковыми provider, runtime, upstream ID, версией, capability, адресом API и каноническими числовыми параметрами получает одну карточку. Разные контекстные окна или параметры генерации создают отдельные подключения, сохраняя прежнюю карточку и историю. Перенос или ротация ключа и изменение таймаута не меняют идентичность. Её исходный компьютер, область конфигурации и alias могут обновлять автоматически созданное подключение. Другие источники привязываются к этой карточке, сохраняя существующее подключение. Ручное изменение карточки или подключения прекращает автоматическую перезапись. Архивная карточка автоматически не восстанавливается.

Удаление или отключение провайдера в корректном снимке меняет состояние источника. Существующие назначения, история и серверное подключение сохраняются: их отзыв или удаление остаются решением администратора. Ошибка чтения, повреждённый JSON, смена папки, неполный снимок и недоступный компьютер не удаляют прежние источники. Последний корректный снимок фиксируется отдельно для общей конфигурации компьютера и каждой проектной конфигурации, включая пустой список, поэтому запоздавший старый ответ не возвращает удалённые записи.

Ручное чтение в каталоге предлагает «Общая конфигурация компьютера» и «Итоговая конфигурация проекта». Вторая включает общие настройки и проектные переопределения в порядке OpenCode. Формат отчёта `schemaVersion:2` различает `scope:global` с ID компьютера и `scope:project` с ID проекта, binding и instance. Формат v1 не принимается новым действием; для старого моста интерфейс предлагает обновление.

## Перенос ключей

Только после отдельного разрешения мост разрешает literal API-ключи, точные `{env:NAME}` и `{file:path}` в `provider.options.apiKey`, а также `type: api` из `auth.json`. Относительный путь файла относится к конфигу, который объявил ключ. OAuth-токены, символические ссылки, составные подстановки и недоступные файлы автоматически не переносятся. Имена переменных и пути файлов не передаются в карточках.

Ключ идёт напрямую через аутентифицированный device-channel API Gateway. Для удалённого сервера требуется HTTPS; локальный HTTP разрешён только для разработки на loopback. Сервер повторно проверяет роль, владельца, привязку и ревизию согласия, затем сохраняет ключ существующим механизмом AES-256-GCM с привязкой к модели и ревизии. В браузер, device reports, задания, аудит и Git ключ не попадает. Перенос не заменяет вручную настроенные серверные credentials. Нужен `NEUROCENTER_MODEL_CREDENTIAL_KEY` на сервере.

Выключение переноса прекращает будущие передачи. Оно не отзывает уже сохранённые ключи; для этого используется действие отзыва подключения модели. Если локальный ключ исчез, прежний серверный ключ автоматически не стирается. Отзыв согласия во время чтения блокирует принятие снимка с прежней ревизией настройки.

## Проверка

Сохранившиеся проверки моста: `mcp/neurocenter-asset-sync/integration/test/opencode-model-scan.test.ts`, `opencode-model-sync.test.ts` и `worker-heartbeat.test.ts`. Их запускают через `npm --prefix mcp/neurocenter-asset-sync test -- <имя-файла>`.

HTTP/SQL-сценарий `scripts/test/opencode-model-sync-http.test.mjs` использует `OPENCODE_MODEL_SYNC_TEST_PG_URL`. PostgreSQL должен иметь отдельный loopback-порт, отличный от 5432; тест создаёт и удаляет собственную базу.

Прежние `services/catalog-service/test/opencode-model-sync.test.ts` и frontend-наборы удалены при рефакторинге тестов. Они не входят в текущий запуск и не подтверждают нынешнее покрытие. Новые unit-тесты размещаются по [общему соглашению](service-eslint.md).
