# Локальная модель эмбеддингов

Нейроцентр запускает отдельный проектный Ollama с моделью `qwen3-embedding:4b`. Веса, служебные файлы и ключи этого экземпляра находятся в `data/embedding/`. Глобальный Ollama и его модели не используются. Первый запуск скачивает образ и примерно 2,5 ГБ весов; последующие запуски используют сохранённые файлы.

## Запуск и проверка

Из корня репозитория, при работающем Docker с Compose v2 и Node.js 24+:

Если Compose ещё не установлен, выполните `npm run compose:install` или общий `scripts/dev.sh install`. [Порядок установки](compose-install.md).

```sh
npm run embedding:up
npm run embedding:status
npm run embedding:check
```

`up` поднимает отдельный Compose-проект, загружает закреплённую модель, проверяет SHA файлов и выполняет настоящий запрос эмбеддингов. Успех означает, что модель вернула корректные векторы размерности 2560. При сетевой ошибке повторите ту же команду: сохранённые веса используются повторно. Несовпадение закреплённых байтов останавливает подготовку; другая модель автоматически не подставляется.

`status` показывает состояние и время последней успешной пробы без скачивания модели и без запуска inference. `check` проверяет готовность подключения настоящим запросом. Здоровый контейнер сам по себе ещё не подтверждает готовность модели: Compose healthcheck проверяет доступность Ollama, а загрузка весов и запрос эмбеддингов проверяются отдельно.

Справка доступна через `npm run embedding:up -- --help`, в том числе при неверной конфигурации. Дополнительные неизвестные аргументы отклоняются до действий. Повреждённая квитанция готовности даёт `unchecked` и причину в `verificationIssue`; ссылка и специальный файл не читаются. [Повторный аудит и границы](model-runtime-refactor-2026-10-19.md).

Остановка сохраняет данные:

```sh
npm run embedding:down
```

Модель запускается независимо от `scripts/dev.sh up` и основного production-стека. Для работы приложения и локальной модели на одной машине запустите оба стека. Остановка приложения не удаляет веса. Каталог `data/` исключён из Git; веса не нужно добавлять в репозиторий или архив исходников.

[Обработка изображений](local-vision.md) использует этот же Ollama, порт и каталог весов. В памяти загружается одна модель; переключение между vision и эмбеддингами может добавить задержку. `embedding:down` и `vision:down` останавливают общий контейнер для обеих моделей, сохраняя данные.

## Подключение OpenCodeRAG

Для автоматической индексации установите через мост **«OpenCodeRAG (плагин)»** и перезапустите OpenCode в связанной папке. Отсутствующие параметры плагин заполняет приведённой ниже локальной моделью и включённой автоматической индексацией; явно заданные параметры, включая отключённую автоиндексацию, сохраняет. Файл конфигурации не переписывается. Вкладка «База знаний» содержит ссылки на установку и настройку.

Отдельная карточка **«OpenCodeRAG» с типом MCP** использует явный `index_project`. Для неё откройте «Настроить MCP»: кнопка «Локальная модель проекта» заполняет следующие поля; старые версии моста позволяют ввести их вручную:

| Поле | Значение |
| --- | --- |
| Протокол | `ollama` |
| URL | `http://127.0.0.1:11435/api` |
| Модель | `qwen3-embedding:4b` |
| API-ключ | Не требуется для этого локального экземпляра |

Для других клиентов с OpenAI-совместимым протоколом доступен `http://127.0.0.1:11435/v1`, модель та же. На CPU используйте таймаут не менее 120 секунд и один запрос одновременно. В мастере OpenCodeRAG выбирайте профиль Ollama из таблицы.

Суффикс `/api` нужен провайдеру Ollama в OpenCodeRAG: он добавляет к нему `/embed`. Этот адрес работает, когда мост и модель запущены на одном компьютере. `127.0.0.1` на другом компьютере указывает на тот другой компьютер. API намеренно доступен только через loopback; адрес не является общим серверным подключением для всей команды.

После сохранения настройки перезапустите OpenCode и проверьте `search_semantic`. Для MCP-адаптера сначала вызовите `index_project` и дождитесь завершения; установка MCP и запуск модели сами не индексируют проект. У нативного плагина автоматическая индексация учитывает настройки проекта. Ограниченная проверка запуска в каталоге подтверждает загрузку инструмента; готовность базы знаний требует успешной индексации и полного подтверждённого снимка на сервере. [Полная инструкция OpenCodeRAG](../frontend/src/modules/Start/docs/OPENCODE-RAG.md).

В поставке OpenCodeRAG `2.4.4-mcp.pack.4` локальный профиль `ollama` + `qwen3-embedding:4b` + loopback-порт `11435` использует один embedding-пакет из одного фрагмента и таймаут 120 секунд. Это ограничивает нагрузку CPU; параметры применяются в памяти и не переписывают конфигурацию проекта. Установки предыдущей поставки требуют обновления инструмента.

Размерность соответствует стандартному `RAG_DIM=2560`. Совпадение размерности не делает разные модели совместимыми. Существующий индекс другой модели нужно сохранить и подготовить новый отдельно; менять модель внутри готового индекса нельзя.

## Изоляция и воспроизводимость

Конфигурация находится в [compose.embedding.yml](../compose.embedding.yml), модель и образ закреплены в [model.lock.json](../scripts/embedding/model.lock.json). Проверяется состав манифеста и SHA весов; изменившийся upstream-тег требует осознанного обновления закреплённой версии. Пользовательский `~/.ollama` не монтируется, системные настройки и порт глобального Ollama не меняются.

Первое скачивание требует доступа к Docker Hub и реестру моделей Ollama. После загрузки обработка текстов идёт локально; облачные функции экземпляра отключены. Для переноса подготовленного окружения сохраняйте весь `data/embedding/` и тот же закреплённый образ; после переноса повторите `embedding:check`.

Первичная подготовка проверяет свободное место с запасом для образа, распаковки и весов: около 13 ГиБ, либо около 5 ГиБ при уже загруженном образе. Это проверка файловой системы хоста; свободное место внутри Docker Desktop контролируется отдельно.

Docker ограничен 5 ГиБ RAM и четырьмя CPU; параллельно обрабатывается один запрос модели. На macOS контейнер использует CPU: Docker Desktop не передаёт Apple GPU этому runtime. Скорость зависит от компьютера и размера текста. При нехватке памяти уменьшите нагрузку и повторите проверку; меньшая модель автоматически не выбирается.

Официальные источники: [Qwen3-Embedding-4B и размерность](https://huggingface.co/Qwen/Qwen3-Embedding-4B), [Docker Ollama](https://docs.ollama.com/docker), [хранение моделей и локальный режим](https://docs.ollama.com/faq), [Ollama 0.35.1](https://github.com/ollama/ollama/releases/tag/v0.35.1).

## Локальная проверка 19 октября 2026

Проверено на macOS ARM64: Ollama 0.35.1 в отдельном Linux ARM64-контейнере, настоящий Qwen3 Embedding 4B и native LanceDB 0.29.0.

- 53 проверки запуска, HTTP-границ, блокировок, принадлежности контейнера и профиля адаптера прошли.
- 570 тестов моста прошли; 11 проверок других нативных окружений и внешних fixtures пропущены. TypeScript и изолированная сборка моста прошли.
- 14 браузерных проверок мастера прошли, включая явное сохранение, сохранность ключа и ширину 390 px.
- 9 настоящих MCP/RAG-сценариев прошли: индексация, русский и английский поиск, повтор, HTTP 503, восстановление и отказ несовместимой размерности без изменения индекса. В финальном проходе все 11 запросов к модели завершились HTTP 200, без таймаутов.
- Native `/api/embed` и OpenAI-совместимый `/v1/embeddings` вернули конечные ненулевые векторы размерности 2560.
- Остановка и повторный запуск сохранили веса побайтно и не скачивали их повторно. Список моделей и ключи глобального Ollama остались прежними.

Это локальная приёмка. Нативная проверка других ОС и промышленный запуск отдельного runtime требуют собственных стендов. Пакеты предыдущей поставки и установленный глобальный мост этой проверкой не обновлялись.
