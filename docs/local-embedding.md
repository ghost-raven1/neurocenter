# Локальная модель эмбеддингов

Веб-каталог содержит вкладку «Модели»: главный администратор может запустить и проверить хостинг, а администратор проекта — добавить модель в проект. Веса и runtime общие для команды, назначение не меняет существующий индекс. [API, права и границы](current-implementation.md#каталог-моделей-и-хостинг).

Нейроцентр запускает отдельный проектный Ollama с моделью `qwen3-embedding:4b`. Веса встроенных embedding- и vision-моделей входят в поставку: **9 файлов, 4 427 274 223 байта**, в `data/embedding/models/`. Служебные файлы и ключи этого экземпляра остаются в `data/embedding/` отдельно от поставки. Глобальный Ollama и его модели не используются.

## Веса в поставке проекта

`scripts/dev.sh up` автоматически подготавливает обе модели до остановки прежних сервисов. В Git находятся [опись с SHA-256](../scripts/models/bundle-release.json), lock-файлы и лицензии; бинарные части закреплены в [release `models-2026-10-19.1`](https://github.com/ghost-raven1/neurocenter/releases/tag/models-2026-10-19.1). При первом запуске части скачиваются, проверяются и собираются в настоящие файлы весов. Другая модель при отказе не подставляется. В production ту же подготовку выполняет `model-volume-init` в томе `model-weights` перед запуском runtime.

На шаге «Запуск хостинга моделей» видны отдельные стадии SHA-проверки, подготовки частей, сборки и активации: процент считается по фактическим байтам текущей стадии. Проверка уже размещённого комплекта тоже показывает прогресс. При ожидании дочерней команды общий запуск сообщает прошедшее время каждые 10 секунд. Подготовка весов ограничена двумя часами, запуск Docker — десятью минутами; после таймаута процесс получает SIGTERM, а через секунду — SIGKILL, если ещё работает. Прерывание через Ctrl+C завершает только процессы этой подготовки и сохраняет прежние сервисы. Повтор использует проверенные части в кеше. При отказе Docker остальные сервисы продолжают запуск; причина и путь к отдельному закрытому логу `.run/model-hosting/*.log` выводятся в терминал. Сбой подготовки самих весов останавливает общий запуск до замены прежнего стека.

Подготовить только файлы или проверить уже размещённый комплект:

```sh
npm run models:prepare
npm run models:verify
```

`models:prepare` не запускает inference; `models:verify` не скачивает файлы. При полном комплекте подготовка не обращается за весами в сеть. Для переноса сохраните весь `data/embedding/models/` в таком же пути нового checkout и выполните `models:verify`; пользовательские ключи Ollama и служебные квитанции переносить вместе с весами не требуется. Закреплённый Docker-образ нужен отдельно. Сам `git pull` обновляет опись и код; недостающие веса размещает следующий штатный запуск.

## Отдельный запуск и проверка

Из корня репозитория, при работающем Docker с Compose v2 и Node.js 24+:

Если Compose ещё не установлен, выполните `npm run compose:install` или общий `scripts/dev.sh install`. [Порядок установки](compose-install.md).

```sh
npm run embedding:up
npm run embedding:status
npm run embedding:check
```

Standalone `embedding:up` сохраняет прежнее поведение: поднимает отдельный Compose-проект, при необходимости получает выбранную модель из реестра Ollama, проверяет SHA файлов и выполняет настоящий запрос эмбеддингов. Эта команда не вызывает bundle-подготовку обеих моделей; если комплект уже размещён через `models:prepare` или общий запуск, используются его файлы. Успех означает, что модель вернула корректные векторы размерности 2560. При сетевой ошибке повторите ту же команду: сохранённые веса используются повторно. Несовпадение закреплённых байтов останавливает подготовку; другая модель автоматически не подставляется.

`status` показывает состояние и время последней успешной пробы без скачивания модели и без запуска inference. `check` проверяет готовность подключения настоящим запросом. Здоровый контейнер сам по себе ещё не подтверждает готовность модели: Compose healthcheck проверяет доступность Ollama, а загрузка весов и запрос эмбеддингов проверяются отдельно.

Справка доступна через `npm run embedding:up -- --help`, в том числе при неверной конфигурации. Дополнительные неизвестные аргументы отклоняются до действий. Повреждённая квитанция готовности даёт `unchecked` и причину в `verificationIssue`; ссылка и специальный файл не читаются. [Повторный аудит и границы](model-runtime-refactor-2026-10-19.md).

Остановка сохраняет данные:

```sh
npm run embedding:down
```

Отдельный CLI позволяет работать с моделью без запуска приложения. Обычный `scripts/dev.sh up` уже поднимает этот же проектный runtime; второй контейнер не требуется. Production использует свой внутренний `model-runtime`. Остановка приложения не удаляет веса. Каталог `data/` исключён из Git; бинарники поставляются закреплённым release, а не добавляются в историю исходников.

[Обработка изображений](local-vision.md) использует этот же Ollama, порт и каталог весов. В памяти загружается одна модель; переключение между vision и эмбеддингами может добавить задержку. `embedding:down` и `vision:down` останавливают общий контейнер для обеих моделей, сохраняя данные.

## Подключение OpenCodeRAG

Для автоматической индексации установите через мост **«OpenCodeRAG (плагин)»** и перезапустите OpenCode в связанной папке. Отсутствующие параметры плагин заполняет приведённой ниже локальной моделью и включённой автоматической индексацией; явно заданные параметры, включая отключённую автоиндексацию, сохраняет. Файл конфигурации не переписывается. Вкладка «База знаний» содержит ссылки на установку и настройку.

Отдельная карточка **«OpenCodeRAG» с типом MCP** использует явный `index_project`. Для неё откройте «Настроить MCP»: кнопка «Локальная модель проекта» заполняет следующие поля; старые версии моста позволяют ввести их вручную:

| Поле | Значение |
| --- | --- |
| Протокол | `ollama` |
| URL | `http://127.0.0.1:11435/api` |
| Модель | `qwen3-embedding:4b` |
| API-ключ | Не требуется для этого локального экземпляра |

Для других клиентов с OpenAI-совместимым протоколом доступен `http://127.0.0.1:11435/v1`, модель та же. На CPU используйте таймаут не менее 120 секунд и один запрос одновременно. В мастере OpenCodeRAG выбирайте профиль Ollama из таблицы.

Суффикс `/api` нужен провайдеру Ollama в OpenCodeRAG: он добавляет к нему `/embed`. Этот адрес работает, когда мост и модель запущены на одном компьютере. `127.0.0.1` на другом компьютере указывает на тот другой компьютер. API намеренно доступен только через loopback; адрес не является общим серверным подключением для всей команды.

После сохранения настройки перезапустите OpenCode и проверьте `search_semantic`. Для MCP-адаптера сначала вызовите `index_project` и дождитесь завершения; установка MCP и запуск модели сами не индексируют проект. У нативного плагина автоматическая индексация учитывает настройки проекта. Ограниченная проверка запуска в каталоге подтверждает загрузку инструмента; готовность базы знаний требует успешной индексации и полного подтверждённого снимка на сервере. [Полная инструкция OpenCodeRAG](../frontend/src/modules/Start/docs/OPENCODE-RAG.md).

В поставке OpenCodeRAG `2.4.4-mcp.pack.4` локальный профиль `ollama` + `qwen3-embedding:4b` + loopback-порт `11435` использует один embedding-пакет из одного фрагмента и таймаут 120 секунд. Это ограничивает нагрузку CPU; параметры применяются в памяти и не переписывают конфигурацию проекта. Установки предыдущей поставки требуют обновления инструмента.

Размерность соответствует стандартному `RAG_DIM=2560`. Совпадение размерности не делает разные модели совместимыми. Существующий индекс другой модели нужно сохранить и подготовить новый отдельно; менять модель внутри готового индекса нельзя.

## Изоляция и воспроизводимость

Конфигурация находится в [compose.embedding.yml](../compose.embedding.yml), модель и образ закреплены в [model.lock.json](../scripts/embedding/model.lock.json). Опись поставки сверяется с обоими lock-файлами; проверяются SHA частей и итоговых файлов. Существующие финальные файлы не перезаписываются, теги публикуются после подготовки всех blobs. Пользовательский `~/.ollama` не монтируется, системные настройки и порт глобального Ollama не меняются. [Лицензия Apache 2.0](../scripts/models/LICENSE-APACHE-2.0.txt) и [источники моделей](../scripts/models/THIRD-PARTY-NOTICES.txt) входят в поставку.

Первая подготовка через `models:prepare` или штатный запуск требует GitHub Releases; при отсутствии образа нужен также Docker Hub. Standalone `embedding:up` при отсутствии весов использует реестр Ollama. После подготовки обработка текстов идёт локально; облачные функции экземпляра отключены. После переноса файлов и образа повторите `models:verify` и `embedding:check`.

Поставка обеих моделей проверяет свободное место для сохранения частей и сборки полных blobs с резервом 1 ГиБ. Дополнительно нужно место для Docker-образа; объём скачивания весов — около 4,43 ГБ. Старый standalone `embedding:up` сохраняет собственную проверку места для одного профиля и образа. Свободное место внутри Docker Desktop контролируется отдельно.

Воспроизводимые встроенные веса не включены в полный резервный комплект площадки: после восстановления они готовятся из того же release. Пользовательские модели вне описи требуют отдельной копии весов и сведений об источнике; их наличие в каталоге PostgreSQL не заменяет файлы. [Восстановление](production-recovery.md).

Docker ограничен 5 ГиБ RAM и четырьмя CPU; параллельно обрабатывается один запрос модели. На macOS контейнер использует CPU: Docker Desktop не передаёт Apple GPU этому runtime. Скорость зависит от компьютера и размера текста. При нехватке памяти уменьшите нагрузку и повторите проверку; меньшая модель автоматически не выбирается.

Официальные источники: [Qwen3-Embedding-4B и размерность](https://huggingface.co/Qwen/Qwen3-Embedding-4B), [Docker Ollama](https://docs.ollama.com/docker), [хранение моделей и локальный режим](https://docs.ollama.com/faq), [Ollama 0.35.1](https://github.com/ollama/ollama/releases/tag/v0.35.1).

## Локальная проверка 19 октября 2026

Исправление отображения подготовки и зависшего ожидания проверено отдельно: 181 тест запуска, отмены, таймаутов, поставки весов, CLI и runtime прошёл без пропусков. Проверка существующих 9 файлов (4 427 274 223 байта) заняла 3,8 секунды; первый статус появился через 68 мс. Docker и рабочие сервисы для этой проверки не перезапускались. Зависание и отказ Docker воспроизводились в изолированных дочерних процессах; удалённый сервер этим проходом не проверялся.

Для новой поставки отдельно подтверждены холодный импорт всех 9 файлов из release-частей в пустой каталог, итоговые SHA и повтор без сетевых запросов. Новый контейнер из перенесённого комплекта с `--network none` вернул два ненулевых вектора по 2560 измерений; vision-проверка того же комплекта тоже прошла. Все 117 проверок подготовки, запуска и production-интеграции прошли без пропусков. Это локальная приёмка; production не разворачивался. Приведённая ниже приёмка относится к прежнему standalone-сценарию.

Проверено на macOS ARM64: Ollama 0.35.1 в отдельном Linux ARM64-контейнере, настоящий Qwen3 Embedding 4B и native LanceDB 0.29.0.

- 53 проверки запуска, HTTP-границ, блокировок, принадлежности контейнера и профиля адаптера прошли.
- 570 тестов моста прошли; 11 проверок других нативных окружений и внешних fixtures пропущены. TypeScript и изолированная сборка моста прошли.
- 14 браузерных проверок мастера прошли, включая явное сохранение, сохранность ключа и ширину 390 px.
- 9 настоящих MCP/RAG-сценариев прошли: индексация, русский и английский поиск, повтор, HTTP 503, восстановление и отказ несовместимой размерности без изменения индекса. В финальном проходе все 11 запросов к модели завершились HTTP 200, без таймаутов.
- Native `/api/embed` и OpenAI-совместимый `/v1/embeddings` вернули конечные ненулевые векторы размерности 2560.
- Остановка и повторный запуск сохранили веса побайтно и не скачивали их повторно. Список моделей и ключи глобального Ollama остались прежними.

Это локальная приёмка. Нативная проверка других ОС и промышленный запуск отдельного runtime требуют собственных стендов. Пакеты предыдущей поставки и установленный глобальный мост этой проверкой не обновлялись.
