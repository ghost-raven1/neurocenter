# Транзакции, допуск вызовов и подтверждения в браузере

Продолжение [аудита ранних возможностей](earlier-features-audit-2026-10-22.md) на исходной точке `a26c788`. Проверены выбранные границы заданий компьютерам, обучения, вызовов моделей, исследовательского MCP и трёх браузерных хранилищ подтверждений. Это приёмка перечисленных сценариев, а не всех функций проекта.

## Подтверждённые проблемы

| Область | Воспроизведение | Исправление |
| --- | --- | --- |
| Подтверждение задания компьютера | После выполненного SQL терялся ACK журнала или COMMIT не доходил до сервера; неудачный ROLLBACK оставлял транзакцию в пуле. Следующий заёмщик фиксировал прежний результат вместе с журналом | При неподтверждённом откате `completeDeviceJob` уничтожает соединение; исходная ошибка сохраняется. Успешный откат сохраняет обычное повторное использование сессии |
| Выдача задания | Та же неисправность при `queued → running` позволяла следующему запросу зафиксировать чужую выдачу и lease; ошибка отката заменяла исходную | `DeviceJobs.claim` уничтожает неопределённую сессию и сохраняет первоначальную ошибку |
| Обучение | Шесть владельцев транзакций возвращали сессии после неподтверждённого отката. Несвязанный следующий read мог зафиксировать опыт, enqueue или переход восстановления; read/current также оставляли lifecycle locks | Feature-local helper используется в `read`, `mutation`, `enqueue`, `current`, `recoverExpired`, `reconcile`. Он разрешает повторное использование только после подтверждённого ROLLBACK; прежняя обработка unique violation сохранена |
| Платный вызов модели | Проверка флагов проходила до ожидания `usage.begin`. Выключение возможности во время этого ожидания не предотвращало новый запрос провайдеру | Допуск повторяется после ожидания durable reservation, непосредственно в callback до dispatch. Полученный платный ответ сохраняется при последующем выключении флага; ошибка terminal writeback повторяет только запись учёта |
| Внешний исследовательский MCP | Во время последней асинхронной проверки флагов отзывалось назначение MCP, доступ пользователя либо отменялся turn. Запрос успевал уйти инструменту до последующего отказа | После этого ожидания повторяется `active()`: abort, актуальные права, назначение, состояние turn/recipient/lease. Проверенные сценарии не отправляют запрос и не расходуют external-call budget |

Транзакционные воспроизведения используют настоящий PostgreSQL, независимого наблюдателя и пул с одним соединением. Fault injection заменяет конкретный ACK или неотправленный ROLLBACK; следующий настоящий BEGIN/COMMIT доказывает прежний побочный эффект. Отдельно проверены здоровое повторное использование, уже завершённый COMMIT с потерянным ACK, exact replay, журнал и lease. SQL не заменён таблицей ответов.

Новые тесты допуска моделей/MCP используют настоящие orchestration classes с контролируемыми ledger methods, провайдерами и флагами. Это причинная проверка порядка вызовов, а не доказательство SQL-durability или распределённой атомарности всех сервисов. Последующие SQL-регрессии проверяют мигрированную схему, usage ledger, историю и исследовательские receipts; внешние провайдеры/MCP остаются fixtures.

Положительные наборы выше без failed/skipped/todo/cancelled. Файлы проверены по фактической квитанции до collection и итоговым результатам. Без QA URL новые два device SQL-файла видимо дают 0 выполненных и 11 skipped; это не положительный прогон.

У 17 новых unit есть фактический before-collection inventory; окончательные SHA наблюдались после прогона. Заморозка production и равенство SHA до/после подтверждены последними 31 SQL-регрессией. Это ограничение unit-provenance не скрывается за полной файловой квитанцией.

В selected fixtures исправлены устаревшие migration/version и feature-response ожидания; отрицательные проверки флагов и SQL/assertions не ослаблены. Строгие URL guards требуют `postgres/postgresql`, loopback-адрес, явный порт кроме 5432, `/postgres`, отсутствие query/hash. Learning/device допускают только `127.0.0.1`; research/usage также допускают `localhost` и `[::1]`. Отдельная проверка 24 решений двух actual before-Pool фрагментов research/usage не выполняет сеть и не прибавляется к Vitest-кейсам.

Общий owned-PG runner теперь передаёт `LEARNING_TEST_ADMIN_PG_URL`: без этого новый набор из десяти SQL-кейсов оставался бы skipped в полном профиле. Дополнительный smoke использует настоящий `startOwnedPg`, его environment и все десять кейсов без пропусков; это повтор входящих в 54 сценариев, а не ещё десять уникальных тестов. Он не является полным owned-PG/S3-прогоном.

Исходные RED сохранены: реальные дефекты, прежние fixture/version отказы, асинхронное закрытие уничтожаемой SQL-сессии и ошибка е/ё в новом assertion повреждённой записи. Окончательные прогоны выполнены после исправлений; предыдущие файлы отчётов не переписаны. Последний frontend-набор — `frontend/final-v2`, chat SQL — `chat/pg-regression-frozen`, learning — `learning/regression-frozen`.

## Сборка, остаток и свидетельства

Production TypeScript Catalog и строгие проверки затронутых тестов проходят. Catalog собран в отдельный каталог без incremental cache; проверены exports семи изменённых модулей, SHA production до/после совпали. Активный `dist` не заменялся. Frontend production не менялся, новый тест проверен строгим TypeScript.

Все собственные UUID-базы удалены обычным DROP, тестовые соединения и отдельный browser fixture server закрыты. Основные PG5432/S319010, ключи, release pins и рабочие файлы пользователя не использовались для тестовых мутаций. Шесть основных HTTP readiness ответили успешно; реестр процессов сохранился. Это состояние прежнего работающего runtime, а не применение новых исправлений.

Полный workspace/unit-safe/owned-PG повтор, остальные transaction owners, агентские испытания целиком, полная UI-матрица, настоящий IdP/OpenCode/provider, Ceph, cross-host DR, CI и production этим проходом не приняты. При текущей нагрузке на swap выполнялись ограниченные последовательные SQL-наборы. B01–B06 остаются открытыми. Новые изменения прошли авторское, root и независимое перекрёстное ревью; коммиты разделены по областям.

Локальные raw RED/GREEN, exact hashes, collection inventories, AST-карты, browser receipt и cleanup: `.run/functional-audit-next-20261022/{devices,learning,chat,frontend,tooling,candidate}/`. Эти evidence-файлы не включены в публичный Git. [Методика покрытия](coverage.md) · [Флаги](feature-flags-coverage-plan.md) · [Бэклог](backlog-2026-10-22.md).
