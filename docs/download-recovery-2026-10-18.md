# Загрузка готовых комплектов и восстановление подготовки — 18 октября 2026

Исправлены два связанных отказа: авария worker при скачивании архива и отсутствие сохранённого результата, если процесс завершился до файловой транзакции установки. Это свидетельства исходников и изолированных тестов; приёмка выпущенного моста 0.9.3 добавляется отдельно.

## Причина аварии

Выпущенный worker завершился на `Parser.finish` → `onHttpSocketEnd` с `assert(!this.paused)`. Проверенный Node **24.22.0** содержит **undici 7.29.1**. Стек совпадает с известной ошибкой: HTTP/1 parser приостанавливается из-за backpressure, затем закрытие сокета вызывает неперехватываемый assertion. Обычный `try/catch` вокруг `fetch` не защищает процесс. [Upstream issue #5360](https://github.com/nodejs/undici/issues/5360).

Полное исправление вошло в undici 8.6.0; перенос в ветку 7.x на момент проверки остаётся открытым. Поэтому повторная упаковка с тем же Node сама по себе недостаточна. [Исправление #5474](https://github.com/nodejs/undici/pull/5474), [релиз 8.6.0](https://github.com/nodejs/undici/releases/tag/v8.6.0), [backport #5553](https://github.com/nodejs/undici/pull/5553). Медленное чтение архива и закрытие соединения через Vite соответствуют этому механизму, но Vite не доказан как единственный возможный источник FIN.

## Новый контракт

- Только бинарные готовые комплекты загружаются через `node:http` / `node:https`. Запрос идёт на точный job-маршрут доверенной площадки с Bearer и исходными job/lease; device сверяется с локальным подключением. Перенаправления запрещены, допустим только HTTP 200 с точным `Content-Length`. Ограничены ожидание запроса и чтение тела.
- Поток передаётся прежнему кэшу: ограничения числа байтов, SHA, распаковки и публикации проверенного каталога сохранены. Новых зависимостей и замены Node нет. Остальные JSON-запросы этим изменением не переводились на другой транспорт.
- Перед сетевой подготовкой install/repair сохраняется атомарный intent с правами 0600: PID, job, lease, device и исходная идентичность результата. Значения настроек и содержимое проекта в него не копируются.
- Начало обработки очереди выполняет `recoverFileJobs` → `recoverRuntimePreparations` → `deliverCompletions`. Для завершившегося процесса сохраняется durable `failed` / `unchanged:true`, затем удаляется intent. Уже восстановленная файловая квитанция имеет приоритет. Живой PID, другое устройство, повреждённая аренда или ссылка вместо каталога не разрешают ложное завершение.
- Успешная подготовка удаляет intent перед передачей управления installer/repair. Повторяется доставка результата, **автоматического повторного выполнения установки нет**.

## Проверка

**66/66** targeted Vitest: 9 проверок транспорта, 9 подготовки/восстановления и 48 существующих проверок кэша. TypeScript исходников проходит. [Машинный отчёт тестов](../output/playwright/neurocenter-add-methods/runtime/download-recovery-tests.json), [контракт и SHA исходников](../output/playwright/neurocenter-add-methods/runtime/download-recovery-fix.json).

Настоящий TCP-сервер отправляет 512 КиБ и FIN до чтения тела; задержанное чтение и медленный Writable сохраняют все байты без вызова `fetch`. Проверены redirect, HTTP-ошибки, неверный размер, усечённый ответ, сетевой отказ и таймауты заголовков/тела. Интеграционный HTTP→cache тест подтверждает наличие intent **до GET** и последующую проверку SHA.

Отдельный Node subprocess сохраняет intent и останавливается SIGKILL во время подготовки. Восстановление доставляет один отказ без повторного выполнения, повторное восстановление ничего не добавляет. Второй случай сохраняет уже существующий успешный результат.

Старое QA-задание остановилось на 5% ещё до появления нового intent. После проверки отсутствия установки, config entry, receipt и pending-журнала оно завершено через аутентифицированный device completion с `unchanged:true`, без прямой записи в БД. [Квитанция сверки](../output/playwright/neurocenter-add-methods/bridge/download-reconciliation.json).

## Границы

Intent защищает фазу скачивания и подготовки кэша. Окно между его успешным удалением и созданием прежнего installer-журнала остаётся вне этого изменения. Полная транзакция записи проекта здесь не перерабатывалась.

Исправление не добавляет supervisor или автоматический перезапуск worker. Текущий `connect.ts` запускает detached `--worker`; последующий запуск MCP или повторное подключение может запустить worker заново. Описанные проверки не подтверждают LaunchAgent/KeepAlive, живой цикл обновления 0.9.3 или нативную приёмку остальных ОС.
