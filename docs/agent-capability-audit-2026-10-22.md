# Проверка возможностей агентов — 22 октября 2026

Область: шаблон в каталоге → проектное переопределение → доставка в OpenCode → групповой чат → обучение и использование моделей. Это проверка текущих исходников и перечисленных локальных регрессий; она не подтверждает готовность рабочего сервера, всех native-платформ или произвольного внешнего провайдера.

## Подтверждённые исправления

| Проблема | Текущее поведение и доказательство |
| --- | --- |
| Модель каталога могла попасть в OpenCode без доказуемого соответствия native-провайдеру | `agent-model-requirements.ts`, `agent-job-compiler.ts` и bridge `features/project-agents/model-compiler.ts` закрепляют доступную модель проекта, pin и безопасное соответствие `provider/configKey`. Несовпадение даёт `OPENCODE_AGENT_MODEL_SETUP_REQUIRED`; старые файлы сохраняются. Доставка v2 не читает ключи и не подтверждает inference. Существующие PostgreSQL, HTTP и native-срезы перечислены в `agents-opencode-2026-10-21.md`. |
| Worker обучения мог вызвать модель при отключённом `model_hosting` | `learning-analysis.service.ts` проверяет `project_learning` и `model_hosting` перед enqueue и перед inference. `ModelRuntime` повторяет проверку как последняя граница реального вызова. Регрессии проверяют off/revoke/retry; уже оплаченный ответ не отбрасывается только из-за последующего выключения флага. |
| Отключение агента при выключенной функции блокировалось из-за неверного списка полей recovery | `AgentsService.configure` разрешает только точное выключение `{enabled:false,expectedRevision,requestKey}`. Активная настройка продолжает требовать флаг; произвольное `enabled:false` не освобождает клиентский payload от серверной проверки. |
| Исследование могло начать подготовку RAG или очередное сжатие после выключения `research_tools` | Исполнение проверяет флаг до подготовки контекста; требование передаётся через `withModelUsage` в подготовку и каждое сжатие. Новые planner/tool/final вызовы имеют свежую проверку. Сохранение уже оплаченного результата проверяет права, pin и источники, без повторного флага. |
| Проверка исследования могла повторно занять собственный пул внутри транзакции | `current(db)` использует переданный transaction для закреплённого MCP; отдельная проверка pending выполняется вне `owned`. Регрессия с пулом из одного соединения завершает внешний раунд. |
| Предыдущие попытки исследования хранились, но их нельзя было перечислить | Добавлена приватная пагинация всех попыток по сообщению. Список содержит только метаданные; полный результат доступен отдельным GET под текущим owner/project/model ACL. PostgreSQL проверяет курсор другого диалога, удалённое сообщение и одинаковые timestamps без пропусков и дублей. |

## Подтверждённые ограничения

| Область | Что уже есть | Оставшийся пробел |
| --- | --- | --- |
| Одобренное знание | `LearningRepository.context` формирует только одобренные активные записи; bridge предоставляет явный MCP `projectLearningContext` | В `chat-group.ts`/`chat-round.ts` нет автоматического включения этого контекста в запрос проектного агента. Наличие принятого знания ещё не означает, что агент его получил. |
| Контекст локальной модели | Удалённое подключение имеет собственные параметры; групповой чат рассчитывает бюджет каждого участника | Для управляемого локального Ollama `ModelChatService.settings` использует общую операционную настройку `MODEL_CHAT_CONTEXT_WINDOW_TOKENS`, передаваемую также как `num_ctx`. Отдельной административной настройки для каждой локальной модели пока нет. Неизвестное окно внешней модели остаётся неизвестным. |
| Промпт и восстановление | Неизменяемые версии, exact project pin, сохранённые overrides и CAS; редактор показывает актуальный текст при конфликте | Нет отдельного полного просмотра различий версий и управляемого отката промпта с предварительным сравнением. Повторное сохранение текста создаёт новую версию, но не заменяет этот процесс. |
| Готовность агента | Квитанция моста подтверждает согласованные файлы и ревизию; native-проверка умеет прочитать установленную конфигурацию | Нет отдельного проверочного задания, которое подтвердит реальную доступность модели, применённый промпт и разрешённые инструменты конкретного агента. Статус `configured` не является таким испытанием. |
| Учёт внешнего OpenCode | Центральный ledger учитывает реальные вызовы через `ModelRuntime`, включая agent/compaction/research | Внешний OpenCode может вызывать своего провайдера напрямую. Collector сохраняет только ограниченные счётчики инструментов, без токенов и содержимого. Эти вызовы не представлены как измеренное потребление центрального ledger. |

## Границы исследования и группового исполнения

Пользователь явно выбирает источники; snapshot согласия неизменяем при retry. Обычное сообщение получает один ответ каждого адресованного агента; `targetAgentIds` ограничивает получателей. Межагентного бесконечного цикла нет. Каждому получателю доступны до шести шагов исследования; внешних вызовов не больше шестнадцати за раунд, общий срок исполнения ограничен пятнадцатью минутами. Окна моделей проверяются отдельно, с фактическими проектными overrides.

Результаты инструментов передаются как недоверенные данные. Проектный read допускает только найденные фрагменты; внешний вызов использует закреплённый нативный MCP и фиксированный набор инструментов. После network повторно проверяются текущие права, модель, назначение MCP и поколение индекса. Остановка сохраняет полученные ответы и терминальные квитанции; новые попытки не переписывают прежние.

Физический контракт research19 проверен на отдельном PostgreSQL: 48 фактов схемы; 17 тестов репозитория, включая upgrade18→19, неизменяемость, CAS, lease, cascade, пагинацию и scope. Ещё15 тестов ledger прошли с актуальной схемой19. Независимый срез executor/access: 13 PostgreSQL и21 проверки доступа, включая единственное соединение. Эти наборы пересекаются с другими отчётами и не складываются в процент покрытия.

## Что здесь не проверено

Не выполнен реальный платный вызов каждого пользовательского провайдера, работа стороннего OpenCode вне управляемого канала и испытание на рабочем сервере. Native-проверки ограничены целями, явно указанными в отчёте доставки; наличие архивов других платформ не заменяет их запуск. Полное покрытие всех модулей измеряется отдельным отчётом coverage, а не этим аудитом.
