# Импорт моделей и параметры адаптеров

Чтение OpenCode собирает метаданные на выбранном компьютере. Серверные запросы выполняются на сервере. Поэтому `localhost` из обнаруженной конфигурации не импортируется автоматически: укажите доступный серверу API вручную. Ручное серверное подключение может использовать свой `localhost`.

Для `@ai-sdk/openai` сохраняются Responses API, уровень рассуждений и политика хранения. Если `store` не указан, применяется используемое OpenCode значение `false`. `@ai-sdk/openai-compatible` использует Chat Completions. Существующие серверные подключения без `apiFormat` сохраняют Chat Completions. Автоматического повторного запроса с другим протоколом нет.

Провайдер `codexbridge`, официальный транспорт ChatGPT Codex и локальные OAuth-сессии не превращаются в серверный API копированием адреса. CodexBridge получает авторизацию и специальный `fetch` от локального плагина. В настройке провайдера проекта выберите «Codex Bridge — локальный вход». Серверные модели и локальная настройка остаются отдельными операциями.

Неизвестные SDK-параметры блокируют автоматический импорт. Отчёт показывает имена и типы; значения остаются в исходной конфигурации на компьютере. Произвольный JSON из локального файла не экспортируется под видом безопасных настроек. Для явной серверной настройки откройте подключение модели и поле «Дополнительные параметры адаптера (JSON)».

JSON поддерживает произвольные имена, вложенные объекты и массивы, строки, числа, `false` и `null`. Ограничения ресурсов: 64 КиБ, 8 уровней, 4096 узлов. Имена и значения должны соответствовать API конкретного провайдера. Совпадение с уже заданным полем основной формы вызывает явную ошибку; ни одно из двух значений не отбрасывается.

Адаптер определяет место дополнительных полей:

| Адаптер | Протокол | Место JSON-параметров |
| --- | --- | --- |
| `openai-chat-completions` | `/chat/completions` | тело запроса |
| `openai-responses` | `/responses` | тело запроса |
| `ollama` | `/api/chat`, `/api/embed` | `options` |

Адрес, ключи, заголовки, модель, сообщения, инструкции, инструменты, история и управление потоком принадлежат отдельным настройкам и не могут заменяться этим JSON. Определения и валидатор находятся в `services/shared/adapter-parameters.cjs`; этот контракт можно использовать в динамических формах и помощниках настройки.

Параметры остаются в приватном версионированном подключении, входят в его семантический pin и сохраняются при изменении других полей. В общем аудите сохраняется только количество дополнительных параметров, без их имён и значений. Вложенные ключи канонизируются; порядок массива сохраняется. Изменение значения требует новой проверки подключения. Открытие формы, сканирование и синхронизация не запускают модель. Кнопка сохранения с проверкой явно выполняет один тестовый запрос.

Локальный мастер `opencode-providers-v1` поддерживает только своё исходное подмножество Chat Completions. Если серверное подключение использует Responses или дополнительные параметры, создание локального задания отклоняется с объяснением вместо потери настроек. Такой локальный провайдер настраивается отдельно.

Существующие native-селекторы локального Codex или loopback-провайдера могут назначаться агентам на том же компьютере. Серверная модель сопоставляется с локальной только при точном совпадении протокола, параметров и остальных закреплённых метаданных. Приватный JSON требует явной локальной настройки и не попадает в компиляцию агента.

Протокол сверялся с [OpenCode 1.14.48](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/provider/provider.ts), [его настройками по умолчанию](https://github.com/anomalyco/opencode/blob/v1.14.48/packages/opencode/src/provider/transform.ts), [документацией OpenAI-провайдера AI SDK](https://ai-sdk.dev/providers/ai-sdk-providers/openai) и [схемой Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create). Текстовая история передаётся как `EasyInputMessage` с `input_text`, включая роль `assistant`; поля прежних output items не выдумываются. Реальный inference, установленный мост, CI и площадка проверяются отдельно от локальных HTTP-фикстур.
