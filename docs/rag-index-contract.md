# Подтверждённый индекс базы знаний

Управляемый плагин OpenCodeRAG использует локальную `qwen3-embedding:4b` и автоматическую индексацию. Параметры отсутствуют в исходном JSON — применяются defaults в памяти: Ollama `http://127.0.0.1:11435/api`, для явно выбранного OpenAI-протокола `http://127.0.0.1:11435/v1`. Явные модель, адрес, размерность, дополнительные функции и `autoIndex.enabled: false` сохраняются. Конфиг проекта не перезаписывается. Для произвольной модели без размерности выполняется проверка провайдера; известная локальная модель использует 2560 координат без startup-запроса.

Наличие строк не означает готовность базы знаний. Native-проход под `index.lock` записывает `neurocenter-index-profile.json`: `schemaVersion: 1`, `state`, публичный профиль `provider/model/dimension`, SHA-256 `embeddingSignature`; после успеха — `indexedAt`, равный `manifest.lastIndexedAt`. Подпись учитывает адрес подключения без credentials, query и fragment; адрес и ключ в sidecar не сохраняются. Смена модели той же размерности или неизвестное происхождение существующих векторов вызывает полное перестроение в отдельном временном каталоге. При ошибке embedding, extraction, description либо отмене временный rebuild не заменяет прежнюю базу; профиль становится `failed`. Изменение runtime-подключения при живом старом embedder требует перезапуска OpenCode.

Открытый OpenCode удерживает `neurocenter-session.lock`, включая режим с отключённой автоиндексацией. Восстановление требует закрыть OpenCode. Native-проходы и восстановление используют эксклюзивный `index.lock`; при замене каталога lock и session presence сохраняются. Освобождается только собственный token. Восстановление lock завершившегося PID сериализовано отдельным recovery guard; повреждённый или неподтверждённый lock автоматически не удаляется.

Серверный протокол сохраняет legacy `ids = sha256(content)`, добавляя `fingerprintVersion: 1` и полные `fingerprints`, которые учитывают путь, метаданные и float32-вектор. Профиль модели привязывается к проекту один раз. Иная модель или старый клиент без профиля получают 409 до изменения строк. Legacy-строки мигрируют с `sync_hash = NULL` и повторно передаются новым мостом.

Каждая ограниченная порция содержит полный целевой `snapshot: { hash, rowCount, complete: false }`. Финальный пустой запрос `complete: true` под блокировкой проверяет профиль, число строк, отсутствие непроверенных и нулевых векторов и SHA полного снимка. Только после этого `/summary`, `/manifest` и `/chunks` возвращают `complete: true`, `indexState: ready`, `snapshotHash`. Частично загруженный индекс остаётся `syncing`. Восстановление проверяет seal и полный снимок до замены целевого каталога. Произвольная смена серверной модели требует отдельной будущей процедуры перестроения.

Прежний мост мог завершить большую передачу ошибкой «Синхронизация требует проверки плана в MCP». Веб-задание текущего моста само передаёт изменения порциями по 500; ручная проверка плана для него не нужна. Для такой старой ошибки «Операции» предлагают открыть базу знаний проекта и запустить новое задание для текущей папки. Прежняя операция сохраняется в истории. Проверки владельца и актуальных прав действуют также для этого перехода.

Регрессия с настоящей LanceDB проверяет 1201 фрагмент, три прохода моста и HTTP-порции до 100 строк. Повтор совпадающего снимка не отправляет строки заново. Сбой после 700 принятых строк сохраняет прогресс; повтор передаёт оставшиеся 501, удаляет устаревшую строку и подтверждает полный снимок. Серверный транспорт этой изолированной проверки заменён тестовым обработчиком контракта V1; отдельный локальный прогон с настоящими PostgreSQL и моделью проверил перенос 6 фрагментов.

Платформенные архивы проверяются по SHA и inventory; нативное выполнение текущего прохода проверяется на macOS arm64 с настоящим LanceDB, закреплённым OpenCode и локальными HTTP fixtures. Сборка других целей не заменяет запуск на соответствующей ОС.
