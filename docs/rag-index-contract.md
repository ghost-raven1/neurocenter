# Подтверждённый индекс базы знаний

Без отдельного подключения серверной модели управляемый плагин OpenCodeRAG использует локальную `qwen3-embedding:4b` и автоматическую индексацию. Если параметры отсутствуют в исходном JSON, применяются defaults в памяти: Ollama `http://127.0.0.1:11435/api`, для явно выбранного OpenAI-протокола `http://127.0.0.1:11435/v1`. Явные модель, адрес, размерность, дополнительные функции и `autoIndex.enabled: false` сохраняются. Конфиг проекта не перезаписывается. Для произвольной модели без размерности выполняется проверка провайдера; известная локальная модель использует 2560 координат без startup-запроса.

Наличие строк не означает готовность базы знаний. Native-проход под `index.lock` записывает `neurocenter-index-profile.json`: `schemaVersion: 1`, `state`, публичный профиль `provider/model/dimension`, SHA-256 `embeddingSignature`; после успеха — `indexedAt`, равный `manifest.lastIndexedAt`. Подпись учитывает адрес подключения без credentials, query и fragment; адрес и ключ в sidecar не сохраняются. При запуске native-индексации смена модели той же размерности или неизвестное происхождение существующих векторов требует полного перестроения в отдельном временном каталоге. При ошибке embedding, extraction, description либо отмене временный rebuild не заменяет прежнюю базу; профиль становится `failed`. Изменение runtime-подключения при живом старом embedder требует перезапуска OpenCode.

## Выбранная модель проекта через мост 0.9.8

Назначение модели в каталоге и выбор embedding-профиля — разные действия. Администратор сохраняет через `PATCH /api/projects/:id/embedding` ровно `{expectedRevision, modelId}`: только назначенную embedding-модель с закреплённым descriptor SHA и размерностью `RAG_DIM`, либо `null` для очистки. CAS и аудит выполняются одной транзакцией; очистка не сбрасывает ревизию. GET возвращает сохранённые revision/model/pin/profile и причину несовместимости, без неявного выбора другой модели.

После явного согласия разработчика задание `connect-rag-model` закрепляет компьютер, binding/instance, точные версию/SHA одобренной установки и revision/pin выбора. Поддержка объявляется `hostedEmbedding: {schemaVersion: 1}` только в пакете со строгим `localUi` OpenCodeRAG и платформенными runtime-архивами. Мост проверяет установленный комплект и два настоящих embedding-ответа, затем сохраняет профиль в приватном хранилище. JSON проекта и старый `runtime-overrides.json` не перезаписываются, Device Bearer в них не добавляется.

Native OpenCodeRAG получает в памяти OpenAI-профиль: alias `neurocenter/<modelId>/sha256/<pin>`, размерность и loopback relay `/v1/embeddings` с отдельным приватным локальным ключом. Мост передаёт серверу текущий Device Bearer и точную привязку; `/api/device-channel/embedding/context` читает выбор, `/api/device-channel/embedding` проверяет каждую порцию. Проверки устройства, прав проекта, binding/instance, назначения и revision/pin повторяются перед и после inference. Отзыв или изменение не дают продолжить со старым разрешением, другой моделью либо кешированными векторами. Профиль использует batch 8 и concurrency 1; новый серверный профиль не даёт доступ к vision/chat или произвольному внешнему API-клиенту.

Подключение не перестраивает индекс и не объявляет его готовым. Для подключённой серверной модели автоиндексация всегда выключена начиная с pack.7; после перезапуска OpenCode полное native-перестроение запускают отдельно. Проверенный hosted-профиль не применяет старую модель из `runtime-overrides.json`, сохраняя исходные байты файла. Обычный профиль сохраняет строгую проверку overrides. При свидетельстве прежнего hosted-подключения потеря marker/private-файла или смена server/instance закрывает доступ и требует повторного подключения, вместо fallback к defaults. Серверный профиль уже загруженной копии остаётся неизменяемым даже после успешной локальной переиндексации: переход требует отдельной миграции или нового проекта. [Проверки реализации и границы приёмки](project-embedding-bridge-2026-10-20.md).

Публичный prerelease `catalog-2026-10-20.2` содержит pack.7: все 23 файла каталога проверены свежими анонимными GET по SHA/размеру. Семь файлов моста 0.9.8 подтверждены отдельным анонимным свидетельством и свежей сверкой метаданных. После восстановления Docker локальная macOS ARM64-приёмка pack.7 проверила настоящий MCP index/search, native plugin hooks внутри OpenCode без planner/chat, рестарт relay и отказ 409 после снятия назначения. Повторная UI-синхронизация четырёх строк сверена с фактическими native float32-векторами через release `exportRow`, полные fingerprints и PostgreSQL seal; постоянный индекс и private profile сохранились. Собственный стенд очищен без активных/pending заданий; граница квалифицированной очистки — post-recovery baseline, raw-оговорка о смене Docker PID сохранена. После очистки локальные catalog/gateway обновлены с прежними окружениями и готовностью зависимостей. Эта same-Mac dev/test-приёмка и локальное применение не подтверждают остальные ОС или production.

Новый блок модели виден и в рабочем интерфейсе после reload; это не равнозначно настройке существующего пользовательского проекта. Назначение/выбор модели, совместимая версия моста и привязка папки остаются обязательными. Проверка рабочего UI не выполняла эти изменения за пользователя.

## Блокировки, интерфейс и передача индекса

Открытый OpenCode удерживает `neurocenter-session.lock`, включая режим с отключённой автоиндексацией. Восстановление требует закрыть OpenCode. Native-проходы и восстановление используют эксклюзивный `index.lock`; при замене каталога lock и session presence сохраняются. Освобождается только собственный token. Восстановление lock завершившегося PID сериализовано отдельным recovery guard; повреждённый или неподтверждённый lock автоматически не удаляется.

Комплекты OpenCodeRAG `pack.5` добавляют управляемые команды `mcp` и `ui`.
После установки MCP мост выполняет initialize/listTools/close без обращения к
модели; это не подтверждает готовность индекса или embedding. Подключение включено
в конфигурации OpenCode, поэтому для уже открытого приложения требуется перезапуск.

Веб-интерфейс открывается отдельным окном на компьютере выбранного моста 0.9.5+.
Он слушает случайный порт только на `127.0.0.1`; одноразовый токен не передаётся
площадке и не выводится в журнал. Просмотр допускается при работающем плагине,
а изменения конфигурации и индекса требуют эксклюзивной блокировки и возвращают
409, пока OpenCode владеет индексом. Живой `neurocenter-ui-session.lock` запрещает
восстановление каталога; при полном rebuild его presence переносится вместе с
остальными блокировками. Перед восстановлением worker дожидается завершения
записи и закрывает свой UI; интерфейс другого процесса остаётся препятствием.
Worker также закрывает свой UI при остановке или изменении привязки папки.
Запуск UI не изменяет проектную конфигурацию и не
проверяет доступность embedding-провайдера.

Серверный протокол сохраняет legacy `ids = sha256(content)`, добавляя `fingerprintVersion: 1` и полные `fingerprints`, которые учитывают путь, метаданные и float32-вектор. Профиль серверной копии индекса привязывается к проекту один раз, отдельно от изменяемой CAS-настройки выбора модели. Иная модель или старый клиент без профиля получают 409 до изменения строк. Legacy-строки мигрируют с `sync_hash = NULL` и повторно передаются новым мостом.

Каждая ограниченная порция содержит полный целевой `snapshot: { hash, rowCount, complete: false }`. Финальный пустой запрос `complete: true` под блокировкой проверяет профиль, число строк, отсутствие непроверенных и нулевых векторов и SHA полного снимка. Только после этого `/summary`, `/manifest` и `/chunks` возвращают `complete: true`, `indexState: ready`, `snapshotHash`. Частично загруженный индекс остаётся `syncing`. Восстановление проверяет seal и полный снимок до замены целевого каталога. Произвольная смена серверной модели требует отдельной будущей процедуры перестроения.

Прежний мост мог завершить большую передачу ошибкой «Синхронизация требует проверки плана в MCP». Веб-задание текущего моста само передаёт изменения порциями по 500; ручная проверка плана для него не нужна. Для такой старой ошибки «Операции» предлагают открыть базу знаний проекта и запустить новое задание для текущей папки. Прежняя операция сохраняется в истории. Проверки владельца и актуальных прав действуют также для этого перехода.

Регрессия с настоящей LanceDB проверяет 1201 фрагмент, три прохода моста и HTTP-порции до 100 строк. Повтор совпадающего снимка не отправляет строки заново. Сбой после 700 принятых строк сохраняет прогресс; повтор передаёт оставшиеся 501, удаляет устаревшую строку и подтверждает полный снимок. Серверный транспорт этой изолированной проверки заменён тестовым обработчиком контракта V1; отдельный локальный прогон с настоящими PostgreSQL и моделью проверил перенос 6 фрагментов.

Платформенные архивы проверяются по SHA и inventory; нативное выполнение текущего прохода проверяется на macOS arm64 с настоящим LanceDB, закреплённым OpenCode и локальными HTTP fixtures. Сборка других целей не заменяет запуск на соответствующей ОС.
