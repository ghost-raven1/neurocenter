# Модели для изображений

Vision-модель управляется через вкладку **Модели**. Главный администратор импортирует локальную поставку из **Ассетов** или добавляет удалённое OpenAI/Ollama-подключение. Адреса и ключи находятся в приватной конфигурации сервера. Наличие карточки или файлов не означает успешную обработку изображения: **Проверить модель** выполняет содержательную пробу. [Удалённые подключения](remote-models.md).

Локальные версии используют общий runtime и раздельные immutable aliases по SHA манифеста. Пользовательский Ollama и его ключи не участвуют. Прямые standalone-команды `vision:*` удалены: управление, права, прогресс и результат проверки проходят через каталог и API Gateway.

## Подготовка собственной поставки

На машине с уже размещённой локальной моделью producer читает её манифест и проверяет все blobs. Пользователь не пишет рецепт. Для неоднозначного типа требуется только capability; размерность задаётся исключительно embedding-моделям.

```sh
npm run models:publish -- --model namespace/vision:tag --capability vision --release models-example-v1
```

Без `--publish` создаются локальные части и `asset.json` с `published:false`. Приватные ключи, runtime receipts и посторонние модели не включаются. Повтор использует полный проверенный output; изменение версии или содержимого требует нового output. С `--publish` producer создаёт Release в `neurocenter-assets`, проверяет размеры и серверные SHA, затем читает опубликованный выпуск повторно. В Git больше нет отдельного реестра моделей или default lock-файлов.

Сохранённый descriptor добавляется в индекс `neurocenter-assets` новой неизменяемой версией. Импорт в общий каталог — явное действие главного администратора.
