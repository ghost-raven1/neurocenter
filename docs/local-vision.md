# Локальная модель для изображений

Веб-каталог содержит вкладку «Модели»: главный администратор может запустить и проверить хостинг, а администратор проекта — добавить модель в проект. Веса и runtime общие для команды, назначение не меняет существующий индекс. [API, права и границы](current-implementation.md#каталог-моделей-и-хостинг).

`qwen3-vl:2b-instruct` принимает изображение и вопрос, возвращает текст: описание, распознанные надписи или ответ о содержимом. Модель работает в проектном Ollama вместе с эмбеддингами. Её веса и projector занимают примерно 1,93 ГБ и сохраняются в `data/embedding/models/`; глобальный Ollama не используется.

## Веса в поставке проекта

Обе встроенные модели уже предусмотрены в поставке: 9 файлов общим размером **4 427 274 223 байта**, включая vision-веса, projector, конфигурацию и лицензию. `scripts/dev.sh up` автоматически размещает их в проекте до остановки прежних сервисов. В production `model-volume-init` готовит тот же комплект в томе `model-weights` до запуска runtime.

В Git хранятся [опись и SHA-256](../scripts/models/bundle-release.json), lock-файлы, [лицензия Apache 2.0](../scripts/models/LICENSE-APACHE-2.0.txt) и [атрибуция](../scripts/models/THIRD-PARTY-NOTICES.txt); большие бинарные части поставляются из закреплённого [release `models-2026-10-19.1`](https://github.com/ghost-raven1/neurocenter/releases/tag/models-2026-10-19.1). Подготовка без запуска приложения:

```sh
npm run models:prepare
npm run models:verify
```

Проверяются части и итоговые SHA всех файлов; теги появляются после подготовки blobs. `models:verify` ничего не скачивает. Полный каталог весов позволяет повторить подготовку без сетевых запросов. Для переноса сохраните весь `data/embedding/models/`, разместите его в новом checkout и выполните `models:verify`; Docker-образ переносится отдельно. Пользовательские ключи, история и квитанции готовности в поставку не входят.

## Отдельный запуск

Из корня репозитория, при работающем Docker с Compose v2 и Node.js 24+:

Если Compose ещё не установлен, выполните `npm run compose:install` или общий `scripts/dev.sh install`. [Порядок установки](compose-install.md).

```sh
npm run vision:up
npm run vision:status
npm run vision:check
```

Standalone `vision:up` сохраняет прежний сценарий: использует существующий проектный контейнер или запускает его, при отсутствии весов получает выбранную модель из реестра Ollama, проверяет SHA всех её файлов и выполняет пробу с изображением. Эта команда не вызывает bundle-подготовку обеих моделей; уже размещённые файлы используются повторно. При сетевом отказе повторите ту же команду. Несовпадение закреплённых байтов останавливает подготовку; другая модель автоматически не выбирается.

`status` показывает состояние и время последней успешной проверки без запуска inference. `check` выполняет настоящий запрос с изображением; здоровый контейнер и наличие модели сами по себе такую проверку не заменяют.

Справка доступна через `npm run vision:up -- --help`; команда `vision:down -- --help` тоже показывает справку и не останавливает runtime. Неизвестные и лишние аргументы отклоняются до действий. Повреждённая квитанция готовности даёт `unchecked` с причиной `verificationIssue`. [Повторный аудит и границы](model-runtime-refactor-2026-10-19.md).

Описание собственного файла:

```sh
npm run vision:describe -- ./image.png
npm run vision:describe -- ./image.png 'Прочитай надписи на изображении.'
```

Укажите существующий локальный PNG, JPEG или WebP до 10 МиБ и, при необходимости, вопрос. Изображение передаётся локальному runtime; его не требуется публиковать по внешней ссылке. CLI ждёт ответ до пяти минут, ограничивает его 256 токенами и сообщает об усечении. Скорость и точность чтения зависят от размера, качества изображения и компьютера.

## Подключение клиентов

| Параметр | Значение |
| --- | --- |
| Модель | `qwen3-vl:2b-instruct` |
| Ollama API | `http://127.0.0.1:11435/api` |
| OpenAI-совместимый API | `http://127.0.0.1:11435/v1` |
| Ключ | Не требуется; SDK, требующему непустое значение, можно передать `ollama` |

Native-запрос: POST `/api/chat`, `stream: false`, сообщение пользователя с полями `content` и `images: ["<base64 изображения>"]`. OpenAI-совместимый запрос: POST `/v1/chat/completions`, сообщение с текстовым элементом и `image_url`, содержащим `data:image/png;base64,<base64 изображения>`. Передавайте изображение внутри запроса; внешний URL ему не нужен.

Пример тела OpenAI-совместимого запроса:

```json
{
  "model": "qwen3-vl:2b-instruct",
  "stream": false,
  "max_tokens": 256,
  "temperature": 0,
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "Опиши изображение."},
      {"type": "image_url", "image_url": {"url": "data:image/png;base64,<base64 изображения>"}}
    ]
  }]
}
```

Замените placeholder настоящими base64-байтами. `127.0.0.1` работает только для клиента на том же компьютере, где запущен проектный runtime. API привязан к loopback и не публикуется как общий сетевой сервис. На CPU задавайте клиенту достаточный таймаут для обработки изображения.

## Общий runtime и остановка

Vision и [эмбеддинги](local-embedding.md) используют один контейнер, порт и каталог весов. В памяти загружается одна модель; при переключении возможна задержка, запросы обрабатываются через очередь. Оба набора весов остаются на диске.

```sh
npm run vision:down
```

Эта команда останавливает общий контейнер для vision **и эмбеддингов**, сохраняя веса. `embedding:down` действует так же. Для продолжения выполните обычный `scripts/dev.sh up` либо отдельный `vision:up`/`embedding:up`; готовность нужной модели проверьте соответствующей командой `check`. Второй проектный контейнер не требуется.

Общий runtime ограничен 5 ГиБ RAM и четырьмя CPU. На macOS Docker использует CPU. Второй контейнер и одновременная загрузка обеих моделей не требуются. Глобальный Ollama, его порт, ключи и модели не изменяются.

## Воспроизводимость и границы

Модель, projector, параметры и лицензия закреплены в [model.lock.json](../scripts/vision/model.lock.json). Образ runtime и изоляция определены в [compose.embedding.yml](../compose.embedding.yml). Проверяются SHA всего закреплённого комплекта; изменение upstream-тега требует явного обновления пина.

Vision имеет собственную квитанцию `data/embedding/vision-readiness.json` и общую с эмбеддингами управляющую блокировку. Бинарные веса, квитанции и пользовательские изображения не включаются в Git. Для переноса готовой поставки достаточно каталога `data/embedding/models/` и закреплённого образа; после переноса выполните `models:verify` и содержательные проверки обеих моделей.

Встроенный кеш весов воспроизводится из закреплённого release и не входит в полный резервный комплект площадки. Пользовательские модели вне описи нужно резервировать отдельно вместе со сведениями об источнике. Карточки и назначения из PostgreSQL сохраняются независимо от файлов весов. [Восстановление](production-recovery.md).

Этот механизм предоставляет обработку изображений через локальный API. Автоматическое извлечение картинок в OpenCodeRAG и построение мультимодального индекса здесь не включаются; существующий текстовый индекс и его embedding-модель сохраняют свой контракт.

## Локальная проверка — 2026-10-19

Для новой поставки отдельно прошли холодный импорт всех 9 файлов в пустой каталог, проверка итоговых SHA и повтор без сетевых запросов. Новый контейнер из перенесённого комплекта с `--network none` распознал число `42` и красный квадрат; embedding-проверка того же комплекта тоже прошла. Все 117 проверок подготовки, запуска и production-интеграции прошли без пропусков. Это локальная приёмка; production не разворачивался. Ниже приведены результаты прежнего standalone-сценария.

На macOS arm64, Node.js 24 и Docker с указанными ограничениями прошли 45 автоматических проверок без пропусков. Проверены форматы и предел файла, неверный ввод до обращения к Docker, конфликт подготовки моделей, SHA projector, независимость квитанций и совместимость прежней embedding-конфигурации.

Настоящие запросы прочитали две собственные PNG 384×256: `42/red` и `17/blue`. Один и тот же вопрос без ожидаемого ответа дал разные правильные признаки; OpenAI API с data URL также вернул `42/red`. Усечённых ответов нет. Новый пример обрабатывался около 2,5 минуты, первая проба с загрузкой модели в память — около трёх минут. Эти времена относятся к проверенному CPU-окружению.

Команда `npm run vision:describe` с русским вопросом о собственном PNG вернула `42, красный`, exit 0. Сохранённые embedding-файлы проверены по SHA, inode, размеру и времени изменения; глобальные модели, ключи Ollama и идентификаторы работающих контейнеров сохранились.

После vision-запросов `embedding:check` снова получил два корректных вектора размерности 2560. Оба статуса остались `verified`: переключение в общем контейнере не требует повторной установки моделей.

Повторяемая проверка обоих API после `vision:up`:

```sh
node scripts/vision/smoke.mjs --timeout-ms 1200000
```

Она создаёт собственные PNG и сохраняет ответы, SHA файлов и времена в `output/vision/smoke.json`, сводку — в `.run/vision/smoke.json`. Пользовательские изображения для проверки не читаются. Локальные отчёты не публикуются в Git.
