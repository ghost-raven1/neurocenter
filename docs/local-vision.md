# Локальная модель для изображений

`qwen3-vl:2b-instruct` принимает изображение и вопрос, возвращает текст: описание, распознанные надписи или ответ о содержимом. Модель работает в проектном Ollama вместе с эмбеддингами. Веса и projector занимают примерно 1,93 ГБ и сохраняются в `data/embedding/models/`; глобальный Ollama не используется.

## Запуск

Из корня репозитория, при работающем Docker с Compose v2 и Node.js 24+:

```sh
npm run vision:up
npm run vision:status
npm run vision:check
```

`up` использует существующий проектный контейнер или запускает его, скачивает закреплённую модель, проверяет SHA всех её файлов и выполняет пробу с изображением. При сетевом отказе повторите ту же команду: завершённые файлы используются повторно. Несовпадение закреплённых байтов останавливает подготовку; другая модель автоматически не выбирается.

`status` показывает состояние и время последней успешной проверки без запуска inference. `check` выполняет настоящий запрос с изображением; здоровый контейнер и наличие модели сами по себе такую проверку не заменяют.

Описание собственного файла:

```sh
npm run vision:describe -- ./image.png
npm run vision:describe -- ./image.png 'Прочитай надписи на изображении.'
```

Укажите существующий локальный PNG, JPEG или WebP до 10 МиБ и, при необходимости, вопрос. Изображение передаётся локальному runtime; его не требуется публиковать по внешней ссылке. CLI ждёт ответ до пяти минут, ограничивает его 256 токенами и сообщает об усечении. Скорость и точность чтения зависят от размера, качества изображения и компьютера.

## Подключение клиентов

| Параметр | Значение |
| --- | --- |
| Модель | `qwen3-vl:2b-instruct` |
| Ollama API | `http://127.0.0.1:11435/api` |
| OpenAI-совместимый API | `http://127.0.0.1:11435/v1` |
| Ключ | Не требуется; SDK, требующему непустое значение, можно передать `ollama` |

Native-запрос: POST `/api/chat`, `stream: false`, сообщение пользователя с полями `content` и `images: ["<base64 изображения>"]`. OpenAI-совместимый запрос: POST `/v1/chat/completions`, сообщение с текстовым элементом и `image_url`, содержащим `data:image/png;base64,<base64 изображения>`. Передавайте изображение внутри запроса; внешний URL ему не нужен.

Пример тела OpenAI-совместимого запроса:

```json
{
  "model": "qwen3-vl:2b-instruct",
  "stream": false,
  "max_tokens": 256,
  "temperature": 0,
  "messages": [{
    "role": "user",
    "content": [
      {"type": "text", "text": "Опиши изображение."},
      {"type": "image_url", "image_url": {"url": "data:image/png;base64,<base64 изображения>"}}
    ]
  }]
}
```

Замените placeholder настоящими base64-байтами. `127.0.0.1` работает только для клиента на том же компьютере, где запущен проектный runtime. API привязан к loopback и не публикуется как общий сетевой сервис. На CPU задавайте клиенту достаточный таймаут для обработки изображения.

## Общий runtime и остановка

Vision и [эмбеддинги](local-embedding.md) используют один контейнер, порт и каталог весов. В памяти загружается одна модель; при переключении возможна задержка, запросы обрабатываются через очередь. Оба набора весов остаются на диске.

```sh
npm run vision:down
```

Эта команда останавливает общий контейнер для vision **и эмбеддингов**, сохраняя веса. `embedding:down` действует так же. Для продолжения выполните `vision:up` или `embedding:up`; готовность нужной модели проверьте соответствующей командой `check`.

Общий runtime ограничен 5 ГиБ RAM и четырьмя CPU. На macOS Docker использует CPU. Второй контейнер и одновременная загрузка обеих моделей не требуются. Глобальный Ollama, его порт, ключи и модели не изменяются.

## Воспроизводимость и границы

Модель, projector, параметры и лицензия закреплены в [model.lock.json](../scripts/vision/model.lock.json). Образ runtime и изоляция определены в [compose.embedding.yml](../compose.embedding.yml). Проверяются SHA всего закреплённого комплекта; изменение upstream-тега требует явного обновления пина.

Vision имеет собственную квитанцию `data/embedding/vision-readiness.json` и общую с эмбеддингами управляющую блокировку. Веса, квитанции и пользовательские изображения не включаются в Git. Для переноса сохраняйте общий каталог `data/embedding/` и закреплённый образ; после переноса повторите проверки обеих моделей.

Этот механизм предоставляет обработку изображений через локальный API. Автоматическое извлечение картинок в OpenCodeRAG и построение мультимодального индекса здесь не включаются; существующий текстовый индекс и его embedding-модель сохраняют свой контракт.

## Локальная проверка — 2026-10-19

На macOS arm64, Node.js 24 и Docker с указанными ограничениями прошли 45 автоматических проверок без пропусков. Проверены форматы и предел файла, неверный ввод до обращения к Docker, конфликт подготовки моделей, SHA projector, независимость квитанций и совместимость прежней embedding-конфигурации.

Настоящие запросы прочитали две собственные PNG 384×256: `42/red` и `17/blue`. Один и тот же вопрос без ожидаемого ответа дал разные правильные признаки; OpenAI API с data URL также вернул `42/red`. Усечённых ответов нет. Новый пример обрабатывался около 2,5 минуты, первая проба с загрузкой модели в память — около трёх минут. Эти времена относятся к проверенному CPU-окружению.

Команда `npm run vision:describe` с русским вопросом о собственном PNG вернула `42, красный`, exit 0. Сохранённые embedding-файлы проверены по SHA, inode, размеру и времени изменения; глобальные модели, ключи Ollama и идентификаторы работающих контейнеров сохранились.

После vision-запросов `embedding:check` снова получил два корректных вектора размерности 2560. Оба статуса остались `verified`: переключение в общем контейнере не требует повторной установки моделей.

Повторяемая проверка обоих API после `vision:up`:

```sh
node scripts/vision/smoke.mjs --timeout-ms 1200000
```

Она создаёт собственные PNG и сохраняет ответы, SHA файлов и времена в `output/vision/smoke.json`, сводку — в `.run/vision/smoke.json`. Пользовательские изображения для проверки не читаются. Локальные отчёты не публикуются в Git.
