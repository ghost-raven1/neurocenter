# Модель проекта → OpenCodeRAG через мост — 20 октября 2026

Реализован первый этап явного подключения серверной embedding-модели к управляемому OpenCodeRAG через мост **0.9.8**. Назначение модели в каталоге само по себе по-прежнему не меняет OpenCode, не скачивает веса и не запускает индексацию. Проверки кода и изолированной PostgreSQL выполнены; настоящий MCP и передача серверной копии проверены в своей области. Приёмка остальных частей нового сценария **в процессе**. Общий [P0-допуск](implementation-readiness.md) остаётся **NO-GO**.

## Сценарий и границы

1. Администратор проекта назначает модель из каталога. Главный администратор отдельно управляет её общим хостингом.
2. На вкладке «База знаний» администратор проекта явно сохраняет модель эмбеддингов. Доступны только назначенные embedding-модели Ollama с закреплённым manifest SHA и размерностью `RAG_DIM`; текущая поставка использует **2560** измерений и Qwen3 Embedding 4B.
3. Разработчик выбирает компьютер, связанную папку и точную установку OpenCodeRAG со сверенными файлами. После согласия на эту модель и компьютер нажимает «Подключить модель к OpenCodeRAG».
4. Мост проверяет одобренный пакет, привязку и реальный ответ модели на два текста, затем сохраняет приватное подключение. В результате нет адреса relay, локального ключа или Device Bearer.
5. OpenCode требуется перезапустить. Успешное подключение не подтверждает готовность локального или серверного индекса. При смене профиля полную native-переиндексацию запускают отдельно после проверки настроек и сохранения нужной копии.

В этом этапе нет vision/chat-профиля OpenCodeRAG, новых API-ключей для сторонних клиентов, автоматического выбора другой модели, автоматического перестроения или замены серверной копии. Существующие API хостинга embedding/vision сохраняют прежний контракт.

## Выбор модели, CAS и pin

`GET /api/projects/:id/embedding` возвращает `projectId`, `revision`, `expectedDimension`, `model | null`, `modelPin | null`, `profile | null` и при необходимости `blocker`. Первое чтение возвращает revision 0 без выбранной модели. Несовместимое сохранённое состояние не подменяется новым: GET сохраняет прежние pin/profile и объясняет причину, чтобы администратор мог исправить выбор.

`PATCH /api/projects/:id/embedding` принимает ровно `{expectedRevision, modelId: string | null}`. Чтение требует доступа к проекту; изменение — роли администратора проекта. Репозиторий перечитывает права после ожидания блокировки, проверяет назначение и техническую совместимость модели. Выбор и аудит фиксируются одной SQL-транзакцией. Конкурентный иной выбор получает 409; повтор уже сохранённого значения не создаёт второй аудит. Очистка сохраняет возрастающую ревизию. Ошибка аудита откатывает изменение.

`modelPin` — SHA-256 технического descriptor: `id`, `runtime`, `model`, `manifestSha256`, `dimension`, `capability`. Отображаемое имя и описание его не меняют. Публичный профиль имеет provider `openai`, dimension и alias `neurocenter/<modelId>/sha256/<pin>`. Изменение технической карточки, снятие назначения или удаление модели блокирует прежний выбор без fallback. Устаревший pin той же модели можно явно закрепить заново; недоступный выбор — очистить.

## Подключение и свежие проверки

Задание `connect-rag-model` закрепляет project/device, binding/instance, asset kind/ID/version/manifest и expected embedding revision/pin. Нужны capability `hosted-rag-model-v1`, одобренный установленный пакет, поддержка управляемого OpenCodeRAG и сверенные файлы. Права, точный пакет, одобрение, привязка и выбор проверяются при создании, получении задания и повторной авторизации перед завершением. Новая команда не включена в общий автоматический retry запрещённых видов заданий.

Поддержка объявляется ровно `hostedEmbedding: {schemaVersion: 1}`. Публикация принимает этот marker только вместе с нормализованными runtime-архивами и строгим `localUi` OpenCodeRAG: фиксированные `opencode-rag.mjs` и `ui --port 0 --no-open`. Проверка SHA и непустой UI-точки в описи архива сохранена. Marker не добавляет произвольную внешнюю команду или install hook. Состав и SHA конкретных архивов принимаются отдельно от этой проверки контракта.

Браузер не запускает задания при чтении модели, mount или восстановлении связи. Согласие относится к точному компьютеру, общей и проектной папкам, установке и revision/pin; смена контекста сбрасывает его. Смена владельца/прав синхронно блокирует старый обработчик ещё до перерисовки. Принятый queued ACK блокирует второй запуск до обновления очереди. При неопределённом ACK явный повтор сохраняет исходный requestKey; совпавшее по имени чужое задание не считается успехом. Результат проверяется по revision, pin и полному профилю, а не только по transport-статусу succeeded.

## Приватный relay и device API

Приватный профиль хранится на компьютере моста и связан с origin, физическим root, проектом, binding/instance и пакетом. В JSON проекта и `runtime-overrides.json` Device Bearer не добавляется. Native OpenCodeRAG получает в памяти OpenAI-подключение к loopback `/v1/embeddings` с отдельным локальным ключом; batch 8, concurrency 1, timeout 120 секунд.

- `POST /api/device-channel/embedding/context`: `{projectId, bindingId, instanceId, expectedRevision?, expectedModelPin?}` → текущий подтверждённый выбор.
- `POST /api/device-channel/embedding`: те же поля, обязательные expected revision/pin, `model: alias` и `input: string | string[]` → OpenAI-совместимый embedding-ответ. Допустимы 1–64 непустых текста, суммарно до 256 КиБ.

Мост использует текущий существующий Device Bearer из приватных credentials. Перед каждой порцией он проверяет локальную установку. Сервер заново проверяет устройство и его владельца, действующую рабочую роль проекта, существование проекта, текущие binding/instance, выбор и назначение модели. Эти серверные проверки повторяются после inference: отзыв или изменение во время запроса не возвращает старые векторы. Выбранный alias проверяется точно; клиент не может подменить тег runtime. `model_hosting` ограничивает новый inference и подключение; чтение выбора не запускает модель.

Relay слушает только `127.0.0.1`, проверяет Host и локальный ключ, отклоняет Origin и посторонние маршруты, ограничивает размеры и конкурентные запросы. Перенаправления к брокеру запрещены. Ответы проверяются по модели, числу, размерности, порядку и конечным ненулевым float32-векторам. Смена live-профиля во время запроса возвращает 409; запрос A не получает векторы B. После перезапуска моста приватный relay восстанавливается без обращения к backend; старый порт сохраняется, занятый порт не заменяется молча. Бюджет device-запроса на gateway и в relay — 120 секунд, хотя внутренний Ollama inference допускает 600 секунд. Порция дольше внешнего бюджета завершится отказом; более длинный runtime timeout не продлевает его.

## Сохранность индексов и старых настроек

Подключение не открывает и не перестраивает vector store. Начиная с pack.7 адаптер всегда отключает автоиндексацию в памяти для подключённой серверной модели, включая совместимый ready-индекс. Локальные настройки без hosted-подключения сохраняют прежнее поведение. Файлы проекта и старый `runtime-overrides.json` сохраняются. Игнорировать его прежнюю модель может только проверенный приватный hosted-профиль; обычный профиль сохраняет строгую проверку runtime overrides. При свидетельстве прежнего hosted-подключения потеря marker/private-профиля либо смена server/instance останавливает fallback к defaults. Повреждённый sidecar обычного проекта без hosted-свидетельств сохраняет возможность явного native rebuild.

Явное native-перестроение и поиск используют прежние блокировки, атомарную замену и профиль происхождения векторов; отказ не заменяет старый индекс. Профиль **серверной копии** отдельно привязан при первоначальной передаче и остаётся неизменяемым. Изменение CAS-выбора и локальная переиндексация не разрешают загрузить другой профиль поверх неё: сервер возвращает 409 до изменения строк. Для перехода нужны отдельная процедура миграции или новый проект. Автоматическая серверная индексация и миграция в этом этапе не запускаются. [Полный контракт индекса](rag-index-contract.md).
