# Переходы, отказы и сохранения — UI-плейтест 18 октября 2026

Продолжен предыдущий проход на локальном стенде. Проверены переходы между проектами, поздние ответы, ручное добавление MCP/плагинов, конфликты квот и редакторов, отзыв доступа и клавиатура операций. Основные пути пройдены на desktop и 390/320 px. **806 frontend-тестов прошли без падений и пропусков; TypeScript и production-сборка frontend успешны.**

## Исправлено

| Дефект | Результат |
| --- | --- |
| Back возвращал адрес A, а каталог оставался для B | Проект определяется адресом; Back/Forward, снятие выбора и начальное восстановление согласованы. Неизвестный ID не подменяется единственным доступным проектом. |
| Поздний ответ добавления в A показывал его инструмент в B | Каталог принадлежит проекту и auth scope. Старый callback не читает и не меняет новый каталог. При задержанном настоящем POST: ложная кнопка удаления в B до исправления — 1, после — 0; сервер B в обоих случаях пустой. |
| Ошибка чтения каталога исчезала вместе с toast | Постоянное сообщение, явный повтор и блокировка изменений до восстановления чтения. Отказ доступа очищает прежние назначения. |
| Ошибки ручной публикации оставались вне экрана или только в общем сообщении | URL, JSON, программа, аргументы и окружение проверяются у полей; форма прокручивается к первому неверному полю. Логика проверки общая с отправкой payload. |
| Проектные знания, квота и ссылки на копии оставались после 403/404 | Недоступные данные и действия убираются. Сетевой 503 сохраняет известную информацию с предупреждением; повтор возвращает настоящий ответ. |
| Обслуживание сохраняло прежние сведения и доступные действия после 401/403 | Политика, ревизия, размеры и сведения о копии очищаются; действия блокируются. При временном сбое черновик сохраняется. |
| Сводки обслуживания переживали смену владельца сессии | Redux и локальный результат копирования привязаны к auth scope. Выход и смена аккаунта/роли отбрасывают прежние ответы; поздний результат ручной операции не показывает чужой toast и не обновляет новый экран. |
| Быстрый Escape из вложенных подробностей оставлял фокус на body | Фокус возвращается на «Подробнее», следующий Escape закрывает очередь и возвращает фокус на «Операции». Проверены четыре rapid/settled варианта на desktop/mobile. |

Состояние каталога проекта вынесено в небольшие feature-модули. Сохранены React, Redux, Ant Design и существующие контракты API; backend-код в этом проходе не менялся.

## Настоящие пользовательские сценарии

- Два QA проекта: создание, прямые ссылки, A/B, Back/Forward, reload, нормализация неизвестной вкладки с сохранением query/hash. Поздний настоящий GET A не подменяет B.
- Квота в двух окнах: успешное сохранение → реальный 409 → сохранённый черновик → обновление и успешное повторное сохранение → reload. Пустое, неправильное и повторное имя проекта обрабатываются без потери формы.
- Проектная копия: реальное создание и браузерное скачивание 18 498 байт, SHA-256 `67cf92189e0d197105cf151df878eb9c6225409f9dfc402ce2f83ca3f9d1ec35` совпала. Это локальный дамп, внешнее восстановление не проверялось.
- Remote MCP, локальная команда и плагин созданы и отредактированы через UI. Аргументы с пробелами/кириллицей и ссылки `{env:…}` сохранены. Зависимость закреплена на точную версию/SHA; новая версия зависимости не меняет уже выбранную. Самозависимость отсутствует в выборе.
- Два редактора MCP: реальный 409, один способ загрузить актуальную версию, предыдущий черновик доступен для сравнения. Закрытие формы создания сохраняет черновик.
- Восемь мобильных экранов проекта не растягивают документ; таблицы используют собственную прокрутку. В операциях проверены фильтр, Escape, подробности, старый `/operations`, reload и Back. Исторические задания не перезапускались.

## Отказы и проверка кода

Успешные создания, изменения, конфликты квот/редакторов и скачивание копии использовали настоящий сервер. GET-отказы 401/403/404/503 — явно обозначенные UI-fixtures; последующие повторы получили настоящие ответы. В проверке поздней мутации настоящий upstream POST выполнился, задерживалась только доставка его ответа. Смена владельца обслуживания и задержанная копия проверены в управляемом браузерном контексте: оба POST системного backup полностью перехвачены. Старые GET/POST не показали данные и toast, не запустили обновление нового экрана; уже завершённый fixture-результат также исчез при смене scope. Настоящая системная копия не создавалась. Это не приёмка корпоративного IdP.

Полный frontend Vitest: **806 passed, 0 failed, 0 skipped**. Целевые наборы агентов входят в это число и повторно не суммируются. Новые тесты обслуживания сначала воспроизвели ошибки очистки и auth ownership, затем прошли. Проверены порядок запросов и потеря владельца, отказ доступа, временный сбой, восстановление и черновики.

Независимые reviews проверили Store ownership и обработку отказов. Найденный при review пробел auth scope обслуживания исправлен и повторно проверен: [review](../output/playwright/neurocenter-ui-followup-20261018/catalog/independent-review.md). Полный backend-набор не повторялся: его исходники не менялись. Шесть локальных сервисов отдельно прошли health/readiness. Перезапуск сервисов не требовался.
