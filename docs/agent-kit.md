# Neurocenter Agent Kit 0.1.0

Общий workflow Neurocenter: цель и критерии готовности → исследование → минимальная реализация и регресс → независимое ревью → проверенный результат. Правила интерфейса действуют во всех изменяемых сценариях продукта. Простая правка не требует полного ритуала большого проекта.

Канонический исходник — `.opencode/skills/neurocenter-task-flow`. OpenCode использует его непосредственно в этом проекте; Codex получает копию в локальный каталог skills. Общие инструкции написаны самостоятельно под текущую работу; [Everything Claude Code / ECC](https://github.com/affaan-m/ECC) использован как образец организации набора, его hooks и полный каталог не импортировались.

| Среда | Размещение | Вызов |
| --- | --- | --- |
| OpenCode, этот проект | `.opencode/skills`, `.opencode/agents`, `.opencode/commands` | `/neurocenter-task <задача>`; роли `neurocenter-explorer`, `neurocenter-reviewer` |
| Codex, этот компьютер | `~/.codex/skills/neurocenter-task-flow`; совместимые роли в `~/.codex/agents` | `$neurocenter-task-flow <задача>` |

Набор содержит **64 роли**, у каждой отдельный профильный skill, и один общий `neurocenter-task-flow`: всего **65 skills**. Восемь групп по восемь ролей: продукт, frontend, backend, модели/агенты, знания/хранение, поставка, качество и эксплуатация. [Полный каталог](../.opencode/skills/neurocenter-task-flow/references/catalog.md) связывает каждую роль с её входом, результатом, проверками и границами. Общий профиль Neurocenter загружается по необходимости.

Подробные инструкции роли загружаются для выбранной задачи. Наличие 64 ролей не означает их одновременный запуск: действует текущий лимит параллельности. Модели, провайдеры, MCP, hooks, учётные данные и права запуска kit не устанавливает. Проверку типов и тесты выполняют существующие инструменты проекта. Роли исследования/ревью используют доступное read-only чтение и просмотр diff; необходимые тесты и сборки выполняет основной агент.

## Обновление набора

Исходные определения находятся в восьми JSON-файлах `scripts/agent-kit/roles/`; общие инструкции редактируются непосредственно в `neurocenter-task-flow`. Адаптеры и профильные skills формируются одной командой:

```sh
node scripts/agent-kit/generate.mjs
node scripts/agent-kit/generate.mjs --check
```

Генератор сохраняет SHA в manifest и отклоняет замену вручную изменённого сгенерированного файла. Установщик Codex сначала проверяет весь план и целостность исходников. Существующий изменённый пользовательский файл не перезаписывается; повтор одинаковой установки не меняет файлы.

```sh
node scripts/agent-kit/install-codex.mjs          # показать план
node scripts/agent-kit/install-codex.mjs --apply  # установить или обновить свои файлы
node scripts/agent-kit/install-codex.mjs --check  # проверить установленную копию
```

Путь Codex берётся из `CODEX_HOME`, иначе используется `~/.codex`. В проекте OpenCode читает размещённые файлы непосредственно, установка npm для самого kit не нужна.

## Как проверить обнаружение

В новой сессии Codex вызови `$neurocenter-task-flow` или конкретный `$neurocenter-react-developer` и попроси назвать загруженный файл. Для независимого машинного контроля `skills/list` должен вернуть 65 имён `neurocenter-*`, включённые записи и ожидаемые пути без ошибок. Сравнение SHA установленного набора с manifest дополнительно подтверждает версию файлов.

Обнаружение skill, загрузка роли и качество её работы — разные проверки. На установленной CLI Codex 0.146.0 изолированная проверка вернула все 65 skills, показала все 64 роли в схеме `spawn_agent` и действительно запустила `neurocenter-reviewer`. Запрос дочернего агента содержал точные инструкции установленной роли; ожидание вернуло контрольный ответ. Ответы обеспечивал локальный синтетический стенд: внешних и платных запросов не было. Это проверяет механизм загрузки и запуска, но не качество решений настоящей модели.

Пользовательские роли зависят от версии клиента; наличие TOML-файла не доказывает, что конкретный клиент его загрузил. Сам skill сохраняет workflow и при отсутствии native custom roles. Существующие настройки и skills сохраняются; одноимённые изменённые файлы требуют разбора конфликта перед обновлением.

Проверки: формат skill и TOML/YAML, разрешение внутренних ссылок, независимые сценарии применения. Это не гарантия роста качества модели: оценивай набор по тому, сокращает ли он забытые требования, ручные шаги, повторные дефекты и неподтверждённые заявления о готовности. Новые правила добавляй по наблюдаемой причине, а не для объёма.
