# Упаковка инструментов

Главный администратор открывает **Каталог → Упаковать инструмент** и выбирает npm, GitHub или исходные файлы/архив. Сервер закрепляет точную версию npm, полный commit или файл GitHub Release с SHA-256, собирает готовые поставки и добавляет карточку. Дополнительные параметры нужны для выбора типа, подпапки, файла запуска и платформ. Если метаданных недостаточно, исходник необходимо уточнить перед сборкой.

Операция, карточка и привязка к исходному ассету сохраняются согласованно. Закрытие окна и перезагрузка страницы не меняют уже принятый запрос. Повтор запроса с тем же UUID возвращает прежнюю операцию; изменение содержимого с прежним UUID отклоняется. Серверная очередь ограничена десятью заданиями, выполняется одна сборка. Ожидающие операции переживают перезапуск, прерванная сборка получает явную ошибку. Статус упаковки не означает, что инструмент уже запускался на каждой платформе.

Готовая карточка устанавливается в связанный проект через мост и API Gateway. Первая установка точной версии требует предусмотренного проектом одобрения. Кнопка **Скачать поставку** возвращает tar.gz с неизменяемым `asset.json`, точными исходными и runtime-байтами, сохранённым публичным рецептом при его наличии и README. Отдельное скачивание `asset.json` доступно рядом. Оба экспорта читают сохранённую историю, включая после очистки временных файлов.

## Один формат результата

Единственный переносимый источник карточки — `neurocenter-assets` v1, проверяемый пакетом `@neurocenter/asset-contract`. Нативные `toolpkg` v5, `skillpkg` v4 и model bundle остаются собственными форматами доставки внутри envelope.

Сборка инструмента сохраняет:

- `asset.json`: исходник, версия ассета, карточка и точная SHA-опись платформ;
- `artifacts/<sha256>.tar.gz`: готовые нативные архивы, проверяемые по содержимому;
- `source/<sha256>.source` для archive-исходника: точные исходные байты до 256 МиБ, включая бинарный архив; расширение не означает JSON или UTF-8;
- `recipe.json`, `provenance.json`, descriptors и npm locks как свидетельства сборки.

Последние файлы не являются дополнительными форматами импорта. Поля `runtimeArtifacts` не дублируются в карточке: общий адаптер получает их из `delivery.artifacts`. Локальная сборка использует `source.type: archive` и content-only delivery без выдуманного публичного URL. Сервер удерживает и проверяет исходный снимок и готовые архивы перед публикацией. npm и GitHub сохраняют точные исходные pins.

Скачанная браузером поставка после безопасной распаковки сразу пригодна для `tools:publish -- --asset <папка>/asset.json --dry-run`, без переименования или перекладывания файлов. Один и тот же layout используют builder, публичный экспорт и импорт CLI. Публичный рецепт, если он объявлен, находится ровно по `recipe.path`, ограничен 1 МиБ и проверяется по SHA. Пути, ссылки и конфликтующие роли отвергаются до публикации.

Повтор установки использует готовые байты выбранной версии, не разрешает транзитивные зависимости заново. Старая версия и связанные с ней проекты сохраняются при выпуске следующей.

## Источники

| Источник | Поведение |
| --- | --- |
| npm | Точная версия закрепляется до очереди. Production-зависимости готовятся отдельно для каждой цели с `--ignore-scripts --no-bin-links`. TS/TSX компилируется в готовый JS. Клиенту npm и компилятор не нужны. |
| GitHub | Публичный HTTPS-репозиторий, полный commit и безопасная подпапка. Загрузка codeload закрепляется по commit. Защита downloader проверяет публичный адрес, ограничение размера, SHA и cache; опасные пути и ссылки TAR отклоняются. |
| JS/TS-папка | Файлы UTF-8, безопасные переносимые пути, обычные файлы без ссылок. Зависимости готовятся на сервере. `.d.ts`, `.d.mts`, `.d.cts` не являются исполняемыми исходниками. |
| ZIP/TAR | Браузер/сервер проверяют `.zip`, `.tar`, `.tar.gz`, `.tgz` до сборки и используют тот же файловый pipeline. До 8 МиБ архива, 100 файлов, 1 МиБ на файл, 5 МиБ распакованного содержимого. Дубликаты, traversal, ссылки, шифрование, повреждения и превышение лимитов отклоняются. |
| Готовая поставка в GitHub / Release | Рецепт определяется по проверенным байтам. Mach-O, ELF и PE задают платформу; Python требует запускаемый .py и встроенный Python, Java — Main-Class в JAR и встроенную Java, .NET — готовую managed DLL, runtimeconfig и встроенный runtime. Несколько программ требуют явного выбора. |

Ссылка `/releases/tag/v1` показывает файлы релиза; `/releases/download/v1/file.zip` выбирает конкретный файл. Release ID, asset ID, тег, commit и SHA повторно проверяются перед постановкой в очередь. Обычный npm `main` без `bin` или признаков MCP/OpenCode остаётся библиотекой, а не автоматически назначенным MCP. JS/TS компилируются закреплёнными Node/esbuild; исходники Python, JVM, .NET, Go и Rust без готовой поставки не получают выдуманный системный компилятор. `neurocenter.tool.json` может служить явной подсказкой существующего проекта, но для обнаруживаемых готовых поставок не нужен.

Конфиги registry, `.env`, ключи, `.git`, `node_modules` и служебные файлы не включаются в локальную файловую поставку. Архив с готовыми зависимостями следует пересоздать из исходников. CJS-плагины получают проверенный ESM facade, сохраняя оригинальные пути и прямой CLI guard. Нативные архивы сохраняют права executable и бинарные байты.

## Команды разработчика

Из корня checkout команды `tools:*` выбирают установленный Node 24. Нужны сборочные зависимости и собранный `catalog-service` для native-валидации.

```sh
npm run tools:build -- --recipe scripts/catalog-plugins/examples/file-plugin/recipe.json --output output/example-context --dry-run
npm run tools:build -- --recipe scripts/catalog-plugins/examples/file-plugin/recipe.json --output output/example-context
npm run tools:publish -- --asset output/example-context/asset.json --dry-run
npm run tools:publish -- --asset output/example-context/asset.json
npm run tools:check
```

Recipe здесь — внутренний план исполнения builder, не формат каталога и не обязательный документ для пользователя. Внешний источник проходит проверку, подготовку по платформам, USTAR, SHA-опись, native-валидацию и экспорт общего envelope. JSON recipe не допускает shell-команд и install hooks. Подробные примеры источников находятся в `examples/` и `recipes/`.

`--dry-run` сборки и публикации проверяет локальные данные без сети, БД и создания output. `--publish` сборки вызывает тот же импорт и несовместим с `--dry-run`. `--progress` выводит JSONL с реальным числом подготовленных платформ. Output должен быть новым или пустым, не пересекаться с исходниками и не содержать ссылок; готовая поставка не перезаписывается.

Помощник публикации использует сессию главного администратора в локальном Gateway. Если dev SSO отключён, он может открыть собственную dev-сессию; иначе передайте `--cookie-file`. Он проверяет архивы, удерживает точные source/recipe-файлы в серверном SHA-хранилище и передаёт тот же `asset.json` в `POST /api/tool-builds/imports`. Большие исходники не превращаются в base64 внутри JSON. Общая source/native-привязка сохраняется согласованно. Повтор после сетевой ошибки использует неизменённый envelope. Новый request UUID не создаёт ещё одну карточку того же source ID/version. Приватные cookies не попадают в descriptor.

Встроенные рецепты проходят тот же builder. Подготовка набора создаёт локальный репозиторий исходников с `index.json`, проверяемыми descriptors и архивами:

```sh
node scripts/catalog-plugins/prepare.mjs --output output/catalog-next --only project-context,git-context --dry-run
node scripts/catalog-plugins/prepare.mjs --output output/catalog-next --only project-context,git-context
```

Изменение адаптера получает новую ревизию `pack.N`; опубликованные байты прежней ревизии не заменяются. OpenCodeRAG использует только платформы, для которых существует готовая поставка. Явный запрос неподдерживаемой платформы отклоняется.

## Публичный экспорт

Исходники общего каталога находятся в отдельном публичном [neurocenter-assets](https://github.com/ghost-raven1/neurocenter-assets). Выборочный импорт из него выполняет обычный каталог. Старт окружения не заменяет пользовательские карточки сборкой presets.

```sh
node scripts/catalog-plugins/release.mjs --asset output/example-context/asset.json --release team-tools-v1 --output output/team-tools-v1 --dry-run
node scripts/catalog-plugins/release.mjs --asset output/example-context/asset.json --release team-tools-v1 --output output/team-tools-v1
```

Экспорт создаёт новую source version, добавляет предполагаемые Release URLs и сохраняет точные native pins. Результат помечен `published: false`: публикация GitHub Release и проверка фактического inventory/байтов должны пройти до добавления его в публичный индекс. Наличие URL в подготовленном descriptor само по себе не является квитанцией публикации.

Для локальных моделей применяется тот же envelope; отдельный native producer и offline-верификация описаны в [local-embedding.md](../../docs/local-embedding.md). Управление моделью, содержательная проверка и установка выполняются каталогом через Gateway.
