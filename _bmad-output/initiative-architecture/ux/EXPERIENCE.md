# EXPERIENCE.md — user paths, progressive disclosure, состояния, тупики

Пары с `DESIGN.md` (внешний вид) для entry «UI-polish + UX-спека». Пилотный пользователь — «вообще» (состав
пилота Q1 определяется пользователем отдельно): пилот идёт на **локальном auth-режиме как interim**
(решение из epic-pilot, 2026-11-06: Blitz IdP — после пилота, эпик 3; вход — oauth2-bridge `/auth/login`, не dev-обход).
Контракт: PRD UJ-1 (вход), UJ-3 (устройство), NFR-1 (ядро без документации, completion-rate, число шагов),
NFR-3 (каждая ошибка actionable, recovery на каждый failure mode), FR-901 (4 роли, интерфейс ограничивает).

Роли (PRD «Пользователи и роли», код — `features/UserBlock/roles.ts`): **Главный админ** (4, всё),
**Админ проекта** (3, всё кроме `assign_admin`/`maintenance`), **Разработчик** (2, read+content+ops),
**Наблюдатель** (1, только read). Доступ к проекту = min(уровень активной роли, роль-грант в проекте) —
`roles.ts:89-107`.

## 1. Карта user paths (вход → панель → ядро → админ)

### P1. Вход (UJ-1)
```
1. Открывает панель (nginx) → / → redirect /start (routes.tsx:43-45)
2. Core: authInit → GET /auth/me
   ├─ 401/нет сессии → LoginScreen: «Войти в Нейроцентр» → window.location.assign('/auth/login?returnTo=…')
   │   (actions.ts:79-84) → oauth2-bridge → IdP (Blitz / локальный режим) → back → /auth/me → app
   ├─ 403 → LoginScreen с «Доступ к рабочему пространству не подтверждён. Обратитесь к администратору.»
   │   (UserBlock/redux/reducers.ts:55)
   └─ ошибка сети → LoginScreen с «Не удалось подключиться к серверу. Проверьте соединение и повторите вход.»
       (reducers.ts:64)
3. Точки решения: (a) нет сессии → IdP; (b) сессия есть, но authInit ещё pending → LoginScreen flash
   (см. D10 — дефект); (c) 403 → «обратитесь к администратору» (тупик, если админ не определён в пилоте — D11).
```

### P2. Первая полезная операция (ядро, NFR-1)
Два равноправных входа (PRD UJ-1: «чат с агентом проекта или открытие карточки инструмента»):
```
A. Чат: шапка → [Чат] (ChatLauncher)
   ├─ нет доступа к проектам → кнопка disabled + tooltip «Для чата нужен доступ к проекту. Подключить проект»
   │   → /start (ChatLauncher.tsx:60-91) — actionable
   ├─ есть проект (из ?p или страницы) → ChatOverlay (modal 1280px): выбор модели (автопервый готовый),
   │   выбор проекта/режима (личный/командный/системная роль), отправка
   └─ нет модели в проекте → панель «Подключить модель» → /store?tab=models (ChatOverlay.tsx:210-219)
B. Карточка инструмента: /store (или вкладка «Каталог» проекта) → AppCard → StoreDetailsModal:
   провенанс (версия/SHA/издатель — FR-203), действия (установить в проект, история версий)
```
Число шагов P2 сейчас: вход → [Чат] → (выбор модели авто) → сообщение = **2 клика после логина** (хорошо);
но при каждом F5 добавляется лишний login-flash (D10).

### P3. Подключение компьютера и настройка проекта (UJ-3)
```
/start «Начало работы» (свёрнутый мастер, 6 шагов, UnifiedProjectSetup.tsx:151-487):
  Шаг 0 Мост:  [Подключить компьютер] → ссылка-паринг (?connect=…) → BridgePairing:
     сверка отпечатка → «Подключить компьютер» → «Ждём ответ компьютера…» (30 c, pairingProgress.ts:39)
     → timeout: warning «Компьютер ещё не ответил… нажмите «Проверить снова»» (pairingProgress.ts:62-63)
  Шаг 1 OpenCode: автопроверка (startAutoChecks) / установка через мост
  Шаг 2 Провайдеры: LocalOpenCodeProvidersStep (версия auth-конфига)
  Шаг 3 Папка проекта: выбор проекта → «Связать папку проекта» (WorkspaceBindingWizard)
  Шаг 4 Агенты и инструменты: AgentCatalog (embedded) + StartProjectAssets (скиллы/MCP/плагины)
  Шаг 5 Проверка: «Проверить актуальное состояние» + LocalInstallations (статусы установок, repair)
Точки решения: компьютер не ответил → «Проверить снова» / «Открыть подключение моста» (help-модалка,
:488-512); проект недоступен → «Выберите действующий проект» (:138-140); нет проектов → «Мои проекты» (:145-147).
Состояние мастера в URL (?setup&step=N) — переживает перезагрузку.
```

### P4. Проекты (единица продукта, FR-101)
```
/projects: список (таблица: имя, папка на компьютере, состояние, данные, копия знаний, активные операции,
  действия) + поиск + «Создать проект» (Permission projects#create + флаг 'projects')
  → /projects/:id (вкладки, ProjectDetail.tsx:235-253, ?tab= deep-link):
    Обзор | Сотрудники | Каталог (Store embedded) | База знаний (RAG: quota, sync, restore)
    | Обучение (опыт→гипотезы→кандидаты, UJ-4) | Снимки (FR-104) | Резервные копии | Квоты | История (операции)
  Права на вкладки: quotas/backups — уровень ≥3; audit — только Главный админ (canUseTab, :93-95).
  Удаление проекта: Modal.confirm danger, level ≥3 (:255-297) — отказ onOk держит модалку для повтора (:290).
```

### P5. Каталог / «Магазин» (FR-2xx)
```
/store (общий каталог виден level ≥3; проектный — участникам): поиск/фильтры, AppCard-сетка
  → карточка: провенанс + «Установить в проект» (picker модалка, :1241-1266)
  → локальная установка через мост: InstallPlanModal (план) → операции (queue, progress)
  → недоступные назначения: UnavailableProjectAssets (retired-версии и т.п.) с «перепроверить»
Публикация (Главный админ/админ): ToolPackagingModal (npm/архив/репозиторий → build → package → publish),
  recovery: buildRecovery, nameConflictRecovery, AssetImportRecovery.
```

### P6. Админ-сценарии
```
/access: участники платформы, назначения по проектам, «фактические права текущей роли» (FR-902: главный
  админ добавляет по почте; письма вне контракта)
/maintenance: capacity, backup-статус + «Сделать бэкап», restore (WebRestore), лимиты (FR-1001..1003)
/audit: транзакционный аудит (FR-903): события, фильтры, детали
/settings: источники каталога, bridge-источники
/operations: глобальная очередь (drawer из шапки + legacy redirect /operations → drawer ?operations=open)
  → OperationDetail (drawer): прогресс, retry (CAS: requestKey+expectedDigest), cancel
```

### P7. Обучение (UJ-4)
```
/projects/:id?tab=learning: Опыт (добавить запись) → «Построить гипотезы» → Проверка → Кандидаты знания
→ одобрение админа проекта (только одобренная версия в контексте, FR-502) → откат/отзыв с аудитом (FR-503).
```

## 2. Что видит пилотный пользователь на первом экране (NFR-1)

**/start, авторизован, роль ≥1** (`UnifiedProjectSetup.tsx`):
- `PageHeading` «Начало работы» + описание «Подключите мост и настройте проект по шагам» + кнопки
  «Помощь» / «Мои проекты» (второстепенные).
- Одна карточка: заголовок «Подготовьте компьютер и проект» + строка-схема «Мост → OpenCode → провайдеры →
  папка проекта → агенты и инструменты → проверка» + **один primary-кнопка** (смысл зависит от состояния:
  «Начать настройку» / «Проверить OpenCode» / «Посмотреть состояние и настройку» — полировка DESIGN.md P2.11).
- Мастер **свёрнут** до первого нажатия — сложность не показана заранее (правильное progressive disclosure).

**Шапка** (постоянная): хлебные крошки; справа: компьютер, выбор проекта (скрыт без проектов —
`ProjectTargetSelect.tsx:20-22`), Операции (badge+прогресс, tooltip со статусом — `OperationsButton.tsx:20-33`),
Чат, пользователь (роль-переключатель).

**Опционально/скрыто** (раскрывается по готовности): wizard-шаги (по клику), drawer «Операции»,
help-модалка, Swagger-ссылка (группа «Справка»), feature-flag-функции (установщик, unified setup,
help center — с `FeatureAvailabilityNotice` и причиной), «Мониторинг моделей» (только если задан
`VITE_MODEL_MONITOR_URL`).

**Принцип по факту**: сложность не убрана, а *отложена* — и это соответствует NFR-1. Дефекты: login-flash
(D10), непоследовательность primary-CTA (DESIGN.md P2.11), 5 контролов шапки сразу на первом входе.

## 4. Progressive disclosure (что/когда показывается)

1. **По аутентификации**: до `authInit` — (дефект) LoginScreen; после — app. Должно быть: splash
   «Проверяем сессию…».
2. **По роле (FR-901)**: навигация фильтруется `routePermissions` (`Core.tsx:129-132`); вкладки проекта —
   `canUseTab`; действия — `Permission`/`roleCan`/`FeatureButton`. Проблема: три разных визуальных
   результата «нет права» (скрыто / 403 / disabled+tooltip) — закрепить единый паттерн (DESIGN.md P1.5).
3. **По готовности данных**: `ProjectTargetSelect` скрыт без проектов; `ComputerHeader` показывает
   статус компьютера; OperationsButton-tooltip меняется по состоянию (доступ отозван / stale / прогресс /
   «Нет активных операций»); empty-состояния каталога/проектов зависят от роли и данных.
4. **По feature flag**: `FeatureButton` (disabled + tooltip с причиной), `FeatureAvailabilityNotice`
   (Alert + «Проверить») — отключение не ломает просмотр данных (контракт: «visible explanation… without
   removing existing data», `FeatureAvailability.tsx:64-87`).
5. **По URL-состоянию**: `?p` (проект), `?tab` (вкладка проекта), `?setup&step` (мастер), `?operations=open`
   (drawer), `?connect` (pairing-модалка) — deep-link'и позволяют делиться состоянием и переживают перезагрузку.
6. **Слои сложности**: первый экран = 1 CTA; wizard раскрывает 6 шагов только по действию; drawer'ы
   (операции, детали) — по запросу; «Справка» + Swagger — для докопания.
