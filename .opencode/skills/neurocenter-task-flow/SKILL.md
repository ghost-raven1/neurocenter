# Выполнение задачи

Сначала установи результат, который нужен пользователю, и несколько наблюдаемых критериев готовности. Используй уже принятые решения и разрешения. Новые сообщения обычно уточняют текущую задачу; меняй цель, когда пользователь явно её заменяет. Уточняй только то, что существенно меняет результат и не выводится из контекста.

Проверь относящиеся к задаче исходники, Git-состояние и существующие средства проверки. Обозначь предположения и короткий план. Для простого изменения сократи этот процесс до необходимого минимума. Держи реализацию в авторизованном объёме; вопросы о состоянии выполняй без побочных изменений.

При исправлении дефекта сначала воспроизведи отказ на наблюдаемом поведении, затем внеси минимальную правку. Для новой функции проверь основной путь и реальные границы её использования. Не расширяй покрытие тестами, которые повторяют реализацию без проверки полезного свойства.

Параллельные независимые задачи делегируй с точным владельцем файлов, входом, ожидаемым результатом и границами запуска. Общие файлы меняет один владелец. Итог собирает основной агент. Для существенного изменения запроси независимое ревью по исходной задаче и текущему diff; исправь подтверждённые замечания и повтори затронутые проверки. [Общие роли](references/roles.md).

Для пользовательского интерфейса применяй [критерии понятного сценария](references/interface.md). Для изменяемых API и библиотек используй актуальные первичные источники и доступные MCP. Инструмент выбирай под задачу; наличие инструмента само по себе не причина его вызывать.

Проверь критерии готовности подходящими командами проекта. Повторяй и расширяй проверки при новых изменениях, отказах или остающихся рисках. Зелёный unit-тест не подтверждает работу всего сценария. Сохраняй отдельно пройденное, пропущенное и непроверенное; для покрытия указывай область измерения. [Проверка и продолжение](references/verification.md).

Заканчивай результатом: что изменилось, чем проверено и какое существенное ограничение осталось. Не называй готовым то, что подтверждено только планом, сборкой или заглушкой. Если работа не завершена, оставь точку продолжения с конкретным следующим шагом.

Загружай дополнительные инструкции только по необходимости:

- [Каталог 64 ролей](references/catalog.md) — для выбора нужного специалиста; каждый профиль имеет отдельный skill. Назначай только относящиеся к задаче роли с учётом доступной параллельности.
- [Codex](references/codex.md) — для делегирования и передачи контекста в Codex.
- [OpenCode](references/opencode.md) — для проектных команд и подагентов OpenCode.
- [Neurocenter](references/neurocenter.md) — только при работе с этим проектом; команды и ограничения других проектов проверяй в них самих.
