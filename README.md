# Neurocenter — Нейроцентр

Веб-каталог инструментов и знаний команды: проекты, скиллы, MCP-серверы, плагины OpenCode и локальный мост для работы с папками пользователя.

## Возможности

- Общий и проектный каталог, версии и зависимости инструментов.
- Вкладка «Модели»: добавление моделей Ollama, назначение проектам, запуск и проверка хостинга с прогрессом.
- Упаковка npm-пакетов, публичных Git-репозиториев, ZIP/TAR-архивов и подготовленных приложений разных runtime.
- Установка, настройка, диагностика и восстановление через локальный MCP-мост.
- Синхронизация проектных баз знаний LanceDB ↔ PostgreSQL/pgvector.
- Локальная модель эмбеддингов с отдельным API и весами внутри проекта.
- Локальная обработка изображений: описание, чтение надписей и ответы на вопросы.
- Роли, отзыв доступа, журнал операций и транзакционный аудит изменений.
- Флаги функций: отдельный сервис и управление хостингом моделей, сборкой инструментов и синхронизацией знаний в «Обслуживании».
- Полные резервные комплекты, расписание обслуживания, S3-доставка и контроль ресурсов.

Состояние: разработка и локальная приёмка. Production-допуск **NO-GO**: настоящий IdP, полная матрица клиентских платформ и независимое восстановление требуют отдельной проверки. Точные границы: [готовность](docs/implementation-readiness.md), [реализация](docs/current-implementation.md), [сценарии](docs/publication-scenarios.md).

## Быстрый старт

Нужны **Node.js 24**, npm и установленный Docker CLI/Engine; dev-скрипты рассчитаны на macOS/Linux. Node.js 24 нужен для локальной упаковки автономного моста. Compose устанавливается автоматически. Порт 5432 должен быть свободен.

```sh
git clone https://github.com/ghost-raven1/neurocenter.git
cd neurocenter
cp .env.example .env
node -e "require('node:fs').appendFileSync('.env','\nNEUROCENTER_INTERNAL_TOKEN='+require('node:crypto').randomBytes(32).toString('hex')+'\n')"
scripts/dev.sh install
scripts/dev.sh up
```

`install` сохраняет рабочий `docker compose` v2 или новее. Если плагина нет или он не поддерживает `up --wait`, скачивается закреплённый Compose 2.40.3 с проверкой SHA-256. Отдельная установка: `npm run compose:install`. Docker Engine устанавливается заранее; для `up` он должен быть запущен. [Платформы, повтор и восстановление при сбое](docs/compose-install.md).

Случайный внутренний ключ создаётся один раз в локальном `.env` и используется всеми сервисами; не публикуйте этот файл.

`feature-flags-service` запускается штатными dev/Compose-командами. Главный администратор переключает функции в «Обслуживании»; изменения защищены от конфликтующих сохранений и попадают в аудит. Значения хранятся в PostgreSQL и сохраняются при перезапуске. [Контракт и поведение при сбоях](docs/current-implementation.md#флаги-функций).

Интерфейс: <http://localhost:5173>. В шаблоне включён локальный вход `SSO_DISABLE=true`; для реального SSO задайте параметры своего IdP. Production-конфигурация проверяется отдельно и не допускает dev-авторизацию.

Dev-команда сама выбирает установленный стабильный **Node.js 24** до загрузки модулей проекта. Если Node из `PATH` или `NODE_BIN` отсутствует, имеет другую версию либо не запускается, скрипт ищет подходящий Node 24; выбранная версия используется также npm и дочерними процессами. Ничего не скачивается автоматически. Если подходящего runtime нет, команда завершается с понятной ошибкой до установки зависимостей, Docker и остановки прежних сервисов. При нескольких подходящих версиях можно задать `NODE_BIN` абсолютным путём к нужной. Остановка `scripts/dev.sh down` сохраняет PostgreSQL и данные. Проверки: `npm run check` или `scripts/dev.sh check`; они собирают проект и останавливаются при первой ошибке. Для Vitest обязателен согласованный JSON-отчёт: отсутствующий или повреждённый отчёт считается ошибкой даже при коде выхода 0. Сводка `.run/check/.../report.json` сохраняет причину отказа и отдельные счётчики passed, failed, skipped и todo.

Справка по командам: `scripts/dev.sh --help` (также работает `scripts/dev.sh up --help`). Установка, сборка и запуск показывают этапы и итог; `status` выводит готовность сервисов и адрес интерфейса, `tail` — последние 20 строк каждого лога. Подробный вывод npm и сборщиков сохраняется в терминале. Цвета включаются только в TTY; `NO_COLOR=1` отключает их явно.

Объём подготовки при запуске выбирается явно:

| Команда | Подготовка ассетов | Модели |
| --- | --- | --- |
| `scripts/dev.sh up --profile fast` | Использует сохранённые файлы и каталог; пропускает загрузку ассетов | Пропускает подготовку весов и запуск runtime |
| `scripts/dev.sh up --profile standard` | Предзагружает текущие ассеты без моделей по закреплённому источнику | Пропускает подготовку весов и запуск runtime |
| `scripts/dev.sh up --profile full` | Готовит всю закреплённую поставку | Предзагружает файлы и запускает runtime; модели активируются из каталога |

Все профили собирают приложения и запускают PostgreSQL с семью сервисами. `fast` относится к загрузке ассетов: npm при восстановлении зависимостей и Docker при отсутствии образа могут обращаться к сети. Сохранённые модели, ассеты и уже работающий хостинг остаются доступными. Без параметров используется `fast`. Подготовка файлов не добавляет карточки: их состав выбирает главный администратор отдельным импортом.

Подготовить только мост и инструменты без запуска приложений: `npm run assets:sync -- --without-models`; проверить их без сети: `npm run assets:verify -- --without-models`. Частичная подготовка сохраняет прежний кэш и не выдаёт квитанцию готовности всей поставки. Ошибка подготовки прерывает запуск до остановки прежних сервисов; повтор использует уже проверенные файлы.

Запуск привязан к каталогу проекта, даже если папка вызова была удалена или переименована. Готовность интерфейса включает компиляцию стилей Ant Design: ошибка Less не позволяет объявить фронт готовым по одному ответу HTML.

Повторный запуск распознаёт собственные процессы после переноса папки. При сбое показываются сервис, порт, код выхода и путь к его логу. Для сохранения существующей базы после переноса укажите прежнее имя Docker-проекта в `.env.local`: `COMPOSE_PROJECT_NAME=...` (имена видны в `docker compose ls`).

Запуск приложений сохраняет существующий состав общего каталога. Инициализация схемы моделей и хранилища скиллов также не добавляет демонстрационные карточки. Импорт ассетов — отдельное действие главного администратора с выбором, предварительным просмотром и проверкой файлов; наличие метаданных само по себе не подтверждает готовность инструмента.

Общий каталог наполняется в разделе **Ассеты**: главный администратор выбирает описания из публичного [neurocenter-assets](https://github.com/ghost-raven1/neurocenter-assets). Импорт проверяет происхождение, зависимости и байты, затем создаёт связанные версии карточек. Обновление источника само не меняет назначения проектов. [Формат и доставка](docs/assets.md).

При потере или повреждении `.run/processes.json` команды `up` и `down` находят сервисы по команде Node и рабочему каталогу проекта. После остановки `up` проверяет освобождение портов; оставшийся конфликт отменяет запуск с указанием сервиса и порта.

### Ассеты, запуск и обновление

Опубликованный источник поставки — `neurocenter-assets`; локальный упаковщик создаёт тот же source-формат. В приложении закреплены commit и SHA индекса: `services/shared/asset-source.lock.json`. Описания инструментов, скиллов, моделей и моста используют один source-формат; большие файлы лежат в Releases и проверяются по SHA-256 и размеру.

После установки корневых зависимостей (`npm ci --ignore-scripts`, Node.js 24) можно подключить Git-хуки:

```sh
npm run assets:init
```

Хуки после pull/rebase/смены ветки проверяют только описания. Они не загружают веса, не создают карточки и не активируют модели. Прежние пользовательские хуки сохраняются. `npm run update` выполняет `git pull --ff-only` и ту же проверку; локальные изменения отслеживаемых файлов останавливают обновление.

Предзагрузка выбранных файлов, без изменений каталога и runtime:

```sh
npm run assets:sync -- --asset mcp-filesystem
npm run assets:sync -- --without-models
npm run assets:verify -- --without-models
npm run assets:sync -- --metadata-only
```

`assets:verify` использует только сохранённые описания и файлы, без сети и записи. Профиль `standard` предзагружает текущие ассеты без моделей; `full` — все текущие ассеты и запускает общий runtime. Ни один профиль не импортирует карточки автоматически. Повреждённый файл не принимается как готовый; ошибка подготовки останавливает запуск до остановки прежних сервисов.

Файлы хранятся по SHA в `RUNTIME_ARTIFACT_DIR/.asset-source-blobs`, описания — в `.asset-source-metadata`. Квитанция `.run/assets-ready.json` содержит конкретный режим и набор ассетов; готовность частичного набора не означает готовность всех ассетов. `.env`, `.env.local` и окружение учитываются в этом порядке.

Модель выбирается в каталоге. Сервер подготавливает только проверенную поставку, импортированную из источника. Для каждой версии используется отдельный внутренний тег runtime; подготовка новой версии сохраняет версии, используемые проектами. Удалённые модели настраиваются через интерфейс или импорт конфигурации OpenCode. [Модели и подключения](docs/remote-models.md).

Установщик компьютера, архив моста и инструменты выдаёт API Gateway. Отсутствующий импорт моста возвращает понятную ошибку: случайный локальный архив не подставляется. Подготовка нового выпуска моста выполняется отдельно: `npm run bridge:prepare` создаёт нативные архивы и descriptor нового source-формата. Цели задаются через `--targets=darwin-arm64,linux-x64`; Linux glibc собирается через Docker, остальные отсутствующие цели — на целевой ОС. Для выпуска публикуются проверенные файлы и descriptor в `neurocenter-assets`.

Production запускает сервисы и миграции, а импорт ассетов остаётся явным действием главного администратора. [Установка](docs/production-setup.md), [обновление](docs/production-update.md), [восстановление](docs/production-recovery.md).

Если мост уже установлен, на странице «Начало работы» → «Компьютер» выберите «Мост уже установлен» и выполните команду подключения. Повторное скачивание не требуется; установка и обновление доступны отдельно. [Подключение, продление доступа и ограничения](docs/bridge-upgrade-recovery.md#подключение-уже-установленного-моста).

Зеркало OpenCode для всех систем готовится командой `node scripts/prepare-opencode.mjs`: 12 пакетов для восьми системных целей, включая обычные и baseline-варианты x64. Архивы и SHA-256 сохраняются в `bridge-dist/opencode/`; повтор использует проверенные готовые файлы. [Подробности установки](docs/catalog-mvp.md#автономная-установка).

## Структура

| Каталог | Назначение |
| --- | --- |
| `frontend/` | React, TypeScript, Vite, Ant Design, Redux Toolkit, Less |
| `services/` | NestJS, PostgreSQL/JSONB, pgvector, Socket.IO |
| `mcp/neurocenter-asset-sync/` | Локальный MCP и worker |
| `scripts/catalog-plugins/` | Общая упаковка и публикация инструментов |
| `scripts/embedding/` | Запуск, проверка и закреплённая версия локальной модели |
| `scripts/vision/` | Закреплённая vision-модель и обработка изображений |
| `scripts/models/` | Проверка и подготовка нативных model payload из выбранных asset descriptor, лицензии |
| `scripts/production/` | Настройка, обслуживание, backup/restore и обновление |
| `docs/` | Архитектура, контракты, runbooks и история проверок |

Файлы `.env`, `data/`, бинарные веса моделей, резервные копии, зависимости, сборки и локальные отчёты в Git не входят. Веса встроенных моделей входят в воспроизводимую поставку через закреплённый release, а опись, SHA и лицензии находятся в Git. В исторических документах ссылки на `output/` и `.run/` относятся к локальным свидетельствам; они не поставляются в публичном репозитории. Идентификаторы проектов, адреса, учётные записи и пользовательские пути в примерах и исторических отчётах обезличены. Внутренние сведения о рабочем стенде и расчёты инфраструктуры исключены из публичной документации.
