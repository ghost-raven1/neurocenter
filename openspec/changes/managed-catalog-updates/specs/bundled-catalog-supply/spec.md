# Spec Delta

## Purpose

Позволяет устанавливать и обновлять Нейроцентр с текущим немодельным каталогом из одного основного репозитория, сохраняя проверяемое происхождение и старые квитанции.

## ADDED Requirements

### Requirement: Rebuild prepares current catalog packages
Основная пересборка SHALL готовить текущую поставку моста и передавать запрос фактической подготовки встроенных немодельных пакетов в действующие очереди. Только новое описание источника SHALL NOT считаться обновлённым опубликованным пакетом. Сбой необязательного проверщика снимков SHALL оставлять исполнитель недоступным, сохраняя независимую подготовку моста и каталога.

#### Scenario: Пересборка при старом RAG и недоступном проверщике
- **WHEN** в общем каталоге остаётся управляемый OpenCodeRAG2.4.4, в текущих исходниках закреплён2.12.2 и сборка образа снимков завершается ошибкой
- **THEN** текущий мост подготавливается независимо, RAG проходит обычную очередь сборки и runtime validation, а успешная публикация создаёт новую редакцию общего каталога; прежние project pins и файлы сохраняются

#### Scenario: Повтор и ручная карточка
- **WHEN** подтверждение постановки потеряно или приложение перезапущено во время той же пересборки, либо пользователь изменил управляемую карточку
- **THEN** повтор использует тот же ключ/операцию, неизвестный исход не создаёт дубль, а изменённый head блокирует автоматическую замену до явного разрешения конфликта

#### Scenario: Отозванный владелец или выключенная функция
- **WHEN** настроенный администратор установки не подтверждён либо выключены необходимые флаги
- **THEN** новые действия не допускаются, прежние операции и результаты доступны, веса моделей не загружаются, а предыдущий опубликованный пакет сохраняется

### Requirement: Current source accompanies application Git
Система SHALL получать текущие немодельные описания, исходники, рецепты и точные dependency locks вместе с основным Git. Запуск не требует доступа к прежнему asset-репозиторию или GitHub Releases; неподготовленный optional runtime имеет явное состояние и путь подготовки.

#### Scenario: Недоступно прежнее хранилище
- **WHEN** новый собственный checkout не имеет blob-кэша, прежний asset-репозиторий и GitHub Releases недоступны, а обычный npm разрешён
- **THEN** базовый запуск и текущие описания немодельного каталога доступны; подготовка выбранного компонента использует проверенные локальные исходники и точные обычные зависимости

### Requirement: Immutable history and stable identity
Система SHALL сохранять прежние descriptor SHA, native ID, project pins, квитанции и историю; пересборка с иными байтами создаёт новую immutable версию. Новая текущая поставка не перезаписывает пользовательские карточки, forks, конфигурацию или активные задания.

#### Scenario: Старое закрепление и изменённая карточка
- **WHEN** сервер содержит старое закрепление, прежнюю квитанцию и пользовательское изменение общего инструмента
- **THEN** история остаётся читаемой, импорт новой текущей версии требует действующего явного разрешения конфликта и не создаёт дубликат стабильного инструмента

### Requirement: No implicit model weight delivery
Система SHALL доставлять веса hosting-моделей только по явному импорту GGUF/архива. Git pull, post-pull, install, up, full, синхронизация и восстановление прошлых выборов могут читать metadata, но не загружать веса автоматически.

#### Scenario: Сохранён прежний выбор модели
- **WHEN** обычное обновление выполняется с прежним сохранённым model ID
- **THEN** веса не скачиваются; интерфейс предлагает разрешённый явный импорт и не показывает отсутствующий runtime готовым

### Requirement: Verified local preparation preserves previous generation
Система SHALL проверять источник, lock, target, SHA и фактический комплект до активации. Отмена, повтор, нехватка файлов или отказ optional builder сохраняют предыдущую рабочую generation и дают явное продолжение.

#### Scenario: Несовместимый локальный архив
- **WHEN** пользователь выбирает архив с иной target либо несовпадающей SHA
- **THEN** компонент не активируется, прежние настройки и generation сохраняются; остальные готовые немодельные компоненты остаются доступны

### Requirement: Recipe and published runtime remain distinct
Система SHALL показывать source revision отдельно от версии готового source envelope и нативной редакции каталога. Готовность текущего подготовленного компонента требует успешного задания с точной application revision и совпадения его результата с текущим native head и активной квитанцией.

#### Scenario: В каталоге есть прежняя упаковка
- **WHEN** Git содержит новый RAG recipe, а каталог содержит прежнюю либо отдельно импортированную упаковку
- **THEN** интерфейс показывает точные исходники и прежнюю редакцию, предлагает явную подготовку и не объявляет пакет текущим или установленным

#### Scenario: Исходник обновился во время ожидания очереди
- **WHEN** сохранённое задание содержит прежнюю application revision, а текущая опись приложения уже изменилась
- **THEN** сборщик отклоняет подстановку нового рецепта под прежним UUID; исходное намерение, прежняя карточка и история доступны для отмены и новой явной попытки

#### Scenario: Adapter изменён без новой approval
- **WHEN** исходники adapter/helper отличаются от exact producer SHA, включённого в application revision
- **THEN** прежнее successful job не объявляет их текущими, новая подготовка не подменяет bytes; история, отмена и проверка accepted job остаются доступны
