# Spec Delta

## Purpose

Провести пользователя от подключения компьютера до проверенного окружения проекта через один последовательный мастер с понятным следующим действием.

## ADDED Requirements

### Requirement: One primary setup owner
По уточнению пользователя «Старый мастер не нужен» каждый `/start` SHALL использовать основной мастер. Прежний мастер и его render fallback MUST быть удалены. Исторические ссылки SHALL сохранять проект, код подключения, справку расширения и якорь. Выключение новых действий SHALL сохранять основной UI чтения состояния и восстановления.

#### Scenario: Historical folder or pairing link
- **WHEN** пользователь открывает прежний `step=1`/`step=2`, pairing или add-computer URL
- **THEN** открывается основной этап компьютера и папки; адресный контекст сохраняется при дальнейшей навигации, прежний мастер не отображается.

#### Scenario: Explicit primary stage
- **WHEN** ссылка содержит `setup=1` и этап основного мастера
- **THEN** открывается этот основной этап; оставшийся pairing-контекст не возвращает пользователя на прежний шаг при следующем переходе.

#### Scenario: Collapse with pairing context
- **WHEN** пользователь сворачивает мастер из ссылки с кодом подключения и затем возобновляет его
- **THEN** мастер остаётся свёрнутым до явного открытия, проект, код подключения, справка и якорь сохраняются; помощь открывает основное подключение, включая режим выключенных новых действий.

### Requirement: Bridge-first primary path
Основной `/start` SHALL вести по порядку: мост, пользовательский OpenCode, локальные провайдеры, проект и папка, агенты и инструменты, проверка. Первая доверенная связь MUST требовать запуска моста на выбранном компьютере и подтверждения доступа.

#### Scenario: New computer
- **WHEN** компьютер ещё не подключён
- **THEN** мастер предлагает одно основное подключение; после подтверждения последующие поддержанные операции выполняются через этот мост.

#### Scenario: Existing installation
- **WHEN** выбран уже подключённый компьютер с установленным OpenCode
- **THEN** мастер получает фактическое состояние через мост и продолжает настройку без повторной ручной установки.

### Requirement: Compact actionable stages
Каждый открытый шаг SHALL показывать актуальное состояние и одно основное действие. Пустые сводки, технические абзацы и повторные legacy-переходы MUST не занимать основной поток; помощь и восстановление MUST оставаться доступны на любом шаге.

#### Scenario: Project is not selected
- **WHEN** проект или папка ещё не выбраны
- **THEN** мастер показывает переход к выбору без повторных строк «Выберите проект» и недоступных проверок.

#### Scenario: Readiness needs attention
- **WHEN** проверка окружения завершилась ошибкой
- **THEN** видны конкретная проблема и следующее исправление; отдельные технические результаты доступны в подробностях.

### Requirement: Observed readiness and owned recovery
Мастер SHALL отделять навигацию, приём задания и подтверждённый результат. Смена компьютера или полномочий MUST отсекать поздние ответы; выключение допуска новых действий MUST сохранять историю, чтение и восстановление принятых операций.

#### Scenario: Response is lost
- **WHEN** после принятия установки или проверки потерян ответ
- **THEN** UI читает исходную квитанцию и не создаёт вторую операцию автоматически.

#### Scenario: User changes computer
- **WHEN** пользователь выбирает другой компьютер во время проверки
- **THEN** результат прежнего компьютера не подтверждает готовность нового; прежнее задание остаётся доступно в своей истории.
