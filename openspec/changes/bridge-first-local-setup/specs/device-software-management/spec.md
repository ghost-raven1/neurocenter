# Spec Delta

## Purpose

Позволить владельцу подключённого компьютера проверять и устанавливать OpenCode, наблюдать версию моста и управлять его обновлением с проверяемым результатом.

## ADDED Requirements

### Requirement: Actual user CLI observation
Система SHALL проверять пользовательский OpenCode через выбранный мост ограниченным по времени запуском `opencode --version`. Отчёт MUST содержать компьютер, время, состояние и фактическую версию при успехе; наличие SDK или встроенного probe MUST не заменять эту проверку.

#### Scenario: CLI exists
- **WHEN** пользователь выбрал подключённый компьютер
- **THEN** мастер запрашивает безопасное наблюдение и показывает найденную версию пользовательского OpenCode без ручной команды.

#### Scenario: CLI is missing or hangs
- **WHEN** команда не найдена, завершается ошибкой или превышает срок
- **THEN** отображается соответствующее состояние и действие установки либо повтора; операция не висит бесконечно и не подтверждает готовность.

#### Scenario: Worker fails before obtaining an observation
- **WHEN** общий worker либо транспорт завершается ошибкой до получения наблюдения CLI
- **THEN** existing completion `failed {}` сохраняется как непроверенный отказ со статическим серверным сообщением; время, статус CLI и версия не выдумываются, готовность не подтверждается.

#### Scenario: Observation receipt contains unsupported data
- **WHEN** наблюдение содержит другой device/job, неканоническое время, недопустимую версию, stdout/stderr, путь либо лишнее поле
- **THEN** первый completion отклоняется до изменения результата и Operations; `installed|missing` принимаются только с `succeeded`, `failed|timed-out` — только с `failed`.

### Requirement: Bridge-managed OpenCode installation
Владелец компьютера SHALL запускать установку OpenCode через подключённый мост без выбора фиктивного проекта. Установка MUST проверять платформу и поставку, сохранять ручные настройки и подтверждать результат фактическим запуском установленного CLI.

#### Scenario: Empty computer after bridge connection
- **WHEN** пользователь запускает установку OpenCode
- **THEN** он видит её стадии и конечную версию; ошибка сохраняет предыдущую рабочую установку и доступное продолжение.

#### Scenario: Existing newer CLI
- **WHEN** обнаружен более новый либо ручной пользовательский OpenCode
- **THEN** мастер предлагает использовать его и не выполняет скрытое понижение версии или замену ручной установки.

### Requirement: Truthful bridge versions and update
Карточка выбранного компьютера SHALL показывать сообщённую версию моста и свежесть подключения. Доступное обновление MUST определяться проверенной совместимой поставкой; действие обновления MUST сохранять видимый ход и подтверждать результат новым работающим мостом.

#### Scenario: New compatible release is available
- **WHEN** установлена прежняя версия и площадка имеет проверенную совместимую новую поставку
- **THEN** видны обе версии и действие «Обновить»; приём запроса не выдаётся за завершённую установку.

#### Scenario: Update is interrupted
- **WHEN** обновление не завершилось либо ответ потерян
- **THEN** состояние остаётся наблюдаемым по исходной операции; восстановление сохраняет подключение, настройки и рабочую версию, а новая попытка не создаётся скрыто.

#### Scenario: Device report is stale
- **WHEN** компьютер недоступен либо отчёт устарел
- **THEN** версия обозначена как последнее наблюдение; новая установка не обещается выполненной, а проверка связи остаётся доступной.

### Requirement: Scoped admission and recovery
Новые действия SHALL проверять владельца компьютера, актуальные полномочия, флаг и capability при приёме и исполнении. Выключение функции MUST сохранять чтение, исходные квитанции и разрешённое восстановление; произвольная команда от браузера MUST не исполняться.

#### Scenario: Authority changes after admission
- **WHEN** исполнитель получил задание после отзыва прав или смены выбранного компьютера
- **THEN** он проверяет свежие права и точный target; чужая установка или результат не принимаются.

#### Scenario: Feature is disabled after acceptance
- **WHEN** `computer_setup` либо его зависимость выключены после приёма точного request
- **THEN** новые admission/claim/authorize запрещены, а история, исходный receipt, exact request replay, разрешённая отмена и completion принятого результата сохраняются при соответствующих правах.

#### Scenario: Cancelled observation acknowledges late completion
- **WHEN** собственник отменил `inspect-opencode-cli` в queued/running/reconciling и мост позднее прислал completion
- **THEN** поздний ACK не заменяет отмену результатом CLI; принятый terminal receipt повторяется без нового исполнения, а изменённый terminal-result конфликтует.

### Requirement: Canonical CLI identities
Идентификаторы компьютера, задания и request key нового CLI-контракта SHALL использовать канонические UUID в нижнем регистре. Схема и runtime MUST согласованно отклонять неканонические идентификаторы: admission проверяется до поиска компьютера, observation — до изменения результата. Существующие идентификаторы и хеширование других device jobs не изменяются.

#### Scenario: Noncanonical CLI admission identity
- **WHEN** новый CLI-запрос содержит UUID с буквами в верхнем регистре
- **THEN** вход отклоняется как некорректный до поиска компьютера, новое задание не создаётся и процесс не запускается.
