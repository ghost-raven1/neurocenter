# Spec Delta

## Purpose

Команда запускает полный цикл выбранного агента от сообщения и получает проверяемую квитанцию в том же разрешённом диалоге, сохраняя личные границы компьютера и восстановление после отказов.

## ADDED Requirements

### Requirement: Explicit selected-agent launch from a saved message
Система SHALL запускать задачу методики от опубликованного сообщения пользователя только после явного выбора пригодного агента, компьютера, папки и проверок. Исходный текст и связь с сообщением MUST сохраняться независимо от обычного черновика чата.

#### Scenario: Start from an existing question
- **WHEN** администратор открывает выполнение задачи у сообщения пользователя
- **THEN** мастер показывает исходный текст, адресатов результата и выбор агента; открытие не отправляет запрос к модели и не очищает черновик чата.

#### Scenario: Missing executor or target
- **WHEN** агент, подтверждённая настройка, подключение или capability недоступны
- **THEN** отправка заблокирована с доступным продолжением, текст сохраняется и default агент автоматически не подставляется.

### Requirement: Durable atomic origin and exact recovery
Система SHALL атомарно связывать задание с исходным сообщением того же проекта и диалога. Повтор принятого запроса MUST возвращать прежнюю квитанцию; изменение origin с прежним ключом MUST отклоняться.

#### Scenario: Lost admission acknowledgement
- **WHEN** принятие запроса подтверждено сервером, но браузер потерял ответ и перезагрузился
- **THEN** восстановление находит прежнее задание и связь; повтор не создаёт дополнительное исполнение.

#### Scenario: Origin mismatch
- **WHEN** запрос ссылается на другой диалог сообщения, проект, несуществующий source или меняет origin принятого ключа
- **THEN** сервер отклоняет новый запрос без постановки задания и изменения чужой истории.

### Requirement: Shared receipt with private execution authority
Система SHALL показывать участникам исходного диалога структурированную квитанцию с точным исполнителем и реальными проверками после перезагрузки. Личные payload, модельные настройки и сырые журналы MUST не попадать в общий результат. Единственный исполнитель MUST не запускать дополнительную сводку.

#### Scenario: Another room member reads the completed task
- **WHEN** другой действующий участник перечитывает исходное сообщение после завершения задания
- **THEN** он видит состояние, pinned исполнителя и безопасный результат, сохраняя прежние ограничения чтения и отмены личных заданий владельца компьютера.

#### Scenario: Long execution history
- **WHEN** у исходного сообщения несколько запусков
- **THEN** последняя квитанция видна сразу, предыдущие доступны ограниченными страницами; cursor другого сообщения не раскрывает его данные и ошибка загрузки сохраняет уже прочитанное.

#### Scenario: Private command arguments in a shared launch
- **WHEN** прямой API запрос общей задачи передаёт произвольные аргументы вместо поддержанных UI команд проверки
- **THEN** он отклоняется до постановки задания; приватный legacy workflow сохраняет свой прежний контракт команд.

#### Scenario: Access revoked during execution
- **WHEN** инициатор теряет доступ к закрытому диалогу до публикации результата
- **THEN** поздние данные исполнения не публикуются в диалоге, карточка объясняет отсутствие опубликованного результата и подтверждение локального исхода не вызывает повторного выполнения.

### Requirement: History recovery and cancellation survive disablement
Система SHALL управлять новыми запусками отдельным флагом и актуальными правами. При OFF уже принятые квитанции, проверка отправки и разрешённая владельцу отмена MUST оставаться доступны.

#### Scenario: Disabled after acceptance
- **WHEN** функцию выключают после принятия задания
- **THEN** новые задания не создаются, но прежняя связь и история читаются; exact replay возвращает прежнюю запись без новой работы.

#### Scenario: Owner cancels an active task
- **WHEN** действующий владелец отменяет ожидающее, работающее или сверяемое задание
- **THEN** последующая авторизация исполнения прекращается и поздний успешный ответ не заменяет принятое состояние отмены.
