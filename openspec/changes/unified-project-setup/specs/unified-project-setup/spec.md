# Spec Delta

## Purpose

Единый мастер на странице начала работы позволяет подготовить компьютер и окружение выбранного проекта, сохраняя прогресс, точные назначения и понятное продолжение после отказа.

## ADDED Requirements

### Requirement: One explicit bootstrap entry
Система SHALL по умолчанию открывать основной режим с одной точкой входа «Установить OpenCode», объединяющей OpenCode, мост и подготовку проекта. По уточнению пользователя «Старый мастер не нужен» прежний мастер и его render fallback MUST быть удалены; исторические ссылки SHALL использовать основной мастер. Первый запуск установщика MUST оставаться явным локальным действием.

#### Scenario: First installation
- **WHEN** пользователь открывает единый мастер на `/start`
- **THEN** он получает общую команду с проверенным адресом этой площадки, видит порядок действий и может продолжить подключение без поиска другого установщика.

#### Scenario: Partial bootstrap failure
- **WHEN** OpenCode установлен, но установка или подключение моста завершились отказом
- **THEN** установленный OpenCode и настройки сохраняются, исходный код ошибки не подменяется успехом и доступен повтор только моста.

#### Scenario: Historical setup link
- **WHEN** пользователь открывает прежний `step=1`/`step=2`, pairing или add-computer URL
- **THEN** основной мастер открывает этап компьютера и папки; прежний `step=0` открывает основной этап установки. Явный `setup=1` сохраняет индексы основного мастера. Проект, код подключения, справка расширения и якорь остаются при дальнейшей навигации; прежний UI не отображается.

#### Scenario: Pairing fails
- **WHEN** подключение завершилось ошибкой и пользователь выбирает продолжение
- **THEN** открывается основной этап компьютера, просроченный `connect` и obsolete `legacy` удаляются, а проект, справка расширения, прочий query-контекст и якорь сохраняются.

#### Scenario: Help and resume
- **WHEN** пользователь открывает помощь, сворачивает мастер или возобновляет настройку
- **THEN** помощь возвращает к основному подключению и не обещает отдельный прежний мастер; сворачивание не теряет адресный контекст и не открывает мастер повторно из-за сохранённого кода подключения.

### Requirement: Actionable local setup continuation
Система SHALL показывать настройку локального окружения там, где она нужна выбранному сценарию, и давать доступное продолжение при отсутствии компьютера. Видимость следующего действия MUST учитывать готовность списка и полномочия пользователя.

#### Scenario: No computer for provider setup
- **WHEN** пользователь с правом управления провайдером получает подтверждённый пустой список компьютеров
- **THEN** доступно действие «Подключить компьютер», открывающее основной этап подключения с выбранным проектом; настройка провайдера не запускается автоматически. При непрочитанном списке или без права это действие не предлагается.

#### Scenario: Chat-only model catalog
- **WHEN** в каталоге нет действующих embedding-моделей
- **THEN** каталог не требует компьютер для OpenCodeRAG. При наличии действующей embedding-модели настройка назначения доступна пользователю с правом управления, в том числе когда фильтр показывает только назначенные проекту модели.

### Requirement: Project-scoped setup reuses existing approvals
Система SHALL настраивать папку, агентов, модель и назначенные ассеты выбранного проекта через существующие полномочия, immutable планы и квитанции. Выбор проекта MUST не устанавливать весь общий каталог или автоматически создавать учётные данные.

#### Scenario: Assigned project tools
- **WHEN** проект и подтверждённая папка выбраны
- **THEN** мастер показывает назначенные проекту навыки, плагины и MCP с точными версиями, даёт действующие шаги установки и настройки агентов в том же сценарии.

#### Scenario: Missing pin or permission
- **WHEN** у ассета нет проверенного pin, нужного права, одобрения или поддерживаемого runtime
- **THEN** новый запуск блокируется с конкретным следующим действием, выбранный проект и ранее принятые задания сохраняются.

### Requirement: Measured readiness and recoverable navigation
Система SHALL различать скачивание, подключение, доставку настроек и фактическую проверку runtime. Сохранённый этап мастера MUST не служить доказательством готовности; OFF MUST сохранять действующие историю и способы восстановления.

#### Scenario: Reload or stale report
- **WHEN** пользователь перезагружает мастер либо отчёт компьютера устаревает
- **THEN** выбранный проект и этап остаются доступны, а неподтверждённая папка или установка не показываются готовыми до актуального чтения.

#### Scenario: Understand progress before and after connection
- **WHEN** пользователь открывает последний шаг без выполнения установки или переходит между шагами клавиатурой
- **THEN** посещённые этапы не объявляются завершёнными; интерфейс отличает открытый шаг от наблюдённого состояния, сообщает о прогрессе в терминале до подключения моста и сохраняет доступный фокус.

#### Scenario: Setup feature disabled
- **WHEN** новая точка входа выключена после начала настройки
- **THEN** новые общие bootstrap запрещены, разрешённые история, состояние заданий и восстановление доступны в основном мастере; прежний UI не возвращается.
