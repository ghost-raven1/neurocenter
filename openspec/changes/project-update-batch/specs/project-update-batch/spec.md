# Spec Delta

## Purpose

Позволяет увидеть все проекты, где общий каталог новее закрепленной редакции, закрепить точные редакции одним подтверждением и следить за статусами установки — без поочередного открытия каталога каждого проекта.

## ADDED Requirements

### Requirement: Вкладка «Обновления проектов»
Система SHALL показывать вкладку «Обновления проектов» в общем каталоге, когда флаг `project_update_batch` включён и пользователь управляет каталогом хотя бы одного проекта (роль ≥ 3). Вкладка MUST перечислять назначения проектов, где закреплённая редакция устарела, — строки, в которых общий каталог предлагает более новую редакцию, чем закреплена в проекте. Вкладка не показывается в каталоге проекта (embedded) и при выключенном флаге.

#### Scenario: Есть обновления
- **WHEN** в одном или нескольких проектах закреплена редакция, а в общем каталоге опубликована более новая
- **THEN** вкладка показывает строку для каждого такого назначения с проектом, инструментом и версиями «текущая → новая».

#### Scenario: Обновлений нет
- **WHEN** все закреплённые редакции совпадают с общим каталогом
- **THEN** вкладка объясняет, что обновлений сейчас нет, и перечисляет проекты, чей каталог не удалось прочитать.

#### Scenario: Проект без права управления
- **WHEN** пользователь не управляет каталогом проекта
- **THEN** назначения этого проекта в вкладки не попадают.

#### Scenario: Флаг выключен
- **WHEN** флаг `project_update_batch` выключен
- **THEN** вкладка не существует, запросы каталогов проектов не выполняются, прямой URL `?tab=updates` возвращает пользователя на вкладку «Инструменты».

### Requirement: Массовое закрепление точных редакций
Система SHALL позволять закрепить показанные редакции одним подтверждением: перед закреплением показывается таблица точных версий (проект, инструмент, текущая, новая). Закрепление выполняется последовательно по проектам действующим API пинирования с CAS (expectedVersion и expectedManifest из закреплённой строки проекта). После батча каталоги MUST перечитываться.

#### Scenario: Подтверждение батча
- **WHEN** пользователь с правом управления нажимает «Закрепить редакции»
- **THEN** открывается подтверждение с таблицей точных версий; после согласия версии закрепляются последовательно, каждая со своим CAS.

#### Scenario: Параллельное изменение пина
- **WHEN** при закреплении сервер вернул конфликт (значение пина изменилось)
- **THEN** строка помечается «закрепление изменили параллельно», батч продолжается по остальным строкам, и каталоги перечитываются.

#### Scenario: Ошибка закрепления
- **WHEN** закрепление строки завершилось ошибкой без конфликта
- **THEN** строка помечается с причиной ошибки, батч продолжается, и показывается итог «закреплено X из N».

#### Scenario: Смена аккаунта или роли
- **WHEN** во время батча изменился аккаунт или роль инициатора
- **THEN** оставшиеся строки не закрепляются, итог не публикуется и каталоги не перечитываются чужим владельцем.

### Requirement: Живые статусы установки
Система SHALL показывать по каждой строке статус установки предложенной редакции из заданий моста (в очереди, устанавливается, установлено, сбой), не читая каталог проекта: задания моста глобальны и несут projectId, assetId, assetKind и version. Терминальный статус («установлено», «сбой установки») MUST относиться только к заданию, которое ставило именно предложенную редакцию: завершение установки прежней редакции не считается установкой обновления.

#### Scenario: Установка в процессе
- **WHEN** по назначению есть активное (в очереди или выполняемое) задание установки
- **THEN** строка показывает статус «устанавливается» или «в очереди» без отдельного запроса к проекту.

#### Scenario: Установка завершена
- **WHEN** последнее завершённое задание установки по назначению ставило предложенную редакцию
- **THEN** строка показывает «установлено» при успехе или «сбой установки» при отказе.

#### Scenario: Установлена только прежняя редакция
- **WHEN** по назначению есть завершённое задание, но только за предыдущую редакцию
- **THEN** строка показывает, что предложенная редакция ещё не установлена.

### Requirement: Установка по-прежнему с явным одобрением
Система SHALL сохранять одобрение установки в каталоге каждого проекта: вкладка закрепляет редакции, но не ставит их в очередь. Для перехода к установке каждая строка предлагает «Открыть проект».

#### Scenario: Переход к установке
- **WHEN** пользователь нажимает «Открыть проект»
- **THEN** открывается каталог этого проекта на вкладке «Инструменты», где установка новой редакции подтверждается планом как прежде.
