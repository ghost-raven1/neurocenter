# Design

## Context

См. proposal.md. Существующая tool_source_uploads ограничена 256 МиБ и не подходит для весов. Каталог и immutable версии находятся в Postgres; Gateway уже передаёт raw-потоки с backpressure.

## Goals / Non-Goals

**Goals:** отдельная таблица model_gguf_uploads, streaming SHA-256, ограниченный parser, единая транзакция приёмки и истории модели.

**Non-Goals:** загрузка весов по URL, конвертация, выполнение Modelfile, автоустановка Ollama, фиктивный bundle export.

## Decisions

- Используем отдельные UUID-файлы в runtime-artifacts/.gguf-imports, wx, nofollow, fsync, readonly. Альтернатива tool uploads нарушила бы действующий лимит и семантику.
- Поток держит session advisory lease; краткие проверки прав и lease-token останавливают отменённого владельца. При commit-неопределённости байты сохраняются до следующего повтора.
- Перед READY и ACCEPTED транзакция блокирует upload и platform_users; source_upload_auth_epoch защищает revoke/restore. Storage capacity проверяется перед записью и повторно перед READY/ACCEPTED.
- Parser читает заголовок до настроенного metadataBytes (64 МиБ по умолчанию), лимитирует количества и строки, пропускает неизвестные метаданные по типу. Поддерживает распространённые GGML scalar и quant типы; неизвестный tensor type требует обновления поддержки.
- Stable model ID получается из upload UUID. Accept fingerprint и модель фиксируются вместе с descriptor, history и audit. File SHA никогда не записывается как manifest SHA.
- Новая feature policy выполняется владельцем после поиска точной квитанции, чтобы OFF сохранял повторы. Fresh ACL проверяется независимо от флага.
- Лимиты читаются через RuntimeLimitsService и сохраняются в upload receipt; runtime intent использует этот snapshot. Настройки новых операций не обрывают принятые.
- Миграция 50 хранит RESERVED → CREATE_SENT → CREATED отдельно от приёмки. CREATE_SENT фиксируется до POST; любая неоднозначность разрешается только чтением manifest и tags, повторный POST не выполняется.
- Ollama 0.35.1 получает HEAD/POST blob и POST create с единственными model/files/stream полями. Owned alias зависит от UUID импорта, публичное имя пользователя не используется для перезаписи.
- Сверка читает ограниченный manifest из MODEL_STORAGE_PATH, требует один model layer с фактическим SHA/размером исходника и совпадение digest tags до/после чтения. Проба Ollama затем закрепляет настоящий manifest в истории модели.
- Browser UI передаёт File напрямую через общий axios-клиент с application/octet-stream и AbortSignal, не читая веса целиком. Процент upload обозначает передачу браузером; READY приходит только из проверенной квитанции.
- Контроллер UI сохраняет только UUID запроса через durableJournalOwner, отдельно использует полный authDataScope для File/ACK/callback fencing. Смена грантов не уничтожает квитанцию; смена роли или пользователя выбирает отдельный журнал. Новый допуск повторно читает серверный policy, существующий импорт использует собственный snapshot.
- Неопределённые ответы оставляют явную проверку состояния и точный повтор, отмена прерывает браузерную передачу и подтверждается отдельной серверной квитанцией. Принятая карточка не означает готовность inference. Launcher каталога интегрируется отдельным владельцем.
- UI не принимает регресс READY или terminal квитанции, сохраняя последний подтверждённый барьер даже после 404. Новый импорт и повторная активация контроллера заменяют состояние целиком, чтобы не переносить прежние File/model/receipt.

## Risks / Trade-offs

- Ограниченный parser не доказывает семантическую совместимость модели с Ollama → UI сообщает необходимость runtime-проверки.
- Сбой процесса после fsync до READY → сохранённый файл сверяется при следующем PUT; сервер не удаляет байты после неопределённого COMMIT.
- Внешние писатели файлов и Ollama не подчиняются DB lease → immutable локальные файлы проверяются повторно, runtime не получает обещаний CAS.
- Неопределённый CREATE_SENT без появившегося manifest → операция требует повторной проверки и диагностики Ollama; автоматический повтор создания запрещён.

## Migration Plan

Миграция 48 добавляет загрузки после неизменной 47, центральные лимиты добавляются отдельной 49, намерения runtime — 50. Сначала применяются миграции на собственном стенде, затем обновляются Catalog и Gateway. Отключение gguf_import запрещает новые импорты и сохраняет историю; model_hosting независимо управляет новыми запусками и проверками. Основная БД и работающие daemon не используются как тестовая фикстура.
