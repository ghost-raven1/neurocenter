# Proposal

## Why

Администратор должен импортировать имеющийся GGUF без публикации в GitHub Releases и без загрузки весов из сети. Проверенная загрузка и готовность runtime требуют отдельных свидетельств.

## What Changes

- Отдельный поток GGUF с настраиваемым пределом (64 ГиБ по умолчанию), серверным SHA-256, квитанциями, отменой и повтором по UUID.
- Ограниченная проверка GGUF v2/v3 LE и явный отказ split, adapter и projector.
- Приёмка создаёт существующую карточку модели с отдельным fileImport и пустым manifestSha256.
- Новые операции управляются флагом gguf_import; история, отмена и точный повтор принятого запроса остаются доступны при OFF.
- Отдельная активация в Ollama 0.35.1 через проверенный blob и files-create, устойчивое намерение и сверку manifest. Проба inference закрепляет manifest отдельно от SHA исходного GGUF.
- Компактный браузерный импорт: явный File, свежий лимит, подтверждение серверной проверки и карточки, восстановление по UUID без сохранения весов или ключей в браузерном журнале.

## Capabilities

### New Capabilities

- `gguf-model-import`: приёмка пользовательского файла в каталог моделей с устойчивой идентичностью.

### Modified Capabilities

Нет.

## Impact

Catalog models/gguf-import и gguf-runtime, Gateway raw forwarding, shared DTO и флаги, миграции 48 и 50 после отдельной центральной политики 49, frontend GgufImport и отдельный launcher каталога. Веса принимаются только из выбранного файла. Экспорт bundle не объявляется готовым; реальный daemon и модель требуют отдельной приёмки.
