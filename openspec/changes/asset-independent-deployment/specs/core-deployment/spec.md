# Spec Delta

## Purpose

Обеспечивает базовое развёртывание Нейроцентра при недоступном внешнем хранилище ассетов, сохраняя данные и понятное состояние дополнительных функций.

## ADDED Requirements

### Requirement: Asset-independent base startup
Система SHALL устанавливать и запускать базовый профиль без обращения к хранилищу ассетов, предзагрузки моделей и обязательной подготовки Native-поставки. Существующий контракт ассетов MUST входить в исходную поставку.

#### Scenario: Cold base deployment
- **WHEN** пользователь запускает документированный базовый профиль из чистого checkout с пустым asset-кэшем и недоступными asset-hosts
- **THEN** основные приложения достигают readiness, отсутствуют запросы к asset-hosts, доступны вход, проекты, база знаний и UI архивного импорта
- **AND** необходимые npm/ОС-зависимости устанавливаются штатно; полная автономность от всего Интернета не подразумевается

#### Scenario: Repeat preserves existing state
- **WHEN** базовый профиль запускается повторно на существующей установке
- **THEN** опубликованные архивы, установленный мост, ручная конфигурация, ключи, проекты и история не заменяются или удаляются

### Requirement: Explicit hosting weight import
Все профили штатного запуска SHALL оставлять получение весов hosting-моделей явному импорту GGUF/архива. Сохранённый выбор ассетов MUST NOT разрешать скрытое скачивание весов. Подключение провайдеров OpenCode и remote API SHALL оставаться отдельными поддерживаемыми маршрутами.

#### Scenario: Full profile with a saved model selection
- **WHEN** пользователь запускает full со старым сохранённым выбором моделей
- **THEN** веса не скачиваются; hosting runtime использует только уже подготовленный pinned image без pull/build, а отсутствие image показано как требующая подготовки дополнительная функция

### Requirement: Optional snapshot executor
Система SHALL различать готовность основных приложений и проверщика снимков. Без подготовленного исполнителя новые публикации снимков MUST быть недоступны, а история, отмена и восстановление сохраняться.

#### Scenario: Missing verifier image
- **WHEN** образ проверщика отсутствует при базовом запуске
- **THEN** запуск основных приложений успешен, состояние снимков явно сообщает о необходимой подготовке, image build не запускается

#### Scenario: Stale verifier cannot enable publication
- **WHEN** базовый профиль отключил исполнителя, но в базе ещё есть его свежий heartbeat
- **THEN** новая публикация снимка отклоняется как неподготовленная без изменения пользовательского feature flag и прежних подписей

#### Scenario: Re-enable verifier
- **WHEN** пользователь явно подготавливает проверщик
- **THEN** образ, SDK и сохранённая signing identity проходят существующие проверки, принятые проверки восстанавливаются по прежним lease-правилам
