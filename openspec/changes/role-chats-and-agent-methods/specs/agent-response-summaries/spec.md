# Spec Delta

## Purpose

Устранить повторный итог одиночного ответа и давать пользователю общую сводку только тогда, когда действительно ответило несколько агентов.

## ADDED Requirements

### Requirement: Conditional multi-agent summary
Система SHALL создавать отдельную сводку только после успешных ответов как минимум двух уникальных агентов. При одном ответившем агенте MUST отсутствовать отдельная сводка и дополнительный synthesis-вызов модели.

#### Scenario: One responder
- **WHEN** успешно отвечает один агент
- **THEN** пользователь получает его ответ без отдельной сводки

#### Scenario: Several responders
- **WHEN** успешно отвечают два различных агента
- **THEN** индивидуальные ответы сохраняются и появляется общая сводка

#### Scenario: Partial failure
- **WHEN** из двух выбранных агентов один ответил, а другой завершился ошибкой
- **THEN** система показывает единственный ответ и ошибку второго без сводки

#### Scenario: Several contributions from one responder
- **WHEN** один агент внёс несколько промежуточных ответов
- **THEN** это не считается несколькими ответившими агентами

### Requirement: Preserve historical and operational results
Система SHALL сохранять прежнюю историю, атрибуцию ответов, точный повтор и отмену. Краткое поле заголовка результата одной сервисной роли MUST сохраняться и не считаться многоагентной сводкой.

#### Scenario: Existing stored summary
- **WHEN** открывается ранее завершённый диалог
- **THEN** сохранённая история остаётся доступной без перезаписи результатов

#### Scenario: Retry missing response
- **WHEN** повтор добавляет успешный ответ второго агента
- **THEN** прежний ответ не перезапускается, а сводка соответствует фактически принятым ответам
