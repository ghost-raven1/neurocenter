# Proposal

## Why

Пользователю нужны отдельные понятные чаты сервисных ролей и полноценный цикл работы агентов по BMAD/OpenSpec внутри Нейроцентра. Текущий смешанный сервисный диалог, повторный итог одного агента и inference без доступа к локальным методикам не дают этот результат.

## What Changes

- Вместо общего «Сервисного чата» доступны отдельные приватные чаты каждой сервисной роли, с сохранением прежней истории и квитанций.
- Отдельная многоагентная сводка появляется только при нескольких фактически ответивших уникальных агентах; один успешный ответ не вызывает synthesis.
- Проектный цикл BMAD/OpenSpec получает версию методики, этапы, артефакты и задания локальному мосту: подготовка, изменение кода, проверки, проверяемый результат.
- Исполнение использует точную привязку проекта, ограниченную область файлов и действующие права; выключение новой функции сохраняет историю, отмену и восстановление.

## Capabilities

### New Capabilities

- `service-role-conversations`: приватный чат одной роли, доступная прежняя история, отправка/повтор/отмена.
- `agent-response-summaries`: условная сводка по нескольким фактическим ответам во всех исполнительных цепочках.
- `agent-method-workflows`: полный проектный цикл BMAD/OpenSpec через локальный мост с устойчивыми этапами, артефактами и проверками.

### Modified Capabilities

Нет существующих OpenSpec capabilities; поведение описывается впервые.

## Impact

Frontend ChatOverlay/SystemRoleChat/настройки проекта; Catalog system-role-chat, project-chat, model-chat, coordinator и новый владелец workflow; shared feature flags/contracts; задания и исполнитель локального моста. Потребуются совместимая миграция и тесты реальных границ. Основная рабочая БД не используется как QA-фикстура.
