# Spec Delta

## Purpose

Позволяет администратору изменять действующие ограничения без новой сборки и позволяет пользователю заранее узнать применяемые значения. Принятые операции и их квитанции сохраняют исходную политику независимо от следующих изменений.

## ADDED Requirements

### Requirement: Effective policy is explicit

Система SHALL возвращать авторизованному пользователю безопасную ревизионную политику текстовых операций и импорта GGUF с техническими границами поддерживаемых значений.

#### Scenario: User reads actual limits
- **WHEN** пользователь открывает форму загрузки
- **THEN** форма получает действующую политику сервера и показывает ограничения новых операций, без ключей и путей конфигурации

### Requirement: Fresh administrator authority and atomic configuration

Система MUST сохранять политику только при действующих правах главного администратора, совпавшей ревизии и корректных значениях. Изменение, аудит и квитанция SHALL фиксироваться атомарно.

#### Scenario: Concurrent edit or revoked role
- **WHEN** ревизия устарела либо права администратора отозваны до записи
- **THEN** изменение отклоняется, действующая политика не изменяется, введённый draft остаётся в форме

### Requirement: Exact recovery outlives feature admission

Система SHALL возвращать собственную принятую квитанцию при точном повторе запроса после потери ответа, уменьшения лимита или выключения настройки. Тот же ключ с другим содержимым MUST отклоняться.

#### Scenario: Lost ACK after lowering limits
- **WHEN** уже принятый запрос повторяется с прежними данными после уменьшения лимитов
- **THEN** возвращается прежняя квитанция без повторной мутации или проверки новых лимитов

### Requirement: Runtime owners enforce the selected policy

Новая операция MUST использовать актуальную политику и сохранять принятый снимок. Размеры загрузки, выдачи поиска и цитат SHALL реально проверяться исполнителем; UI не является границей авторизации.

#### Scenario: Admin changes text and GGUF limits
- **WHEN** администратор сохраняет допустимые значения
- **THEN** следующая загрузка и поиск используют новые значения, а уже принятый импорт GGUF продолжает по своему снимку

### Requirement: Valid policy fits supported transport and storage

Система MUST отклонять политику за техническими границами JSON-транспорта, схемы и безопасных целых чисел. Изменение политики SHALL не менять semantic profile, embedding dimensions, поколения и Quirk baseline.

#### Scenario: JSON expansion and old history
- **WHEN** допустимый UTF-8 текст или запрос расширяется при JSON-кодировании
- **THEN** поддерживаемый максимальный запрос проходит транспорт и ограничения сохранения, а старые квитанции остаются читаемыми
