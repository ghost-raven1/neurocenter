# Proposal

## Why

Когда в чате нет готовой модели, пользователь уходит в каталог моделей, ищет свою модель и закрывает пробел (назначение проекту, провайдер, личный ключ, проверка подключения), теряя контекст диалога. Запрошено: модель — одним сценарием, прямо в чате.

## What Changes

- Панель «Модель для чата» прямо в окне чата: при выбранном проекте и отсутствии готовой модели для каждой модели проекта показывается причина и inline-действие — «Добавить в проект», «Настроить провайдера и ключ» или «Проверить подключение» (флаг `chat_model_setup`).
- Цепочка провайдера и ключа переиспользует владельцев каталога: общий адрес — только главный администратор (CAS), личный ключ — «Мой доступ»; после сохранения провайдера открывается шаг личного ключа с уведомлением.
- После каждого действия каталог перечитывается; socket-автообновление и переход «Подключить модель» в каталог сохраняются.
- Флаг off — прежний welcome-текст и переход в каталог без изменений.

## Capabilities

### New Capabilities

- `chat-model-setup`: готовность модели для чата без перехода в каталог.

### Modified Capabilities

Нет. Переиспользуются существующие API назначений, провайдеров и hosting.

## Impact

ModelChat (новая панель, чистый хелпер, стили), каталог флагов (JSON + union), тесты и справка. API и компоненты ModelCatalog не изменяются.
