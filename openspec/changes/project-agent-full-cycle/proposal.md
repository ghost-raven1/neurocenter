# Proposal

## Why

Полный BMAD/OpenSpec цикл пока использует default agent локального OpenCode. Выбор проектного агента должен определять фактического исполнителя, его закреплённый профиль и модель, чтобы команда получала проверяемый результат работы выбранного специалиста.

## What Changes

- Добавить выбор enabled проектного агента для локального полного цикла и сохранять его вместе с точным запросом.
- Сервер фиксирует актуальное назначение и доказанную доставку compiled agent в выбранную папку. Мост проверяет приватную квитанцию и фактические файлы, запускает явный native agent и модель.
- Изменение профиля, модели, привязки или локальных файлов блокирует новый dispatch; старый результат и восстановление не повторяют исполнение.
- Ввести отдельные флаг и capability; сохранить прежние workflow без выбранного агента и их историю.
- Показывать выбранного исполнителя в результате и следующий шаг при отсутствии настройки, без ложного успеха.

## Capabilities

### New Capabilities

- `project-agent-execution`: полный цикл выбранного проектного агента через проверенную native-конфигурацию и существующий мост.

### Modified Capabilities

Нет архивированных main specs. Новый контракт расширяет работу методик из изменения `role-chats-and-agent-methods`, сохраняя совместимость прежних заданий.

## Impact

Shared workflow contract, Catalog agent-method jobs и fresh authorization, project-agent configuration receipts, локальный method executor/OpenCode HTTP runner, frontend AgentMethods/AgentCatalog, feature flags и scoped regression. Новая очередь/таблица и универсальная изоляция project plugins не требуются.
